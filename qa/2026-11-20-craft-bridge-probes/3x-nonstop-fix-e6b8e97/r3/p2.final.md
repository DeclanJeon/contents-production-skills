**Using creative-production**으로 라우팅했습니다. 텍스트 전용이고, 승인된 생성·렌더 실행은 없습니다. 모션 스타일 사전의 키네틱 타이포 계열에서 골랐고 파일은 만들지 않았습니다.

## 1. 추천 스타일: 푸시인 타이포 (기본) + 셔터 밴드 (보조)

**선택 이유**
- 앱·SaaS 런칭 티저용 스타일입니다.
- 카메라가 큰 단어 층을 계속 뚫고 전진해 로고에 도착하는 구조라, 글자 자체가 움직임이고 전환도 겸합니다.
- 원 스타일은 6–15초용입니다. 30초에는 비트를 6–7개로 늘리고, 중간에 셔터 밴드의 가로 색 띠 전환을 1–2번만 섞어 단조로움을 깹니다.

**대안**
- 플랫 비트: 경쾌한 음악에 컷으로 가는 소비자 앱용입니다.
- 벨로시티 라인: 속도·성능이 핵심 메시지일 때 씁니다.

## 2. 화면 구성 (16:9, 시작값)

- **색:** 종이색 `#F2EEE6` 단색 바탕에 잉크 `#16161A` 글자를 쓰고, 핵심어에만 `#F0532B` 포인트를 줍니다. 노랑 `#F7C534` 슬래시는 날아 지나가는 용도로만 씁니다.
- **서체:** 굵은 그로테스크 대문자(한글은 굵은 고딕)를 씁니다. 레이어당 2–3단어 이하, 같은 중심축에 놓습니다.
- **UI 장면:** 기능 비트에는 **실제 앱 화면**을 폰/창 목업으로 넣습니다. 이 화면은 사용자가 제공해야 합니다.
- **엔드 카드:** 정상 크기의 로고, 제품명, 한 줄 약속을 놓습니다.
- **안전 여백:** 주요 단어는 좌우 각 10% 이상 안쪽에 둡니다.
- **우선순위:** 승인된 브랜드 키트(색·글꼴)가 있으면 위 값보다 우선합니다. 포인트색만 일대일로 교체합니다.

## 3. 움직임 설계 (30초 타임라인안)

| 구간 | 내용 | 움직임 |
|---|---|---|
| 0–3s | 훅: 문제 단어 1개 | 60%→100%로 자라며 등장하고 0.5초 이상 정지합니다. |
| 3–8s | 전환 문장 ("이제…") | 앞 레이어가 600–900%로 6–12px 블러를 입고 지나갑니다. 다음 레이어는 150–250ms 겹쳐 올라와 빈 프레임이 없습니다. |
| 8–13s | 기능 1 | 단어가 푸시인으로 들어온 뒤 앱 화면 카드로 이어집니다. |
| 13–18s | 기능 2 | 중간에 셔터 밴드를 한 번 씁니다(띠 300–350ms, 30–40ms 간격). |
| 18–23s | 기능 3 | 푸시인으로 복귀합니다. |
| 23–27s | 약속 한 줄 (핵심어만 포인트색) | 레이어가 자라며 정지하고, 이어서 로고로 푸시합니다. |
| 27–30s | 엔드 카드 | 0.8초에 안착하고 **2초 이상 유지**합니다. |

**타이밍 규칙**
- 레이어는 0.8–1.2초에 자라고, 0.4–0.6초에 지나가며 사라집니다.
- 카메라는 멈추지 않습니다. 회전과 기울임은 쓰지 않습니다.
- 이징은 튀지 않는 감속형으로 통일합니다.
- 컷과 전환은 음악 비트 ±2프레임에 맞춥니다. 음악이 없으면 BPM만 먼저 정합니다.
- 음악·내레이션을 새로 생성하려면 별도 동의가 필요합니다.

**피할 것**
- 레이어당 세 단어 초과
- 푸시 안의 작은 본문
- 푸시 대신 컷
- 포인트색 둘 이상
- 지어낸 수치·사양·후기

## 4. 검수 기준

**가독성**
- [ ] 모든 레이어가 정지 상태에서 0.5초 이상 읽힙니다.
- [ ] 빈 프레임이 없습니다.
- [ ] 글자 잘림이 없고 주인공 단어가 프레임 안에 있습니다.
- [ ] 글자와 바탕 대비가 3:1 이상입니다.

**타이밍**
- [ ] 컷이 비트 ±2프레임 안에 있습니다.
- [ ] 셔터 전환은 띠가 프레임을 완전히 덮은 뒤에 교체합니다.
- [ ] 셔터는 30초에 2번 이하입니다.

**일관성**
- [ ] 장면당 포인트 요소가 하나입니다.
- [ ] 모든 장면이 같은 움직임 언어(푸시인)를 씁니다.

**사실성**
- [ ] 기능 문구와 앱 화면이 실제 제품과 같습니다.
- [ ] 수치와 인용은 공급된 값만 씁니다.

**엔드 카드**
- [ ] 로고가 선명하고 2초 이상 정지합니다.
- [ ] CTA는 목적지(URL·스토어)가 제공됐을 때만 넣습니다.

**프레임 확인**
- [ ] 키 프레임(각 비트 첫 정지 프레임, 셔터 전환 중간, 엔드 카드)을 프레임 단위로 직접 봤습니다.
- [ ] 폰 크기에서도 읽히는지 확인했습니다.

## 5. 확정을 위해 필요한 입력

1. 앱 이름, 로고, 브랜드 색·글꼴
2. 기능 3개 (각각 짧은 한 줄)
3. 실제 앱 화면 캡처나 녹화
4. 음악 트랙이나 BPM
5. 엔드 카드 CTA (URL·스토어 링크)

입력이 오면 비트별 카피, 프레임 단위 타임코드, Remotion/FFmpeg 제작 계획까지 이어서 정리할 수 있습니다. 실제 렌더와 생성 실행은 별도 승인 뒤에 진행합니다.
