**Using creative-production**으로 모션 스타일 요청을 처리했습니다. 모션 스타일 사전(33)에서 키네틱 타이포 계열만 열어 아래 값을 가져왔습니다. 텍스트 답변만 하고 파일은 만들지 않았습니다.

## 1. 추천 스타일: 푸시인 타이포
- 선택 이유: 이 스타일은 앱·SaaS 런칭 티저를 위한 것입니다. 카메라가 큰 단어 층을 계속 뚫고 전진해서 로고에 도착합니다. 키네틱 타이포 느낌이 가장 직접적으로 나고, 구성이 단순해서 30초를 끌고 가기 좋습니다.
- 대안은 두 가지입니다.
  - **플랫 비트**: 경쾌한 음악에 맞춰 단색 전체화면을 하드컷합니다. 소비자용 앱이고 음악이 중심일 때 어울립니다.
  - **셔터 밴드**: 가로 색 띠가 전환과 타이포를 겸합니다. 더 펀치 있는 인상을 원할 때 씁니다.
- 원본 사양은 6–15초용입니다. 30초로 늘리면서 카피 비트를 3–5개에서 5개로 맞추고, 비트마다 레이어를 2–3개씩 두는 방식으로 조정했습니다.

## 2. 화면 구성 (1920×1080, 시작값)
- **배경**: 종이색 `#F2EEE6` 단색입니다.
- **글자**: 굵은 고딕을 레이어당 2–3단어로 쓰고 잉크색은 `#16161A`입니다. 모든 레이어는 같은 축의 정중앙에 둡니다. 한글은 대문자가 없으므로, 영문을 병기할 때만 대문자를 씁니다.
- **색**: 핵심어에만 `#F0532B`를 쓰고, 노랑 `#F7C534` 슬래시가 날아 지나가게 합니다.
- **엔드 카드**: 정상 크기의 로고, 앱 이름, 한 줄 약속을 둡니다.
- **우선순위**: 승인된 브랜드 키트, 색, 글꼴이 있으면 위 값보다 먼저 적용합니다.

## 3. 움직임·타이밍
- **레이어 진입**: 0.8–1.2초 동안 약 60%에서 100%로 자랍니다.
- **레이어 퇴장**: 0.4–0.6초 동안 600–900%로 커지고 6–12px 블러가 들어가며 지나가고 사라집니다.
- **레이어 연결**: 다음 레이어가 150–250ms 겹쳐 올라오게 해서 빈 프레임이 없게 합니다. 카메라는 멈추지 않고, 회전이나 기울임도 없습니다.
- **엔드 카드**: 0.8초에 안착하고 2초 이상 유지합니다.

**30초 배분안** (제 제안이고 비트 수는 조정 가능)

| 구간 | 내용 |
|---|---|
| 0–4초 | 훅: 사용자가 겪는 문제를 말하는 단어 레이어 |
| 4–12초 | 전환과 약속: 앱의 핵심 가치를 2–3 레이어로 |
| 12–22초 | 기능 한 줄씩 3개, 각 약 3초 |
| 22–27초 | 클라이맥스: 앱 이름 공개, 핵심어를 주황으로 |
| 27–30초 | 로고·약속 엔드 카드를 2초 이상 정지 유지 |

기능 설명에 UI 화면이 필요하면 푸시 안에 작은 본문을 넣지 말고 정지 카드로 따로 넣으세요. 이 카드는 원본에 없는 확장안이라 별도로 합의하는 편이 좋습니다.

## 4. 피할 것
- 레이어당 3단어를 넘기는 것
- 푸시 대신 컷으로 넘기는 것
- 푸시 안에 작은 본문을 넣는 것
- 카메라 회전과 기울임
- 지어낸 수치, 인용, 사양

## 5. 검수 기준
1. 각 레이어가 정지 상태에서 0.5초 이상 읽힙니다.
2. 빈 프레임이 없습니다.
3. 최종 로고가 선명하고 2초 이상 유지됩니다.
4. 강조색이 비트당 하나이고, 노랑 슬래시는 장식으로만 쓰입니다.
5. 16:9 안전 여백에서 글자가 잘리지 않고, 모든 단어에 최소 3:1 대비가 있습니다.
6. 키 프레임(각 비트의 정지 순간, 전환 중간, 엔드 카드)을 프레임 단위로 실제 확인합니다.
7. 모든 수치와 문구가 공급된 값과 일치합니다.

## 6. 정하면 좋은 입력
- 앱 이름과 로고
- 카피 5비트 (문제, 전환, 기능 3개 등)
- 브랜드 색과 글꼴
- 음악 사용 여부와 BPM. 음악이 있으면 레이어 전환을 비트에 맞춰 조정합니다.
- 실제로 인용할 수치가 있는지 (없으면 수치 없이 갑니다)

이 값을 주시면 비트별 카피 배치와 프레임 단위 타임라인으로 구체화하겠습니다. 이미지·음성·음악 생성이나 렌더링은 별도 승인이 필요합니다.
