## 1. 결론 먼저

**주 스타일: 플랫 비트(Flat Beat) 기반 키네틱 타이포 + 앱 화면 증거 삽입 + 1회성 푸시인 공개**

이유: 30초 16:9 앱 런칭은 (a) 박자로 끊는 리듬이 있어야 "키네틱"이 살고, (b) 앱은 화면이 증거라서 타이포만으로는 공허해지고, (c) 30초는 와우 모먼트를 한 번만 쓸 수 있는 길이다. 세 조건을 동시에 만족하는 조합은 이 하나다.

- **리듬 뼈대** = 플랫 비트: 단색 전체화면 하드컷, 컷마다 둥근 굵은 단어 하나
- **제품 증거** = 코랄 타이틀 카드 구조: 타이틀 카드 ↔ 실제 앱 화면(폰 목업) 교차, 카드 사이 하드컷
- **와우 1회** = 푸시인 타이포: 카메라가 단어 레이어를 뚫고 전진해 앱 화면/로고에 도착 (앱 이름 공개 순간에만)
- **금지**: 셔터 밴드·에코 스택·스플릿 슬롯을 같이 쓰지 않는다. 전환 기법 1계열, 이징 1계열, 모티프 1개.

**대안 후보(택1 시 교체 근거)**

| 후보 | 30초 앱 런칭 적합 | 강점 | 리스크 |
|---|---|---|---|
| **플랫 비트 (채택)** | ★★★★☆ | 비트 컷·단어 1개·엔드 워드마크로 30초를 정확히 채움 | 앱 화면 증거 없으면 공허 → 화면 3장 필수 |
| 푸시인 타이포 단독 | ★★★☆☆ | 앱/SaaS 티저 정통, 압도적 전진감 | 원형이 6–15초 → 30초 전체로 늘리면 "계속 밀기"로 피로, 제품 정보 전달 약함 |
| 셔터 밴드 단독 | ★★★☆☆ | 단어 교체 펀치 + 전환 겸용 | 30초에 4회 초과 셔터는 소음, 앱 화면 넣을 자리가 애매 |
| 에코 스택 단독 | ★★☆☆☆ | 단어 4–6개 티저에 최적 | 30초에는 정보량 부족, 앱 기능 3개를 담기 어려움 |

> 브랜드 키트(색·폰트·로고 클리어스페이스)가 오면 아래 시작값보다 **브랜드가 항상 우선**한다. 지금 제시한 HEX·px는 승인 전 기본값이다.

## 2. 화면 구성 (Composition)

### 2.1 캔버스·그리드
- 1920×1080, 30fps, 16:9. 총 900프레임 = 30.0초
- **타이틀 세이프**: 상하좌우 5%(96px/54px) 안쪽. 하단 12%(≈130px)는 자막·플랫폼 UI 회피 여백으로 비워 둔다
- 텍스트 한 줄 최대 폭 = 프레임 폭 80%. 그 이상은 줄바꿈이 아니라 **카피 단축**으로 해결
- 중앙 정렬 단일 축(플랫 비트 규칙). 좌우 분할은 "카드 ↔ 폰" 교차 컷에서만
- 한 프레임에 시선을 다투는 요소 **1개**. 히어로 = 그 컷의 단어 또는 앱 화면 하나

### 2.2 타입 위계 (3층 고정)
| 층 | 역할 | 크기 시작값 | 색 |
|---|---|---|---|
| 히어로 | 컷당 1–3단어 | 180–260px, 자간 -2~-4% | 배경 대비 4.5:1 이상 |
| 서포트 | 라벨·기능명·수치 | 60–72px | 히어로보다 명도 낮게 |
| 텍스처 | 인덱스(01/02/03)·얇은 규칙선 | 22–28px | 40–60% 불투명 |

- 폰트는 디스플레이 1종 + 본문 1종. **그라디언트 채움은 앱 이름에만 1회**, 나머지는 단색
- 헤드라인·수치는 이미지에 굽지 않고 살아 있는 텍스트로 둔다(수정·자막 대응)

### 2.3 팔레트 (시작값)
- 크림 `#F7F1E8` / 코랄 `#FF5A5F` / 네이비 `#16213E` / 선 `#FFD166` / 청록 `#2EC4B6`
- **컷마다 단색 배경 하나**, 한 배경에 두 색 금지, 포인트 요소는 화면당 1개
- 색 면적 비율 대략 70(바탕) : 25(잉크/타입) : 5(포인트)

### 2.4 앱 증거 화면 구성
- 폰 목업: 실제 앱 화면을 **늘리지 않고** 비율 유지, 모서리 46px, 복숭아 `#FFE6DC` 바탕 위
- 화면 점유: 목업 높이 = 프레임 높이 68–75%, 좌우 여백 대칭
- 화면 옆 제목 60–64px, 목업과 텍스트는 **겹치지 않게** 분리
- 목업 안 콘텐츠는 로렘 입숨·가짜 평점·가짜 지표 금지 — 실제 화면만
- 폰 3대 부채꼴 배치는 1회만, 100ms 간격, 정지 후 최소 1.2초

## 4. 움직임 규칙 (Motion)

### 4.1 한 작품 = 한 세트
- **이징 계열 1개**: 등장 `cubic-bezier(0.22,1,0.36,1)`(감속), 퇴장은 그 반대(가속). 세 번째 곡선 금지
- **시간 단위**: 0.4s 기준. 미세 0.2s / 표준 0.4s / 큰 이동 0.8s / 대형 공개 0.9–1.8s
- **스태거**: 60–80ms(단어), 문자 단위는 40ms. 한 묶음 전체 500ms 이내
- **오버슈트**: 2% 이하(스케일 1.02→1.00). 앱 화면 목업은 0%에 가깝게 — 정밀 기구는 튕기지 않는다
- **컷 규칙**: 모든 색 전환은 컷. 페이드·디졸브·와이프 사용 금지(플랫 비트 규칙). 컷은 비트 ±2프레임
- **홀드 규율**: 모든 읽기 단어 최소 0.5초, 앱 화면 1.2초 이상, 로고 1.5초 이상. 비트 직후 0.3초는 정지

### 4.2 위계와 안무
- 히어로가 먼저 또는 가장 두드러지게, 서포트가 응답, 텍스처는 마지막에 낮게
- 위에서부터 움직이고 **먼저 멈춘다**. 화면 전체를 동시에 움직이지 않는다
- 에너지 곡선: 낮은 시작 → 빌드(C8–C10) → 피크(C12) → 정돈된 엔드카드
- 컷 사이 빈 프레임 금지: 다음 컷은 앞 컷이 떠난 방향으로 이미 움직이며 들어온다(푸시인 C6 예외 — 연속 전진이 규칙)

### 4.3 금지 목록
- 비트를 벗어난 컷, 그라디언트·사진 배경, 컷당 4단어 초과, 한 배경 두 색
- 읽는 중인 텍스트 위 루프 모션, 남은 모션블러, 회전·기울임(영상 전체 1회·≤12° 초과 금지)
- 스트로브, 반복 깜빡임, 장식용 파티클로 약한 구도 덮기
- 지어낸 수치·평점·"1위"·스토어 배지(입점 안 한 것)

### 5.1 계획 단계 — 지금 이 문서에 적용 (실행 가능)

### 5.2 렌더 후 검수 — **현재 UNVERIFIED** (파일 없음)
실제 출력이 생기면 이 순서로:
1. **프레임 정지 비교**: 14컷 각각의 홀드 프레임을 비트맵 표와 1:1 대조(레이아웃·카피·크롭)
2. **이음매 훑기**: 컷 경계 ±5프레임을 프레임 단위로 — 빈 프레임·중복 프레임·1프레임 깜빡임
3. **가독성**: 히어로 단어 0.5초 이상 유지, 앱 화면 1.2초, 로고 1.5초. 대비 3:1 이상(본문 4.5:1)
4. **비트 정렬**: 컷이 음악 비트 ±2프레임. 오디오 없으면 리듬 판정 보류로 표기
5. **모션 규율**: 샷별로 같은 움직임에 같은 이징인가, 길이가 0.4s 배수인가, 오버슈트 2% 이하인가
6. **기술 스펙**: `ffprobe`로 1920×1080 / 30fps / 길이 30.0s / 색 태그 bt709 / 오디오 트랙 존재
7. **감도**: 모션 감소 버전은 최종 마크만 정지 노출 경로 필수

판정은 `pass / pass_with_notes / needs_revision` + **검사 범위 명시**. 눈으로 본 것과 명세만 한 것을 섞지 않는다. 지금 상태는 "계획 검수 통과, 실제 렌더·가독성·비트 정렬은 미검증".
