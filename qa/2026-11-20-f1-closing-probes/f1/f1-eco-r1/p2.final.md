## 1. 선택: 푸시인 타이포 (Push-in Type) — 단일 스타일

| 후보 | 판정 | 이유 |
|---|---|---|
| **푸시인 타이포** | **채택** | 사전에서 "앱·SaaS 런칭 티저"로 명시된 유일한 키네틱 계열. 카메라가 멈추지 않고 단어 레이어를 뚫고 전진 → 30초 내내 하나의 메커니즘으로 유지 가능 |
| 플랫 비트 | 보류 | 컷마다 배경색 하드컷 = 30초에 15컷 이상 필요, 앱 UI 증거를 넣을 자리가 없음 |
| 매니페스토 팝 | 보류 | 문제→전환→제품 선언문 구조는 맞지만 점 입자·원 그라디언트가 키네틱 타이포보다 장식 중심 |
| 에코 스택 | 탈락 | 비트당 단어 1개 × 4–6단어 = 6–10초용 템포 |
| (참고) 코랄 타이틀 카드 | 탈락 | 앱 출시 전용이지만 product-commerce 계열 = 키네틱 타이포 아님. 이번 요청 축과 불일치 |

**핵심 결정 하나**: 타이포가 문법의 주인, 실제 앱 화면은 증거 컷. 30초를 타이포만으로 채우면 후반이 단조로워지고 "제품이 실제로 뭘 하는지"가 0이 됩니다(08a 제품 필름 검수 항목 위반). 따라서 9.6–16.8초는 **전진 push를 유지한 채 레이어만 실제 화면으로 교체**합니다. 화면 미공급이면 그 구간은 타이포로 대체하고 **가짜 UI를 만들지 않습니다**.

## 3. 30초 비트맵 (시간 → takeaway → 초점 → 변형 → 카피/오디오 → 퇴장)

|---|---|---|---|---|---|---|
| 1 | 0.0–2.4 (0–72) | 이 영상이 뭘 대체하는지 | 히어로 단어 1–2개 | 60→100% 0.9초 push, 정지 0.8초 | `[동작 단어]` | 600→800% + 블러 통과 0.5초 |
| 2 | 2.4–4.8 | 지금 방식의 마찰 | 문제 문구 3단어 | 진입 0.8초, 스태거 70ms | `[문제 A]` | 통과 0.4초 |
| 3 | 4.8–7.2 | 마찰이 반복된다는 감각 | 문제 문구 2번째 | 레이어 2가 앞 레이어를 밀어냄 | `[문제 B]` | 통과 0.4초 |
| 4 | 7.2–9.6 | 전환점 | 단어 1개 + 노란 슬래시 | 슬래시가 화면을 가로지름 (영상당 1회) | `[전환 동사]` | 슬래시가 UI를 열며 소멸 |

| 7 | 14.4–16.8 | 실제로 하는 일 3 | 실제 앱 화면 | 마지막 컷만 1.5배까지 더 밀고 정지 | 라벨 2단어 | 타입이 화면 위로 재진입 |

## 4. 화면 구성 (16:9 그리드)

- **축**: 중앙 세로축 하나. 모든 레이어는 같은 축에 정렬하고 좌우로 흩지 않음(전진 push가 축을 벗어나면 흔들림으로 읽힘).
- **안전 여백**: 좌우 8%(154px), 상하 10%(108px). 하단 15%(162px)는 자막·플랫폼 UI 회피 구역 — 로고·핵심 단어 금지.
- **타입 스케일**: 히어로 단어 300–340px / 2–3단어 160–200px / 라벨 64–80px / 태그라인 48–56px. 행간 0.92, 레이어당 최대 3단어·3줄.
- **채움률**: 정지 판독 프레임에서 줄 너비 62–86%. 통과 중에만 100% 초과 허용.
- **3층**: 후경(플랫 배경+그레인) / 중경(타이포·UI) / 전경(슬래시·강조 1요소). 층마다 움직임 원인이 하나.
- **UI 배치**: 화면 중앙~우측 2/3. 같은 프레임에 타입과 UI를 동일 무게로 두지 않음 — 타입이 주인 컷에서는 UI를 하단 20% 띠나 블러 아웃으로 후퇴. UI는 비율 유지, 1.6–2.2배 크롭, 늘이지 않음, 모서리 12px 고정, 그림자 없음.
- **앵커**: 프레임마다 시선이 머물 닻 1개(보통 정지한 마지막 단어). 전 요소가 동시에 출발하지 않음.

## 5. 움직임 규칙 (실행 값)

1. **카메라 불정지**: 레이어 진입 0.8–1.2초에 60→100%, 통과 0.4–0.6초에 600–900% + 6–12px 모션블러. 다음 레이어는 150–250ms 겹쳐 올라와 **빈 프레임 0**.
2. **등장 > 퇴장**: 등장을 퇴장보다 30–50% 길게. 등장 감속, 퇴장 가속.
3. **주도–응답**: 주 동작(단어 push) 먼저, 보조(라벨·그림자·슬래시)가 100–200ms 뒤 응답. 앰비언트 층은 읽기 방해할 때만.
4. **의미 없는 반복 금지**: 같은 push를 11번 반복하면 슬라이드쇼로 읽힘 → 4번(슬래시)·7번(더 깊은 push)·10번(축소 정지)에서 변주 3개를 미리 배정.
5. **홀드**: 08a 문법 검사대로 "안정된 읽기 창"을 레이어마다 확보. 정지가 리듬 도구이고, 정지 중 텍스트는 루프·드리프트 없음.
6. **오디오**: 음악 미공급 상태 → 지금은 무음 기준으로 컷 그리드만 확정. 트랙이 오면 액센트를 위 비트맵에 ±2프레임으로 재정렬(음악은 음성보다 낮게). 보이스오버는 공급 전까지 만들지 않음.

## 6. 검수 기준

**판정 형식**: `pass` / `pass_with_notes` / `needs_revision` + 검사 범위 명시. 미실행은 `failed`가 아니라 **UNVERIFIED**.

| ID | 항목 | 합격선 | 방법 |
|---|---|---|---|
| A | 비트 정렬 | 컷·강조가 0.6초 그리드 ±2프레임(±67ms) | 타임라인 마커 전수 대조 |
| B | 판독 홀드 | 레이어 정지 ≥0.5초, 문장형 ≥ 단어수×0.25+0.4초 | 프레임 스텝 |
| C | 빈 프레임 | 이음매 ±5프레임에 텍스트·UI 없는 프레임 0 | 이음매 전수 훑기 |
| D | 시선 경쟁 | 프레임당 주 요소 1개 (뒤 샷 히어로 재등장은 예외) | 정지 프레임 |
| E | 상수 일관성 | 이징 곡선 ≤2개, 모든 길이가 0.3의 배수, linear 0 | 키프레임 속성 검사 |
| F | 안전·클리핑 | 안전 여백 침범 0, 글자 잘림 0, 기준선 흔들림 0 | 가이드 오버레이 |
| G | 대비 | 헤드라인 ≥3:1, 라벨·태그라인 ≥4.5:1 | 명도 샘플링 |
| H | UI 무왜곡 | 종횡비 유지(늘어남 0), 실제 화면과 내용 1:1, 가짜 UI 0 | 원본 캡처 대조 |
| I | 근거 | 숫자·인용·사양·날짜는 공급값만, 임의 반올림 0, 출처 표기 | 카피 원장 대조 |
| J | 색 | 팔레트 3색+중립, 포인트색 프레임당 1회, 밴딩 0 | 시작/중간/끝 캡처 |
| K | 로고·엔드카드 | 클리어스페이스 침범 0, ≥2초 정지, 모션감소용 정지 프레임 존재 | 고정 프레임 3장 |
| L | 오디오 (렌더 후만) | 실제 출력에서 트랙 청취, 액센트 시각 ±2프레임 | 재생 청취 |

**현재 상태**: 계획만 완료. A–L 전 항목 `UNVERIFIED` — 렌더·재생·청취를 하지 않았으므로 통과 주장 없음.

**결함 → 결정 규칙**: 슬라이드쇼처럼 보임 → 한 단어를 의미 있는 변형으로 운반 / 텍스트 안 읽힘 → 홀드·대비 강화(카피 단축은 허용 시만) / 바쁨 → 장식 제거 후 인과 동작만 / 무게 없음 → 이동 시간·가감속 조정 / 단조로움 → 샷 스케일과 동작·휴지 교대.
