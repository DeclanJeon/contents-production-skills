---

## 0. 전제

- 구조: **위 줄 = 실제로 말한 언어(원문), 아래 줄 = 번역**. 한국어 인터뷰 + 영어 번역을 기본으로 서술하고, 반대 방향이면 두 줄의 역할만 바꾼다(폰트 규칙은 그대로).
- 녹음·단어 단위 타이밍 대본이 있는 **본인/승인된 발화**에만 적용. 남의 발화에는 얹지 않는다.
- 자막의 **내용·타이밍 측정·caption_mode·접근성**은 15-delivery 정본, 여기서는 **룩과 배치**만 정한다.
- 이름·직함·소속은 **사용자가 준 철자 그대로**. 성·직함·경력을 만들지 않는다.

## 1. 한영 이중 자막 스타일

### 1-1. 블록 구성
| 항목 | 규칙(시작값) |
|---|---|
| 패널 | `rgba(14,18,16,.66)`, 반경 16px, 하단 15% 안전 영역 중앙 정렬 |
| 원문 줄 | 굵은 산세리프, 흰색 `#FFFFFF`, **말한 단어만** `#FFD45C` |
| 번역 줄 | 원문과 같은 너비, 크기는 원문의 약 **70%**, 가는 이탤릭 세리프 또는 같은 산세리프 계열, 색 `#D9E6DC` |
| 줄 수 | **언어당 한 줄**, 줄당 약 42자. 3줄 금지 |
| 간격 | 원문–번역 리딩은 원문 크기의 1.25–1.35배, 번역 줄 optical baseline 정렬 |

- 글꼴은 **두 문자 체계(한글+라틴)를 모두 덮는지 렌더로 확인**한다. 한글용 굵은 산세리프(예: Pretendard/Noto Sans KR 계열)와 라틴 세리프를 섞을 때, 번역 줄의 한글 글리프가 폴백으로 떨어지면 **번역 줄을 같은 산세리프로 통일**한다(이탤릭 세리프는 라틴 전용일 때만).
- 강조색은 **한 계열만**(`#FFD45C`). 두 번째 강조색 금지.

### 1-2. 등장·유지·교체
- 쌍은 **구절의 첫 단어에 컷으로 등장**, 페이드는 150ms 이내.
- 원문 강조는 **측정된 단어 타임코드**를 따른다(글자 수로 균등 분배 금지).
- **번역 줄은 원문보다 120–250ms 늦게** 올린다 → 위 줄을 먼저 읽는 순서를 만든다.
- 쌍 교체는 **구절 경계에서만**, 2–3프레임 간격. 구절 중간 변경 금지.
- 1초를 넘는 침묵에서는 자막을 비운다(필요한 소리 표기는 15-delivery 우선).

### 1-3. 배치·화면비
- 가로(16:9): 얼굴·입·손·제품·플랫폼 UI를 피해 **가슴 높이 이하**. 자막이 입 위로 올라가면 실패.
- 세로(9:16) `inferred`: 폭 80–86%, 블록을 **얼굴 아래·플랫폼 UI 위**로 올리고, 두 줄 구조는 유지하되 줄당 글자 수를 줄인다(3줄로 늘리지 않는다).
- 1:1 인터뷰는 화자 라벨을 넣지 않고 **이름 띠(2절)로 구분**한다. 두 사람이 겹쳐 말할 때만 화자 표기를 넣고, 표기 형식은 브리프·목적지 기준으로 정한다.

### 1-4. 금지 / 검수
- 금지: 말을 바꿔 쓴 자막, 용어집이 유지하는 고유명사·직함 번역, 3줄, 구절보다 오래 남는 번역, 번역이 원문보다 정보를 더하는 것.
- 검수: 1배속에서 **모든 쌍을 두 번 읽을 수 있는가**, 쌍 타이밍 ±2프레임, 번역 등장 지연 120–250ms, 강조가 발화 단어에 ±3프레임, 빠진 글리프 없음, 실제 출력에서 대비·목적지 UI 가림 확인(수치 기준은 15-delivery).

## 2. 하단 이름 자막(로어서드) 디자인 규칙

### 2-1. 텍스트 취급
- **이름 = 사용자 제공 문자열 그대로**(철자·구두점·띄어쓰기). 대문자 처리·자간만 스타일로 바꾼다.
- 둘째 줄(직함·소속)은 **사용자가 준 말로만** 채우고, 없으면 비우거나 뺀다. 추정 금지.
- 한 카드 = 한 사람. 두 사람이면 **순차 등장**(동시 등장 금지).

### 2-2. 형태·배치
| 항목 | 규칙(시작값) |
|---|---|
| 위치 | 좌하단, 모든 픽셀 **가장자리에서 5% 이상 안쪽**, 화면 중앙은 화자를 위해 비움 |
| 이름 | 1080p 기준 **50–80px**, 굵은 산세리프, 흰색 |
| 직함 | 이름의 **약 절반**(24–40px), `#D9E6DC`, 이름보다 낮은 대비 |
| 패널 | `rgba(21,23,28,.88)` 띠 또는 패널 + 미세한 그림자 — 어떤 배경에서도 읽히게. 얇은 밝은 글자를 사진에 직접 얹지 않는다 |
| 포인트 | 왼쪽 3px 세로 라인 또는 하단 라인 한 개, 앰버 `#FFC53D` (브랜드색 없을 때의 시작값) |
| 폭 | 가장 **긴 이름** 기준으로 박스 폭 결정. 넘치면 박스에 맞춰 축소, 닦임·클립 애니메이션은 가장 넓은 내용 기준 |

### 2-3. 타이밍
- 기본 길이 약 8초 = **진입 300–400ms(슬라이드+페이드) → 정지 5–6초 → 퇴장 0.5초**.
- 유지 구간은 **완전 정지**(허용되는 움직임은 느린 광택 하나까지).
- **첫·마지막 프레임은 비운다**(편집 핸들) — 컷에서 튀거나 잘리지 않게.
- 노출 빈도: **첫 등장 1회 + 필요 시 재등장**(직함이 맥락상 다시 필요한 지점). 컷마다 반복 금지.

### 2-4. 자막과의 충돌 규칙
- 로어서드는 **자막 블록 상단에서 최소 24px 위**에 둔다. 공간이 없으면 로어서드가 **먼저 퇴장**하고 자막이 유지된다(자막 우선).
- 우선순위: **얼굴 > 자막 > 로어서드 > 코너 요소**. 코너 버그·구독 알림은 로어서드와 같은 모서리에 두지 않는다.

### 2-5. 검수
- 가장 긴 항목이 들어간 카드의 **정지 프레임**을 어두운 배경·밝은 배경 양쪽에서 확인.
- 사용한 글꼴이 **실제로 로드됐는지**(폴백 렌더 금지), 날짜·성구처럼 숫자가 있으면 라이닝 피겨 글꼴 사용.
- 진입·퇴장 프레임 시트로 글자가 패널보다 먼저 나타나거나 밖으로 나가지 않는지 확인.
- 알파 납품 시(파일 제작 단계): 편집기 = ProRes 4444 `.mov`, 웹·OBS = WebM(+Safari용 HEVC 사본), 알파 미지원 폰 편집기 = 초록 크로마키 MP4. **목적지 확인 후** 결정하며, 알파 없는 H.264를 배경 없이 넘기지 않는다.

## 3. 두 요소를 묶는 시스템 규칙

1. 타이포 계열 **하나**: 원문·이름 = 같은 굵은 산세리프, 번역·직함 = 같은 보조 계열.
2. 강조색 **하나**(`#FFD45C` 또는 브랜드색) — 자막 강조와 로어서드 포인트가 같은 색을 쓴다.
3. 공통 안전 영역: 가장자리 5%, 하단 15%(가로) / 목적지 UI 높이(세로).
4. 등장 모션 단위 하나: 컷 인 또는 300–400ms 1회성 진입. 요소마다 다른 이징을 쓰지 않는다.
5. 화면에 정보 요소는 **동시에 두 개까지**(자막 + 이름 띠 또는 카드 하나). 그 이상은 겹침 사고의 원인.

## 4. 확정이 필요한 입력 (차단 아님, placeholder)

- `[화자 이름]` `[직함/소속]` — 사용자 제공 문자열 그대로 들어감
- 원문 언어 / 번역 언어 방향(한→영 기본 가정), 번역·용어집 확정본
- 목적지·화면비(가로/세로), 플랫폼 UI 높이
- 브랜드 폰트·색(없으면 위 시작값 유지), 자막 방식(burned-in / sidecar) — caption_mode 확정은 15-delivery
- 이름 띠 납품 형식(WebM / ProRes 4444 / 크로마키 MP4)

**미검증 상태:** 위 값은 디자인 제안이며, 실제 렌더 프레임에서의 가독성·타이밍·글리프는 아직 확인되지 않았다(파일 미생성, 요청대로 텍스트만).
