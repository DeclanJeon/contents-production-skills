## 1. 한영 이중 자막 스타일 규칙

**구조**
- 한 쌍 = 위 줄(말한 언어) + 아래 줄(번역). 언어당 **1줄**, 3줄 금지.
- 두 문자 체계(한글+라틴)를 모두 덮는 글꼴 하나로 통일. 폴백 글꼴로 그려지는지 반드시 렌더로 확인.
- 번역은 말한 것보다 더하지 않는다. 고유명사·직함·전문용어는 용어집에 있으면 번역하지 않고 그대로 둔다.
- 같은 화면에 강조색은 하나만.

**시작값**

| 항목 | 값 |
|---|---|
| 패널 | `rgba(14,18,16,.66)`, 반경 16px, 하단 15% 안전 영역 중앙 |
| 원문 | 굵은 산세리프 `#FFFFFF`, 현재 발화 단어만 `#FFD45C` |
| 번역 | 원문과 같은 폭, 크기는 원문의 약 70%, 얇은 이탤릭 세리프 또는 같은 산세리프, `#D9E6DC` |
| 줄 길이 | 약 42자(라틴 기준 시작값) — 한글에 그대로 적용하지 말고 **렌더에서 줄 폭 확인 후 언어별로 확정** |
| 위치 | 하단 3분의 1의 가슴 높이. 얼굴·입·목·플랫폼 UI 회피 |

**타이밍·움직임**
- 쌍은 구절 **첫 단어에 컷으로** 진입, 페이드는 150ms 이내.
- 원문 단어 강조는 측정된 단어 타이밍을 따르고, 구간을 균등 분배하지 않는다(±3프레임 허용).
- 번역 줄은 원문보다 **120–250ms 늦게** 올려 위 줄이 먼저 읽히게 한다.
- 줄 교체는 구절 경계에서만, 2–3프레임 간격. 구절 중간 교체 금지.
- 1초 넘는 침묵에서는 자막을 비운다(필요한 소리 표기는 15 우선).

**금지**
- 말을 바꿔 쓴 자막, 의역으로 원문 의미를 지우는 윤문
- 용어집이 그대로 두는 이름·용어의 번역
- 구절보다 오래 남는 번역 줄, 입 위 자막, 3줄 자막

**검수**: 1배속에서 모든 쌍을 두 번 읽을 수 있는가 / 번역이 원문과 인명·단위·고유명사·화자에서 일치하는가 / 빠진 글리프 없는가 / 강조가 발화 단어에 ±3프레임인가 / 대비·읽기 시간은 실제 출력에서(15 기준).

## 2. 하단 이름 자막(로어서드) 규칙

**텍스트 권한**
- 철자·구두점은 **사용자가 준 그대로**. 대문자 처리만 스타일로 결정.
- 직함·소속·성을 **지어내지 않는다**. 둘째 줄이 없으면 사용자 문구를 쓰거나 뺀다.
- 한/영 병기(예: 홍길동 / Hong Gil-dong)는 사용자가 준 표기만 사용, 임의 로마자화 금지.

**시작값**

| 항목 | 값 |
|---|---|
| 원본 캔버스 | 1920×1080 · 30fps · 약 8초 |
| 길이 구성 | 진입 1초 이내 / 정지 유지 5–6초 / 퇴장 0.5초 |
| 위치 | 좌하단 |
| 안전 영역 | 모든 픽셀은 가장자리에서 5% 이상 안쪽 |
| 이름 | 1080p에서 약 50–80px, 굵게 |
| 직함 | 이름의 약 절반 크기, 낮은 대비 |
| 가독성 | 글자 뒤 패널·띠·진한 그림자로 어떤 배경에서도 읽히게 |
| 점유 | 프레임의 몇 %만. 중앙은 화자를 위해 비운다 |
| 오디오 | 없음(무음) |

**움직임**
- 움직임은 진입·퇴장에만, 유지 구간은 정지(느린 광택 하나까지 허용).
- 첫·마지막 프레임은 비워 편집에서 튀거나 잘리지 않게.
- 인터뷰에서는 **첫 등장 시 한 번** 전체 길이, 이후 재등장은 이름만 짧게(같은 디자인, 별도 카드 파일).

**자막과의 충돌 규칙**
- 자막 패널(하단 중앙)과 로어서드(좌하단)는 같은 하단 영역을 공유한다. 로어서드 상단과 자막 패널 상단 사이 최소 간격을 두고, 로어서드 첫 등장은 자막이 비는 지점(구절 경계·침묵)에 앉힌다.
- 로어서드 때문에 자막을 얼굴 위로 올리지 않는다. 자리를 못 비우면 로어서드를 자막 패널 위 좌측으로 올린다.

**금지·주의**
- 글자 넘침·잘림(긴 이름은 박스에 맞춰 축소, 닦임·클립은 가장 넓은 내용 기준)
- 얇고 연한 글자를 사진 위에 직접 얹기
- 숫자가 있는 카드에서 구식 숫자가 줄 아래로 내려가는 세리프 → 라이닝 숫자 글꼴로 교체하고 스틸로 확인

## 3. 납품 형식

- 목적지별 후보: OBS·스트림 = WebM / Premiere·Resolve·FCP = ProRes 4444 `.mov` / 알파 없는 폰 편집기 = 크로마키용 초록 바탕 MP4. 목적지 미지정만으로 ProRes를 확정하지 않는다.
- 알파 없는 H.264 MP4를 바탕색 없이 내보내지 않는다.
- 검수: 유지 구간 프레임을 바둑판 위 어두운·밝은 배경으로, 진입·퇴장은 프레임별 시트로. WebM·`.mov`는 디코딩해 알파 실재 확인. 자동 점검은 잘림·가독성을 대신하지 못한다.
