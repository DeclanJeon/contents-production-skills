## 1단계 — 멀티캠 동기화 (카메라 2대 + 마이크)

1. 전사 겹침으로 구조를 먼저 판별: 같은 말이 같은 시각에 있으면 별개 앵글, 공유 발화 없이 시간만 이어지면 재시작된 카메라 하나.
2. **동기화 마스터**와 **컷 초안**을 서로 다른 타임라인에 둡니다(중첩 멀티캠 객체 생성 금지).
3. 오프셋은 짐작하지 않고 측정값으로 기록. 흘러가면 클럭 드리프트/프레임 드롭으로 보고.
4. 각 앵글의 시작·중간·끝에서 립싱크를 ±1프레임으로 확인. 신뢰도 낮은 매칭은 숨기지 말고 목록화.

산출물: `sync_offsets`(앵글별 측정 오프셋, 신뢰도, 미검증 항목).

## 2단계 — 숏츠 후보표 (자르기 전에 먼저)

후보표 없이 편집을 시작하지 않습니다.

**후보 1건당 필드**: 시작–끝 시각 / 전사에서 **그대로 인용한 훅 줄** / 원본 없이 단독으로 서는 이유 / 점수 0–100 / 위험(앞 맥락 필요 · 사적 인물 지칭 · 오디오 불명확).

**제안 점수 설계(초안, 외부 표준 아님)**: 단독 이해 30 · 첫 1–3초 훅 25 · 결말 명확 20 · 감정·대비·구체적 예시/숫자 15 · 기술 상태 10.

**시작값**
- 후보 수: 원본 5–10분당 약 1개 → 60분이면 **6–12개**. 할당량이 아니며, 강한 순간이 적으면 채우지 말고 그렇게 보고합니다.
- 우선 제시: 4개 이상(원본이 받쳐 줄 때).
- 길이: **20–75초**, 요청 없으면 90초 초과 금지. 전체 숏츠 합계는 원본 길이의 1/2 이하(≤30분).

**신호**
- 강함: 첫 1–3초 훅, 분명한 결말, 감정·대비, 구체적 예시·숫자
- 위험: 앞 맥락 필요, 목차식 요약, 끊긴 엔딩, 상대방 실명/미공개 정보, 웃음·겹침으로 단어 불명

**결정**: 사용자가 후보를 고릅니다(자동 확정 아님). 고른 뒤에도 각 후보에 "원본 없이 이해되는가 / 첫 줄이 훅인가"를 다시 검사합니다.

## 3단계 — 파일럿 1편 → 스타일 승인 → 나머지 배치

한 편을 끝까지 만들어 스타일(컷 리듬, 9:16 레이아웃, 캡션 위치, 오프닝 처리)을 승인받은 뒤 같은 스타일로 나머지를 배치합니다. 승인 전 일괄 제작 금지.

## 4단계 — 편집 명세 (숏츠 1편당)

**컷 표 필드** (source와 최종 타임라인 분리)
- `shot_id` / 앵글(A·B) / `source_in_s`–`source_out_s` / `final_start_s`–`final_end_s` / `playback_rate`(**샷당 상수 1개**) / 컷 이유(감정·정보·리듬 중 무엇이 바뀌는가) / 전환 / 검수 상태

**멀티캠 화자 추적(16:9 기준 시작값)**
- 말하는 사람 클로즈업, 겹침·웃음·오프닝은 와이드
- 새 화자 발화 시작 후 **4–8프레임 또는 숨**에서 컷, 최소 샷 1.5초
- 두 목소리 0.8초 초과 겹침 → 와이드
- 반응 샷은 듣는 사람 클로즈업 0.5–1초, **눈에 보이는 반응이 있을 때만**, 분당 2개 이하
- 긴 발언은 20–40초마다 와이드로 끊기

**9:16 리프레임 — 후보마다 결정**
- 얼굴·화면 내용이 실제로 어디 있는지 확인한 뒤 결정(무확인 중앙 크롭 금지)
- 1인 화면: 얼굴 추적 크롭 / **2인 대화: 상하 스택 레이아웃** / 화면 공유: 흐린 배경 위 전체 프레임
- 말하는 사람이 잘리는 크롭 금지

**오디오·캡션**
- 훅 문장에서 시작, 군말·긴 공백은 걷되 숨은 남김, 단어 중간 절단 금지
- 캡션은 **전사의 단어 시간**에 맞추고 하단 1/3, 플랫폼 UI와 겹치지 않게
- J/L 컷을 쓰면 오프셋을 프레임으로 기록(미사용이면 생략)
- 음악을 얹으면 원본 음성보다 크지 않게, 권리 근거 없으면 게시 불가로 표시

## 5단계 — 검수 (계획 대 실측)

- 각 숏츠를 **실제 재생**으로 확인: 원본 없이 이해되는가, 첫 줄이 훅인가, 캡션이 발화와 맞는가, 크롭이 화자를 자르지 않는가, 화자 교체 컷이 활성 음성을 따르는가
- 전체 길이·컷 간 방향성, 계획 `final_end_s` 대 실측 차이
- 재생 전 판정은 전부 `UNVERIFIED`. 표본 프레임만 보고 리듬 통과 판정 금지
- 납품 규격·음량·해상도는 목적지 규격 확인 후 **실제 파일에서** 측정
