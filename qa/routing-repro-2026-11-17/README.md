# 세션 간 재현성 (독립 프로세스 3회 비교)

질문: **같은 케이스를 새 프로세스에서 다시 물으면 같은 route가 나오는가?**
정확도와 다른 질문이다. 두 번 100%를 받아도 매번 다른 케이스에서 틀릴 수 있다.

## 결과

| 비교 | 공유 케이스 | 동일 route | 일치율 |
|---|---|---|---|
| stability(53×3) ↔ repro(53×1) | 53 | **53** | **100.0%** |
| flake(26×8) ↔ repro(53×1) | 26 | **26** | **100.0%** |

세 번의 **서로 다른 프로세스**가 53개 케이스 전부에서 같은 route를 냈다.
이 회차 자체도 53/53 정답, 인프라 실패 0.

도구: `scripts/routing_repro_check.py` (두 `summary.json`을 케이스별로 비교)

## 무엇을 비교했고 무엇을 안 했는지

비교한 것:
- 별개 프로세스 실행(각각 새 픽스처, 새 봉인 `CODEX_HOME`)
- 서로 다른 날이 아니라 **같은 날 연속**. 날짜 간 드리프트는 여전히 미측정이다.
- 같은 모델 `gpt-6.1-sol`, 같은 머신.

비교하지 않은 것:
- 모델 버전 변경 시 재현성
- 백엔드 모델이 조용히 바뀌었을 때의 드리프트 (같은 이름, 다른 가중치일 수 있음)
- 실제 사용자 발화 분포

## 일치율은 정확도가 아니다

`routing_repro_check.py`는 **틀린 route에 두 번 일치해도 "재현됨"으로 센다.**
그래서 이 표는 반드시 각 런의 정확도와 함께 읽어야 하고, 도구도 그 문장을
매번 출력한다. 일치율만 인용하면 "일관되게 틀리고 있다"를 "안정적"으로
오독하게 된다.

## 폐기한 열화 회차

`qa/routing-repro-2026-11-17-degraded/` — 53케이스 중 14건이 `codex exit 101`로
실패해 판정에 쓰지 않았다. 그 회차가 하네스 결함을 하나 드러냈다: 크래시를
"일관되게 틀린 케이스"로 표기하고 있었다. 수정 내용은 해당 디렉터리의
`SUPERSEDED.md`에 있다.

## 재현

```bash
ROUTING_EVAL_TMP=/path/with/disk \
  python3 scripts/routing_eval.py --repeat 1 --retries 5 --out qa/routing-repro-<date>

```
