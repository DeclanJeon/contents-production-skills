## 발견 사항

### F01 · P1 — 상태 기입을 전량 분석 단계의 종료 조건으로 삼고 있다

**위치:** 설계 18, 121–129, 146–152행.

**문제:** C단계 종료 기준은 “92개 모두의 구간 상태가 명시”되는 것이다. 반면 직접 영상 연속 시청·음향 청취 수단은 미검증이고, 불가능한 항목을 BLOCKED로 남길 수 있다. 4개 파일럿만 검사하고 88개는 미검토 상태·공백을 정확히 기입해도 이 C 종료 문장 자체는 충족할 수 있다. 문서가 전체 완료의 허위 선언을 별도로 금지하는 점은 맞지만, C를 통과해 D/E로 가기 위한 실질적 전량 내용 검토 기준은 없다.

**영향:** “미완료를 정직하게 보고하는 방법”은 있으나 사용자가 선택한 “92개 전량 분석”을 달성하거나 확장을 멈추게 하는 계약은 부족하다. 특히 준비 안 된 매체 검사를 그대로 둔 채 수십 개의 추가 추출·기록 작업으로 확장할 수 있다.

**수정:**
1. 인벤토리 완료, 내용 검사 완료, 부분 산출물 인계, BLOCKED 중단을 다른 단계 상태로 정의한다.
2. 92개 각각의 시간 구간·해당 분석 영역·실제 검사 모드에 대해 검사 완료 조건을 둔다. 구간 상태를 적었다는 사실만으로 내용 검사 완료가 되지 않게 한다.
3. 파일럿 종료 시 모드별 GO/STOP 관문을 둔다. 필수 모드가 미지원이면 해당 모드의 전량 확장은 STOP이고 영향 범위·해결에 필요한 권한·재개 증거를 남긴다.
4. 독립적인 정적 시각 작업은 계속할 수 있으나, 그것이 “전량 분석을 끝낸 다음의 통합 단계”로 오인되지 않게 부분 작업 경로로 구분한다.
5. 미검토/실패/UNKNOWN을 0으로 덮지 않고 보존하는 현 정책은 유지한다. 무리한 전 프레임 시청 보장으로 대체하지 않는다.

**재QA 시나리오:** `4 reviewed + 88 NOT REVIEWED`, `92 probes + 0 content review`, `정적 시각 확인 + 필수 음향 UNKNOWN`을 넣었을 때 전량 내용 검사 통과는 모두 거부하고 부분 결과만 인계되는지 검사한다.

### F02 · P1 — 수정 전후 행동 평가의 비교 조건과 합격 기준이 고정되지 않았다

**위치:** 설계 137, 188–198행. 관련 과거 기록: `docs/implementation/2026-10-12-rofan-craft-skill-test-plan.md` 36, 42–46, 127–137, 163–173행.

**문제:** fresh-context 5회와 수동 판정은 있으나, baseline 전에 고정할 과제/채점 항목, 양쪽 입력의 동등성, 모델·설정/패키지 버전 기록, 평가용 정답·과거 응답의 실행 컨텍스트 배제, 통과/회귀/중단 기준이 계약으로 없다. “동등한 브리프”만으로는 모델·프롬프트·제공 근거를 바꾸고 결과를 개선으로 해석하는 것을 막지 못한다.

**실제 관련성:** 같은 저장소의 과거 테스트 기록은 prompt/context/rubric 불일치 때문에 채워진 crosswalk를 요구하면서 실제로 필요한 semantic ledger·owner template을 제공하지 않아 기준을 충분히 검사할 수 없었던 실패를 명시한다. 따라서 단순한 이상적인 추가 요구가 아니라 재발 방지가 필요한 기존 실패 유형이다.

**수정:**
1. 구체적 테스트 과제는 구현 계획에서 작성하더라도, baseline 전에 prompt·semantic rubric·안전 실패·수락 기준을 고정한다는 원칙은 설계에 둔다.
2. old/new 조건은 동일 과제·동일 근거·동일 모델/설정 또는 실제 차이의 공개를 요구한다. 패키지·컨텍스트 파일 목록/해시, raw response, run status를 보존한다.
3. 실행 에이전트의 context에서 rubric·정답·이전 응답·현재 설계의 기대 출력 예시를 제외한다. 채점은 그 뒤 별도 단계에서 한다.
4. 각 필수 항목의 합격 기준, 안전 실패 시 승격 금지, 무관한 브리프의 회귀 허용 여부, 오류/미완료 실행 처리와 재시험 기준을 사전 명시한다. 구체적 문구·개별 과제는 담당자에게 남겨도 된다.
5. 작게 반복한 결과는 기술적/서술적 증거로만 보고하며 통계적·인과적 품질 향상을 주장하지 않는 기존 제한은 유지한다.

**재QA 시나리오:** baseline/green에서 제공 템플릿 또는 모델이 달라진 경우, rubric이 실행 에이전트에게 노출된 경우, 안전 실패가 있지만 나머지 결과가 좋은 경우, 5회 중 일부가 도구 오류인 경우를 각각 어떻게 판정하는지 문서만으로 결정할 수 있어야 한다.

### F03 · P2 — Whisper PATH 부재라는 사실 주장이 실제 환경과 다르다

**위치:** 설계 145행.

**재현:** 이번 QA에서 `command -v whisper`는 `/home/declan/.local/bin/whisper`를 반환했다. 진입 파일은 `/usr/bin/python3`로 `whisper.transcribe.cli`를 부른다. 해당 인터프리터의 `importlib.util.find_spec('whisper')`도 `/home/declan/.local/lib/python3.14/site-packages/whisper/__init__.py`를 반환했다. 실제 명령과 결과는 `design-qa-runtime.txt`에 보존했다.

**영향:** 준비된 로컬 ASR 가능성을 확인하기 전에 없는 도구로 배제하며, 도구 현황의 신뢰성을 떨어뜨린다.

**수정:** “실행 파일·모듈 발견 / import·CLI 정상 실행 미검증 / 모델 가중치·장치·실제 ASR 미검증 / 직접 음향 청취와 다름”으로 단계를 구분한다. 원래 설계의 조사 시점·명령·오류도 기록한다. 설치·가중치 다운로드·ASR 자동 실행을 승인하는 변경은 아니다.

**재QA 시나리오:** 실행 파일 발견만으로 ASR 성공·정확한 대사·음악 분석·청취 가능을 선언하지 않되, PATH 부재로도 분류하지 않아야 한다.

### F04 · P2 — 확장 검증 파일럿이 장편·몰아보기 분기를 전혀 다루지 않는다

**위치:** 설계 54, 86, 110–129행.

**재현:** 후보 4개의 길이는 약 25/101/168/128초로, 가장 긴 파일도 약 2분 48초다. 실제 대상 중 `[1~5화 몰아보기] 모두가 버린 그녀가 돌아왔다 ｜ AI 로판 회귀물.mp4`는 ffprobe 기준 3,406.390567초(약 56분 46초)다. 장편에서는 장면/회차 경계, 반복 인트로·회상, 누적 locator, 부분 중복, 중단 후 재개가 짧은 회차와 다른 검증 분기다. 문서는 파일럿에서 처리 속도·저장·재개 가능성을 검증한 뒤 나머지 88개로 확장한다고 하지만 이를 대표하는 분기가 없다.

**영향:** 짧은 파일럿은 성공해도 긴 소스의 후반부 누락·장면/회차 합침·재개 시 재집계 문제가 전량 확장 뒤에 드러날 수 있다. 기존 아카이브 기록에도 첫 N개 locator만 남은 사례가 있어 후반 누락은 구체적인 위험이다.

**수정:** 광고2+로판2라는 사용자 선택은 유지하되 로판 중 하나를 몰아보기로 교체하거나, 기존 4개에 더해 명시적인 장편 pipeline 스트레스 검사를 둔다. 최소한 앞/중간/끝 및 회차 접합의 구간 연결, 강제 중단 후 재개, 중복 계수 방지를 검증한다. 이것은 장편 전체 의미 검토의 대체가 아니라 전량 확장 전 파이프라인 검증이다. 추가 시간/대상 선택은 보고한다.

**재QA 시나리오:** 늦은 시각의 경계가 존재하고 중단 후 재개해도 누락/중복 없이 같은 coverage 상태를 유지하는지, 원본 PTS를 chunk-local time으로 잘못 치환하지 않는지 검사한다.

## 수정 순서와 재검토

1. F01: 모드별 검사 능력·전량 내용 검사·부분 인계의 관문을 분리한다.
2. F03: 실제 도구 현황을 바로잡고 발견과 사용 가능성을 구분한다.
3. F04: 장편·회차 접합·후반부·재개를 파일럿/확장 검증에 포함한다.
4. F02: baseline 전에 비교/채점 계약을 고정하도록 설계에 명시한다.
5. 수정된 설계에 직접 QA의 해당 행을 다시 적용하고, 모두 통과하면 fresh-context gate reviewer 1명에게 독립 검토를 요청한다.

좋은 부분은 유지한다: 증거/해석/미확인 구분, 기존 오너 최소 반영, 보호 표현 복제 금지, 원본 타이밍과 새 설계의 분리, 원본/설치본 무단 변경 금지. 이번 판정은 접근 방식 자체를 폐기하라는 뜻이 아니라 실행·검증 관문을 보완하라는 뜻이다.
