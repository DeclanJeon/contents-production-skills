88: ## 5. 증거 모델 — 기존 계약을 그대로 사용
89: 
90: 정본은 `video-production-assets/references/25-reference-video-analysis.md`다. 기존 `archive-audit-template.md`, `shot-dna-template.md`, `archive-craft-crosswalk-template.md`를 채운 분석 산출물을 만든다. production payload/schema를 확장하지 않는다.
91: 
92: - occurrence, SHA/`archive_id`, source-local scene/shot/event/candidate ID를 구분하고 기존 ID를 원문 전체로 보존한다.
93: - 요청 seek 시각과 실제 source frame PTS/timebase를 각각 기록한다. 구간은 가능한 경우 `[start,end)`로 표현하고 추정 경계는 bracket을 보존한다.
94: - 검출 후보·확인된 하드 컷·soft transition·장면·within-shot phase는 별개다. 경계 양쪽의 실제 근거 없이 후보를 `SH###`로 승격하지 않는다.
95: - `OBSERVED`, `DETECTOR_CANDIDATE`, `ESTIMATED`, `[INFERENCE]`, `UNKNOWN`을 분리한다. 업로더 제작 설명·ASR·자동 자막은 해당 출처 등급을 유지한다.
96: - coverage는 probe/full decode/추출/실제 이미지 검토/continuous playback/음향 청취/ASR를 각각 기록한다.
97: - 파일별 처음·끝, 검출 후보가 없는 구간, soft transition, 긴 샷 내부의 동작·표정·그래픽 변화를 별도 확인한다. 컷 검출만으로 영상 전체의 사건을 찾았다고 주장하지 않는다.
98: - 시간순 인덱스에서 비검토 구간과 unresolved scene/shot joins를 모두 남긴다. 빽빽한 프레임 추출도 실제 연속 재생이 아니다.
99: 
100: 각 craft finding의 기존 Shot-DNA 이전 체인은 다섯 칸을 각각 명시한다: `레퍼런스 증거(관찰+위치)` → `메커니즘` → `의도 효과(해석)`(대안 포함) → `새 브리프 제작 요구` → `정성 검증 기준`. 추가로 적용·회피 조건, 정확한 receiving-owner/template/QA slot을 기존 crosswalk의 해당 열에 연결한다. 내용이 없는 양식·동의어로 재명명한 필드는 완성 인계가 아니다.

125: ### C. 92개 전량으로 확장
126: 
127: 파일럿 완료분을 중복 계산하지 않고 나머지 88개로 확장한다. 광고와 로판 각각의 전체 분모를 유지하며, 파일별 완료 구간·미검토 구간·오류·다음 재개 위치를 checkpoint에 남긴다. 배치는 기본 4개 이하로 시작하고 실제 디코딩·추출 용량에 맞춰 조정한다. 리소스에 따라 추출 배치 크기를 줄여도 대상 파일·검사 영역은 줄이지 않는다.
128: 
129: 전량 종료 기준은 선언한 검사 모드에 대해 92개 모두의 구간 상태가 명시되는 것이다. 모든 요청 영역과 필수 증거 gate가 실제로 닫혔을 때만 전체 완료를 선언한다. 부분 시각 결과만 끝났으면 부분 결과와 남은 동작·음향 등의 blocker를 함께 인계한다.
130: 
131: ### D. 교차 영상 패턴 → 공백 판정
132: 
133: 각 finding을 현재 owner의 전체 관련 절차·실제 템플릿·QA와 대조해 `이미 커버 / 부분 커버 / 갭 후보 / 증거 부족`으로 분류한다. 키워드 부재만으로 갭을 판정하지 않는다. 반복 패턴은 지원 occurrence 수, 중복/독립 사례 한계, 실제 검토 구간, 반례를 함께 제시한다. 단일 사례의 유용한 원리도 제한된 적용 조건을 가진 후보가 될 수 있으나 보편 규칙으로 승격하지 않는다.
134: 
135: ### E. 실패 재현 → 최소 수정 → 재검증
136: 
137: 후보 공백마다 기존 패키지의 새 소재 적용 실패를 먼저 재현한다. baseline이 성공하면 불필요한 규칙을 추가하지 않고 이미 커버로 재분류한다. 증거가 빈약하면 분석 상태에 남기고 패키지를 바꾸지 않는다. 실패가 확인된 오너를 한 번에 하나씩 최소 수정하고 해당 변경의 행동 검증을 마친 뒤 다음 오너로 간다.

139: ## 7. 도구·능력·권한 경계
140: 
141: ### 실제 확인된 실행 환경
142: 
143: - 로컬 `ffprobe`, `ffmpeg`, `python3` 존재. ffprobe 메타데이터 조회 성공.
144: - `craft-anything`은 0.6.0 경로를 가리키는 실행 링크가 존재하지만 `--help` 호출이 90초 제한 내 반환하지 않았다. 원인 미진단, 사용 가능성 미검증이며 필수 의존성으로 두지 않는다.
145: - `craft`, `rea-video`, `mpv`, `vlc`, `ffplay`, `whisper`, `faster-whisper`는 이번 PATH 검사에서 확인되지 않았다. 다른 이름의 설치 유무까지 조사한 것은 아니다.
146: - 현 도구 목록에 직접 음향을 듣거나 영상을 연속 시청하는 검증된 수단은 없다. FFmpeg로 미디어를 추출할 수 있다는 사실은 모델의 청취/재생 능력이 아니다.
147: 
148: ### 실행 방식
149: 
150: 로컬 FFmpeg로 버전 기록, full decode 검사, 컷 후보, 시간순 표본·경계 이웃·동작 스트립을 준비한다. 프레임은 실제 image read로 검사한 locator만 observed로 기록한다. 자동 오디오 지표·OCR/ASR는 준비된 로컬 도구가 있고 요청 범위에 맞을 때만 사용하며 청취/텍스트 정확성 검증을 대체하지 않는다.
151:
