# E2 — 아이디어 출발/연기 인계 보완 평가

## 권한과 범위
사용자는 기준판 중간 보고 뒤 `응 진행해`로 **남은 18건 한도 안에서 아이디어 출발 평가를 보강**하는 것을 승인했다. 기존 B안/전문 오너·schema 1.1/권한 경계는 그대로다. 추가 미디어·게시·설치·Git 쓰기·별도 공급자는 승인되지 않았다.

아이디어·정확한 6개 과제 및 아래 배분은 작성자의 실행 판단이다. 승인된 설계를 새 감독/엔진으로 바꾸는 기능 확장이 아니라, 기준판에서 실패가 재현되지 않은 평가 입력을 보완한다. 옛 SD01–08/입력 해시/판정은 수정하지 않고 별도 E2를 동결한다.

## 과제와 미리 고정한 판정
- SD09: 현실 드라마 한 줄→규칙/인물 선택·비용→대본/24초 보드/실제 요청문.
- SD10: 눈보라/도움의 선택→새 비인간·능력 전제/대가→무언 16초 동작/FX.
- SD11: 한 얼굴과 화면 밖 목소리→관계의 재해석→20초 고정 원테이크·청자 반응/보이스/연기.
- SD12: 세탁소에서 소리로 귀환 인지→12초 무발화 장면·소리의 원인/청점·공개/정착.
- SD13: 원래 30초/12샷 콘티 + **PERF_PACKET v1의 독립된 6개 전술/강세/쉼/압력·숨**→10초 3개 실제 요청문. 옛 SD06의 입력 부족을 새 과제에서 해소한다.
- SD14: 기억 통행료라는 아이디어→새 세계 작동 법칙·선택/비용→24초 완결 장면/연기·FX/소리 인계.

각 case의 required_observations는 생성 전 고정한 6개 관찰이다. 제출 형식은 자유다. 내용을 실제로 적은 공통 헤더/블록을 각 작업에 포함한다고 명시하면 공통 블록+작업 본문 전체를 실제 요청문으로 대조한다. 같은 정보를 작업마다 그대로 반복해야만 PASS인 것은 아니다. 외부 ID/경로만 적거나 포함 여부가 없는 요약을 실제 인계로 취급하지는 않는다. 생성 에이전트에는 user_request/supplied_context만 전달하고 과제 ID·정답/루브릭·검토/기존 응답은 주지 않는다. R01–R06과 PASS/FAIL/INCONCLUSIVE/UNREVIEWED는 기존 rubric.md를 재사용한다.

**열린 창작의 의미:** SD09/10/11/12/14는 바뀌어도 되는 이름/소품/플롯/샷 수까지 정답으로 고정하지 않는다. 허구의 실제 내용은 작성 에이전트가 창작한다. 사용자의 형식 잠금·내부 사실/대본/연기→보드/최종 요청문의 일관성·실행 가능한 구체성·증거 정직성을 대조한다. 취향에 안 맞음, 문서 길이, 미사용 음악/효과, 타입/형용사·키워드 개수만으로 FAIL/PASS를 주지 않는다.

후보의 새 이야기가 기준판 이야기와 다르다는 것만으로 실패/개선이 아니다. 양쪽 응답 내부의 인과·선택/비용·시간/상태·연기/소리/효과 인계에 실제 근거를 위치/인용으로 남긴다. 단일 표본·비고정 창작 내용/seed로 인해 결과를 예술성·관객 반응·일반적 우열/통계적 효과로 소개하지 않는다.

## 실행/예산
- 이미 쓴 실제 모델 과제: E1 baseline 8. 선행 설정 실패 2건은 별도 보존했고 모델 생성 전 차단됐다.
- 남은 18건: **E2 baseline 6 + 형성 확인 최대 4 + 최종 동결 비교 8**.
- 최종 8건: 새 SD09–SD14 6종 + 기존 SD03(정적·완전 무음)와 SD08(비서사 QA-only) 2종. 기존 SD03/08의 잠긴 입력/프로필을 재사용하며 새 기준판 호출로 중복 소비하지 않는다.
- 형성 4건은 실제 발견한 실패/수정 묶음에 배정한다. 기존 지침을 충족한 영역은 새 필드 수를 맞추려고 수정하지 않는다. 문서 작업이 여러 오너를 건너면 묶음 중간의 정적 계약 대조와 실제 행동 GREEN을 구별하고, 실제 후속 검증 전 완료로 표시하지 않는다.
- 기준판/후보 모두 native delegate / openai-codex/gpt-6.1-sol:high / fresh / 600000ms / output=false + child outputMode=inline. 부모는 Native 구현, 자식은 읽기+최종 텍스트만. 자동 재시도/CLI 대체 없음.
- 새 source는 만들지 않고 동결한 기준판 215개 파일을 그대로 E2 baseline에 사용한다. 후보가 생기면 별도 source epoch/해시로 동결한다. 동일 common-generation-profile과 입력 바이트를 유지한다.
- 최대 2건 병렬, 번호 순 그룹. actual 실행/범위·비용은 receipt로 확인한다. runtime의 자동 로그는 전송 증거이며 제작 파일이 아니다.
- 실제 FAIL이 없거나 실행/입력 때문에 판단할 수 없으면 실패를 꾸며 스킬을 쓰지 않는다. 이 보완에서도 재현되지 않으면 추가 난이도/새 사례를 계속 자동 추가하지 않고, 실제 출력과 한계를 보고한다.

## 증거와 완료 경계
원본 SD01–08은 기존 evidence root에 보존하고 E2의 입력/dispatch/결과/도구 audit·항목별 검토는 그 아래 epoch-e2/에 둔다. 원시 출력은 고치지 않는다. cases 파일·원문 입력/소스·공통 프로필/dispatch·출력 SHA-256과 실제 provider/model/thinking/context/기한을 기록한다.
새 이야기의 setting/character/script 버전은 응답 내부의 텍스트 제안이며 실제 등록/생성 사실로 취급하지 않는다. 구조/내용/입력 준비/실제 결과/사용자 수락을 분리한다. 최종 독립 리뷰 1회는 아직 수행하지 않았고 최종 인계 gate로 보존한다.

이 문서/JSON은 QA 자료다. 새 production enum/필드·CLI·의미 컴파일러/평가 런너를 추가하지 않는다.
