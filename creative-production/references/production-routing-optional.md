They are provider capabilities, not installable package skills: no new skill, coordinator or approval ledger is created for them. Open one only when the request names it or clearly matches its surface, then route the actual work through the owner below. ## Desktop-app fallback: ArtCraft

When the named desktop app is unavailable, investigate the candidate below for the requested operation. These are conditional alternatives, not verified substitutes or feature-parity promises. Continue reachable preparation; select a fallback only after its installed command/format contract supports the operation and the user's constraints permit substitution. Installation requires explicit authorization; otherwise return the exact missing surface and an editable-output handoff specification, not a claim that a project was produced.

Host availability is not a package fact. Discover the requested executable and its read-only help on the current host before selecting a fallback; historical workstation observations do not prove present installation or absence. Report the executable and version actually observed, or the exact missing capability.

| Named app (absent) | Candidate to inspect | Requested domain, not verified capability |
|---|---|---|
| Photoshop | **PhotoCraft** | Raster/layer/mask/filter/batch/conversion requirements |
| Illustrator | **VectorCraft** | Vector/path/artboard/import/export requirements |
| After Effects | **EffectCraft** | Composition/layer/keyframe/effect/expression/render requirements |
| Premiere Pro | **FilmCraft** | Project/sequence/media/timeline/render/export requirements |
| Lightroom | **LightCraft** | Photo-library/raw-development requirements |
| InDesign | **DesignCraft** | Page-layout/publishing requirements |
| Acrobat | **PdfCraft** | PDF read/organize/combine/split/security requirements |
| Audition | **SoundCraft** | Multitrack/record/edit/mix requirements |
| PowerPoint | **DeckCraft** | Slide/deck/show requirements |
| Excel | **GridCraft** | Spreadsheet/data-analysis requirements |
| AutoCAD | **CADCraft** | CAD/drafting requirements |
| Figma | **FigCraft** | Interface/prototyping requirements |
| Word | **WordCraft** | Word-processing requirements |
| TouchDesigner / DaVinci Resolve | No counterpart identified in the cited thirteen-app catalog | Report the specific missing network/grade capability; an alternative needs explicit authorization and its own verification |

Source scope: the official [application catalog](https://getartcraft.com/apps), read at its lineup and principles sections, identifies these thirteen candidate domains and advertises agent interfaces. This is catalog evidence, not per-command or editable-round-trip verification. The [PhotoCraft](https://github.com/storytold/photocraft#license-and-credits), [VectorCraft](https://github.com/storytold/vectorcraft#license-and-credits), [EffectCraft](https://github.com/storytold/effectcraft#license-and-credits) and [FilmCraft](https://github.com/storytold/filmcraft#license-and-credits) README license sections declare those codebases MIT OR Apache-2.0; that does not license the whole ArtCraft brand, dependencies or bundled assets. PhotoCraft/EffectCraft/VectorCraft explicitly separate asset licenses and trademark restrictions. Inspect the selected release's LICENSE-MIT/LICENSE-APACHE, notices and asset attribution before redistribution; the remaining candidates' component licensing is unresolved here.

Control scope: the four linked repositories document CLI/MCP/control-channel entry points (PhotoCraft README “Automation”, VectorCraft get-started/MCP, EffectCraft “Automation”, FilmCraft command/control documentation). Installed `--help` remains authoritative for actual flags and save behavior; a catalog-wide interface claim does not establish every candidate's command availability. An editable-output handoff names input/version, required edits, native output format, save/export command discovered locally, preserved sources, conversion risks and reopening/inspection criteria. Without executing that save and reopening the actual file, report `PREPARED / OUTPUT UNVERIFIED`, never an editable project delivered.

Rules:
1. **Prefer the named app when it exists.** Fallback is conditional on absence, not preference; do not silently downgrade a workflow the user could run in the requested tool.
2. **Say which app actually ran.** Name the fallback in the delivered result and in the handoff record. Never report an ArtCraft file as a PSD/AI/AEP/PRPROJ, or claim feature parity.
3. **Check maturity before promising.** Several ArtCraft apps are early alpha or in development; a missing command or unsupported format is a real limitation, not a routing failure. Discover with the app's own `commands`/`--help` before planning the edit.
4. **Drive it through the boundary, not the app.** Use the `craft-cli` workflow (installed `--help`/`commands` first, read-only inspect, copy/new output path, verify rendered output) — same "editable project is not the delivery" boundary as the Adobe path.
5. **Format handoff is explicit.** State the output format the fallback actually produces and re-state any conversion loss (e.g. LUT export cannot represent masks/clipping/grouped semantics; a vector export may drop unsupported effects). If a round-trip back to the Adobe format is required, treat that round-trip as its own verify step.
