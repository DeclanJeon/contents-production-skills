# 위임 브리프의 모션 콘셉트 선택

사용자가 소재나 목적만 줬다면 먼저 관객이 **무엇을 이해하거나 느껴야 하는지** 한 문장으로 정하고, 그 장면을 가장 간단하게 표현할 레시피를 하나 선택한다. 의상·카메라·음악처럼 되돌릴 수 있는 선택은 이유를 기록하고 계속한다. 모션이 불필요하면 기존 실사·스틸 등 경로를 유지한다. 스타일·권한·실행기를 동시에 결정하지 않는다.

| 레시피 ID | 맞는 전달 과제 | 최소 장면 구조 | 피하거나 바꿀 때 |
|---|---|---|---|
| `kinetic_type` | 문구 자체의 대비·반전 | 설정 → 대조 카피 → 회수, 분명한 읽기 hold | 인물의 미세 반응이 핵심이면 `character_photo` |
| `ui_state` | 선택에 따른 상태 차이 | 초기 화면 → 행동 → 결과, 다른 시도와 비교 | 실재 제품의 UI가 없으면 가상 UI로 명시하거나 타이포 사용 |
| `diagram_data` | 관계·순서·비교 | 기준 → 한 변화씩 → 읽는 시간 | 통계가 미확인이면 수치 차트 금지, 개념도 또는 절차도 사용 |
| `shape_morph` | 한 대상이 다른 의미나 상태로 바뀜 | 변하지 않는 앵커 → 형태 변형 → 알아볼 수 있는 끝 상태 | 내용보다 효과만 눈에 띄면 컷이나 디졸브로 단순화 |
| `character_photo` | 반응·표정 또는 사진이 이야기의 근거 | 자극 → 반응 → 결과, 사진은 정보 순서에 맞춰 투입 | 초상·자산 권리 또는 출처가 불명하면 추상 모션으로 전환 |
| `brand_product` | 브랜드 인지·기능 공개 | 사용자 과제 → 증거/기능 → 승인 마크 공개 | 로고·제품 기능·효능을 지어내지 않는다 |
| `realtime_3d` | 깊이·시점·실시간 조작이 설명 자체에 필요 | 대표 샷 → 시점/정보 변화 → 가독 상태 | 평면으로 같은 정보를 전달할 수 있으면 2D. 웹과 선형 납품은 별개 |

선택을 `recipe + reason`으로 남긴다. CineForge에서는 `production_spec.motion_recipe`에 기록하고 각 컷에 **보일 것 / 변화 / 끝 상태 / 읽는 시간**을 반영한다. 텍스트 제안만 요청한 경우 프리프로덕션을 넘지 않는다. [일반 제작 지침](../../video-production-assets/references/08b-code-motion-production.md), [기법 사전](../../video-production-assets/references/33-motion-style-library.md), [실시간 경계](../../open-3d-production/references/realtime-motion-direction.md)는 선택과 현재 단계에 맞게 읽는다.

**예:** “MBTI로 영상 하나 만들어줘” → 약속 변경에 두 답장이 나오는 허구 상황극 → `ui_state`. 메시지를 보여준 뒤 포인터가 먼저 움직이고 답장은 나중에 뜬다. J/P 비교 수치나 검사 결과를 꾸며내지 않는다. 대비가 말맛에 있다면 `kinetic_type`이 더 적합할 수 있다. 하나를 결정하고 위임된 선택을 되묻지 않는다.
