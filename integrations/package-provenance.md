# Package provenance and reuse boundaries

## 2.0 consolidation

`contents-production-skills` is the maintained source for eight installable core skills. `creative-production` is the only project coordinator. Existing production schema 1.1, spatial contract camera-spatial-1.0, and version-bound review/execution/publication boundaries remain authoritative.

The update compares currently active content/video skill instructions with this repository and integrates their provider-independent operating procedures. It also consolidates the supplied memorable-video v6 stack into the existing production modules and conditional references. The exact capability map belongs to [skill-routing.md](skill-routing.md); it is a maintenance index, not another installed skill or project-state database.

| Material | Treatment | Reason |
|---|---|---|
| Existing eight core skill folders, templates, examples and validators | Retained and updated where the requested workflow needs it | Preserve working artifact and installation contracts |
| Active content/marketing/source-adaptation/image/audio/video planning instructions | Compare and author package-owned operational guidance; keep specialized live tool execution conditional | Preserve usable creation workflows without vendor-specific credentials or duplicate coordinators |
| Supplied v6 concept, emotion, retention, series, style, identity, product, physics, VFX, sound, finishing and quality guidance | Merge into the existing production owner as selective modules/references | Preserve unique craft with lower discovery and maintenance overhead |
| v6 coordinator, global state ledger, independent budget/asset manifests and repeated agent metadata | Retire after their useful fields/rules are mapped to existing owners | One coordinator, one canonical project.json, one approval history; no second installable aliases |
| Old v6 archive and duplicated usage guide | Remove after consolidation | Avoid shipping a stale competing installation and conflicting execution rules |
| Real provider helpers, OAuth, API keys, model weights, personal paths and server configurations | Not imported or installed | Runtime authorization and user-private data are not reusable skill assets |
| Book text, new PDF summaries, external Notion-derived reference material and third-party examples | Not newly imported | Source attribution is not redistribution permission |
| Selected platform, provider, specialized screenplay/story-commerce and source-retrieval workflows | Conditional external dependencies | Their real live contracts and required runtimes remain owned by that specialist |
| Actual user projects, generated media, approval logs and source documents | Stay in the requested project root | Package assets are reusable instructions/templates and synthetic fixtures, not private production data |

The current source inputs are locally applied skill instructions and the user-supplied v6 folder. An upstream revision or permission not established by these inputs stays unknown. Do not describe active local instruction inspection as a verified third-party release or a license audit. The consolidation is not authorization to publish user/source material or to call paid generation.

## License status

This repository has no reuse license. Public visibility, author metadata, a provenance note, or an AI rights judgment is not a grant to reuse the package or third-party works. No new LICENSE or blanket legal clearance is introduced.

The previously inspected codex-imagen helper has its own MIT notice requirements, but that does not license this package or other skill contents. That helper and its OAuth setup remain external. Before vendoring any external executable/resource, verify its exact upstream revision, terms, notices and private-data exclusions; unknown terms block that import.

## Maintenance and installation

Edit the repository and use `scripts/install_package.py` for explicit installation. The installer copies complete manifest-listed skills and package support; it refuses silent merging and requires an external backup for replacement. Unrelated skills are untouched. Alias-root migration happens only when that root is explicitly supplied.

The package update does not overwrite global user skills. Existing user projects and any old installation customization are not deleted by the repository cutover. A stale v6 installation should not be added beside the consolidated package; select and back up managed legacy installations explicitly when migrating.

## Verification boundaries

Retained historical QA describes earlier releases. The 2.0 record is [consolidation-validation.json](../qa/consolidation-validation.json). Structural/install checks, actual text-artifact model probes, and any media/runtime checks are reported separately. Automated scoring is not user acceptance, creative-quality proof, legal clearance or execution/spend approval.
