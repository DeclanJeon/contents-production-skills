# Package provenance and public-source boundaries

## What this expansion includes

The package keeps the three existing production/camera/Blender skills and their existing bibliography, examples, schemas and validators. It adds an operational coordinator and four text-planning skills according to the [approved design](../docs/superpowers/specs/2026-10-02-creative-production-package-design.md). Installed local skill IDs and their workflow behavior were inspected to retain narrow requests, inherited briefs and approval boundaries; the added public instructions are written for this package's operational contracts.

The added text lane uses its own `orchestrating-video-preproduction/references/video-direction.md`. It does not vendor the installed suite's `book-synthesis.md`, PDF-page summaries, external Notion-adapted reference, or third-party examples. No added instruction represents a cited author's theory or claims an external source granted redistribution permission. Existing bibliography is not a license for source works.

| Component | Included | Boundary |
|---|---|---|
| creative-production coordinator and operational references | Yes | Scope, specialist ownership, canonical project state, host-independent dialogue, review/execution/publication gates and actual output verification |
| Four text-planning workflows and shared operational direction | Yes | Actual requested text artifacts, synthetic eval scenarios and continuity/checkpoint rules; no imported book/Notion material |
| Existing production/spatial resources | Retained | Their prior provenance and limitations remain; expansion does not establish a new legal clearance |
| codex-imagen helper, OAuth files and execution code | No | Conditional external image-review dependency. Its inspected MIT license does not license this package or other skills |
| Other marketing, screenplay, source-adaptation, platform and provider skills | No | Only dependency/activation information; unknown source/version remains unverified, not an auto-install instruction |
| Books, original diagrams, private project references, generated media, account secrets or model weights | No | User/project material stays outside the public package; do not turn backup or output folders into package assets |

## License status

No new `LICENSE` or third-party license grant is introduced. Public visibility, an author metadata field, a provenance note, or an AI-generated rights judgment is not permission to reuse this package or third-party works. This document records the publication boundary; it does not declare general legal/commercial safety or clear the historical source package under a new license.

Before later vendoring an external skill or resource, establish its exact upstream revision, redistribution terms, required copyright/notice files, changes and private-data exclusions. Unknown terms block that vendoring. Don't infer another component's permissions from codex-imagen's MIT license or a frontmatter claim.

## Maintenance and installation

The repository is the maintained source. Copy complete required skill resources through `scripts/install_package.py`; preserve source-level contracts, not the private state of a local installation. Explicit replacement/migration backs up old managed folders outside the source and target roots before replacing them. Review custom changes there; backups are not automatically committed or installed as extra skill aliases.

New package assets are reusable operational templates/references and synthetic examples. Actual briefs, source media, claims, generated outputs, auth and approval evidence belong to the requested project. Changes to the package do not authorize media generation, spending, publication or live platform changes.
