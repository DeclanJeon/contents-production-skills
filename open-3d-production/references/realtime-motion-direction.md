# 실시간 3D 모션 연출과 검수

**적용:** Three.js 등 실시간 공간, 스크롤 구동 모션, 이를 참조하는 컷 연출. 선형 영상이 목표면 웹 상호작용을 추가하지 않는다. 브라우저 미리보기는 영상 납품 파일이 아니다. [Prompt Motion 3D 템플릿](https://prompt-motion.com/templates/realtime/customize)의 브리프 구조를 실제 실행 경계와 결합한다.

1. **PRE — 대표 샷부터:** 피사체와 정서, 가장 오래 볼 대표 샷, 앞뒤 정보 공개 순서를 적는다. 각 구간에 카메라의 목적·주목점·초기/종료 상태를 지정한다. 창의성·속도·완성도는 움직임을 늘리는 슬라이더가 아니라, 예를 들어 “제품 실루엣을 유지하고 회전 속도만 완만하게”처럼 허용할 변경으로 표현한다.
2. **PROD — 웹과 파일 분리:** 웹에서는 스크롤 진행률을 구간별 장면 상태에 매핑하고 중간 진입·역스크롤·리사이즈에서 동일 입력이 같은 핵심 구도를 만드는지 본다. 작은 화면에서 핵심 피사체를 잃으면 크롭이 아니라 카메라/레이아웃을 별도 설계한다. **reduced motion**에는 움직이지 않는 대표 구도와 동일 정보·조작 경로를 남긴다. 선형 영상이면 스크롤 위치를 렌더 타임라인으로 다시 정의하고 출력·확인이 허용된 기존 런타임만 사용한다.
3. **POST — 올바른 표면 검수:** 웹이면 첫/중간/끝과 역방향, 실제 요구 뷰포트, 모션 감소, 입력·카메라 전환을 확인한다. 영상이면 대표 샷과 컷 경계, 화면비, 실제 출력 프레임을 검사한다. 프레임 샘플은 전 구간 재생 검수를 대신하지 않는다. 모델 겹침, 물리적 공간 배치와 카메라 통과 가능성 검증이 목적이면 기존 **Blender** 프리비즈 경로로 보낸다. 브라우저 검사 결과를 Blender 검증으로 기록하지 않는다.

기존 [통합 규칙](integration.md)의 런타임·실행 범위 안에서만 작업한다. 템플릿의 Three.js 코드, 장면 자산, 렌더 설정, 예시 영상은 이식하지 않았다. [공개 원본 카탈로그](https://prompt-motion.com/).

### 3D 렌더 함정 {#t-3d-gotchas}

- **언제:** Three.js 장면을 영상 프레임으로 뽑거나 실시간으로 보여 줄 때
- **방법:** 그림자 바이어스를 설정해 표면 줄무늬를 막는다. near·far 평면은 장면 크기에 맞게 좁혀 깊이 깜빡임을 막는다. 모든 난수는 시드를 고정해 다시 렌더해도 같은 프레임이 나오게 한다.
- **탈락:** 그림자 줄무늬(shadow acne), 깊이 깜빡임(z-fighting), 재렌더 시 배치가 바뀜.
