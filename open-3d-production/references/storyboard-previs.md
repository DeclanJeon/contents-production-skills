# Browser storyboard previs (R30)

For approved Three.js storyboard previs, take the existing scene/shot/panel IDs, editorial timebase, dialogue and asset locks. Preserve them; this is not a new approval or project ledger. A written board remains R10. Native .blend and required physical feasibility use R22.

1. Author a shared metre-scale proxy set for each location in the production root: fixed origin, floor, openings, furniture, performer/prop anchors and allowed camera side. Record proposed versus measured dimensions. Make the overhead view and shot views use the same transforms.
2. Set the delivery aspect, camera position/target/FOV, actor eyelines, beat poses and prop state for every requested panel. Use explicit panel sample times, not animation-wall-clock frames. Compare adjacent shots and location reappearances for screen direction, occlusion and ownership. If the original board disagrees with a camera choice, name the correction and its affected IDs.
3. Pin Three.js; run on localhost with WebGL, checking a real browser. Export clean camera PNGs and overhead views. Bind engine/version, scene/shot/panel IDs, exact sample times, source revision and output hashes. Open and inspect every panel in order; return KEEP/FIX/UNVERIFIED and rebuild affected stills after changes. A camera matrix, blank canvas or canvas screenshot alone is not camera/continuity acceptance.
4. Storyboarding consumes the ordered PNGs as **proxy panels**, with captions outside the pixels. Preserve coverage and page readability. Deliver the reopenable browser scene and readable board or report the exact missing runtime/surface. Do not turn proxy stills into photoreal identity, anatomy, articulated contact, simulation, native Blender or finished-video evidence. Critical physical contact follows the existing storyboard contact gate and may block dependent generation. No video submission, upload or publication from this branch.
