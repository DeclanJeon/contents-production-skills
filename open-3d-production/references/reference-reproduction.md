# 실제 레퍼런스 재현과 수행 검증

사용자가 기존 영상을 그대로 모방하거나 특정 구간의 화면·타이밍 재현을 요청했을 때만 적용한다. 일반 레퍼런스에서 원리를 새 소재로 옮기는 작업과 구분한다. 기존 오너·프로젝트·실행 권한을 유지하며, 이 절차 자체가 다운로드·유료 생성·게시 권한을 추가하지 않는다.

## 재현 계약

1. 실제 원본 파일과 URL/채널, 확보 도구·버전, 길이·FPS/PTS·해상도·해시를 기록한다. 지정 채널은 실제 업로더/채널 근거로 확인한다. 검색 제목·썸네일만으로 재현 계획을 확정하지 않는다.
2. 재현할 **연속 원본 구간**과 출력 로컬 시간의 대응을 잠근다. 컷 경계·동작 시작/정점/끝·카메라 변화·자막/라벨의 실제 시각을 검사한다. 컷 검출값은 후보이며 화면으로 확인한다. 원본 영상의 거친 자막 챕터를 정확 컷 시간으로 쓰지 않는다.
3. 각 샷에 `source interval → output interval → 관찰된 배치/색/재질/텍스트/동작/카메라 → native 구현 → 검사 시각`을 연결한다. 화면 정규화 위치·크기와 실측 공간을 구분한다. 역산되지 않은 카메라·치수·재질 값은 DESIGN_PROPOSAL이고, 재현 목표 화면과 대조해 조정한다.
4. **독립 재구성/빌린 요소**를 나눈다. 원본 프레임을 그대로 배경 평면에 붙이거나 원본을 잘라 내보낸 것은 native geometry 재현 증거가 아니다. 원본 음향·사진·타이포그래피를 재사용하면 그 항목은 borrowed라고 기록하고 새로 제작했다고 주장하지 않는다.

## 실행

1. 해당 native B-ID만 선택하고 `bpy` 저작 파일·소스 입력·프레임/출력 설정을 외부 프로젝트에 둔다. 잠긴 asset/scene/shot ID·허용 델타를 이어받고 원본 소스와 이전 시도를 보존한다.
   Blender의 내장 Python과 host Python은 별도 런타임이다. host의 import 성공/LSP 결과로 Blender의 패키지·API 지원을 판정하지 않는다. 실제 실행 환경의 engine enum·노드 socket·샘플 속성부터 확인하며, 문서 버전의 식별자를 무조건 고정하지 않는다. 추가 패키지가 필요 없으면 표준 라이브러리로 저작하고, 필요한 의존성은 실제 대상 런타임에서 검증한다.
2. named geometry/material/light/camera와 seed·시간 제어를 작성한다. 시뮬레이션 없이 표현한 파형·액체·입자는 illustrative animation이지 물리 검증이 아니다.
   판·완충층처럼 접촉한 여러 물체가 함께 변형하면 같은 공간/시간 변형장과 바닥 기준점을 사용하고 전환 중간의 관통·틈을 검사한다. 각 물체의 위치·스케일을 따로 줄여 같은 변형이라고 가정하지 않는다. 저장한 shape-key의 초기값과 반복 루프 종료값도 다시 열어 확인한다.
3. 전체 렌더 전에 서로 다른 장면/재질/카메라의 대표 프레임을 실제 Blender로 렌더하고 원본의 대응 프레임과 나란히 연다. 사각 대역으로 완성 미감 검증을 대신하지 않는다. 필요한 경우 front/side/three-quarter와 최종 카메라를 함께 검사한다.
4. 구도·주요 형상·레이어 순서·색·가독성부터 고친 뒤 표면·조명·카메라 곡선을 조정한다. 한 번에 한 장면/주요 원인을 바꾸고 실제 새 프레임을 본 다음 다음 변경을 한다. 모델의 완성 예상이나 스크립트 성공을 화면 검사로 보고하지 않는다.
5. 검토한 scene을 저장하고 다시 열어 요청 범위를 렌더한다. 실제 프레임 수·fps/timebase로 조립하고 최종 encode의 길이·해상도·프레임·디코딩·해당 오디오/자막 동기화를 검사한다. 인코딩하지 않은 PNG sequence는 MP4가 아니다.
   긴 렌더의 재개가 필요하면 단일 writer를 유지하고 `.blend` 내용과 실제 엔진·해상도·FPS·샘플 설정의 지문을 잠근다. 파일 이름만 보고 이전 프레임을 재사용하지 않고, 완료 표시와 내용 무결성이 확인된 동일 작업의 프레임만 이어 쓴다. 설정/장면이 바뀌면 새 출력 버전으로 분리한다.

## 대조와 수정

기존 QA/인계 기록에 다음 표를 붙인다. 별도 승인 원장이나 보편 유사도 점수를 만들지 않는다.

| 요구/샷 ID | 원본 시각 | 결과 시각·버전 | 실제 확인한 화면/재생/청취 | 충족 / 차이·수정 필요 / 미검증 | 최소 수정·보존 조건 |
|---|---|---|---|---|---|

- 컷 순서·정보 공개·카메라 방향/움직임·주요 형상/층 순서·라벨과 요구된 소리를 각각 판정한다. 사용자가 원본 재현을 목표로 잠갔다면 그 관측값을 이번 제작의 목표로 명시한다.
- source/output 동시 시각과 시작/정점/끝·컷 직전/직후·문제 프레임을 비교한다. 시간/길이는 실제 측정하며 추출 프레임 수를 전체 재생 증거로 바꾸지 않는다.
- 실제 재생을 보지 못한 동적 품질, 듣지 않은 소리, 검사하지 않은 export는 미검증이다. 비슷한 주제·한 장의 유사한 구도·평균 이미지 점수로 필수 차이를 상쇄하지 않는다.
- 필수 재현 요소가 다르면 해당 입력/장면/시간을 고쳐 재렌더하고 영향 구간을 다시 검사한다. 중요한 남은 차이가 있으면 “그대로 재현 완료”라고 하지 않고 사용자가 볼 비교 파일과 차이 목록을 반환한다.

## 수행 평가와 재사용

새 방법을 실전 검증했다고 기록하려면 **읽은 스킬 경로/버전 → 선택한 native 절차 → 실제 저작·실행 명령 → 생성 파일 → 직접 검사 → 수정 이력**이 이어져야 한다. 에이전트가 문서만 요약한 결과나 기존 단위 테스트 통과를 새 Blender 장면 수행 증거로 쓰지 않는다.

샷 패킷을 다른 워커에게 넘겼다면 정확한 배정 범위·그 워커가 실제로 읽은 자료·반환한 출력과 부모의 검수를 구분한다. 워커가 없거나 실행에 실패하면 실제 수행자를 기록한다. 단일 성공은 그 장면/런타임 범위의 증거이지 열 가지 레시피 전체의 검증이 아니다.

최소 납품은 요청된 `.blend`, 재현 가능한 script/입력, 실제 영상/sequence, 원본 구간 대응, 비교 파일, 설정·검사·남은 차이와 `.history`다. 원본 미디어를 스킬 저장소에 번들하지 않고 필요한 실행 예제/검증 기록만 기존 패키지 관례에 맞게 남긴다.
