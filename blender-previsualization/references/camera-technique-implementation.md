# 카메라 카탈로그 → Blender 구현표

이 표는 `camera-spatial-design/references/camera-language-catalog.md`에 등록된 모든 항목을 Blender 프리비즈·AI 제어·편집 작업으로 연결한다. **Blender 구현 가능**은 현재 프리비즈 어댑터가 최종 미감이나 실물 촬영을 재현한다는 뜻이 아니다. 실제 적용 시 설치된 Blender 버전, 현재 어댑터, 입력 에셋과 장면 명세를 확인하고 인계 양식에 증거를 남긴다.

이 표의 프레이밍·가림·접촉 검수는 [GUIDE-01](../../video-production-assets/references/29-reference-driven-production.md#space-performance)의 공간·연기·카메라 분리 원칙(R3, GUIDE-01 pp44–63·77–89)을 따른다. 프리비즈 카드 구성(구분·행동·카메라-공간·보존 금지·종결)과 컷 리듬은 같은 출처의 씬/행동 비트(R3, pp48–60)에서 온다.

## 현재 어댑터가 직접 사용하는 명세

현재 `camera-spatial-1.0`과 `build_previs.py`는 샷별 카메라 위치·target·렌즈·roll·키프레임, 피사체 대역의 크기·위치·subject tracks, 기본 장애물, FPS·해상도·시간 보간을 사용한다. 어댑터는 대역 장면(`--proxy box` 추상 박스, `--proxy figure` 토르스·목·머리 점토 대역), 카메라/피사체 이동, PNG 렌더, 화면 좌표와 head/center 주목점 ray-cast 검사를 만든다. 검사는 실루엣 전체 가시성·연기·미감·최종 영상 품질을 증명하지 않는다.

상태 정의:

- **현재 어댑터 대역 구현:** 기존 스펙 값으로 Blender 프록시 장면과 렌더를 만들 수 있다. 실제 장면 에셋을 대체하지 않는다.
- **스키마/어댑터 확장 필요:** 원하는 효과에 필요한 입력·애니메이션·검수 방식이 현 스펙에서 직접 지원되지 않는다. 설계 단계에서 동작을 지원한다고 단정하지 않는다.
- **Blender 밖의 편집 작업:** 시간 재배치나 컷 전환 등 편집 타임라인 담당이다. Blender 프리비즈 완료와 편집 효과 완성을 구분한다.
- **프롬프트/관찰 의도:** provider나 실제 영상에서 확인하기 전까지 정량 제어 또는 결과로 보고하지 않는다.

## 장면별 실행 규칙

1. 카탈로그 항목을 shot_id와 camera-intent/camera_spec 버전에 연결한다. 이미지 비율을 사용할 경우 분모와 계획/측정 상태를 적는다.
2. actual scene-specific 3D 배치·카메라 경로·가림·clearance·접촉 검증이 요청되면 `camera-spatial-design`의 스펙을 받아 실제 Blender를 사용한다. 단순 서사 선택만으로 실행을 만들지 않는다.
3. 빌드 전에 위 표에서 현 adapter 구현·추가 구현·외부 편집·미지원 중 하나를 표시한다. 지원하지 않는 입력은 스펙에 몰래 끼워 넣지 않는다.
4. 현 대역 어댑터(box/figure)의 실제 결과는 `previs.blend`, PNG, numerical-analysis, blender-inspection, manifest로 나누어 기록한다. 요청된 파일을 다시 열고 shot/panel에 연결된 실제 프레임을 검사한다. 선택 입력(`--focus-map`, `--look-cards`, `--engine`)을 쓰면 그 경로와 범위를 manifest에 남기고, 룩 카드는 프레이밍 참고로만 인계한다.
5. proxy 검사에서 통과한 것은 그 proxy 범위만 통과다. 전신 포즈, 표정, 소품 판독, focus pull, final cut/audio 또는 실제 연기까지 확인한 것으로 확대하지 않는다.
