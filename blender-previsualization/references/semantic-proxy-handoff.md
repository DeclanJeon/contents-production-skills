# 의미 대역 프리비즈와 생성 인계

레퍼런스의 카메라·동선·컷을 바꾸거나, 소품의 상태/소유/동작을 수정할 때 적용한다. 외형을 완성하는 렌더가 아니라 **수정 가능한 동작·공간 입력**을 만든다. 일반 영상·텍스트 콘티에 Blender 실행을 추가하는 규칙이 아니다.

출처는 [브랜드 도적단 / 반토막AI의 지정 영상](https://www.youtube.com/watch?v=lyNzEk8H9AM)이다. 2026-11-03 Flucto로 영상/자막을 확보하고, 전체 자막과 전 구간 10초 간격 77장·08:00–09:34의 2초 간격 48장을 검사했다(115개 고유 시각). 연속 동작·오디오·원본 `.blend`·비용 실험은 검사하지 않았다. 관찰/자막에서 방법을 일반화했으며 제작자의 정확 복제·비용 효과를 검증한 것은 아니다. 세부 대조는 소스 저장소의 `docs/analysis/2026-11-03-blender-previs-video.md`에 있으며, 설치판의 실행에 그 조사 문서가 필요하지 않다.

## 1. 가져올 정보부터 잠근다

입력 영상의 실제 버전/구간과 기존 shot·scene·panel ID를 이어받는다. 타임라인마다 `관찰한 동작 / 보존할 카메라·배치 / 바꿀 동작 / 외형 소스 / 미확인`을 나눈다. 컷 직전·직후, 행동 시작·정점·끝, 손-소품 접촉·가림이 바뀌는 시점을 검사한다. 샘플 정지 화면만 봤으면 연속 동작·정확 접촉·전체 시청을 확인했다고 쓰지 않는다.

레퍼런스에서 추정한 초점거리·깊이·실측 크기는 추정으로 남긴다. 영상만으로 정확한 3D 카메라가 복원됐다고 말하지 않는다. 카메라·좌표 명세는 기존 `camera-spatial-design` 오너가 작성하며, 실제 트래킹/캘리브레이션은 별도 [네이티브 방법](../../open-3d-production/references/native-blender-workflows.md)을 쓴다.

## 2. 목적에 충분한 최소 대역

- 머리·몸통·하체와 소품의 실측 bounding volume부터 만든다. 고정된 세 블록 할당량이 아니라, 전달하려는 동작이 읽히는 최소 형상을 선택한다.
- 얼굴·로고·옷 주름·최종 재질은 외형 참조로 분리한다. 단순 대역으로 확인하려는 프레이밍을 복잡한 모델링 때문에 늦추지 않는다.
- 손의 집기·힌지 회전·착용이 결과를 결정하면 손/소품의 필요한 관절·접점만 추가한다. 단순 박스가 정밀 손동작을 검증한다고 하지 않는다.
- 실측은 출처·단위·상태를 기록한다. 접힌 소품과 펼친 소품의 크기는 별개다. 미제공 치수는 추정으로 표시하고 중요한 맞춤/접촉 판정에 쓰지 않는다.

**현재 어댑터의 한계:** `build_previs.py --proxy box|figure`는 프레이밍/가림용 대역이다. figure에는 관절 손동작·소품 소유권 전환·접힘 힌지 기능이 없다. 이 문서가 그런 CLI 옵션을 추가하지 않는다. 필요한 작업은 별도 범위의 native Blender 구현으로 배정하고, 기존 공간 명세와 결과 ID를 연결한다. `--look-cards` 역시 외형 카드이지 접촉·깊이 검증 기능이 아니다.

## 3. 대역 색은 주소이고 최종 팔레트가 아니다

교체 대상별로 `proxy object 이름 → 안정 ID → 역할 → 대역 색 → 외형 참조 버전`을 기록한다. 색이 비슷한 군중·주연·소품을 구분하고, 검토 화면에는 ID도 함께 제공한다. 색만으로 정체성을 추측하지 않는다.

프로젝트의 실제 의상·제품색과 혼동되면 대역 팔레트를 바꾼다. 보라/노랑/청록/주황 같은 원본 예시는 고정 규칙이 아니다. 셰이딩·노출·색 관리 후 렌더에서도 구분되는지 확인한다. 최종 생성에서는 대역색을 가져오지 않는다고 역할 표에 쓴다.

회전 제품처럼 앞/뒤가 중요한 경우 면·방향을 별도 표식으로 구분하고, 정면/후면/접힘 등 실제로 드러나는 상태의 참조가 있는지 확인한다. 뒤쪽 사진이 없으면 그 부분은 미확인/승인된 설계 제안이지 정확 재현이 아니다.

## 4. 동작 수정은 상태와 전환으로 작성한다

기존 [프리비즈 인계](../assets/previs-handoff-template.md)에 아래 정보를 붙인다. 별도 정본 원장을 만들지 않는다.

| 로컬 프레임·FPS | 소품 상태·크기 근거 | 소유자/부모·접점 | 바뀔 움직임 | 유지할 카메라·배치 | 검사할 전환 |
|---|---|---|---|---|---|
| 실제 명세 값 | 접힘/펼침/착용 등 공급 상태 | 기존 ID와 왼손/오른손/주머니 등 | 허용 델타 | 기존 버전·고정 구간 | 접촉 전/중/후·가림 |

Blender native 구현에서는 부모/Child Of 등의 관계와 키프레임을 현재 버전에서 확인한다. 소유권 전환 전후의 world transform을 비교하고 원치 않는 튐·관통·슬립을 실제 렌더로 검사한다. Child Of의 influence는 애니메이션 가능하지만 자동으로 올바른 손-물체 접촉을 풀어 주지 않는다([공식 문서](https://docs.blender.org/manual/en/latest/animation/constraints/relationship/child_of.html)).

사용자가 바꾸라고 한 구간만 수정하고 앞 구간·카메라·다른 인물·화면 방향을 보존한다. 수정 버전과 이전 버전의 같은 시각을 비교해 허용 델타 밖 변화가 있는지 확인한다. 물리/리그가 필요하면 그 구현의 범위를 명시한다.

## 5. 세 채널을 분리해서 인계한다

1. **프리비즈:** 검사된 배치·동선·카메라·컷·타이밍만.
2. **외형 참조:** 실제 파일/버전이 있는 얼굴·의상·제품의 앞/뒤·장소. 컷 전체에 일관된 기준을 사용한다.
3. **텍스트:** 프리비즈에 담기지 않는 표정·손 제스처·질감·보존 조건. 관측되지 않은 동작을 이미 검증한 것처럼 쓰지 않는다.

이 셋은 기존 [AI camera control packet](../../ai-camera-control/assets/camera-control-template.md)의 reference roles/action beats/preservation constraints로 보낸다. 업로드 순서와 **실제 전송된 slot tag**를 확인한다. `색 → 대상 → 외형 slot` 대응을 검토하고, 공급자가 해당 영상/이미지 입력과 길이·종횡비를 지원하는지 확인한다. 색 지시·텍스트는 soft guidance이며 완벽 복제 보장이 아니다.

Depth/Normal/ID/Cryptomatte 같은 패스는 별도로 요청된 합성/제어 입력일 때만 만든다. 색 대역 영상은 segmentation mask가 아니며, 모든 모델이 패스를 받는 것도 아니다.

## 6. 충분 조건과 멈춤

요청된 `.blend`와 실제 출력, 버전·엔진·fps·프레임 대응, 대역 매핑, 허용 수정표, 검사한 시각과 미검증 범위를 반환한다. 정지 프레임은 구도 증거이고, 움직이는 프리비즈는 별도 인코딩·재생 확인이 필요하다. 소유권/접힘 전환은 시작/끝뿐 아니라 변화 중간을 검사한다. 승인된 외형과의 동일성은 최종 생성/합성에서 별도로 확인한다.

재작업 횟수·토큰·영상 크레딧·작업시간은 실제 측정값만 기록한다. 원본의 “반값”, 고정 크레딧, 한 번 성공 사례는 범용 절감률이나 현재 공급자 가격이 아니다. 이 과정은 로컬 수정의 통제 가능성을 높이는 방법이며, 영상 생성·유료 재시도 승인을 추가하지 않는다.
