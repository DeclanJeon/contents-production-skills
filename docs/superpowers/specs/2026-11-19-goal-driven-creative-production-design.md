# Creative Production — 목표 중심 영상 제작 오케스트레이션 설계

- 날짜: 2026-11-19
- 상태: 이번 구현 범위를 모은 통합 설계, 상세 검토용. 이 문서는 도구 설치·스킬 배포나 작품의 생성·비용·게시 승인이 아니다.

## 1. 목적과 접근

사용자는 만들고 싶은 영상과 제약을 말한다. `creative-production`은 해당 목표를 끝까지 맡는다. 사용자가 스킬 이름, 중간 산출물 순서, 다음 실행 명령을 알 필요가 없어야 한다. 일반적인 신규 영상 제작에서는 **실제 이미지 스토리보드 시트가 기본 이정표**다. 완성 영상이 목표라면 시트·컷·씬은 내부 점검 단위이고, **전체 편집본의 내부 검수가 끝났을 때만 사용자에게 완성본 검수를 요청한다.**

현재는 [총괄 진입점](../../../creative-production/SKILL.md)이 산출물 경로 하나를 먼저 고른다. [R24 전체 패키지](../../../creative-production/references/production-routing.md#full-package-sequence)는 이미 이미지 시트까지의 경로를 갖지만, 일반 영상 목표에서 이 경로를 자연스럽게 시작·이어 가는 규칙이 약하다. [텍스트 기획 레인](../../../orchestrating-video-preproduction/references/stage-execution.md)도 협의가 기본이라 사용자가 중간 답변을 하지 않으면 멈춘다. 이번 설계는 두 문제를 함께 해결한다.

| 접근 | 판단 |
|---|---|
| 기존 루트에 FrameAtlas 문서만 연결 | 새 연출 기준은 전달되지만, 중간 단계에서 멈추는 동작은 그대로다. |
| **기존 총괄에 목표와 종료 조건을 먼저 정하게 하고, 내부 라우팅·검수로 계속 진행** | **선택.** 전문 스킬과 승인·검수 계약을 재사용하면서 사용자 진입점은 하나로 유지한다. |
| 별도 워크플로 엔진·스킬 팩 재구축 | 실행 인프라와 중복 계약이 늘어난다. 이번 범위가 아니다. |

## 2. 목표와 범위 판정

진입 시 **최종 목표**, **사용자가 지정한 종료점**, **제작·검수 제약**, **현재 확보한 입력과 실행 권한**을 한 번 분리해서 읽는다. 기존 프로젝트를 재개할 때도 목표와 실제 진척도를 별도로 확인한다. 목표, 현재 단계, 작업 권한은 서로 대체하지 않는다.

| 요청 | 총괄의 기본 동작 |
|---|---|
| “이 아이디어로 30초 영상 만들어줘.” | 목표는 완성 영상. 실제 이미지 시트를 거쳐, 실행 권한과 도구가 확보된 범위에서 **모든 필수 컷·씬의 테이크 확보 및 채택 → 전체 편집·출력 → 전편 내부 QA → 사용자 검수 요청**까지 이어간다. 컷·씬마다 사용자 확인을 기다리지 않는다. |
| “이 시나리오를 스토리보드 시트로 만들어줘.” | 목표는 실제 이미지 시트. 시나리오를 재작성하지 않고 필요한 연출·카메라·공간·음향 설계와 검수를 채운다. 시트 납품 이후 영상 생성·편집으로 넘어가지 않는다. |
| “대본까지만”, “텍스트 콘티만”, “저장 없이 제작 방향만 봐줘.” | 명시한 범위·매체·저장 제한이 기본 흐름보다 우선한다. 해당 산출물에서 종료한다. |
| 제작 중 “시나리오 먼저 보여줘.” | 현재 산출물과 검수 상태를 공유한 뒤 계속한다. “내가 승인할 때까지 기다려”라고 하면 그 지점에서 대기하고, 재개 시 목표나 기존 승인을 다시 묻지 않는다. 새 요청이 시나리오만 요구한다면 단일 산출물로 종료한다. |
| “이 승인된 보드로 편집해줘”, “완성본의 음량만 수정해줘.” | 이미 검증된 선행 작업은 재사용하고 요청된 단계에서 시작한다. 필요한 입력 누락만 보완한다. 후반 단독 요청을 이유로 시트를 새로 만들지 않는다. |

`routing.csv`의 산출물·매체·권한 축은 **현재 단계의 담당자와 실행 한계**를 고르는 데 계속 사용한다. 한 단계의 `stop_boundary`는 그 담당자의 작업 경계이며, 총괄의 최종 목표까지 완료했다는 뜻이 아니다. 다만 단일 산출물 요청에는 그 경계가 프로젝트 종료점이 된다. 일반 글쓰기·웹사이트 등 비영상 작업의 진입 범위는 넓히지 않는다.

**흐름 선택 우선순위:** 명시된 종료점·금지사항 → 제공 소재/제작 방식에 맞는 기존 전용 흐름 → 일반 신규 제작의 이미지 시트 경유 흐름. 예를 들어 기존 삽화만 쓰는 영상은 스틸 편집 경로(`R12` 또는 `R29`)의 소재 제한을 따른다. 전용 설명 영상은 조건에 맞는 기존 담당과 검수 방식을 사용한다. 전용 흐름에 새 패널이나 생성형 영상을 강제하지 않고, 사용자가 시트를 별도로 요청했을 때만 소재·권한 제약 안에서 포함한다. 소재 제한과 추가 요청이 충돌하면 어느 쪽을 우선할지 확인한다.

## 3. 진행 방식과 단계 간 계약

총괄은 기존 공유 스토리 스파인에 작업 목표·감정 여정·확정된 제약을 유지한다. 시나리오가 있으면 그것부터, 캐릭터 관계가 중심이면 인물부터, 세계의 규칙이 이야기를 결정하면 세계관부터 들어갈 수 있다. **작성 순서는 유연하지만 앞뒤 산출물의 의존성은 지킨다.** 이미 받은 입력은 현재 버전과 적합성을 확인하고 재사용한다.

**누락된 창작 결정:** 총괄 위임 모드에서 고정되지 않은 톤·감정 여정·콘셉트·시놉시스·촬영 방식·가변 길이 등은, 브리프에서 합리적으로 추론할 수 있고 되돌릴 수 있는 범위라면 근거와 함께 `proposed`로 기록하고 기획·내부 검수를 진행한다. 후보 목록과 선택 질문을 정기 체크포인트로 요구하지 않는다. 미확인 사실을 채우거나 제안을 사용자 승인으로 바꾸지 않는다. 외부 실행을 열기 위해 작품의 핵심 방향이나 고비용 재작업을 좌우하는 결정이 필요하면 §5의 중단 조건을 따른다.

| 단계 | 다음 단계로 넘길 수 있는 상태 |
|---|---|
| 의도·이야기 | 관객이 느끼거나 알아야 할 것이 명확하다. 적용되는 플롯·인물 관계·선택·결과가 씬과 비트로 연결된다. 사실·브랜드 제약·결말·금지사항은 보존한다. |
| 시나리오·시각 앵커 | 씬별 행동, 감정 변화, 대사·내레이션 또는 무언 조건이 있다. 필요한 인물·공간·소품·제품·LOOK 앵커는 기존 계약으로 고정하거나 잠금 상태를 명시한다. |
| 기술 콘티 | 비트→씬→컷→패널이 연결된다. 각 컷의 관객 정보와 감정 변화, 인물의 위치·행동·시선, 공간과 조명, 구도·카메라 움직임과 동기, 대사·음성·사운드 또는 침묵의 타이밍을 관련 항목에 반영한다. 카메라가 고정되거나 인물·대사·음향이 없는 경우에도 의도적 선택으로 다룬다. |
| 이미지 시트 | 허용된 이미지 경로로 실제 패널을 제작하고 기존 시트 계약에 맞춰 배열·추출한다. 실제 시트와 추출한 패널을 이야기 순서로 열어 읽힘·정체성·공간·행동 연결을 검수한다. 프롬프트, 텍스트 콘티, 빈 템플릿은 시트 이정표를 충족하지 않는다. |
| 영상·후반 제작 | 그 단계가 목표에 포함되고 실행 권한이 있으면 기존 [시퀀스 실행 계약](../../../video-production-assets/references/sequence-execution.md)에 연결한다. 실제 채택 구간·컷 경계·전체 재생·청취를 검사하고 요청 형식으로 납품한다. 게시가 승인되지 않았다면 게시하지 않는다. |

`creative-production`은 다음 단계와 종료를 결정하는 유일한 총괄이다. `orchestrating-video-preproduction`은 텍스트 전담으로 유지하며, 총괄이 붙인 목표 중심 진행 방식을 이어받는다. 직접 요청한 협의 모드와 단일 전문 스킬의 기존 사용법은 유지한다. 총괄은 현재 필요한 담당 스킬과 필수 참조만 읽고, 스토리보드·연기·카메라/공간·타이밍·음향·검수 전문 스킬을 해당 입력이 필요한 경우에만 연결한다. 전문 스킬에 넘기는 것은 해당 단계의 산출물, 선행 ID/버전, 보존할 설정과 제약, 적용할 연출 기준, 검수 조건이다. 필요한 도구나 실제 독립 검수자를 쓸 수 없으면 수행하지 못한 검사를 명시한다. 새 스케줄러·원장·스키마를 추가하지 않는다.

### 완성 영상의 사용자 검수 조건

1. **전체 커버리지:** 현재 대본·콘티·편집 계획의 모든 필수 씬과 컷에 실제 검수된 채택 테이크 또는 허용된 원본 구간이 연결되어 있다. 한 생성 클립이 여러 컷을 맡으면 각 구간으로 확인한다. 탈락 후보까지 완성할 필요는 없지만, 필수 컷을 임의로 생략하거나 플레이스홀더로 채워 통과시키지 않는다.
2. **전체 편집본:** 채택 구간을 순서대로 편집하고, 요청에 해당하는 대사·음향·자막·전환을 적용해 재생 가능한 영상 파일로 출력한다. 클립 묶음이나 편집 타임라인만으로는 충족하지 않는다.
3. **전편 내부 QA:** 출력된 파일을 처음부터 끝까지 재생하고 필요한 경우 청취한다. 컷 경계, 필수 사건·대사, 연속성, 감정·공개 타이밍, 음향 싱크, 요청 형식을 확인한다. 필수 결함이 없을 때 영상 파일과 확인 결과를 묶어 **검수용 완성본**으로 전달한다. 사용자 수락·게시는 별개다.

## 4. FrameAtlas: 공통 연출 원칙

원본은 사용자가 전달한 `foundations.md`, `scenes.md`, `method.md`(각 문서 표기 CC0-1.0)다. 구현 시 출처 표시를 유지해 `creative-production/references/frameatlas/`에 보관하고, 하나의 짧은 공통 참조에서 현 단계에 적용할 판단을 안내한다. 기존 연출 전문 문서가 상세 기법과 기술 검수 기준을 계속 소유한다.

| 원칙 | 설계와 검수에 쓰는 방법 |
|---|---|
| **Foundations — 감정과 세계의 논리** | “관객에게 무엇을 느끼게 할 것인가?”를 한 문장으로 잡는다. 빛·재질·공간·행동에서 바뀌지 않아야 할 규칙과 피할 표현을 정하고, 감정이 읽히는 화면이나 소리의 구체적인 근거를 남긴다. |
| **Scenes — 행동과 공개** | 인물·장소·압박에서 장면을 시작한다. 욕망·관계·감정이 행동, 거리, 시선, 소품 사용으로 나타나게 한다. 카메라 움직임에는 새로 알려주는 정보나 감정 변화가 있어야 하며, 그렇지 않으면 정지 구도도 선택한다. |
| **Method — 컷 연결과 재현** | 컷마다 고유한 역할을 주고 행동→반응·결과, 빛 방향·동선·시선·소품 상태·음향 타이밍이 이어지는지 확인한다. 선택 이유와 유용한 탈락 기준은 기존 인계·기록에 남겨 다음 단계가 재현할 수 있게 한다. |

3컷·4컷, 한 광원, 세 가지 규칙은 적용 예이지 고정 산출물 규격이 아니다. 창작 원칙은 승인된 사실·제약이나 전문 스킬 계약을 덮어쓰지 않으며 새 작업 단계나 실행 권한을 만들지 않는다.

## 5. 내부 QA와 중단 조건

각 단계에서 총괄은 다음 단계가 소비할 내용과 그 근거를 검사한다. 검사 결과에 따라 **통과 → 바로 진행 / 범위 안에서 수정 가능 → 최소 수정·재검수 / 차단 → 영향받는 단계만 멈춤**으로 처리한다. 평범한 작화·카메라·타이밍·묘사 판단은 승인된 방향 안에서 근거를 남기고 진행한다. 아직 사용자 수락이 없는 창작 판단은 제안으로 유지한다.

**완성 영상 작업에서 컷·씬별 보고는 진행 상황이지 검수 요청이나 중단 지점이 아니다.** 내부 QA가 통과하면 남은 컷·씬의 제작과 편집을 이어간다. 불합격이면 §5의 수정 루프를 적용하고, 막힌 컷에 의존하지 않는 작업은 계속한다. 실제로 필수 컷이 막혔다면 부분 결과를 완성본이 아닌 진행 상태로 표시한다.

사용자에게 묻거나 기다리는 조건은 다음과 같다.

- 사용자가 중간 승인 지점으로 지정했다.
- 확정된 대사·사실·브랜드 제약·결말·핵심 메시지를 바꿔야 하거나, 큰 재작업을 낳는 방향이 사용자 입력 없이는 정해지지 않는다.
- 필수 입력·실제 검수 증거·실행 환경이 없거나, 이미지/영상/외부 도구 실행에 필요한 권한·비용 승인·권리 확인이 없다.

진행이 막혔으면 정확한 원인, 완료한 범위, 필요한 결정이나 자료, 재개 지점을 한 번에 알린다. 범위 안에서 독립적으로 진행할 수 있는 작업은 계속한다. 수정으로 다시 확인할 대상은 실제 의존 관계를 따라 좁히되, 전체 이야기의 연속성 판정은 기존 게이트를 따른다.

**수정 루프 종료:** 결함마다 원인 가설·수정 대상·통과 기준을 먼저 적고, 기존 승인 한도 안에서 가장 작은 수정 1회와 재검수를 한다. 같은 실패라면 동일 조건에서 반복하지 않는다. 새 증거로 원인과 수정 방법이 달라진 경우에만 남은 승인·시도 한도에서 후속 수정을 검토한다. 한도 소진, 원인 미해결, 필수 검사 미통과/미확인이면 해당 단계와 의존 작업을 멈추고 결함·시도·재개 조건을 기록한다. 처리 상태가 불명확한 외부 요청은 재제출하지 않고 먼저 상태를 대조한다.

기존 [승인·실행 정책](../../../creative-production/references/policy.md), 콘텐츠 수락과 실행·비용·게시 승인의 분리, 단일 `project.json` 작성자와 `.history`, 현재 버전의 자산 잠금과 `PRELIMINARY`/`FINAL` 조건을 보존한다. **목표에 시트나 완성 영상이 포함된 것과 실제 생성 권한이 열린 것은 다르다.** 반대로 이미 주어진 권한은 적용 범위 안에서 재사용한다. 진행 상태는 목표와 별개로, 실제 산출물·검수·승인에 근거해 기록한다.

### 실행 권한 판정

| 실행 | 최초 요청이 여는 범위와 중단 조건 |
|---|---|
| 일반 신규 영상의 기본 이미지 시트 / 명시적 시트 요청 | 첫 요청은 이미지 시트를 **제작 범위에 포함**한다. 텍스트 전용·생성 금지 같은 제한이 없고 기존 정책상 허용된 이미지 실행자의 권한·런타임·권리·필수 자산 조건을 충족하면, 시트 직전에 별도의 창작 승인 질문을 하지 않는다. 실제 실행 권한이나 필요한 동의가 없으면 이미지 단계만 차단한다. 기본 스틸 경로 `codex-imagen`에 기존 정책에 없는 가격·쿼터 확인을 추가하지 않는다. |
| 영상 생성·외부 실행·비용 | “영상 만들어줘”는 완성 목표이지 임의 모델·비용·제출 승인으로 해석하지 않는다. 현재 입력 버전과 작업·제공자·허용 비용/재시도 범위에 유효한 명시적 실행 승인으로 기존 진행 게이트를 충족하면 같은 확인을 다시 요구하지 않는다. 없거나 변경으로 무효화됐으면 필요한 실행 승인만 묻고 그 직전에서 기다린다. 시트 통과나 사용자 콘텐츠 수락은 영상 실행 승인이 아니다. |
| 게시 | 납품 가능한 파일을 만들라는 요청, 실행·비용 승인, 콘텐츠 수락만으로 게시하지 않는다. 대상·범위에 유효한 명시적 게시 승인이 필요하다. |

이 표는 승인 절차를 우회하는 새 권한 표가 아니다. 구현 시 최초 목표 판정과 `R24`의 실행 승인 조건을 연결하고, 기존 영상 경로의 별도 진행 요청을 **이미 주어진 유효한 명시적 승인도 충족할 수 있는 조건**으로 정합화한다. 현재 문서 변경만으로 기존 스킬의 게이트가 바뀌지는 않는다.

## 6. 연기·사운드·음성 보정: 필요한 컷에만 적용

총괄은 기존 [연기](../../../video-production-assets/references/04-performance.md), [대사·립싱크](../../../video-production-assets/references/22-dialogue-lipsync.md), [편집·사운드](../../../video-production-assets/references/09-edit.md)의 기준으로 실제 테이크를 비교한다. 계획 단계에서 감정·행동·발화·사운드 큐를 설계하고, 기존 영상 내 음성·사운드 생성 기본값과 프로젝트별 예외는 유지한다. 채택 테이크에 결함이 있을 때만 해당 구간의 최소 수정 방식을 고른다. Higgsfield는 선택 가능한 실행자이지 연출 담당자나 사용자 승인 지점이 아니다.

**조사 근거 (2026-11-19):** [공식 CLI 문서](https://github.com/higgsfield-ai/cli), [Genjutsu 공식 설명](https://higgsfield.ai/genjutsu), [Lipsync Studio](https://higgsfield.ai/lipsync-studio), 현재 Higgsfield CLI 전체 모델·워크플로 목록과 아래 후보의 상세 계약을 읽었다. 공개 UI, CLI에 노출된 계약, 이 패키지에서 허용된 실행은 별개다. 작업 제출·미디어 업로드·비용 확인·결과 품질 테스트는 하지 않았다.

| 결함 | 확인된 후보와 적용 한계 |
|---|---|
| 동작·몸 연기 타이밍이 맞지 않음 | **Genjutsu**(`hf_mult_motion_control`) / **Kling 3.0 Motion Control**(`kling3_0_motion_control`). 이미지와 동작 레퍼런스 영상을 받는 모션 전이 후보. 기존 컷의 표정만 정확히 고치는 기능으로 간주하지 않는다. 배우 정체성·시선·동작·배경·카메라·컷 연결을 전후 비교한다. |
| 효과음·폴리·앰비언스가 부족함 | **Seed Audio 1.0**(`seed_audio`) / **Mirelo Text to Audio**(`mirelo_text_to_audio`). 별도 오디오 생성 후 사운드 큐에 맞춰 편집하는 후보이며, 기존 트랙의 노이즈 제거·소스 분리나 자동 싱크 기능으로 간주하지 않는다. 실제 충돌음 위치, 룸톤, 대사 명료도, 최종 믹스를 청취한다. |
| 발음·음색·언어 보정 | 발음 오류는 [최소 구절 교체 절차](../../../video-production-assets/references/29-reference-driven-production.md)를 우선한다. CLI의 **Eleven v4**(`elevenlabs_v4`)는 대사 오디오 후보지만 현재 `higgsfield-generate`의 TTS 제외 규칙을 우회하지 않는다. **Voice Change**(`voice_change`)와 **Dubbing**(`dubbing`, 한국어 `kor` 포함)은 원본 영상 입력 워크플로 후보다. CLI 상세에 비용 매개변수가 있으나 공식 문서는 비용 추정 미지원을 명시하므로, 비용이 별도로 검증되기 전까지 실행은 차단한다. 승인된 보이스·대사·발화 의도를 보존하고 앞뒤 구절과 씬 믹스를 다시 청취한다. |
| 실제 입 모양과 최종 음성 불일치 | **Lipsync Studio** 공개 UI에서는 이미지/영상과 오디오 입력을 확인했다. 조사한 CLI·MCP 카탈로그에서는 전용 립싱크 실행 계약을 확인하지 못했다. 따라서 자동 호출 후보가 아니라 별도 검증 대상이다. 더빙·오디오 참조 기능만으로 입 모양 보정을 보장하지 않는다. |

실행 직전 기존 [Higgsfield 승인 게이트](../../../higgsfield-generate/references/package-gate.md)에서 현재 모델/워크플로와 사용할 실행 경로, 실제 입력 역할, 외부 전송·음성/초상 권리, 견적 및 승인 한도를 확인한다. 지원·승인되지 않은 도구로 자동 전환하지 않는다. 적용하는 보정에는 컷·테이크·오디오 ID/버전, 교체 범위와 보존할 요소를 넘긴다. 결과가 통과하면 그 구간만 채택하고 실제로 영향받은 자막·립싱크·컷 연결·씬 믹스를 재검사한다. 허용된 보정과 재검수는 내부에서 이어가며, 컷별 사용자 검수를 새로 요구하지 않는다. 완성본 전달 전에는 전편을 다시 재생·청취한다.

### 6.1 공급자 공통: 테이크 최소 보정

[비-Higgsfield 조사 노트](../../analysis/2026-11-19-performance-voice-audio-repair-research.md)의 후보를 모두 조건부 목록에 반영한다. **외부 스킬을 전부 활성화하는 대신, 기존 `video-production-assets` 안에 결함별 선택과 QA를 담당할 공통 참조를 하나 둔다.** `creative-production`은 필요한 순간에만 참조를 열고 적용 범위를 배정한다. 기존 테이크 재사용·편집으로 해결할 수 있다면 먼저 비교하고, 국소 보정으로 충분하면 씬 전체를 다시 생성하지 않는다. 음성이 정확히 들려야 하는 범위, 의도된 침묵·잡음·속삭임, 보이는 입의 가독성을 구분한다.

| 결함 | 우선 적용과 대안 | 보존 및 검사 |
|---|---|---|
| 잡음·치찰음·레벨 불균형 | 대사 트랙의 로컬 FFmpeg 필터를 필요한 것만 적용. 표준 필터로 해결하기 어려운 음성 잡음은 DeepFilterNet 검증 후보. | 숨·속삭임·룸톤·발화 타이밍을 유지했는지 같은 청취 레벨에서 A/B 비교. 납품 믹스의 레벨·피크도 별도로 확인. |
| 좋은 연기의 음색만 변경 | 권리 확인된 기존 보이스가 있으면 ElevenLabs 공식 `voice-changer` 또는 승인된 Higgsfield `voice_change` 검토. 둘은 현재 각각 실행 경로/비용 확인이 필요하다. | 대사, 정서, 강세, 말의 길이 및 화자 연속성 유지. 음색 변환을 발음 교정이나 연기 재창작으로 간주하지 않는다. |
| 발음·감정·톤·강세·호흡 오류 | 승인된 화자의 ADR(대사 재녹음)이나 **Fish Audio Drama 3 / Typecast**로 최소 연결 구절을 재발화. 새로운 언어가 실제 목표일 때만 승인된 더빙 경로 검토. | 발화 텍스트·발음 지시·화자 정체성·감정 큐를 분리. 앞뒤 문장과 처음부터 한 사람이 말한 것처럼 이어지는지 청취. 전달 의미를 임의로 바꾸지 않는다. |
| Foley·앰비언스·효과음 누락 | 확보한 합법적 소재를 우선 맞춰 보고, 필요하면 ElevenLabs 공식 `sound-effects` 또는 기존 Higgsfield Seed Audio/Mirelo로 해당 큐만 제작. | 실제 접촉·움직임에 맞는 프레임, 공간감, 대사 명료도를 확인. 믹스 보정과 SFX 생성을 구분. |
| 표정·시선·몸 연기 불일치 | 기존 채택 가능 테이크나 다른 앵글을 먼저 대조. 부족하면 Runway `character_performance`, Higgsfield Genjutsu/Kling을 필요한 짧은 컷의 연기 재작업 후보로 검토. | 정체성·표정·시선·동작·배경·카메라·연속성을 다시 확인. 모션 전이는 기존 화면에서 표정만 정확히 수정하는 기능으로 간주하지 않는다. |
| 최종 대사와 화면 속 입이 어긋남 | 발화 트랙을 먼저 확정한다. 입이 실제로 보이고 중요할 때 적합한 대체 컷을 비교한 뒤, LatentSync 또는 확인된 립싱크 경로를 검토. Higgsfield Lipsync Studio는 현재 UI 확인만 된 후보. | 실제 자음·강세·입 타이밍과 얼굴 정체성·경계 프레임을 확인. 입이 보이지 않으면 근거를 남기고 별도 보정 생략. 들리지 않거나 보지 못한 구간은 미검증. |

**공통 인계:** 기존 비트/씬/컷·테이크·오디오 ID와 버전, 원본·타임라인 타임코드, 관찰한 결함, 변경할 요소와 유지할 요소, 실행 권한과 통과 조건을 전달한다. 원본을 덮어쓰지 않고 수정본만 별도 버전으로 등록한다. 교체 구절 → 앞뒤 대사 → 장면 믹스 → 입 모양·컷 연결 순으로 확인하고, 음성만 바뀌면 실제로 영향받은 자막·싱크·타이밍·믹스만 다시 연다. 필수 QA나 권한이 없으면 해당 작업만 차단한다. 정책의 범위 안에서 내부 검수·채택 후 제작을 이어가며, 컷별 사용자 검수는 새로 요구하지 않는다.

### 6.2 도입 수준과 설치·실행 경계

| 도입 수준 | 대상과 완료 조건 |
|---|---|
| **이번 구현: 공통 절차와 기본 로컬 경로** | 기존 `video-production-assets`의 연기·대사·사운드·[최소 구절 교체](../../../video-production-assets/references/29-reference-driven-production.md#dialogue-repair) 계약을 그대로 소비한다. FFmpeg 경로는 지원 필터를 확인한 후 권리 확보된 테스트 파일을 비파괴로 처리하고 청취·타이밍을 검증한다. 필요한 도구가 없으면 설치 대신 의존성 누락을 표시한다. |
| **이번 구현: 현행 실행자에 조건부 연결** | Fish Audio Drama 3·Typecast는 노출된 실행 경로에서 실제 모델·보이스·옵션을 확인하고, Higgsfield는 기존 실행자·게이트를 재사용한다. 모델 또는 음성 선택에 필요한 필드가 지원되지 않으면 다른 기본값으로 바꾸지 않는다. 재발화·SFX·모션 전이는 각각 독립 작업이므로 영상 전체 승인만으로 자동 제출하지 않는다. |
| **이번 구현: 후보 등록과 사전 점검, 실운영 연결은 검증 후** | ElevenLabs 공식 `voice-changer`·`sound-effects`는 이식 후보로 등록하고 공식 소스·라이선스·지원 파일·인증/전송 방식을 확인한다. 실제 도입 승인 후 사용한 업스트림 리비전을 고정한다. DeepFilterNet·LatentSync는 로컬 도구/모델 후보로 등록하고 GPU·포맷·코드/가중치 라이선스·테스트 적합성을 확인한다. Runway는 실행 경로·권리·비용을 확인할 때만 연결하며, 웹 전용 기능은 자동 실행하지 않는다. 준비되지 않은 후보는 사용 불가 이유를 표시하고 필수 런타임으로 만들지 않는다. |

후보 등록은 설치·업로드·복제·실행 승인이 아니다. 외부 실제 제출은 [공통 제작 실행 정책](../../../video-production-assets/references/24-production-execution.md)의 현재 입력 버전, 지원 기능, 권리·동의·전송, 견적·시도 상한을 충족해야 한다. 다른 실행자는 명시적으로 허용된 범위에서만 선택한다. 공급자 예제나 `SKILL.md`가 현재 사용 가능한 도구를 증명하지 않는다.

## 7. 이번 구현 범위와 순서

| 순서 | 구현 묶음 | 연결할 기존 표면과 완료 기준 |
|---|---|---|
| 1 | **목표 중심 총괄·단계 위임** | `creative-production/SKILL.md`와 기존 라우팅 참조에서 목표/종료점과 현재 단계의 작업 경계를 분리한다. 텍스트 레인의 단계 실행·방향 안내에서 총괄 위임과 직접 협의 모드를 명확히 구분한다. 기존 단일 산출물·전용 경로·범위 제한 회귀가 없다. |
| 2 | **FrameAtlas와 이미지 시트** | 원본 세 문서의 출처를 포함해 보관하고 기존 스토리 스파인·핸드오프·QA에서 해당 연출 원칙만 참조한다. 시트 경로는 기존 R24, 이미지 실행·자산 잠금, 실제 시트/패널 검수 규칙을 재사용한다. |
| 3 | **보정 선택과 기존 도구 연결** | `video-production-assets`에 조건부 보정 참조를 하나 만들고 모듈 인덱스·편집·대사·시퀀스 실행의 필요한 지점에 연결한다. §6.2의 기본 로컬 경로, 현행 실행자, 후보 등록을 각각 검증하고 상태를 구분한다. 공급자별 절차는 해당 실행 경로의 참조만 읽는다. |
| 4 | **전편 편집·전편 QA·회귀** | 모든 필수 컷의 채택 구간을 편집·출력하고 전편 검수 후에만 사용자 검수를 요청한다. 기존 테스트에 목표 중심·보정·실행 중단 사례를 붙인다. 공급자 없는 실패 테스트와 실제 로컬 미디어 검수를 분리한다. |

라우팅 담당 선택의 정본, 기존 스킬의 입출력, 단일 `project.json` 작성자와 `.history`, 비영상 활성화 범위, 진행 중인 Three.js 프리비즈 변경은 보존한다. 새 경로 ID나 파일 단위 분리는 기존 형식으로 표현이 불가능할 때만 계획에서 결정한다. 이번 설계는 외부 후보 전체 설치, 비용 집행, 게시, 제작 프로젝트 데이터 마이그레이션을 포함하지 않는다.

## 8. 검증 기준

기존 라우팅·경계 회귀 사례를 유지하고 다음 케이스를 새 대화와 고정 테스트 자료로 확인한다. 실제 공급자 호출이나 비용 테스트는 별도 실행 승인 후에만 실시한다. 도구 호출 순서 검증과 실제 화면·오디오 품질 검증은 별도로 보고한다.

| 검증 사례 | 통과 조건 |
|---|---|
| 최종 영상 목표만 있는 일반 브리프 | 시놉시스·대본 완료가 최종 보고가 되지 않는다. 필요한 전문 단계와 내부 QA를 이어가며 허용된 환경에서는 실제 이미지 시트를 확인한다. |
| 영상 실행이 이미 승인됨 / 승인되지 않음 | 같은 목표에서도 승인된 실행만 이어간다. 미승인 상태에서는 승인 요청 및 재개 지점을 남기고 완성 영상으로 보고하지 않는다. |
| 승인된 다중 씬·다중 컷 제작 | 시트·첫 컷·첫 씬이 완성돼도 일상적인 사용자 검수 요청은 없다. 필수 컷 전체의 채택 구간을 연결하고 전편을 출력·재생·검수한 뒤에만 완성본 검수를 요청한다. |
| 한 필수 컷이 누락 또는 반복 불합격 | 독립적인 컷 작업은 이어간다. 누락·불합격 컷이 남으면 조립된 초안이 있더라도 완성본으로 표시하지 않고, 막힌 컷과 재개 조건을 알린다. |
| 실제 시트 요청 / 텍스트 콘티만 / 대본만 / 저장 금지 | 각각 지정된 산출물과 매체·저장 범위를 지키고 작업 범위를 확대하지 않는다. |
| 내부에서 수정 가능한 컷 오류 / 확정 결말 변경 필요 | 전자는 수정·검수 후 자동으로 이어가고, 후자는 변경 이유와 영향만 묻는다. |
| 검증된 자산과 미완료 작업이 있는 재개 | 검증된 버전은 재사용하고 대기 중 작업을 먼저 확인한다. 입력·승인·비용을 다시 만들지 않는다. |
| 이미지 생성기나 필수 실제 검수 사용 불가 | 가능한 계획은 남기되 파일·검수 결과를 꾸며내지 않고, 시트 미완료와 차단 항목을 표시한다. |
| 중간 공유 / 승인 전 대기 / 편집만 요청 | 공유 후 계속, 지정 지점에서 대기, 기존 편집부터 시작이라는 세 결과가 구분된다. |
| 미확정 감정·콘셉트·길이 | 범위 안의 가역적 선택을 제안으로 남기고 다음 기획 작업을 시작한다. 중간 콘텐츠 승인이나 사용자 수락을 만들어내지 않는다. |
| 기존 삽화만 사용하는 전용 숏폼 | 기존 전용 경로가 유지되고 새 이미지·생성형 영상 호출이 없다. |
| 반복 결함 또는 외부 작업 상태 불명 | 동일 조건 재시도·중복 제출이 없고 차단된 단계, 실패 근거, 재개 조건이 표시된다. |
| FrameAtlas 연출 및 결함 검수 | 고정 테스트 장면에서 목표 감정 → 인물의 행동·거리·시선 → 카메라가 공개하는 정보 → 실제 패널에서 읽히는 결과를 `비트→컷→패널` ID로 대조한다. 예: ‘불신에서 안도로’가 목표인 열쇠 반환 장면에서 시선이 다른 곳을 향하거나 열쇠 소유자가 컷 사이에서 순간적으로 바뀐 패널을 넣는다. 검수가 결함을 찾아 해당 컷만 수정하고, 수정된 패널과 앞뒤 이야기 순서를 다시 열어 검사하기 전에는 통과하지 않는다. 텍스트 체크만으로 시각 검수를 통과시키지 않는다. |
| 연기·사운드·음성 보정 | 결함 유형에 맞는 보정만 배정한다. 예: 한 단어의 발음만 틀리면 승인된 음성의 해당 구절과 앞뒤 맥락을 대조하고, 변경 구간과 실제 입·타이밍·믹스를 재검수한다. 사용자 중간 검수 없이 나머지 제작을 이어간다. 지원되지 않은 립싱크나 견적 미확정 더빙을 넣은 테스트에서는 실제 제출과 완료 처리가 차단된다. |
| 10–15초 한국어 합성/권리 확보 구간 A/B | 잡음만 있는 테이크는 로컬 복원만 적용하고, 발음·감정이 틀린 테이크는 최소 구절 교체로 분기한다. 실제 처리 파일을 열어 원본과 동일 청취 레벨에서 발음·톤·숨·룸톤을 비교하고, 입이 보이는 컷은 실제 싱크를 검사한다. 실제 외부 도구 없이 되돌림·재검수 분기를 시험할 때는 미리 준비한 대체 구절만 사용하며 공급자 QA로 보고하지 않는다. |
| 미검증 공급자 또는 음성·초상 권한 누락 | 보정 조건에 맞더라도 해당 작업을 제출·업로드하지 않는다. 후보별 누락 이유를 구분하고 무단 대체 없이 독립 작업은 이어간다. |

이 설계의 구현 착수는 상세 문서 확인 이후다. 설계 자체의 검토는 스킬의 실제 경로 변경이나 프리프로덕션·영상 제작 성공을 의미하지 않는다.
