# 콘텐츠·영상 제작 스킬 패키지 설계

## 1. 상태·목표·현재 근거

- 상태: **사용자의 후속 진행 요청으로 구현 승인됨**. 이 문서는 목표 계약이며 실제 구현·검증 증거는 [package-validation.json](../../../qa/package-validation.json)에 기록한다.
- 승인된 방향: `creative-production`을 단일 총괄로 삼고 콘텐츠 전문 스킬의 재사용 에셋과 실행 의존성을 같은 repo에서 관리한다. 로컬 스킬 전체를 무차별 복사하지 않는다.
- 설계 작성 단계: 설계와 기존 계약 확인만 수행했다. 당시에는 스킬 복사·설치·이동, 실행기 구현, 커밋·푸시, 미디어 생성·게시를 수행하지 않았다. 후속 진행 요청은 패키지 구현·검증·설치·커밋/푸시 범위를 승인한 것으로 적용하며 미디어 실행/게시 승인은 아니다.
- 대상 repo: `DeclanJeon/video-production-skills`. repo 이름과 기존 설치 가능한 루트 폴더를 유지한다.
- 성공 조건: 이 repo의 핵심 패키지만 설치한 환경에서 콘텐츠 초안과 텍스트 영상 기획을 수행할 수 있고, 선택형 실행 의존성은 필요한 단계에서만 요구한다. 같은 버전의 스킬·자료·계약을 재현할 수 있어야 한다.
- 이 설계는 기존 [프리프로덕션 검토 설계](2026-10-02-preproduction-review-gate-design.md)의 “총괄은 로컬에만 두고 공개 패키지에 포함하지 않는다”는 패키징 경계만 대체한다. 기존 폴더·이미지 검토·영상 실행/과금·게시 승인 계약은 유지한다.

설계 작성 당시 확인한 사실:

| 근거 | 현재 상태 | 설계에 주는 제약 |
|---|---|---|
| [manifest.json](../../../manifest.json) | 버전 1.2, 설치 스킬 3개 | 총괄이 배포 목록에 없다. 설치 목록의 단일 원장은 이 파일로 유지한다. |
| [README](../../../README.md) | 총괄과 다른 전문 스킬은 외부 설치 전제; 재사용 라이선스 없음 | 현재 repo만으로 로컬 제작 환경 전체를 재현한다고 소개할 수 없다. |
| 설치된 `creative-production` 1.1.0 | 콘텐츠·영상 단일 총괄. `$deep-interview`, `$plan`, `$interactive-collaboration`, `$team` 등 참조 | 총괄 파일 복사만으로 독립 패키지가 되지 않는다. 호스트 통합과 핵심 기능을 구분해야 한다. |
| 설치된 텍스트 기획 스킬 4개 | 상호 참조와 공유 방향·서적 종합 자료 존재 | 개별 `SKILL.md`만 복사하지 않고 필요한 형제 스킬과 참조 자료를 함께 관리한다. 재배포 권한은 별도 확인한다. |
| [제작 계약](../../../video-production-assets/references/contract.md) | 프로젝트 스키마 1.1, artifact·dependency_versions·approval·asset_registry·검사 프로필 | 새로운 제작 원장이나 승인 상태 머신을 만들지 않는다. |
| [기존 검토 설계](2026-10-02-preproduction-review-gate-design.md) | 이미지 기반 검토와 영상 실행 승인이 분리됨 | 이 경계를 유지하면서 텍스트 기획에는 적용하지 않는다. |

## 2. 구조 선택과 제외 범위

| 대안 | 장점 | 문제 | 결정 |
|---|---|---|---|
| 수정한 로컬 스킬 65개를 전부 복사 | 현재 설치에 가까운 형태 | 외부 저작권·개인 서버 경로·프레임워크·도구 의존성까지 포함하고 설치/업데이트 범위가 커진다. | 채택하지 않음 |
| 기존 3개에 총괄만 추가 | 변경량이 작다. | 총괄이 부르는 텍스트 기획 레인이 여전히 별도 설치에 의존한다. | 채택하지 않음 |
| 총괄 + 닫힌 핵심 기획 묶음 + 선택형 전문/실행 의존성 | 기본 기획의 이식성, 전문 스킬 경계, 공급자 선택을 함께 보존한다. | 핵심에 넣을 자료의 출처와 의존성 구분이 필요하다. | **채택** |

제외: 새 영상 엔진/SDK/데몬, 별도 에이전트 런타임, 새 전역 승인 DB, 모든 스킬의 일괄 벤더링, 고정 생성 모델, 자동 과금·게시, repo 이름 변경, 실제 프로젝트 산출물 보관, 로컬 전체 스킬 설치의 강제 동기화. 일반 UI·브랜드 설계의 기존 소유권은 바꾸지 않는다.

## 3. 핵심 패키지와 전문 레인

### 3.1 포함 대상으로 정한 핵심 8개

아래 목록은 목표 패키지 구성이다. 신규 포함 대상의 공개 반입은 §9 출처·권리 검사를 통과해야 한다. 권한 미확인 상태를 배포 허가로 해석하지 않는다.

| 스킬 | 책임 | 경계 |
|---|---|---|
| `creative-production` | 요청 분류, 레인 선택·순서, 공유 브리프/근거/연속성, 승인 인계, 최종 납품 확인 | 유일한 프로젝트 총괄. 요청한 산출물만 조율한다. |
| `video-production-assets` | 기존 15개 모듈의 제작 계획·근거·에셋·검토 계약 | 모듈은 별도 스킬 15개가 아니다. 렌더/게시는 하지 않는다. |
| `camera-spatial-design` | 카메라·화각·공간·블로킹의 수치 설계 | 실제 Blender 실행과 구분한다. |
| `blender-previsualization` | 명세를 Blender 프록시/프리비즈로 구현·검사 | 선택된 Blender 런타임과 적용되는 실행 승인이 필요하다. 최종 영상 품질 보장은 아니다. |
| `orchestrating-video-preproduction` | 콘셉트→시놉시스→필요한 캐릭터→스토리보드의 텍스트 기획 레인 | 총괄의 내부 단계 묶음. 프로젝트 총괄이나 미디어 실행기가 아니다. |
| `developing-video-synopses` | 콘셉트·시놉시스·비트 작성 | 요청된 단계만 작성한다. |
| `designing-video-character-sheets` | 캐릭터 시각 설계·연속성·범용 이미지 프롬프트 | 텍스트 캐릭터 시트. 실제 이미지 생성과 구분한다. 인물이 없는 작업에는 생략한다. |
| `storyboarding-video` | 내러티브/정보 비트 단위 패널과 범용 프롬프트 | 실제 이미지, 샷 타이밍, 모델별 클립 입력과 구분한다. |

일반 블로그·소셜 원고는 총괄이 공급된 자료와 적용 가능한 브리프·근거 계약으로 작성할 수 있다. 전문 플랫폼 운영이나 마케팅 전략을 요청한 경우에만 해당 외부 레인을 요구한다. 핵심에 별도 범용 글쓰기 스킬을 새로 만들지 않는다.

### 3.2 선택형 의존성

패키지는 아래 레인의 역할·활성화 조건·부족할 때의 정지 지점을 선언한다. 실제 외부 스킬 내용과 실행 코드를 검증 없이 복사하거나 설치하지 않는다.

| 레인 | 대표 전문 스킬 | 필요해지는 조건 |
|---|---|---|
| 마케팅·출처 기반 변환 | `content-production-marketing`, `youtube-content`, `youtube`, `podcast` | 캠페인 전략·성능 목표·실제 출처 미디어를 다루는 요청 |
| 플랫폼 원고/운영 | `tistory-blog`, `wordpress-blog` | 선택한 플랫폼의 형식 또는 명시된 라이브 작업 |
| 스토리커머스/각본 | `story-pipeline`, `sw-workflow`, `synopsis-craft`, `script-craft`, `char-design`, `storyboard-craft`, 적용되는 `sw-*` | 해당 형식이나 전문 단계가 명시된 요청 |
| 영상 기술·모델·비평 | `video-pipeline`, `video-shotlist`, `video-prompt`, `video-model-router`, `video-critique`, `video-prompt-atlas` | 기술 연결, 모델별 입력, 샷 분해, 비교 또는 비평 |
| 이미지 검토/콘텐츠 이미지 | `codex-imagen`, 필요한 일러스트·제품 사진·썸네일 전문 스킬 | 실제 이미지가 필요한 요청. 기존 이미지 기반 프리프로덕션은 `codex-imagen`이 분기별 필수 의존성이다. |
| 실행·조립 | 선택된 `fal-video-production`, `higgsfield-*`, `comfyui`, `remotion-*`, FFmpeg 등 | 선택된 공급자/실행 표면을 실제 사용해야 하는 단계 |
| 오디오 | `songwriting-and-ai-music`, 선택된 `heartmula`, `audiocraft-audio-generation` 또는 음성 도구 | 전문 가사/음악 설계 또는 요청된 실제 오디오 |
| 호스트 통합 | `deep-interview`, `interactive-collaboration`, `plan`, `ultragoal`, `team`, 실제 브라우저/리서치 도구 | 해당 호스트의 기능을 사용하고 현재 작업에 필요한 경우만 |

의존성은 선택형이라도 해당 분기에서는 필수일 수 있다. 필요한 스킬·도구가 없으면 정확한 부족 항목과 이미 완료한 준비를 보고하고 그 단계 전에서 멈춘다. 다른 공급자·형식으로 조용히 대체하지 않는다. 요청을 충족하지 못하는 대안을 완료 결과로 보고하지 않는다.

## 4. 저장소 구조와 에셋 소유권

기존 루트 스킬 디렉터리 방식 유지. 새 `skills/` 계층과 중복 래퍼를 추가하지 않는다.

```text
video-production-skills/
  creative-production/
    SKILL.md
    references/
    agents/
  video-production-assets/
    SKILL.md
    references/
    assets/
    scripts/
    agents/
  camera-spatial-design/
  blender-previsualization/
  orchestrating-video-preproduction/
    SKILL.md
    references/
    evals/
  developing-video-synopses/
  designing-video-character-sheets/
  storyboarding-video/
  integrations/
    skill-routing.md
  examples/
  qa/
  docs/superpowers/specs/
  manifest.json
  README.md
```

각 스킬은 실제 필요한 참조·템플릿·스크립트·평가 자료까지 포함한다. 없는 디렉터리를 빈 틀로 만들지 않는다. 공개 패키지 예제/QA는 `examples/`·`qa/`에 유지하고 설치 시 기존 `video-production-assets/support/` 관례를 따른다.

**패키지 에셋:** 템플릿, ID/스키마 계약, CSV 열 구조, 재사용 가능한 디자인/연속성 규칙, 합성 예제, 검증 스크립트. 소유 스킬의 `assets/`와 `references/`에 둔다. 총괄이 모든 전문 규칙을 다시 복사해 보유하지 않는다.

**프로젝트 에셋:** 실제 원고, 출처 자료, 생성 이미지·영상·오디오, 사용자 제품/인물 참조, 호출 결과·검수. 요청한 프로젝트 루트에 저장하고 패키지 repo에 자동 반입하지 않는다. 출처·사용 권한이 없는 자료를 예제로 공개하지 않는다.

**소스 오브 트루스:** 구현 이후 스킬 수정은 repo에서 하고 명시적 설치로 사용자 스킬 루트에 반영한다. 설치본을 독립 원본으로 계속 편집하지 않는다. 현재 `.codex`와 `.agents`의 기존 사용자 파일을 임의 삭제하지 않으며 중복 ID를 검출하고 정해진 설치본으로 교체/이동할 때만 확인을 받는다. 중복 별칭이나 재귀 래퍼로 해결하지 않는다.

## 5. 총괄 동작과 단계 간 계약

1. 입력에서 목적, 출처, 산출물, 제외 사항, 텍스트/미디어 실행 범위를 읽는다. 이미 공급된 답과 승인은 재사용한다.
2. 핵심 또는 선택형 레인 중 요청에 필요한 것만 선택한다. 스킬과 런타임 사용 가능 여부는 필요한 분기에서 확인한다.
3. 하나의 브리프와 사실/제안 구분을 전달한다. 사용자 지정 캐릭터·소품·배경·샷·버전·승인 상태를 보존한다.
4. 전문 스킬이 요청된 에셋을 만든다. 총괄은 의존 관계와 일관성을 확인하고 필요한 다음 단계에 전달한다.
5. 범위에 해당하는 사용자 검토/실행 승인 게이트에서 멈춘다. 명시적으로 위임된 창작 판단만 그 범위 안에서 진행한다.
6. 실제 요청한 결과와 확인한 증거를 인계한다. 계획, 생성 파일, 검사, 사용자 수락, 게시 상태를 구분한다.

총괄은 에셋을 모으기만 하는 스킬이 아니다. 제작 전 필요한 에셋과 담당을 정하고, 단계 간 의존성·수정 영향을 조율한다. 전문 스킬은 프로젝트 총괄의 승인을 대신하지 않는다.

단독 전문 스킬 호출은 총괄 계약을 한 번만 읽고 해당 작업을 수행한다. 이미 총괄이 위임한 단계는 총괄로 재귀 호출하거나 두 번째 인터뷰·승인 원장을 만들지 않는다. 공유 텍스트 기획 레인은 내부 단계 순서를 가질 수 있지만 전역 조정자는 여전히 하나다.

### 5.1 인계 데이터

[기존 제작 계약](../../../video-production-assets/references/contract.md)의 인계 최소값을 재사용한다. 아래는 의미상 계약이지 새 provider JSON 스키마가 아니다.

- 요청한 출력과 제외 범위, 현재 담당 레인.
- 입력 artifact/shot/asset ID와 버전, 새 출력의 ID·버전·상태.
- 사실/산술/해석/허구·디자인 제안/미확인 주장과 출처.
- 필요한 연속성 앵커와 의도된 변경.
- 실제 출력 텍스트 또는 존재하는 파일의 위치·검사 증거.
- 실제 승인 근거와 적용 범위, 미완료 조건, 다음 레인에서 필요한 사항.

텍스트 한 편은 문서와 브리프만으로 충분하다. 다단계 영상에서만 기존 `project.json` 계약을 사용한다. 기존 story-commerce `manifest.json`이나 screenplay story bible은 해당 레인의 자료로 연결하고 별도 전역 상태를 만들지 않는다.

### 5.2 승인·수정

- 텍스트 요청은 텍스트 결과로 끝낼 수 있다. 폴더·이미지·영상·추가 변형·CTA·게시를 자동 요구하지 않는다.
- 텍스트 기획의 캐릭터 시트/스토리보드는 이미지 프롬프트를 포함할 수 있으나 실제 이미지가 아니다.
- 이미지 기반 전체 패키지는 기존 [검토 절차](../../../video-production-assets/references/preproduction-review.md)에 따라 정확한 폴더와 이미지 실행 조건을 확인한다.
- 프리프로덕션 수락은 해당 입력 버전만 승인한다. 별도 영상 진행 요청 뒤 현재 기능·스키마·가격과 실행 범위를 제안하고 실행/과금 승인을 받아야 한다. 무료/로컬 시험 영상도 이 게이트를 우회하지 않는다.
- 게시·라이브 반영은 별도 명시된 요청 범위다. 원고 리라이트만으로 DB 변경이나 배포를 실행하지 않는다.
- 상위 에셋 변경은 기존 dependencies/dependency_versions로 영향을 받는 검토/실행 계획을 stale로 표시한다. 같은 승인을 수정 버전에 재사용하지 않는다.

## 6. 이식성과 호스트 계약

기본 전제는 `SKILL.md`를 발견·읽을 수 있고 텍스트 작성과 필요한 자료 조회가 가능한 에이전트다. 외부 모델 호출 기능은 기본 기획의 전제가 아니다. 공급자가 선택되면 그 공급자의 실시간 계약을 사용한다.

현재 총괄의 특정 프레임워크 이름을 핵심 기능의 필수 의존성으로 유지하지 않는다. 질문·선택·검토는 호스트의 사용 가능한 대화/구조화 질문 도구로 처리한다. `deep-interview`/`plan` 같은 스킬이 이미 활성화된 환경에서는 그 흐름을 재사용한다. 없는 환경에 가짜 호출을 만들거나 새 승인 체계를 강제하지 않는다. `team`은 해당 실제 런타임이 있는 경우에만 사용하며, 병렬 에이전트는 기본 요구사항이 아니다.

핵심 8개의 형제 스킬 참조는 설치된 스킬 루트 기준으로 닫혀 있어야 한다. 지원 파일은 각 스킬 디렉터리 기준 상대 경로로 읽는다. 개인 홈, 개인 서버, Downloads 경로, 현재 작업 디렉터리를 실행 기본값으로 하드코딩하지 않는다. 특정 제공자의 모델명·가격을 패키지 공통 기본값으로 고정하지 않는다.

## 7. 패키지 manifest와 설치

기존 `manifest.json`을 확장하고 두 번째 패키지 레지스트리를 만들지 않는다. 기존 `skills` 목록과 예제/원문 포함 여부 필드는 유지한다.

추가할 정보:

| 항목 | 의미 |
|---|---|
| `entry_skill` | `creative-production` |
| `skills` | 실제 배포·설치하는 핵심 스킬 ID 8개 |
| `external_dependencies` | 레인별 외부 스킬 ID, 활성화 조건, 필요한 런타임/인증, 확인된 upstream 위치·버전/설치 근거 |
| 패키지 버전 | 배포된 구성의 버전. 개별 스킬 버전과 프로젝트 스키마 버전은 동일하다고 가정하지 않는다. |

확인되지 않은 외부 upstream·버전·권한은 확인 불가로 표시한다. 자동 설치 URL이나 호환 버전을 만들어내지 않는다. 패키지 manifest는 설치/의존성 목록일 뿐 프로젝트 에셋과 승인 기록을 담지 않는다.

설치 동작은 다음으로 고정한다:

1. 초기 지원은 기존 Codex 사용자 루트 규칙 `${CODEX_HOME}/skills`, 미설정 시 사용자 홈의 `.codex/skills`를 유지한다. 다른 호스트는 명시한 스킬 루트에 설치할 수 있으나 실제 검증 전 지원 완료로 소개하지 않는다.
2. 설치 대상은 README의 별도 하드코딩 목록이 아니라 manifest의 실제 스킬 목록에서 읽는다.
3. 모든 스킬·지원 자료와 목표 루트, 대상 충돌·중복 ID를 **쓰기 전에 전체 검사**한다. 하나라도 필요한 원본이 없거나 충돌하면 이번 호출은 어떤 대상도 덮어쓰지 않고 실패한다.
4. 기존 폴더를 무단 덮어쓰거나 병합하지 않는다. 교체는 사용자가 정한 백업/교체 범위에 한해 수행하며 무관한 스킬은 보존한다. 입출력 실패는 실제 반영된 경로를 보고한다; 검증되지 않은 원자적 설치를 약속하지 않는다.
5. 선택형 공급자 스킬, OAuth, API 키, 모델 가중치, CLI 설치를 자동 수행하지 않는다. 필요한 분기에 정확한 준비 항목을 안내한다.
6. 설치 후 핵심 스킬 ID·지원 파일·형제 링크·중복 ID와 패키지 버전을 확인한다. 에이전트 새 세션/목록 갱신이 필요함을 안내한다.

| 상황 | 처리 |
|---|---|
| 텍스트만 요청 | 미디어 도구 없이 요청한 초안/기획을 반환하고 그 범위만 검수한다. |
| 필수 핵심 스킬/참조 누락 | 깨진 설치로 보고한다. 없는 결과를 추정하거나 다른 스킬로 숨기지 않는다. |
| 선택된 분기의 외부 실행기/런타임 누락 | 도달 가능한 계획·인계는 완성하고 실행 전 부족 항목을 보고한다. |
| 이미지 인증·권한 또는 적용 과금 승인 누락 | 해당 이미지 호출 전 멈춘다. 다른 공급자로 자동 전환하지 않는다. |
| 모델 기능·가격 불명 | 실제 제출하지 않는다. 검토 패키지는 모델 미정인 채 유지할 수 있다. |
| 생성 일부만 성공 | 실제 결과만 등록하고 미완료 샷/에셋과 실패를 보고한다. |
| 승인된 입력 변경 | 영향받은 승인/하위 계획을 stale로 표시하고 그 범위만 재검토한다. |
| 검증기 통과 | 구조/파일 검증 범위만 주장한다. 미디어 품질·사실·권리·승인 진위를 보장하지 않는다. |

## 9. 출처·라이선스와 공개 반입 조건

현재 README는 재사용 라이선스가 없다고 명시한다. 새 문서에서 MIT 등 새 라이선스를 임의 선언하지 않는다. `metadata.author: local`과 출처 표기는 재배포 허가를 증명하지 않는다.

핵심 신규 반입과 선택형 벤더링은 원본 출처, 저작권/라이선스 문서, 필요한 notice, 로컬 변경 범위, 비공개 자료 의존성을 각각 확인한다. 스킬 frontmatter의 라이선스 주장만으로 다른 저작물까지 허가됐다고 간주하지 않는다. 확인 기록은 해당 스킬의 출처 문서나 기존 repo provenance 설명에 남기고 법적 clearance를 모델 판단으로 대체하지 않는다.

텍스트 기획의 `book-synthesis.md`는 제공된 서적을 요약·인용하는 자료다. 방향 문서는 외부 Notion 문서를 출처로 표시한다. 이 자료의 새 공개 반입은 권한을 확인하거나 공개 가능한 독립 지침으로 정리한 뒤에만 진행한다. PDF 페이지 근거를 유지한다는 이유로 원문·도판·긴 발췌를 배포하지 않는다. 공유 참조를 제외하면 그 참조를 필요로 하는 호출도 함께 정리하여 끊어진 링크를 남기지 않는다.

`codex-imagen`의 확인한 LICENSE는 MIT이며 notice 보존 조건이 있다. 그 사실이 다른 로컬 스킬의 권한까지 증명하지는 않는다. 이 설계에서는 공급자 helper·OAuth를 핵심에 넣지 않고 외부 분기 의존성으로 둔다.

공개 커밋에는 실제 사용자/프로젝트 자료, OAuth/API 키, auth 파일, 개인 저장 위치, 모델 가중치, 생성 미디어·로그, 재배포 권한이 없는 서적·참조를 반입하지 않는다. 권한 미확인 신규 구성요소가 남으면 완성된 핵심 8개 배포라고 보고하거나 불완전한 묶음을 대신 출시하지 않는다. 설계 검토와 실제 공개 반입 허가는 별개다.

## 11. 검토와 다음 결정

이 설계의 핵심 선택은 핵심 8개 + 선택형 의존성, 기존 루트 구조, 기존 제작/승인 계약 재사용, repo를 스킬 원본으로 삼는 명시적 설치다. 사용자 검토로 포함 범위나 계약이 바뀌면 영향받는 절과 수락 시나리오를 먼저 수정한다.

후속 진행 요청에 따라 [파일별 구현 계획](../plans/2026-10-02-creative-production-package.md)을 작성하고 핵심 패키지·설치 계약을 구현했다. 실제 검증 결과와 미실행 범위는 아래와 QA 기록에 구분한다.

## 12. 이번 설계 단계의 확인 결과

- 설계 문서의 로컬 근거 링크 6개: 모두 실제 파일로 확인. README에서 이 설계안에 연결했다.
- 목표 핵심 스킬 8개: 현재 repo 또는 설치본의 실제 `SKILL.md`와 ID를 확인했다. 신규 공개 반입 권한과 독립 설치 동작까지 검증한 것은 아니다.
- 설계 작성 단계에서 수락 시나리오 A01–A15를 정의했다. 당시 패키지가 미구현이었으므로 그 단계의 문서 검사를 시나리오 전체 통과로 주장하지 않았다.
- 기존 교육 계획에 `python video-production-assets/scripts/validate_project.py examples/15-second-education/project.json --profile plan --base-dir examples/15-second-education`을 실행했다. 결과는 `valid=true`, `errors=[]`; 구조·시간·참조·선언된 검사 기록 범위만 확인했다.
- 설계 작성 당시 배포 manifest는 버전 1.2와 3개 스킬 목록 그대로였다. 그 단계에서는 실제 스킬 반입·설치·커밋·푸시·미디어 생성을 수행하지 않았다.

## 13. 후속 구현 검증

- 구현 manifest는 패키지 1.3, 진입점 `creative-production`, 핵심 8개와 조건부 외부 의존성을 선언한다.
- 신규 총괄/텍스트 기획 지침과 공유 운영 참조를 패키지 계약에 맞게 작성했다. 새 서적 요약·Notion 기반 자료는 반입하지 않았고 끊어진 참조를 남기지 않았다. 기존 재사용 라이선스 제한은 유지한다.
- 실제 CLI의 새 설치, 충돌 시 기존 바이트 불변, 8개 폴더 백업 교체, 명시한 별도 루트의 중복 ID 백업 이전을 확인했다.
- 설치기 21개, 기존 제작 계약 8개, 공간 계약 6개 테스트가 통과했다. 교육 계획과 카메라 예제의 실제 검증 실행도 확인했다.
- 설치된 핵심 지침만으로 새 모델 문맥에서 실제 텍스트 산출물·승인 경계 13개를 적용했다. 이 증거는 도구를 사용하는 실제 공급자·플랫폼·미디어 실행 검증이 아니다.
- 독립 리뷰의 소스 support 충돌 및 인물 없는 기획 단계 누락 지적을 수정하고 해당 회귀 검증·정적 재검토를 통과했다.
- 상세 관찰 출력과 미검증 범위는 [QA 기록](../../../qa/package-validation.json), 변경 사항은 [CHANGELOG](../../../CHANGELOG.md)에 남긴다.
