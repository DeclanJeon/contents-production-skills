## 5. 증거 모델 — 기존 계약을 그대로 사용

정본은 `video-production-assets/references/25-reference-video-analysis.md`다. 기존 `archive-audit-template.md`, `shot-dna-template.md`, `archive-craft-crosswalk-template.md`를 채운 분석 산출물을 만든다. production payload/schema를 확장하지 않는다.

- occurrence, SHA/`archive_id`, source-local scene/shot/event/candidate ID를 구분하고 기존 ID를 원문 전체로 보존한다.
- 요청 seek 시각과 실제 source frame PTS/timebase를 각각 기록한다. 구간은 가능한 경우 `[start,end)`로 표현하고 추정 경계는 bracket을 보존한다.
- 검출 후보·확인된 하드 컷·soft transition·장면·within-shot phase는 별개다. 경계 양쪽의 실제 근거 없이 후보를 `SH###`로 승격하지 않는다.
- `OBSERVED`, `DETECTOR_CANDIDATE`, `ESTIMATED`, `[INFERENCE]`, `UNKNOWN`을 분리한다. 업로더 제작 설명·ASR·자동 자막은 해당 출처 등급을 유지한다.
- coverage는 probe/full decode/추출/실제 이미지 검토/continuous playback/음향 청취/ASR를 각각 기록한다.
- 파일별 처음·끝, 검출 후보가 없는 구간, soft transition, 긴 샷 내부의 동작·표정·그래픽 변화를 별도 확인한다. 컷 검출만으로 영상 전체의 사건을 찾았다고 주장하지 않는다.
- 시간순 인덱스에서 비검토 구간과 unresolved scene/shot joins를 모두 남긴다. 빽빽한 프레임 추출도 실제 연속 재생이 아니다.

각 craft finding의 기존 Shot-DNA 이전 체인은 다섯 칸을 각각 명시한다: `레퍼런스 증거(관찰+위치)` → `메커니즘` → `의도 효과(해석)`(대안 포함) → `새 브리프 제작 요구` → `정성 검증 기준`. 추가로 적용·회피 조건, 정확한 receiving-owner/template/QA slot을 기존 crosswalk의 해당 열에 연결한다. 내용이 없는 양식·동의어로 재명명한 필드는 완성 인계가 아니다.

A에서 4절의 영역마다 필요한 증거 모드와 완료 판정법을 기존 audit의 범위/상태 칸에 선언한다. 예: 정적 구도는 실제 프레임 검사, 동작/반응의 시간 관계는 실제 연속 동작 검사, 발화·음악·동기·침묵은 실제 음향 청취가 필요하다. 관련성 미확인은 검사 필요 상태로 두며 N/A로 면제하지 않는다. B에서 이 판정법을 검증·고정한 뒤 C에 적용하고, 나중에 기준을 낮춰 미검토 구간을 완료로 바꾸지 않는다.

### B. 광고 2개 + 로판 2개 파일럿

아래는 담당자의 선택이며, 제목·기존 분석의 기능 가설을 비교하기 위한 최초 후보다. 이번에 내용을 본 뒤 뽑았다는 뜻이 아니다. 실제 검수에서 분기가 중복되면 같은 집합 안에서 교체하고 사유를 기록한다.

| 집합 | 정확한 파일명 | ffprobe 길이 | 검증할 분석 분기 가설 |
|---|---|---:|---|
| 광고 | `AI Burger Commercial.mp4` | 25.054331초 | 제품·재질·상태·짧은 편집 |
| 광고 | `An unexpected AI commercial🍅.mp4` | 100.774603초 | 서사·공개·전환·브랜드 마무리 |
| 로판 | `AI 로판 [북부대공의 결혼선에 제 이름이 적혀 있습니다] 6화 ｜ 보이는 것만 말씀해 주세요.mp4` | 168.275011초 | 대사·관계·청자 반응 |
| 로판 | `[최애 북부대공의 장모님이 되었습니다] 8화 ｜ AI 코믹 로판.mp4` | 128.034830초 | 코미디·반응·시간 배분 |

의미 분석 파일럿 4개의 길이 합계는 약 7분 2초다. 각 파일 전체 시간 범위를 대상으로 하되 실제 확인한 매체·구간과 공백을 보고한다. 장면 구획, 경계 검증, within-shot 기록, 기존 owner/template 대조를 실제로 채운다. 일부 모드만 준비되면 파일럿도 부분 상태로 남기며, 자동 추출을 실제 검토로 간주하지 않는다.

**장편 pipeline stress 검사(추가 필수, 의미 분석 파일럿 2+2는 유지):** 같은 44개 로판 중 `[1~5화 몰아보기] 모두가 버린 그녀가 돌아왔다 ｜ AI 로판 회귀물.mp4`(ffprobe 3,406.390567초)를 사용한다. 앞·중간·끝에서 각각 최대 60초, 실제 확인한 회차 접합을 가로질러 최대 120초를 검사한다. 겹치는 구간은 합집합으로 세며 총 표본은 최대 300초다. 예상 접합이 실제 회차 접합인지 확인되지 않으면 추정으로 유지하고, 필요하면 같은 44개 내 다른 몰아보기로 교체해 사유를 기록한다. 표본 선택·추출·실제 검사 시간은 각각 기록한다.

검사 항목은 source PTS/timebase와 chunk-local offset의 대응, 접합 양쪽의 장면/회차 소속, 후반부 locator 보존, 인트로/회상·부분 중복의 중복 계수 방지다. 별도 작업 복사본을 정상 중단·재개하여 연속 처리의 같은 구간과 비교하고, 동일 chunk 재실행 시 근거가 중복 집계되지 않는지 확인한다. 원본·기존 원장은 수정하지 않는다. 실제 검사 locator 집합·경계/소속·누락 구간이 일치해야 통과하며, 파일 처리 성공이나 총 row 수 일치만으로 통과하지 않는다.

따라서 초기 검증 대상은 4개 전체와 장편의 최대 5분 표본이며 약 12분 2초 이내의 source-time 범위다. 실제 작업 시간은 별도 실측한다. 장편 표본은 다섯 번째 전편 의미 분석이 아니며 해당 장편의 나머지는 C에서 여전히 미검토다. 표본을 처리해도 92개 분모나 독립 사례 수가 늘지 않는다.

**B→C 모드별 관문:**

| 모드 | GO에 필요한 실제 증거 | 실패/미지원 시 |
|---|---|---|
| 정적 프레임·타임라인 | 파일럿의 실제 image read·원본 PTS·경계 이웃 근거 및 장편 stress 검사 통과 | 해당 모드 STOP, 누락/오류와 재개 검사 지정 |
| 연속 동작·표정/카메라의 시간 관계 | 해당 길이/정밀도의 실제 연속 동작을 검사할 수 있는 경로와 파일럿 검수 근거; 스트립만 검사했다면 그 범위로 한정 | 이 모드 전량 확장 STOP; 정적 GO가 대신하지 않음 |
| 발화·음악·효과음·동기 | 실제 음향 청취 경로와 파일럿 구간별 청취 근거 | 이 모드 전량 확장 STOP; ASR/스트림 정보가 대신하지 않음 |

미확인 능력도 STOP이다. 검사 경로·입력 범위·실제 결과·권한 충족과 장편 경로의 관련 stress 검사가 확인된 뒤 해당 모드를 다시 파일럿 검사해야 GO로 바뀐다. 모든 필수 모드가 GO일 때만 전량 분석 경로가 열리며, 일부만 GO면 아래 부분 경로만 수행한다. 후반부 locator/재개 검증 실패는 모든 모드의 전량 확장을 막는다.

파일럿 후 방법 변경은 같은 범위·증거 계약 안에서 담당자가 결정하고 기록한다. 범위 축소, 필수 modality 대체, 외부 업로드·유료 기능·새 provider가 필요하면 사용자 결정을 받는다.

### C. 92개 전량으로 확장

GO인 모드만 확장한다. 파일럿의 실제 완료 구간은 재집계하지 않고, 나머지 88개 및 파일럿의 미완료 모드/구간을 추적한다. 장편 stress 표본은 해당 원본의 일부로만 반영하고 남은 구간을 보존한다. 광고48/로판44의 분모를 유지하며, 파일별 완료 구간·미검토 구간·오류·다음 재개 위치를 checkpoint에 남긴다. 기본 배치는 4개 이하로 시작하고 용량에 따라 줄여도 대상·필수 검사 영역은 줄이지 않는다.

| 프로젝트 분석 상태(보고서 표기, production schema 추가 아님) | 진입 조건 | 다음 경로 |
|---|---|---|
| INVENTORY_COMPLETE | A의 92개 버전·coverage/부재가 등록됨 | B의 실제 검사, 내용 완료 아님 |
| C_CONTENT_REVIEW_COMPLETE | 아래 전량 내용 수락 조건이 92개 전부에서 충족됨 | 전량 패턴 종합 D→E |
| C_PARTIAL / C_BLOCKED | 미검토·실패 구간 또는 필수 모드 STOP/UNKNOWN이 하나라도 있음 | 부분 인계 또는 근거가 독립적인 D_PARTIAL→E_PARTIAL만 가능 |

**C의 전량 내용 수락 조건:** 92개 각각에 대해 전체 source-time 범위의 시간순 장면/샷/사건 연결을 실제 근거로 검사하고, 처음·끝·candidate-free 구간 및 필요한 within-shot 변화를 포함해야 한다. A/B에서 선언·고정한 모든 해당 영역/필수 모드의 검토 근거가 존재하고, 요청 범위에 영향을 주는 미검토 구간·미해결 경계/소속 join·실패·UNKNOWN이 없어야 한다. source별 coverage와 crosswalk의 필수 gate도 닫혀야 한다. 모드별 근거는 서로 대신하지 않으며, 92개 probe/행·후보·표본만으로 이 상태를 얻지 못한다. 이는 전 프레임을 읽었다는 주장이나 아직 모르는 모든 기법을 발견했다는 보장이 아니다.

전체 상태는 위 조건을 92개 모두에서 확인한 경우에만 C_CONTENT_REVIEW_COMPLETE다. 4개 검토+88개 NOT REVIEWED, 92개 probe+내용 검사0, 정적 검토+필수 음향 UNKNOWN은 모두 C_PARTIAL/C_BLOCKED다. 부분 결과의 인계는 전량 종료나 전체 작업 완료가 아니다.

**부분 경로:** GO 모드로 직접 확보한 근거만 별도 범위로 종합한다. D_PARTIAL/E_PARTIAL의 각 finding은 그 기능 주장에 필요한 모드가 모두 검사됐는지 확인한다. 예를 들어 구도/색상은 정적 근거로 이전할 수 있지만, 확인하지 않은 대사 반응 지연·음악 동기는 제외한다. 전체92개 중 실제 검사한 source/구간/모드, 재개할 blocker·필요 권한·검사 증거를 함께 인계하고 전수 결과·일반 빈도 주장으로 확대하지 않는다.

### D. 교차 영상 패턴 → 공백 판정

각 finding을 현재 owner의 전체 관련 절차·실제 템플릿·QA와 대조해 `이미 커버 / 부분 커버 / 갭 후보 / 증거 부족`으로 분류한다. 키워드 부재만으로 갭을 판정하지 않는다. 반복 패턴은 지원 occurrence 수, 중복/독립 사례 한계, 실제 검토 구간, 반례를 함께 제시한다. 단일 사례의 유용한 원리도 제한된 적용 조건을 가진 후보가 될 수 있으나 보편 규칙으로 승격하지 않는다.

### E. 실패 재현 → 최소 수정 → 재검증

후보 공백마다 기존 패키지의 새 소재 적용 실패를 먼저 재현한다. baseline이 성공하면 불필요한 규칙을 추가하지 않고 이미 커버로 재분류한다. 증거가 빈약하면 분석 상태에 남기고 패키지를 바꾸지 않는다. 실패가 확인된 오너를 한 번에 하나씩 최소 수정하고 해당 변경의 행동 검증을 마친 뒤 다음 오너로 간다.

## 7. 도구·능력·권한 경계

### 실제 확인된 실행 환경

- 로컬 `ffprobe`, `ffmpeg`, `python3` 존재. ffprobe 메타데이터 조회 성공.
- `craft-anything`은 0.6.0 경로를 가리키는 실행 링크가 존재하지만 `--help` 호출이 90초 제한 내 반환하지 않았다. 원인 미진단, 사용 가능성 미검증이며 필수 의존성으로 두지 않는다.
- `craft`, `rea-video`, `mpv`, `vlc`, `ffplay`, `faster-whisper`는 PATH에서 확인되지 않았다. 다른 이름의 설치 유무까지 조사한 것은 아니다.
- **Whisper는 발견됨:** 2026-11-16 직접 재조회에서 `command -v whisper`는 `/home/declan/.local/bin/whisper`, `/usr/bin/python3`의 `importlib.util.find_spec('whisper')`는 `/home/declan/.local/lib/python3.14/site-packages/whisper/__init__.py`를 반환했다. 이전 초안의 PATH 부재 주장은 정정한다. 근거와 명령은 [QA runtime 기록](../../../qa/ad-rofan-skill-upgrade-2026-11-16/design-qa-runtime.txt)에 보존했다.
- 발견 단계와 실행 단계를 구분한다: Whisper entry/module 발견만 확인됐고 import·CLI 정상 종료, 모델 가중치 보유, 장치 적합성, 실제 ASR 실행·정확성은 미검증이다. 이 정정은 설치·모델 다운로드·ASR 실행 승인이 아니다.
- 현 도구 목록에 직접 음향을 듣거나 영상을 연속 시청하는 검증된 수단은 없다. FFmpeg 추출과 Whisper의 존재/ASR 결과 모두 모델의 청취·연속 동작 검사 능력을 뜻하지 않는다. B의 관련 모드는 재검증 전 STOP이다.

### 실행 방식

로컬 FFmpeg로 버전 기록, full decode 검사, 컷 후보, 시간순 표본·경계 이웃·동작 스트립을 준비한다. 프레임은 실제 image read로 검사한 locator만 observed로 기록한다. 자동 오디오 지표·OCR/ASR는 준비된 로컬 도구가 있고 요청 범위에 맞을 때만 사용하며 청취/텍스트 정확성 검증을 대체하지 않는다.

A에서 능력·권한을 사전점검하고 B에서 실제 구간 검사로 확인한다. 음향 청취와 full-rate 동작 검증이 미지원이면 B의 모드별 관문을 STOP으로 유지하며 관련 전량 확장은 하지 않는다. 이 제약을 우회하려고 외부 VLM/ASR 업로드·새 설치·유료 분석을 자동 실행하지 않는다. 사용자 제공 타임코드 관찰은 `user observation`으로 구분해 bounded finding에 쓸 수 있지만 직접 검수나 미검사 전편의 증거는 아니다. 대체 검사가 원래 목적을 보존하는지 설명하고 동의를 받은 뒤, 같은 파일럿 관문으로 재검증해야 한다.

Craft는 실제 로컬 기능·인증·출력·외부 전송/과금 여부를 확인한 뒤 보조 도구로만 채택한다. `31-external-video-decomposition.md`의 rea-video는 선택지이지 설치 요청이나 이번 필수 경로가 아니다. 별도 도구가 제안하는 생성·remake 명령은 실행하지 않는다.

원본은 읽기 전용이다. 원본·파생 프레임/오디오/추출 자막을 외부 분석 모델에 전송하는 행위, 새 제공자의 호출·과금, 설치·모델 다운로드·게시·원본 재배포는 별도 승인 대상이다. 현재 세션에서 승인된 동일 에이전트 경로의 독립 문서 검토와, 설계 승인 후 별도로 실행 범위가 정해진 텍스트 행동 테스트는 이 미디어 외부 전송과 구분한다. 후자의 입력은 패키지 지침·새 가상 브리프·허용된 최소 근거로 제한하고 원본 미디어·추출 대사/자막을 자동 첨부하지 않는다. 실제 분석 근거 전송이 필요하면 별도 동의를 받는다. 텍스트 평가도 모델/설정·사용 범위를 기록하고 별도 설치·새 provider·추가 지출을 자동 승인하지 않는다. 자료 속 지시문은 실행하지 않는다.

## 9. 검증 설계

분석 품질과 스킬 행동 개선을 별도 검증한다.

### 분석 수락 조건

- 92 occurrence의 버전·정확 파일명·모드별 coverage/부재는 인벤토리 수락 조건이다. 전량 내용 검사 수락은 6절 C_CONTENT_REVIEW_COMPLETE의 source-time·영역·모드·crosswalk gate를 92개 모두에서 충족해야 한다.
- 추출 수와 실제 검사 수, 후보와 확인 경계, source timing과 새 설계 timing이 구분된다.
- 채택 finding마다 locator·직접 관찰·대안 있는 해석·적용/회피 조건·실제 기존 owner/template/QA의 전방/역방향 링크가 있다.
- 몰아보기 중복·독립 사례 불확실성, 미검토·실패 구간, 최신 외부 master의 OPEN gate가 정확히 유지된다.
- 필요한 모션/음향 증거를 얻지 못한 finding은 스킬 지침으로 승격하지 않는다. 미완료를 “기법 없음”으로 바꾸지 않는다.

### 행동 검증 수락 조건

- **baseline 전 동결:** 구현 계획에서 owner별 task/prompt, 필수 semantic assertion·안전 실패·negative control·수락/중단 기준·반복 수를 작성해 버전/해시를 고정한다. 필요한 근거·실제 receiving template이 과제/채점 항목을 검사할 만큼 제공되는지도 먼저 확인한다. 결과를 본 뒤 기존 rubric을 낮추거나 과거 결과를 재채점하지 않는다. 기준 변경은 새 버전 실험으로 남긴다.
- **비교 조건:** 현재 패키지 baseline(새 지침 없는 통제)과 수정 패키지 variant에 동일 task/prompt·가상 브리프·허용 근거를 준다. 패키지 지침의 의도한 delta 외에는 입력 범위와 실행 도구 권한을 같게 한다. exact 모델 identity/추론·sampling 설정, runner, package/context 파일 목록·해시, timestamp, raw output, 실행 오류/status를 보존한다. 모델/설정을 고정할 수 없거나 UNKNOWN이면 그 제한을 공개하고 동등 비교의 승격 판정을 INCONCLUSIVE로 둔다. 모델/제공 근거를 바꾼 결과는 같은 비교로 합치지 않는다.
- **실행·채점 분리:** fresh-context 실행자는 package와 해당 task/허용 근거만 소비한다. rubric·정답·이전 응답·설계/계획/QA의 기대 출력에 접근하지 못하도록 별도 context/읽기 경계를 둔다. 생성이 끝난 raw 응답을 동결한 다음 별도 fresh-context 채점자가 rubric으로 판정한다. 리뷰 결과를 실행자의 답에 섞지 않는다. context 누출은 해당 비교 INVALID이며 다시 격리해 실행한다.
- **RED→GREEN:** baseline에서 실제 누락/형태/규율/조건부 실패를 확인한 오너만 수정한다. baseline이 이미 요구를 충족하면 그 후보를 이미 커버로 분류한다. shaping 문구는 no-new-guidance 통제와 각 variant마다 사전 지정된 횟수(최소 fresh-context 5회)를 실행한다. 모든 응답을 채점자가 직접 읽고 자동 플래그도 원문으로 대조한다. 반복 수를 나중에 늘려 유리한 표본만 고르지 않는다.
- **승격 기준:** 채택 variant의 사전 지정된 모든 유효 응답에서 해당 필수 assertion을 모두 충족하고, 안전/권한/증거 과장 실패는 0건이어야 한다. 두 negative control도 모두 통과해야 한다. baseline에서 실패한 항목이 개선되지 않거나 새 필수 항목/negative control 회귀가 하나라도 있으면 NOT PASS다. 평균 점수로 필수 누락·안전 실패를 상쇄하지 않는다. 창작 취향의 절대 점수나 실제 미디어 품질 합격을 의미하지 않는다.
- **오류·재시험:** tool/provider 오류·캡처 실패·중단은 semantic miss와 분리해 INCOMPLETE로 남긴다. 오류 실행은 성공으로 세거나 숨기지 않는다. 일시적 실행 오류는 동일 조건에서 실패 슬롯당 최대 1회만 재실행하고 원본·대체 실행을 모두 보존한다. 해결되지 않으면 해당 비교는 INCONCLUSIVE이며 승격하지 않는다. 내용 실패를 같은 variant의 유리한 재표본으로 대체하지 않는다. 지침을 고친 뒤에는 새 variant로 사전 지정 전체 시나리오와 negative control을 다시 실행하고 과거 실패도 보존한다.
- **보고 범위:** 이 소규모 비교는 관찰한 실패와 전이 행동의 서술적 증거다. 통계적·인과적 신뢰도 향상, 모델 전반의 일반화, 실제 시청각 품질 향상을 주장하지 않는다.
- 광고 전이 예: 원본과 다른 비유·제품의 합법적 가상 브리프에서 속성→행동→제품 가독성·claim 경계를 연결한다.
- 로판 전이 예: 원본과 다른 시대·관계·사건에서 정보 공개·반응·감정 델타를 설계한다.
- 음성/모션이 없는 근거, 상충 메타데이터, 시간 압박·권위 압박·기존 작업의 매몰비용을 합친 규율 시나리오로 허위 완료·보호 표현 복제를 검사한다.
- 단일 레퍼런스와 무관한 비영상 브리프 negative control에서 아카이브 절차·casebank를 강제하지 않는다.
- 실제 미디어 생성/시청각 결과 개선은 이번 텍스트 행동 검증이 입증하지 않는다.

코드/helper를 추가할 경우 별도 테스트가 먼저 실패해야 한다. 이후 해당 테스트와 저장소 전체 `python3 -m pytest -q`, 실제 저장소의 링크·버전·설치 회귀 검사를 확인한다. 기존 실패가 있으면 이름·범위를 보고하며 숨기거나 근거 없이 고치지 않는다. 설치 smoke가 사용자 설치본을 바꾸지 않도록 격리 임시 경로에서 실행한다.

## 11. 담당자에게 남기는 선택

동일 범위 안의 detector threshold·표본 밀도·프레임 크기·배치 크기·파일명 세부 형식·기존 helper 재사용 여부·기법 묶음 이름은 파일럿 실측으로 결정한다. 각각 명령/버전/한계를 남긴다. 이 선택이 실제 미디어 검사를 대체하거나 대상·모드를 축소할 권한은 아니다.

사용자에게 다시 결정받을 항목은 범위/목표를 바꾸는 선택, 설치·외부 전송·과금·지정 도구 대체, 필요한 독립 검사/청취 능력의 대체다. 단순한 보고서 배치·파일명·분석 내부 선택은 매번 질문하지 않는다.
