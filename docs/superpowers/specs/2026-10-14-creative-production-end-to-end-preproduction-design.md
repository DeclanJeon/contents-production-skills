## Actual progression and contract conflicts

1. **Requested one-call scope has no owner in the current routing.** `creative-production/SKILL.md` §3 says `orchestrating-video-preproduction` sequences *only assigned text stages*, and the production-routing film row delegates to the optional film lifecycle module. The delegated lane's own frontmatter/body defines it as text-only. This is incompatible with the requested one coordinator invocation that continues through the authorized still-image package and delivery artifacts.
2. **A guide exists, but is not an executable coordinator contract.** `video-production-assets/references/storyboard-sheet-user-guide.md` §3–9 supplies a comprehensive one-shot prompt and commands. It presumes completion by prompting an agent; it does not override the current `creative-production` routing stop or identify one authoritative orchestration owner. Its former cost-cap wording also conflicts with the current repository contract that Codex Imagen stills require no quote, quota, usage, or cost check; preserve the current explicit Codex Imagen rule.
3. **QA is split across non-equivalent mechanisms.** `creative-qa.md` covers planning/timing/source checks but does not define a package-wide meaning/causality/omission correction loop. The storyboard contract §5–6 requires actual clean-image, image-only narrative reading and minimal indexed fixes/reinspection. `validate_project.py` and `validate_preproduction.py` explicitly validate structure/files/dependencies, not artistic meaning, identity fidelity, rights, or approval truth. A green validator cannot satisfy the visual or causal gate.
4. **Progression requires an explicit content QA stage before final image generation.** The current storyboard contract requires full synopsis beat coverage, beat→scene→shot→panel mapping and technical slots before imagery. The screenplay guide specifies timing and scene/action/dialogue work, but a complete script is not itself the canonical full-package synopsis/board mapping. Current skill text does not spell out the cross-artifact consistency/correction pass from synopsis → screenplay → board, then reconcile corrected text versions before images. Implement the minimum coordinator-owned gate, not a second schema or scheduler.
5. **FINAL vs PRELIMINARY and review vs execution are easy to conflate.** v5.1 `contract.md` §107–127 requires verified current LOOK and applicable locked master assets before `final`; pending/stale critical assets allow only explicitly preliminary work. `preproduction-review.md` §5 and `contract.md` §96–102 separate review acceptance from video execution approval. End-to-end completion must never fake either approval or video authorization.
6. **Image-backed deliverable means actual images, not an attractive substitute.** The full-package contract requires actual image assets; the storyboard contract requires a readable ordered sheet set (≤8 panels/sheet), then actual per-scene and per-panel extraction and inspection. SVG/HTML/mockups, empty templates, JSON-only “final”, prompts, or a few representative panels cannot satisfy this. Existing `render_storyboard_sheet.py` / `split_storyboard.py` are deterministic packaging tools only, not image generators or visual QA.
7. **Storage and ledger must use one writer.** Repo policy requires an existing approved project when available or actual Windows Documents `studio_production` otherwise, initialized by `recording-production-history`; one canonical `project.json` and one coordinator-owned `.history`. The generic preproduction guide's request-to-choose-directory wording must not produce a needless second interview when actual paths/context resolve it. Worker recommendations remain proposals; only coordinator persists canonical state.
