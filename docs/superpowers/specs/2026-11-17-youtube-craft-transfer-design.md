## 1. 목적과 범위

지정 YouTube 12편에서 추린 제작 공정을 기존 스킬에 연결한다. 목표는 문장/규칙을 늘리는 것이 아니라 **실제 과제에서 어떤 입력을 확인하고, 어디를 수정하고, 무엇을 검사해야 하는지 일관되게 선택하게 만드는 것**이다.

- 이번 산출물은 설계다. 스킬·템플릿·평가·실제 매체는 아직 변경/생성하지 않는다.
- 1차 구현 제안: 과제 기반 영상 모델 비교 + 설명 그래픽의 의미 검증.
- 2차 구현 제안: 다중 화자 스틸 편집 연결 예제 + 기존 원인 진단/음향 접합의 회귀 사례.
- 강의의 자막/정지 표본에서 추린 방법이며 전체 재생·실청취·생성 공정 재현으로 효과를 입증한 것은 아니다.

## 4. A — 과제 기반 영상 모델 비교

### 진입 조건·소유자

사용자가 허용한 영상 후보 사이의 선택을 요청하거나, 고실패 샷의 비교 프리뷰가 승인된 경우만 적용한다. 단순 원고·정지 이미지·일반 모델 문의에 실험을 강제하지 않는다. 소유자는 `video-production-assets` 24, 실제 결과 판정은 21, 채택 비용 해석은 29 R7이다.

### 동작

`샷의 필수 요구 → 지원/승인 적격 후보 → 비교 설계 → 승인 범위의 실행 → 실제 출력 검사 → 해당 샷의 선택/보류`

- 동일 목적·입력 버전·필수 사건·수락 기준을 먼저 고정한다.
- 동일 프롬프트 비교와 모델별 조정 비교를 구별한다. 실제 제출문·모드·해상도·길이·오디오·참조 수·횟수/실패를 기록한다.
- 공통 지원 설정이 없으면 차이와 판단 한계를 밝힌다. 비동등 비교를 같은 조건이라고 부르지 않는다.
- 제출은 기존 현재 endpoint 확인·비용/권리·사용자 승인 규칙을 따른다. 명시한 공급자를 임의로 바꾸지 않는다.
- 실제 생성 총분량/채택 구간·지출을 비교한다. 값이 없으면 미확인. 0초 채택의 초당 비용은 N/A.
- 후보 전부 필수 요구를 놓치면 우승자를 만들지 않는다. 표본 한 번의 성공을 성공률로 발표하지 않는다.
- draft·업스케일·재생성·최종 편집본의 검사 범위를 구분한다.

### 예제와 완료

가상의 후보 A/B를 쓴다. A는 질감이 좋지만 인원수 오류, B는 인원수는 맞지만 필요한 행동 누락. 둘 다 해당 필수 요구를 통과하지 못했다는 결론을 보여준다. 실제 공급자 순위/가격이나 생성 결과로 표시하지 않는다.

비교 계획 완료: 후보·조건 차이·입력·평가기준·승인 상한·미확인이 연결됨. **실제 선택 검증 완료**는 출력 파일·검사 범위·결과가 있는 경우만 가능하다.

## 5. B — 설명 그래픽의 의미 검증

### 진입 조건·소유자

영상 이해에 중요한 수치·단위·수식·차트·라벨이 있으면 적용한다. 장식적인 숫자/모든 영상에 차트를 의무화하지 않는다. 사실·계산은 10, 생성/코드/합성 선택은 24, 화면 QA는 21/23, 발화·공개 시점은 09가 소유한다.

### 동작

`근거/가정 → 계산·표시 문자열 → 시각적 매핑 → 내레이션/자막 시간 → 실제 출력`

- 원문 값·기간·분모·단위·불확실성을 기존 claim 기록에 연결한다.
- 계산 결과, 반올림 방식, 표시 문자열을 구별한다. 그래픽 생성 코드의 정상 종료는 의미 검증이 아니다.
- 값과 길이/면적/위치·축·범례·색·방향의 대응을 검사한다. 차트 유형에 맞는 기존 축 규칙을 따르며 모든 비영점 축을 금지하지 않는다.
- 정보 공개 순서·hold·모바일 크기·UI 가림을 최종 출력에서 확인한다.
- 정확 텍스트가 필요하면 기존 결정론적 그래픽/합성 선택을 사용한다. 새 프레임워크 설치나 생성 모델의 반복 재시도를 기본값으로 하지 않는다.

### 예제와 완료

**비정본 교육 fixture:** 값 40→52, 증가량 12, 증가율 30%(분모 40). 실제 시장/채널 통계나 효과 측정이 아니다.

잘못된 분모, 12를 12%로 표시, 단위 누락, 맞는 숫자와 틀린 막대 비율, 잘못된 범례, 발화보다 이른 결과 공개, 글자 잘림을 각각 실패로 분리한다. 기존 2+3=5 계획 예제를 삭제/중복 복제하지 않는다.

계획 검증과 실제 렌더 검증을 구분한다. 파일을 보지 않았으면 글자 가독성/타이밍은 미검증. 실제 출력의 해당 위치·구간을 확인하기 전 최종 통과로 보고하지 않는다.

## 6. C — 다중 화자 스틸 편집 연결 예제

### 진입 조건·소유자

정지 이미지와 음성으로 이야기를 조립하며 다중 화자 또는 반응 hold가 필요한 경우. 실제 조립은 `storytelling-with-still-images`, 시간화 계획은 `animatic-direction`, 대사/보이스는 기존 22가 소유한다. 단일 내레이터 전용 생성 영상 explainer 공정과 합치지 않는다.

### 동작

`보존 대사/화자 확인 → 실제 음성·쉼 측정 → 이야기 비트 → 그림 hold·청자 반응 → 믹스·조립 → 실제 출력 검수`

- 기존 cue-table과 ID/버전 연결을 사용한다. 독립 오디오/시간 원장을 추가하지 않는다.
- 음성이 없으면 추정 계획. 실제 발화 시간을 지어내지 않는다.
- 고정 runtime에서 대사가 넘치면 충돌 위치와 재배분/수정 승인 필요를 보고한다. 자동 전체 배속·대사 삭제로 해결하지 않는다.
- 표정/반응에 필요한 화면을 유지하되 고정 최소 hold·정해진 인물 수를 일반 규칙으로 만들지 않는다.
- 무자막·정지 전용·원문 보존 조건을 지킨다. 스틸을 연속 행동/립싱크 증거로 취급하지 않는다.

예제는 두 화자의 턴과 청자 반응이 연결된 작은 가상 계획이다. 숫자 시간은 fixture 가정/추정으로 표시하고, 실제 제공 음성이 생길 때만 측정값으로 교체한다. **문서 예제 자체를 재생/청취가 검증된 완성 MP4라고 하지 않는다.**

## 7. D — 기존 절차의 실패 반례

별도 일반 규칙이나 새 스킬을 만들지 않고 기존 21/29/09의 적용 사례로 평가한다.

- **참조 모순:** 승인 차량의 운전석/문과 퇴장 지시가 모순인데 텍스트만 계속 고치는 경우. 지역/승인 설정을 확인하고 모순을 해소한다. 우측 운전대 자체는 오류가 아니다.
- **행동 주체:** A가 B를 공격해야 하는데 참조 역할이 혼재. 행동 앵커/역할표를 제안하되 새로운 이미지 실행을 자동 수행하지 않는다.
- **참조 역할 오염:** 장소 분위기만 가져와야 하는데 장소 참조의 다른 인물 얼굴을 사용. 속성 우선 기준으로 되돌린다.
- **인과 손실:** 오류 구간을 잘랐더니 필수 소유 이전이 사라짐. 좋은 구간만 남았다는 이유로 납품 통과하지 않는다.
- **음향 접합:** 두 클립에 다른 음악이 내장됨. 실제 제공 stem·혼합 원음·승인된 분리 결과를 구별하고 대사 자음/숨/잔향/음악 재시작을 최종 믹스로 듣는다. 분리 사이트에 무단 업로드하거나 분리 성공을 보장하지 않는다.

## 9. 평가와 수락 기준

### 평가 사례

1. A: 동일 프롬프트지만 해상도/음성 조건이 다름 → 차이 공개, 공정한 동등 비교라고 단정하지 않기.
2. A: 모든 후보의 필수 사건 실패 → 선택 보류/대안, 상대 1등을 PASS로 만들지 않기.
3. A: 채택 0초/지출 미확인 → 각각 N/A/미산정, 수치 발명하지 않기.
4. A: 문서 비교만 요청 → 실제 생성/지출/공급자 변경 없음.
5. B: 증가율 분모·단위·반올림 오류 → 잘못된 값/표현을 구별해 수정.
6. B: 숫자는 맞지만 차트 비율/범례가 다름 → 의미 불일치 발견.
7. B: 실제 렌더 없음 → 계획 검사만 보고, 가독성/모션 최종 통과 금지.
8. C: 화자 불명 녹음 → 임의 귀속하지 않고 확인 필요 표시.
9. C: 고정 runtime 초과 → 대사 보존, 충돌 보고/국소 재배분.
10. C: 무자막·정지 전용 → 금지된 생성 영상/자동 자막/불필요 립싱크 추가 없음.
11. D: 참조/동작 모순 → 관찰과 가설 분리, 해당 입력층부터 확인.
12. D: 오류를 자르며 필수 인과 제거 → 누락 발견과 보완 검수.
13. D: 혼합 원음만 제공 → 실제 stem이 있다고 하지 않기.
14. 회귀: 일반 글쓰기/단일 원고 → 새 전체 제작·trial·chart 절차를 강제하지 않기.

### 검증 단계

- **구조 검사:** JSON 파싱·링크·기존 템플릿/정책 일치·기존 회귀 테스트. 문자열 존재만으로 행동 개선을 판정하지 않는다.
- **행동 평가:** 변경 전/후 같은 입력에서 기대 행동·실패를 대조하고 실제 응답/근거를 보존한다. 실행할 agent/model/도구를 먼저 확인하며, 미승인 API·대체 공급자·무한 반복을 사용하지 않는다.
- **매체 평가:** 별도 승인된 실제 파일럿이 있을 때만 출력·정속 재생·청취·채택 분량·비용을 확인한다. 문서/행동 평가와 별도 결과로 보고한다.

1차 완료는 A/B가 조건부로 발견되고 위 반례를 올바르게 처리하며 기존 계약/평가가 유지되는 것. 실제 생성 품질이나 수익 개선까지 완료했다고 주장하지 않는다. C/D는 별도 작은 증분으로 검토한다.

## 10. 보존 경계와 다음 결정

사용자 SSOT·전체 image_backed 패키지의 필수 시트·기존 이미지 실행자·인-리퀘스트 오디오 기본값·단일 기록자·기존 승인/판정 계약을 유지한다. 특정 모델/가격/기간/화자 수/컷 간격/크로스페이드 시간을 기본값화하지 않는다. 강의의 장면·인물·대사·다운로드한 미디어를 예제 자산으로 재배포하지 않는다.

현재 진행 중인 다른 변경을 보존한다. 커밋·전역 설치·pons 배포·서비스 재시작·유료 생성·게시 없음.

**사용자 검토 질문:** 기존 오너를 유지하는 이 조건부 보강안으로, 1차 A/B → 2차 C/D 순서를 승인할지 결정한다. 승인 뒤 별도의 구현 계획과 실행 방법을 확정한다.
