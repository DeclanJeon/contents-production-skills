## 1. 문제와 완료 정의

### 1.1 해결할 문제

현재 위험한 작업 방식은 `현재 콘티 → 현재 프롬프트 → 개별 클립 수신 → 단순 연결`이다. 각 클립이 그럴듯해도 다음 문제가 남는다.

- 대본의 원인·행동·결과·반응 중 일부가 이미지나 영상에서 빠진다.
- 앞 컷의 행동 단계와 다음 컷의 시작 단계가 다르다. 접근을 두 번 반복하거나 접촉 없이 결과로 순간 이동한다.
- 개별 프레임은 멋있지만 인물·물건·공간·시선·감정 상태가 서로 맞지 않는다.
- 모델의 최소 생성 길이를 전부 사용하면서 불필요한 대기·반복·정착 꼬리가 영화에 남는다.
- 카메라/공개/대사 타이밍을 프롬프트에 썼다는 사실이 실제 구현의 증거처럼 취급된다.
- 실제 영상에 접근해 보거나 듣지 못했는데 파일 수신·디코드·정지 이미지 검사로 품질을 통과시킨다.
- 뒤늦게 연결 실패가 드러나 사용자가 매번 상태 정리·프레임 선택·오류 지적을 맡는다.

해결 단위는 **씬/시퀀스의 사건 흐름**이다. 생성 작업은 그 흐름의 일부를 확보하는 수단이고, 최종 영화는 검증된 실제 구간을 편집한 결과다.

### 1.2 완료 정의

다음 세 조건을 동시에 만족해야 해당 범위가 완성이다.

1. **대본 일치:** 필수 사건·정확한 대사·화자·반응·공개 순서가 실제 최종 영상에 존재한다.
2. **연출 일치:** 요구한 프레이밍·카메라·동작·속도감·감정·유보/공개·타이밍을 해당 매체에서 확인했다.
3. **연결 성립:** 실제 컷 경계와 재등장에서 상태·인과·공간·동작·음향이 성립하며, 씬 전체의 호흡을 실제 재생으로 검사했다.

생성 성공, 파일 수, 해시, 검사표 작성, 구조 validator 성공, 정지 프레임 유사도는 이 완료 정의의 대체물이 아니다.

### 1.3 보장 가능한 것과 한계

생성 모델에 모든 연출을 100% 강제할 수 있다고 약속하지 않는다. 이 설계가 강제하는 것은 **요구의 누락 방지, 실제 결과 대조, 범위 안의 수정, 미달 결과의 채택·완료 차단**이다. 자연스러움은 특정 숫자나 코드만으로 판정하지 않는다. 필요한 지각·재생·청취 실행자가 없으면 제작 전에 드러내며, 이를 해결하지 않고 완성 영화 제작이 가능한 것처럼 진행하지 않는다.

## 3. 범위·권한·비목표

### 포함

- 대본/각본 → 비트 → 씬 → 샷 → 패널/프레임 → 생성 입력 → 실제 테이크 → 편집 구간 → 최종 파일의 추적.
- 영상 생성 전, 실제 콘티 이미지와 타임라인을 대조·수정·재검수하는 절차.
- 생성 작업의 분해, 참조 역할, 편집 핸들, 실제 선택 구간, 컷/소리 연결, 출력 검수.
- 무대사·무음·원테이크·교차편집·시간 생략·역순/회상 등 의도적 형식 보존.
- 프레임 단위 실행 검증과 사람이 해야 했던 반복 정리를 코디네이터/도구가 맡는 흐름.

### 비목표

- 새로운 생성 공급자, 고정 모델 추천 목록, 별도 전역 상태 DB, 자체 웹 편집기 구축.
- 모든 콘텐츠에 같은 컷 길이·카메라 움직임·과장 연기·빠른 템포를 강제.
- 정지 프레임만으로 물리/연기/립싱크/음성 품질을 판정.
- 승인된 원테이크·이야기·정확한 대사·고정 공개 시점·원본을 임의 변경.
- 사용자에게 매 컷의 상태표·사용 프레임·연결 체크리스트 작성을 요구.

### 자동 처리와 사용자 결정의 경계

코디네이터는 현재 승인된 범위 안에서 조회, 비교, 기술적 오류 진단, 선택 구간 조정, 편집안 수정, 허용된 로컬 렌더와 재검사를 맡는다. 매 프레임마다 재승인을 받지 않는다. 단, 허가된 제작에 포함되지 않은 렌더를 설계 요청만으로 실행하지 않는다.

대본/필수 연출 변경, 잠긴 샷 수·원테이크 형식 변경, 지정 공급자/보이스 변경, 승인 범위를 넘는 추가 생성·비용·설치·게시에는 사용자 결정을 받는다. 프레임 정밀화는 연출 변경 허가가 아니다.

생성 전 미디어 검수 능력·생성/편집 실행 능력·현재 지원 제어·재시도/지출 상한을 확인한다. 포함/무료도 실제 실행 범위를 확인하며 무제한 허가로 해석하지 않는다. 정지 이미지 실행에 대한 기존 예외와 지정 실행자 정책은 그대로 따른다.

| 샷 | 승인된 촬영/화면 설계 단위 | 모델 작업 수와 같다고 가정하지 않음 |

| 생성 작업 | 공급자에 실제 제출한 요청 | 내부 컷 시점이 정확히 통제된다고 가정하지 않음 |
| 테이크 | 특정 작업의 실제 결과 파일 | 최신 테이크를 자동 채택하지 않음 |
| 편집 컷 | 특정 실제 소스 구간을 최종 시간에 배치한 행 | 원본 전체와 채택 범위를 혼동하지 않음 |
| 출력 프레임 | 최종 파일에서 실제 디코드되는 프레임 | 콘티 프레임/소스 인덱스와 혼동하지 않음 |

코디네이터는 전체 연결·정본 쓰기·상태 보고를 책임진다. 코드 도구는 구조/계산/추출/렌더를 담당한다. 의미 검토자는 실제 근거에서 사건·연출·상태를 관찰한다. 의미 검토자는 별도 유료 서비스나 하위 에이전트가 항상 필요하다는 뜻이 아니며 현재 환경에서 가능한 실행자로 구성한다. 전문 검증이나 독립 검토가 필수인 경로는 그 요건을 유지한다.

## 5. 정본과 정보 구조

### 5.1 원칙: 한 정본, 버전 있는 산출물

- 실제 프로젝트의 `project.json`만 ID·버전·권한·에셋·상태의 정본이다. 공유 스킬 저장소에는 작품 데이터를 저장하지 않는다.
- 대본 원문·각본·바이블·승인 콘티는 기존 artifact/asset/version/hash로 참조한다. 공급자 작업 UUID를 canonical asset ID로 대체하지 않는다.
- 기존 편집 표의 `cut_id`, `shot_id/asset_id`, `source_in_s`, `source_out_s`, `playback_rate`, `final_start_s`, `final_end_s`, phase/state, cue/hold, 검수 셀을 유지한다.
- 계산 도구용 상세 구조는 **기존 버전 있는 generation_spec/edit_plan/qa_review 산출물의 실행용 투영 파일**로 둔다. 새 root 필수 필드·프로젝트 단계 enum·독립 승인 원장을 만들지 않는다.
- 투영 파일은 실행할 때 정본의 입력 버전·실제 파일 해시와 대조한다. 단독 편집된 투영 파일은 프로젝트 상태를 바꾸지 않는다. 내용 수정은 소유 artifact의 새 버전과 검토를 거친다.
- 기존 문서의 ‘새 JSON 계약 없음’은 병렬 정본 금지를 유지한다. 구현에서는 도구에 필요한 **비정본·버전 있는 산출물 직렬화 형식**을 명시적으로 설명하여, 존재하지 않는 프로젝트 필드를 발명하는 것과 구분한다.

### 5.2 요구 추적 행

각 필수 요구는 기존 원문 locator 또는 `(artifact ID, version, 문단/행)`으로 식별한다. 임의 요구 ID가 필요하면 해당 산출물 내 지역 키이며 canonical shot/beat ID인 것처럼 쓰지 않는다.

행의 최소 내용:

1. 정확한 원문 위치·연출 지시, 잠금/편집 위임 범위.
2. 기존 scene/shot/beat/panel/speech/cue ID.
3. 관객에게 반드시 읽혀야 할 사건/정보/감정과 발생 순서.
4. 계획 최종 프레임 구간과 핵심 순간, 허용 오차가 있으면 그 실제 출처.
5. 이를 표현하는 계획 이미지와 다음 컷 연결.
6. 제출 전 실제 요청문 문장·참조 슬롯·지원 제어와의 대응.
7. 생성 후 실제 소스 파일/해시·프레임/PTS 구간.
8. 편집 후 실제 출력 프레임/시간과 검사 근거·판정·미검증.

필수 요구와 취향은 원문에서 구분하며, 구현 난도가 높다는 이유로 필수를 취향으로 낮추지 않는다. 수치 오차가 명시되지 않았으면 임의 허용치를 만들어 통과시키지 않고 차이와 서사 영향을 보고한다.

### 5.3 연결 행: 편집 이웃 + 서사 선행 이력

각 연결 행은 `(편집 artifact 버전, 선행 cut_id, 후행 cut_id)`로 식별한다.

- 편집상 선행/후행 shot·scene·cut과 해당 서사 시간선의 선행 상태.
- 관계: 동작 연속, 다른 앵글, 반응/시선, 공간 이동, 시간 생략, 교차편집, 회상, 의도적 불연속 중 실제 적용되는 설명.
- 인물/소품/장소/의상/부상/감정·지식/공개 상태의 들어오는 값·나가는 값·유지 범위·허용 변화.
- 관측된 값, 승인된 계획값, 가림 때문에 직접 보이지 않아 유지하는 값, 미확인 값을 구분한다. 가림을 물건 소멸의 관측으로 기록하지 않는다.
- 카메라·화면 방향·행동축·광원·오디오 관계. 화면 왼쪽/오른쪽과 인물의 해부학적 왼쪽/오른쪽을 구분한다.
- 계획 출구/입구 패널, 실제 선택 구간의 마지막 포함 프레임/첫 포함 프레임과 인접 모션 구간.
- 다음 참조에 가져갈 속성과 가져가지 않을 속성, 충돌 시 현재 승인 설계의 우선순위.
- 판정, 근거, 수정 소유자, 막히는 후속 작업과 재검사 기준.

상태 추출/정규화는 에이전트의 의미 작업이다. 코드는 start_state/end_state의 자유 서술을 정확한 세계 상태로 자동 이해한다고 가정하지 않는다. 에이전트가 근거와 함께 정리한 연결 행을 코드가 검사·전달한다.

### 5.4 상세 실행 투영의 최소 계약

투영은 JSON으로 직렬화하며, 계획·검수·편집 파일은 같은 `format = sequence-execution/1` 규칙을 사용한다. 구현된 상세 필드와 CLI는 `video-production-assets/references/sequence-execution.md`에서 확인한다. 원문 요구의 실제 사건 source 범위와 최종 프레임은 `checks.event_ranges`로, 선택 변경의 검수 유효성은 `checks.cut_ranges`로 고정한다.

| 필드 | 내용 |
|---|---|
| `format`, `phase` | 형식 버전과 plan/generation/edit/export 중 해당 검사 범위 |
| `owner` | 실제 project_id, 소유 artifact ID·버전, snapshot project version |
| `inputs` | artifact 입력 버전 맵, 사용 asset ID·버전·해시, 원문 locator |
| `time_basis` | 최종 FPS 분자/분모, 프레임 원점, 오디오 sample rate, 소스별 FPS/time_base/PTS 정보 |
| `requirements` | §5.2 요구 추적 행 |
| `links` | §5.3 연결 행과 관련 이력 locator |
| `cuts` | 기존 편집 행 + source frame in/out exclusive, final frame in/out exclusive, 소스 결과/테이크 참조, 전환·음향 레이어 참조 |
| `checks` | 대상·범위·검사 방식·근거 locator·관찰·pass/fail/unverified/not_applicable·미해결 이슈 |

각 source/cut/link 참조는 지역 키인지 canonical ID인지 명시한다. 실제 매체가 없는 계획의 소스 프레임·PTS·해시는 null이며 `planned` 근거로만 표시한다. 0을 미확인 값으로 사용하지 않는다. 같은 의미를 원장·표·JSON에서 따로 수동 수정하지 않고 소유 산출물의 기계 판독 투영에서 사람이 읽는 표를 렌더한다. 기존 Markdown 편집안은 명시적 변환·검토 후 이 투영을 만들며 파서가 자유 서술을 사실로 추측하지 않는다.

## 6. 프레임·시간 계산 계약

### 6.1 세 시간축

- **계획/최종 timeline frame:** 0부터 시작하는 정수, `[in, out)`; 프레임 n의 시작은 `n / F`초다.
- **source frame:** 해당 파일의 디코드 표시 순서 0-based index. 파일 ID·해시와 함께 있어야 의미가 있다.
- **generation local:** 공급자가 생성한 원본 안의 구간. 최종 위치와 다르며 앞 핸들·트림을 반영한다.

FPS는 계산 내부에서 유리수 `num/den`으로 유지한다. 24, 25, 24000/1001을 같은 것으로 취급하지 않는다. 기존 project.json의 숫자 fps 표현은 호환 유지하고 정밀한 basis를 투영에 기록한다. SMPTE drop-frame 표시는 사용자 표시 방식이며 프레임 샘플링과 별개다.

### 6.2 같은 CFR·1배속의 정확한 매핑

소스와 출력이 모두 F fps이고 속도가 1이면:

- `L = final_out_frame - final_in_frame`
- `source_out_frame = source_in_frame + L`
- 최종 n 프레임의 소스는 `source_in_frame + (n - final_in_frame)`
- 마지막 포함 소스 프레임은 `source_out_frame - 1`이다. out 시각의 프레임을 끝 이미지로 잘못 추출하지 않는다.

서로 다른 FPS/VFR/배속은 위 단순식을 사용하지 않는다. 실제 PTS와 명시적 conform/retime 정책으로 대응시킨다. 출력 FPS 통일·프레임 복제/삭제·보간·배속은 서로 다른 조작이며 암묵 적용하지 않는다. 원안은 서로 다른 입력의 명시적 CFR conform 생성까지 포함했다. **구현 범위 결정:** 현재 V1 어댑터는 이미 명시적으로 conform된 CFR·같은 FPS·1배속 입력만 실행하고 다른 FPS/VFR는 거절한다. 자동 conform 생성은 구현하지 않았으며, 필요하면 승인된 별도 실행 경로에서 실제 파생본과 raw→conform 프레임/PTS 대응을 확보한 뒤 등록한다. VFR 원본의 index/FPS로 정밀 시각을 발명하지 않는다.

기존 초 단위 편집 필드는 위 정수 프레임에서 파생한다. 소스 초와 final 초를 섞지 않으며, `source_out_s - source_in_s = final_duration_s × playback_rate`가 해당 일정 속도 구간에서 성립해야 한다. 가변 속도는 별도 구간/맵으로 표현하며 현재 단일 playback_rate 필드로 위장하지 않는다.

### 6.3 오디오와 전환

영상 프레임과 오디오 샘플/PTS는 별개다. 비디오 트림 뒤에도 단어·받침·호흡·잔향을 살리는 J/L 컷과 음향 핸들을 승인된 의도에 맞게 배치한다. 원본이 단일 혼합 음원이면 없는 대사/BGM stem을 가정하지 않는다.

오디오 변환·샘플레이트·시작 offset·AAC priming/padding·최종 tail을 실제 디코드 결과와 대조한다. 영상 길이만 맞추려고 단어를 끊거나 무조건 음성을 배속하지 않는다. 기본 영상 구간은 겹치지 않으며 디졸브/음향 중첩은 별도 레이어로 계산해 최종 길이 이중 집계를 막는다.

## 7. 영상 생성 전: 씬·프레임 대조와 수정 루프

### G0 — 제작·검수 능력과 잠금 조건 확인

입력: 현재 대본/각본/콘티/참조의 버전과 승인 범위.

- 요구한 이미지·영상·재생·청취·편집 실행 경로가 실제 존재하고 필요한 파일을 읽을 수 있는지 확인한다.
- 생성 모델은 현재 contract/options의 길이·참조 역할·제어·오디오·해상도·지원 파라미터·가격/포함 조건을 확인한다. 과거 기본값을 현재 기능으로 쓰지 않는다.
- 편집 실행기는 ffmpeg/ffprobe 및 필요한 필터·코덱·쓰기 공간을 확인한다. 다른 편집기나 생성 공급자를 몰래 대체하지 않는다.
- 고정 길이/고정 공개 프레임, 정확한 대사, 잠긴 샷/원테이크, 원본 보존과 비용/재시도 상한을 추출한다.
- 재생기를 실행할 수 있다는 사실과 내용을 실제로 지각·청취할 수 있다는 사실을 구분한다. ASR/파형/모션 수치는 보조 근거다.

출력: 가능 기능·미지원·필수 blocker·허용된 계획 작업. 필수 검사 능력이 없으면 반복 생성 전에 보고한다. 계획 문서 자체는 작성 가능하다.

### G1 — 전체 대본과 계획 타임라인 대조

1. 대본 전체의 필수 사건·대사·반응·정보 공개를 §5.2 행으로 연결한다.
2. 편집 순서와 서사 상태 순서를 별도로 따라가며 §5.3 연결 행을 작성한다.
3. 각 샷에 진입 계기, 주 행동, 필요한 정점/접촉, 결과, 반응/여운, 다음 컷 진입 조건을 정한다.
4. 컷은 해당 변화가 읽히는 지점에 둔다. 패널 수나 공급자 최소 길이로 균등 분할하지 않는다.
5. 단순 도착/손잡기/지지 전환도 필요한 인과가 빠졌는지 확인한다. 계획상 불가능한 동시 행동·카메라 지시 충돌·너무 이른 공개·원인보다 빠른 반응을 찾아 수정한다.
6. 이미 승인된 설계와 충돌하면 제안 수정과 잠금 변경을 구분한다. 변경 권한이 없으면 몰래 고치지 않는다.

출력: 원문 커버리지·연결·계획 프레임 범위가 채워진 계획. 실제 파일이나 motion pass를 주장하지 않는다.

### G2 — 실제 콘티 프레임을 서로 대조

텍스트가 맞다는 이유로 넘어가지 않는다. 현재 등록된 이미지들을 실제로 열어 다음 순서로 검사한다.

- 샷 내부 `start → action_peak/중간 → end`: 요구 행동과 상태 변화가 이미지에서 읽히는가?
- 인접 샷의 `마지막 계획 프레임 → 다음 첫 계획 프레임`: 손·소품·부상·위치·축·시선·행동 단계가 연결 가능한가?
- 씬 전체의 시작·결정적 전환·끝: 인과와 감정·관객 지식이 대본대로 바뀌는가?
- 다른 씬/인서트 뒤 재등장: 마지막 관련 상태를 유지하거나 승인된 변화로 설명하는가?
- 핵심 사건을 가리거나 미리 드러내는 구도, 서로 다른 인물/의상·배경·손, 효과/광원 방향 충돌을 관찰 위치와 함께 기록한다.

비교 자료에는 scene/shot/panel ID·계획 최종 프레임·이미지 버전/해시·비교 대상·가져올/제외할 속성을 표시한다. 관리 라벨은 clean 원본에 덧그리지 않고 별도 검토 자료에 둔다. 검토자는 먼저 캡션 설명과 구분해 실제 픽셀에서 보이는 인물·손·물건·행동을 관찰하고, 그다음 대본/계획과 대조한다. 원하는 사건이 설명에 쓰였다는 이유로 그림에서도 보였다고 기록하지 않는다.

각 실제 작품에서는 생성 제출 전에 **모든 컷 경계의 구체적인 연결 명세**를 산출한다. 이는 가상 예시가 아니라 해당 작품의 실제 ID·현재 버전으로 채운 표다. 필수 열은 `앞 scene/shot/panel → 뒤 scene/shot/panel`, `계획 final out 마지막 포함 프레임 / 다음 in 프레임`, `원문 요구`, `컷아웃 동작 단계 → 컷인 단계`, `유지/허용 변화`, `실제 비교 이미지`, `관찰된 문제`, `수정 대상·결과`, `재대조 상태`다. 원본이 생긴 뒤에는 같은 행에 실제 source frame/PTS·채택 구간과 최종 출력 프레임 대응을 연결한다. 아직 없는 값을 예상 측정치로 채우지 않는다.

정적인 끝/시작이 맞는다는 결과는 `계획 이미지의 연결 가능성`이다. 움직임·속도·실제 접촉·청취 성공으로 승격하지 않는다. 공간/접촉의 실제 3D 검증이 필요한 경우 기존 camera-spatial-design/blender-previsualization 경로를 따른다. 숫자·BBox·대역 정지 포즈만으로 관절/물리 검증을 완료하지 않는다.

### G3 — 타임드보드/애니매틱 수준의 시간 대조

시간 가독성이 필요한 제작에서는 승인된 이미지와 계획 시간을 실제 재생 가능한 러프 보드로 확인한다. 실제 존재하는 임시/최종 음성만 사용하고 없는 보이스를 새로 생성하거나 임시 자막을 음성 청취 증거로 쓰지 않는다.

- 사건이 읽히기 전에 잘리는가, 의미 없는 대기·반응 반복이 있는가?
- 공개·반응·여운·씬 전환의 계획 순서와 상대 시간이 맞는가?
- 대사가 아직 모델 네이티브 생성 예정이면 발화 시간은 추정으로 표시하고 실제 음성/립싱크 게이트는 생성 후로 둔다. 임시 외부 TTS를 강제하지 않는다.
- 정지 보드의 시간 재생은 계획 페이싱 검사일 뿐 생성된 신체 동작의 속도 검사가 아니다.

설계/저장만 요청되었거나 미디어 실행이 승인되지 않은 상태라면 러프 렌더를 실행하지 않는다. 필요한 시간 검증을 pending으로 명시하고 실행 범위를 확인한다.

### G4 — 수정하고 다시 대조한 뒤 제출 준비

문제마다 `원문 요구 → 계획/이미지의 실패 위치 → 관찰 → 수정 대상 → 보존 조건 → 재검사`를 한 행으로 남긴다.

| 문제 | 먼저 수정할 곳 | 재검사 범위 |
|---|---|---|
| 필수 사건/반응이 계획에 없음 | 비트·샷·커버리지 | 해당 사건부터 결과/후속까지 |
| 계획은 맞고 콘티 손/포즈/구도가 틀림 | 해당 패널·참조·스테이징 | 샷 내부와 앞뒤 연결·재등장 |
| 동작 단계가 경계에서 겹치거나 비어 있음 | 컷 phase·시작/끝 상태·필요 커버리지 | 양쪽 샷과 인과 비트 |
| 반응보다 컷이 너무 빠름 | 계획 타이밍·출구·hold | 장면 리듬과 고정 이벤트 |
| 카메라 전환과 프레임 참조가 충돌 | 참조 역할·새 앵글 시작 패널 | 공간/축·초기 구도 |
| 물리/공간 근거 없음 | 전문 입력/필요 검증 | 실제 요구 범위. 텍스트로 면제하지 않음 |

계획 수정이 이미지 변경을 요구하면 실제 이미지도 해당 승인 안에서 수정하고 재검수한다. 수정 프롬프트 작성만으로 이미지 문제가 해결됐다고 하지 않는다. 실행 권한/도구가 없으면 blocker를 남긴다.

**영상 제출 준비 조건:** 해당 범위의 대본 추적, 계획/실제 콘티 대조, 필요한 계획 시간 검사, 참조·실행 지원·권한에 필수 실패가 없어야 한다. 아직 없는 실제 테이크 검사는 여기서 요구하지 않는다. 대신 뒤 샷이 실제 앞 테이크에 의존하면 §9의 제출 시점 게이트를 별도로 적용한다.

## 8. 프레임 단위 연결 예시 — 가상 설계, 실제 제작 증거 아님

다음 ID·시각·이미지·소스 값은 계산과 검사 방식 설명용이다. 실제 프로젝트에 등록하지 않는다. 전제: 24fps, 1배속, 고정 길이 없는 6초 예시. 사건은 **오른손으로 문손잡이에 접근 → 잡고 돌려 문을 열기 시작 → 실내 시점에서 같은 문을 계속 열고 들어감**이다. 실제 수행 가능한 속도인지는 타임드보드와 생성 결과에서 검증한다.

### 8.1 계획 타임라인과 계획 프레임

| 씬/샷 | final 프레임 `[in,out)` | 초 | 계획 프레임/행동 | 넘길 상태 |
|---|---:|---:|---|---|
| EX_S01 / EX_SH01 복도 MS | [0,48) | [0,2) | EX_P01 f0 접근 시작; EX_P02 f47 오른손이 손잡이 접촉 직전 | 문 닫힘, 오른손 접근, 아직 열림 결과 없음 |
| EX_S01 / EX_SH02 손 인서트 | [48,96) | [2,4) | EX_P03 f48 오른손 접촉 개시; f60–75 돌리기; EX_P04 f80 열기 시작; EX_P05 f95 문이 열리는 중 | 동일 오른손/문, 회전→열림 원인 존재 |
| EX_S02 / EX_SH03 실내 역방향 | [96,144) | [4,6) | EX_P06 f96 문 열림의 이어지는 단계; f108–131 통과; EX_P07 f143 실내 진입 결과 | 같은 인물/손/문, 공간만 승인된 역시점 |

문을 통과하며 새 씬으로 나눈 것은 이 가상 예시의 승인된 구성이다. 문/카메라가 바뀔 때마다 새 씬을 만들라는 규칙이 아니다. 실제 프로젝트의 씬 구분을 유지한다.

### 8.2 생성 전 비교에서 잡아야 할 오류

- EX_P02가 왼손을 그리고 EX_P03이 오른손이면 손 상태 충돌이다. 패널을 고치고 양쪽을 다시 연다.
- EX_P03이 이미 활짝 열린 문과 실내 인물을 보여주면 f48에서 필수 잡기·돌리기·열기 인과가 사라진다. 단순히 ‘매치 컷’이라고 이름 붙여 통과시키지 않는다.
- EX_P05는 열리는 중인데 EX_P06이 다시 닫힌 문이면 행동 리셋이다. 시작 패널/참조를 수정한다.
- EX_P06의 화면 진행 방향은 역방향 카메라 때문에 달라질 수 있다. 그림의 좌우만 일치시키려고 반전하지 말고 승인된 공간/행동축 관계로 판단한다.
- f95와 f96의 정지 그림이 맞아도 속도·접촉·문 여는 힘이 자연스러운지는 아직 검증되지 않았다.

### 8.3 생성 후 선택·편집의 계산 예시

실제 파일이 확보됐다고 가정한 계산 예시다. 각 원본은 24fps/120프레임이고 source 기준은 서로 독립적이다.

| cut | 원본 가정 | source `[in,out)` | final `[in,out)` | 마지막 포함 source → 다음 첫 source |
|---|---|---:|---:|---|
| EX_C01 | EX_TAKE01 | [12,60) | [0,48) | TAKE01 f59 → TAKE02 f24 |
| EX_C02 | EX_TAKE02 | [24,72) | [48,96) | TAKE02 f71 → TAKE03 f6 |
| EX_C03 | EX_TAKE03 | [6,54) | [96,144) | TAKE03 f53가 최종 마지막 |

예를 들어 final f60은 C02의 source f36이며, final f95는 source f71이다. f96은 source f72가 아니라 다음 소스의 f6이다. 공급자가 5초를 반환했더라도 2초만 사용하고 나머지는 원본으로 보존할 수 있다.

경계 검토 자료의 기본 확대 창은 24fps 예시에서 앞뒤 12프레임씩이다: final [36,60), [84,108). **12는 합격 임계값이 아니라 검토 창 기본값**이며 준비/접촉/결과가 바깥에 있으면 해당 전체 행동까지 확장한다. 출력 경계의 실제 디코드 프레임과 소스 대응을 검사한다.

어떤 소스의 필수 행동이 이 선택 구간 밖에 있으면 이 편집은 실패다. 임의로 48프레임을 골랐다는 이유로 채택하지 않는다. 연결이 안 되면 다른 구간 조합을 비교하거나 해당 샷을 수정한다.

### 8.4 씬 간 시간 생략의 별도 처리

EX_S03이 ‘다음 날 다른 장소’라면 직전 프레임을 그대로 이어붙이는 것이 목표가 아니다. 새 시간/장소·변경된 조명은 허용하되, 대본상 계속 남아야 하는 부상·소품 소유·인물이 알게 된 사실은 유지한다. 시간 생략 행에 전후 상태·허용 변화·그 변화의 원문 근거를 연결한다. 화면 밖에서 일어난 미확인 행동을 관측된 사실로 만들지 않는다.

## 9. 생성 설계와 실제 제출

### 9.1 생성 길이와 편집 길이 분리

최종 행동 구간과 앞뒤 핸들을 먼저 정하고, 현재 모델이 지원하는 길이로 필요한 원본을 확보한다. 핸들은 연결을 고를 여유이지 행동을 느리게 늘일 지시가 아니다. 모델 최소 길이 때문에 필수 동작이 지연되거나 불필요하게 반복되도록 요청하지 않는다.

정확한 컷 시점은 편집기가 담당할 수 있다. 내부 컷을 hard control로 받지 않는 모델에 여러 카메라·정확한 컷·복합 접촉·대사를 한꺼번에 맡기는 위험을 평가한다. 다만 ‘한 작업=한 샷’, ‘한 접촉=한 컷’을 보편 강제하지 않는다. 승인된 원테이크·샷 수·비용을 보존한다.

### 9.2 참조 선택

- 현재 샷의 시작 구도와 앞 테이크의 인계 상태를 구분한다.
- 같은 앵글 연장: 실제 지원되는 Extend인지 새 생성인지 확인하고 좋은 실제 출구만 사용한다.
- 다른 앵글: 새 앵글의 승인된 시작 이미지를 우선하되 인물/소품/행동 상태는 앞 구간과 대조한다. 이전 구도를 무조건 first_frame으로 강제하지 않는다.
- 각 참조가 가져올 속성·배제할 속성·입력 역할을 명시한다. 일반 reference를 사용했다고 배경/카메라가 안 섞인다고 보장하지 않는다.
- 독립적으로 생성 가능한 샷은 준비/후보 생성이 가능하지만 의존 출구가 없는 후속 샷을 연결된 본편으로 채택하지 않는다. 실제 앞 테이크 상태가 필수인 후속 제출은 그 인계가 확인될 때까지 보류한다.

### 9.3 제출 직전 검사

실제로 보낼 전체 본문·설정·첨부를 요구 추적 행과 역대조한다. 존재하는 파라미터를 누락했다면 명시/생략/서버 기본값/실제 해석 미노출을 구분한다. 파라미터 노출이 의미나 효과 검증을 대신하지 않는다. 자연어 타임코드는 SOFT_PROMPT이며 정확한 실제 컷 증거가 아니다.

현재 입력 버전/해시와 실행 승인, 횟수·비용 상한을 다시 확인한다. 최종 제출 내용과 요청 식별자를 저장한다. 타임아웃은 실패 판정이 아니므로 원래 요청의 상태/결과를 먼저 조회하고 중복 제출하지 않는다. 결과는 실제 child/job/result binding으로 해당 샷에 연결한다.

## 10. 생성 후 검사와 구간 선택

### G5 — 원본 결과 검사

원본 파일·실제 프레임 수/FPS/PTS·오디오·해시를 확인한다. 실제 매체 전체 정속/필요 청취, 중요한 행동의 연속 프레임, 정체성/카메라/연기/대사/소리, 요구 타임라인을 대조한다.

클립 전체 판정, 구간 후보 판정, 편집 후 판정을 분리한다. reject 원본의 일부를 살리려면 해당 구간에 대한 독립 근거와 전체 필수 사건의 다른 커버리지를 제시해야 하며 원본 reject 이력을 accept로 고쳐 지우지 않는다. 원본을 쓰는 수집 규칙도 이 구분을 소비하도록 보완한다.

### G6 — 앞뒤를 함께 보는 선택

한 클립에서 가장 멋진 부분만 고르지 않는다. 선택 구간은 다음을 만족해야 한다.

1. 담당 요구 사건·대사·반응을 빠뜨리지 않는다.
2. 앞 컷 출구와 들어오는 동작 단계·상태가 맞는다.
3. 다음 컷으로 넘길 결과와 읽을 시간을 확보한다.
4. 구간 안에 필수적인 시각/음향 결함이 없다.
5. 최종 타임라인 제약을 지킨다.

복수 후보가 있으면 §5의 요구·연결 행을 기준으로 소수의 실제 조합을 비교한다. 모든 조합을 무한 탐색하거나 자동 미감 점수 최대화로 선택하지 않는다. 범위 안에서 가능한 조합이 없으면 정확한 원인/필요 재작업을 반환한다.

## 11. 과감하되 인과를 보존하는 편집

### 11.1 제거 후보

의미 없는 시작 대기, 중복 동작/정보, 행동이 끝난 뒤의 무기능 정착 꼬리, 다음 컷의 반복, 사건과 무관한 카메라 드리프트, 사용 범위 밖의 생성 불안정은 제외 후보로 삼는다.

유지 후보는 원인·접촉·결과를 이해하는 시간, 중요한 반응, 대사의 완결, 긴장/망설임의 침묵, 의도적 정지, 공개 유보와 여운이다. 움직임이 적다는 이유만으로 제거하지 않는다. 평균 컷 길이·움직임 양·채택률은 합격 기준이 아니다.

### 11.2 프레임 편집의 의미

프레임 단위 선택은 정확한 in/out과 컷 타이밍을 고른다는 뜻이다. 클립 내부의 나쁜 한두 프레임을 무작정 삭제해 동작·음성을 튀게 만들라는 뜻이 아니다. 중간 불필요 구간 제거는 실제로 새 접합을 만드는 편집이므로 그 접합도 경계 검사 대상이다. 원테이크가 잠겨 있으면 내부 점프 컷을 삽입하지 않는다.

승인된 원래 샷 전체의 삭제나 씬/사건 삭제는 단순한 불필요 프레임 제거와 다르다. V1의 기본 자율 편집은 필수 샷/사건을 보존하는 source 선택·트림·허용된 컷 내부 구간 편집과 중복 편집 행 제거다. 잠긴 원본 샷/씬을 없애는 변경은 별도 설계/승인과 원장 참조 이전이 필요하며 현재 upsert 도구가 삭제를 지원하는 것처럼 처리하지 않는다.

트림, 다른 구간 선택, 승인된 커버리지, J/L 컷, 필요한 음향 연결을 우선 비교한다. 디졸브·크롭·검정·배속·음악으로 필수 사건 누락이나 손/얼굴/공간 오류를 숨기지 않는다. 재생 속도 변경은 별도 명시하고 실제 동작·음성·립싱크·최종 요구를 다시 검사한다.

### 11.3 조립에서 픽처 락까지

- **어셈블리:** 대본 사건의 전체 커버리지와 순서를 먼저 확인한다. 임시 결함/미검증을 표시한다.
- **러프 컷:** 씬 단위로 대기·중복을 제거하고 컷의 진입/종료·반응 위치를 조정한다.
- **파인 컷:** 실제 프레임 단위 동작 연결·공개·시선·호흡·음향 접합을 다듬고 전체 맥락으로 재생한다.
- **픽처 락:** 현재 컷 버전에 대한 실제 사용자/위임 범위의 승인만 기록한다. 이후 최종 믹스·그레이드·자막/마스터링은 적용되는 기존 후반 절차를 따른다.

단계를 각각 불필요한 사용자 승인 버튼으로 만들지 않는다. 위임된 편집 범위에서는 코디네이터가 버전/근거와 함께 진행한다. 편집 프로그램 프로젝트/EDL/실행 투영과 원본을 보존해 되돌릴 수 있어야 한다.

### 11.4 러닝타임 정책

- 고정 시간/공개 프레임이 없으면 이야기·연출을 유지하며 최종 길이를 줄이거나 조정한다. 생성 초수를 채택 목표로 삼지 않는다.
- 고정 전체 길이만 있으면 허용된 내부 시간을 재배분하되 관련 cue/자막/리듬을 함께 갱신한다.
- 고정 이벤트 시각까지 있으면 그 anchor를 잠그고 허용 구간 안에서만 편집한다. 남는 시간을 무의미한 hold로 채워 자동 통과시키지 않는다.
- 필수 사건과 고정 길이를 동시에 만족하지 못하면 실제 충돌과 대안을 제시한다. 임의로 대사/원인/여운을 삭제하지 않는다.
- 기존 승인 작품의 고정 시간은 이 공통 스킬 보완으로 해제되지 않는다.

## 12. 실제 편집 실행·출력 검수

### 12.1 V1 실행 범위

기존 설치된 ffmpeg/ffprobe를 사용하는 얇은 로컬 어댑터를 기본 설계로 한다. 새로운 NLE 서비스/설치는 필요 조건으로 만들지 않는다. 실행 전 사용자가 지정한 편집기·원본 방식과 충돌하는지 확인한다.

V1은 명시적 CFR conform, 구간 트림, hard cut 조립, 주어진 음향 레이어의 trim/offset/gain/fade/mix, 명시적 출력 규격과 소스 대응 증거를 지원한다. 영상 디졸브, 가변 속도, 복잡 합성, native NLE round-trip은 V1에서 자동 실행한다고 약속하지 않는다. 요구될 때 승인된 별도 실행 경로로 인계하거나 unsupported로 차단한다. 지원하지 않는 전환을 hard cut으로 몰래 치환하지 않는다.

인코더용 인자는 파일/필터·코덱 지원을 검사해 생성하고 임의 shell 문자열을 실행하지 않는다. 새로운 출력 경로만 사용하고 입력·기존 출력·동시 작성자 파일을 덮어쓰지 않는다. 원본 불변, 부분 실패 결과 구분, 디스크/실행 오류 보고를 지킨다.

### 12.2 정밀 실행 조건

- 프레임 경계 trim이 필요하면 정확한 디코드/필터 기반 선택을 사용한다. keyframe seek/stream copy만으로 임의 프레임 정확도를 주장하지 않는다.
- 출력 FPS·프레임 수·시간 basis·해상도·오디오와 시작/끝 PTS를 명시적으로 제어·측정한다. 24fps 의도가 25fps 출력으로 바뀌면 실패다.
- 소스 변경/삭제/해시 차이는 렌더 전 검출하고 실행 도중 입력 변화도 검사한다.
- 렌더 완료 후 실제 파일을 다시 열어 전체 디코드·프레임 수·시간·첫/끝·모든 컷 경계와 음향을 확인한다. 인코더 종료 코드 0은 품질 성공이 아니다.
- 진단 조립본은 최종 채택/납품과 구분한다. 실제 결과가 기준 미달이면 `needs_revision`/미검증을 유지한다.

### G7 — 컷·씬 연결 검사

모든 실제 선택 경계에서 source out/in과 출력 경계의 대응을 확인한다. 양쪽 인접 모션과 필요한 전체 행동을 보고 상태·속도/위상·시선·공간·빛·음향의 연결을 검사한다. 교차편집/재등장도 서사 선행 이력으로 별도 대조한다.

### G8 — 실제 최종 출력 검사

최종 저장 파일 자체의 전체 정속 재생과 필요한 청취를 수행한다. 대본 요구 추적 행을 최종 시간/프레임에 대조하고 씬 리듬·공개·반응·소리·목적지 규격을 확인한다. 그림 없이 듣기/무음 화면/의심 구간 스텝은 문제에 맞게 추가한다.

`delivery_checks`의 playback/timing/visual/audio/captions/continuity 등 해당 범주에 현재 출력 버전·해시·검사 범위·근거를 연결한다. N/A는 이유가 있고, 미청취/미재생은 unverified다. 최종 파일·수정 가능한 편집 기록·원본 참조·미해결 사항을 인계한다. 게시/외부 업로드는 별도 승인이다.

## 13. 변경·실패·재개 처리

### 13.1 가장 이른 실제 원인으로 되돌린다

| 관측 | 수정 소유자 | 보존/재검사 |
|---|---|---|
| 대본 사건이 계획부터 빠짐 | 비트/콘티 계획 | 사건→결과와 실제 영향받는 후속 |
| 그림 상태/구도 충돌 | 패널/참조 | 정상 디자인·원본, 양쪽 연결 |
| 계획은 맞지만 연기/접촉/카메라 실패 | 생성 요청/참조/지원 경로 | 성공 속성, 해당 시도·실제 결과 |
| 좋은 원본인데 컷 위치가 틀림 | 선택/편집 | 원본 재생성 없이 접합·씬 리듬 |
| 화면은 맞고 발음/음향 실패 | 승인된 오디오/립싱크 경로 | 연기·정확한 원문·앞뒤 음향 |
| 출력 FPS/검정/무음 등 렌더 실패 | 편집 실행/인코딩 | 생성 원본 유지, 출력 재검사 |
| 필요한 검사 능력 없음 | 환경/실행 준비 | 관측 없는 성공 기록 금지, 승인 없는 설치/서비스 전환 금지 |

모든 재작업은 `관찰 → 원인 가설 → 변경 변수 → 보존 조건 → 성공 기준 → 실제 결과`로 기록한다. 연속 실패면 같은 요청의 무의미한 반복을 중단하고 분해/참조/편집/다른 확인된 경로를 비교한다. 추가 작업은 기존 retry_budget/실행 계획 상한 안에서만 허용된다. 해결 불가·예산 소진은 성공이 아니라 구체적인 blocker다.

### 13.2 선택 변경과 stale

채택 테이크 또는 source in/out이 바뀌면 **선택을 소유한 edit_plan artifact 버전**도 바뀐다. 다음 입력, 경계 QA, 씬 컷, 최종 출력은 실제로 소비한 artifact 버전에 의존한다. 파일 해시가 같아도 선택 구간 변경은 다른 인계다.

원장이 artifact dependency를 따라 stale을 전파하도록 연결 의존성을 선언한다. 전체 보드를 한 의존성으로 묶어 모든 샷을 무조건 재생성하지 않는다. 세분한 인계 artifact를 둘 수 있으며 프로젝트 단계/별도 DB가 아니라 기존 artifact다. 영향을 받은 참조/검사를 다시 만들고 정상인 원본은 재사용한다. 의미상 같은 상태여도 출처가 바뀐 경계 증거는 새 버전으로 재확인한다.

서사에서 회상/교차편집 관계가 돌아오더라도 제작 의존성 그래프에는 미해결 순환을 만들지 않는다. 캐릭터/장소 정본의 공유 조건과 과거 시간선 초기 상태를 기준으로 분리한다. 순환이 생기면 제출하지 않고 연결 행을 수정한다.

### 13.3 유연 편집과 현재 원장 제약의 해소

현재 `update_project.py`는 `project` 헤더에서 look_asset_id만 갱신하고, 기본 validator는 shots가 0부터 target_duration_s까지 연속으로 덮도록 요구한다. 단순히 EDL만 짧게 만들면 정본과 출력이 어긋난다.

구현에서는 `project.target_duration_s`의 제한적 원자 갱신을 추가한다. 헤더 전반의 임의 변경은 허용하지 않는다. 활성 편집 위임/고정 anchor 제약을 코디네이터와 시퀀스 검사에서 확인하고, shots의 최종 구간·필요한 storyboard beat/panel 시각·존재하는 rhythm 구간·audio_cues·captions·소유 artifact 버전을 **같은 후보 트랜잭션**으로 반영한다. `storyboard.rhythm`의 갱신이 필요하면 기존 객체의 검증된 교체만 지원하고 불필요한 새 프로젝트 필드는 추가하지 않는다. 후보 전체의 시간/참조 검사가 실패하면 원장은 변경하지 않는다.

편집 초안 중에는 기존 정본 시간은 승인된 계획으로 보존하고 EDL은 제안 시간이다. 최종 채택 편집을 정본에 승격할 때만 위 트랜잭션을 수행한다. 과거 계획/승인/제출문은 이력과 이전 버전으로 보존하고 과거 실행 사실을 다시 쓰지 않는다. 고정 시간/anchor는 무단으로 갱신할 수 없다.

한 기존 shot이 여러 source 구간/테이크로 구성되는 경우 단일 source_in_s/playback_rate에 거짓 요약하지 않는다. 승인된 편집 형식에 한해 해당 shot의 기술적 conform/precomp 파생본을 만들고 정본의 단일 source 표현은 그 실제 파생본(측정 길이·source_in_s=0 등)에 연결한다. raw 구간/프레임 계보는 편집 산출물에 전부 남긴다. 이를 새 공급자 generation_attempt로 기록하지 않는다. 잠긴 원테이크를 내부 편집하려면 별도 연출 승인이 필요하다.

### 13.4 재개

현재 프로젝트/입력 버전, 제출 작업 실제 상태, 확보한 원본, 채택 구간, 변경 이유, 다음 허용 작업, unresolved blocker를 기존 이력에서 조회한다. 최신 파일/버전 번호만으로 재개하지 않는다. 원격 결과 불명은 먼저 조정한다. 기존 lock을 자동 삭제하지 않고 타 작성자의 변경을 보존한다.

## 14. 구현 모듈과 인터페이스 경계

아래 시퀀스 조회·검사·프레임 비교·렌더 CLI와 공통 contract/media/timing 모듈을 구현했다. 기존 프로젝트와 함께 직접 시험하며, 실제 지각 검증·독립 검토를 수행했다고 해석하지 않는다. 스킬의 필수 경로는 구현된 명령으로 연결한다. 새 공개 스킬은 만들지 않고 소유 모듈의 짧은 필수 호출 경로와 온디맨드 참조로 연결한다.

| 모듈 | 책임 | 입력 → 출력 | 하지 않는 일 |
|---|---|---|---|
| 기존 `project_index.py` | 기존 focused 조회 유지, 시퀀스 조회에 필요한 등록 ID/버전 제공 | 정본·focus → 읽기 전용 문맥 | 전 샷 로드 강제/실행 승인 추론 |
| 제안 `sequence_context.py` | scope의 편집 이웃·서사 선행 이력·정본 상태·실제 선택 구간·요구 추적을 묶음 | 정본 + 등록된 계획/편집 투영 + scope → sequence-execution/1 문맥 | 자유 서술의 무근거 상태 추론/원장 쓰기 |
| 제안 `validate_sequence.py` | 단계별 추적·버전·인계·시간·근거·권한 범위의 검사 | 문맥 + plan/generation/edit/export 단계 → blockers·missing evidence·derived ready | 영상 미감 판정/실제 승인 진위 인증 |
| 제안 `inspect_sequence_frames.py` | 실제 계획 이미지 비교 자료, 소스/출력 경계 프레임·인접 클립·시간 대응 추출 | 문맥 + 실제 파일 + scope → 비교 자료와 검수 위치 | 픽셀 유사도로 연속성 합격/없는 프레임 생성 |
| 제안 `render_sequence.py` | 명시적 conform·trim·조립·주어진 음향 레이어·출력 증거 | 검증된 edit 투영 + 등록 파일 → 새 렌더·probe·프레임 대응 | 공급자 호출/자체 컷 선택/미지원 전환 치환 |
| 기존 `update_project.py` | 단일 작성자·원자 정본 통합, 필요한 제한적 시간 갱신 | 현재 버전 + 후보 delta → 현재 정본 또는 오류 | 시각/사용자 승인 추론/자동 lock 제거 |
| 코디네이터/해당 전문 스킬 | 의미 관찰, 프레임/씬 비교, 수정 결정, 실제 공급자 실행, 검사 결과 소비 | 위 결과 + 실제 도구 → 버전 있는 산출물/선택/정본 변경 제안 | 도구 결과를 읽지 않은 채 다음 단계로 진행 |

각 CLI는 입력 검증, 프로젝트 루트 경계, 상대/절대 경로와 symlink 탈출, 기존 파일 덮어쓰기·출력 충돌을 사전 검사한다. 반환은 기계 판독 결과와 짧은 사람용 요약을 함께 제공한다. 실패를 빈 성공 JSON으로 반환하지 않는다. 파생 readiness는 프로젝트 artifact 상태 enum과 별개이며 검사 범위가 준비됐다는 뜻만 갖는다.

## 15. 수락 시험 설계

문서 키워드 검사는 보조다. 아래 결과가 관측돼야 구현을 완료로 볼 수 있다. 지금은 시험을 설계한 상태이지 실행/통과한 상태가 아니다.

### 15.1 순수 계산·구조/계보 시험

| 시험 | 입력/유도 오류 | 기대 결과 |
|---|---|---|
| T01 요구 누락 | 원문 필수 접촉에 panel/cut 대응 없음 | 누락 원문·shot 위치, 제출 blocked |
| T02 손/소품 충돌 | 왼손 계획 출구 → 오른손 시작, 승인 변화 없음 | 관련 연결 실패. 단순 좌우 그림 반전으로 면제 안 됨 |
| T03 비인접 상태 | 소품 놓음 → 인서트 → 다시 손에 있음 | 서사 이력에서 충돌 탐지/의미 검토 반환 |
| T04 교차편집/회상 | 편집 이웃과 서사 선행이 다름 | 해당 시간선 상태 조회, 편집 이웃을 무조건 상속하지 않음 |
| T05 프레임 경계 | §8의 세 source 구간 | 정확히 144프레임, f47/f48·f95/f96 대응, out 프레임 제외 |
| T06 다른 FPS/VFR | 25fps를 24fps 식으로 직접 사용 | 명시적 conform/PTS 없으면 blocked. 24000/1001 드리프트 시험 포함 |
| T07 소스 밖/부족 핸들 | in/out 초과, 필수 구간 절단 | 렌더 전 오류. 원본 파일 불변 |
| T08 최신 실패 꼬리 | 최신 take reject, 기존 선택 출구 유효 | 최신 raw tail을 다음 참조로 자동 교체하지 않음 |
| T09 선택 변경 | 같은 파일, source_out만 변경 | 다음 입력/경계/편집/출력의 실제 의존 버전 stale |
| T10 권한 구분 | plan 통과, 영상 실행 승인 없음 | 텍스트 준비만 가능, 생성/렌더 실행 불가 |
| T11 계획/관측 구분 | 실제 파일 없음, 계획 이미지 있음 | plan 검사 가능, 실제 모션/대사/납품은 unverified |
| T12 시간 원자 갱신 | 유연 컷으로 길이 감소, cue 한 개가 새 끝을 초과 | 후보 전체 거절·원장 불변. 모두 맞춘 후보만 반영 |
| T13 잠긴 시간 | 고정 공개 anchor를 앞당기는 트림 | 권한 없는 변경 blocked |
| T14 불완전 검수 | ASR/파형/스틸만 있고 실제 playback/listening 없음 | 해당 perceptual check는 unverified |
| T15 현재 입력 차이 | 버전/hash/테이크 결과 binding 불일치 | stale/다른 결과 사용 차단, 임의 재제출 금지 |
| T16 지원 경로 누락 | 디졸브 요구인데 V1 hard cut만 지원 | unsupported 반환, hard cut으로 조용히 변경하지 않음 |
| T17 복합 샷 표현 | 여러 raw 구간을 단일 source_in으로 기록 | 거절 또는 실제 precomp+계보로 정규화, 원테이크 잠금 확인 |
| T18 의도적 형식 | 긴 hold·무음·원테이크·시간 생략 | 현재 브리프 근거로 유지. 보편 템포 규칙으로 실패시키지 않음 |

T02/T03의 코드는 **주어진 구조화 관측/계획값의 모순**을 검사한다. 실제 이미지에서 손/소품을 알아본다고 주장하지 않는다. 그 능력은 별도 실제 매체 시험으로 평가한다.

### 15.2 실제 도구 통합 시험 — 생성 비용 없는 합성 fixture

기존 설치 도구로 식별 가능한 프레임·색/문자·오디오 펄스를 가진 짧은 테스트 소스를 만든다. 이는 제품/실사/물리 품질 증거가 아닌 소스 매핑·인코딩 fixture다. 구현 시험 실행 허가 안에서만 수행한다.

- 선택 구간 조립 후 정확한 FPS·프레임 수·경계별 식별 프레임·첫/끝을 자동 대조한다.
- 24fps 요청에 25fps/124frame 출력이 나오면 잡히는 음성 포함 회귀 시험을 둔다.
- 오디오 offset·fade·샘플레이트·끝의 잘림/패딩·무음 정책을 별도 시험한다.
- ffmpeg/ffprobe 없음, 필터 미지원, 디코드 실패, 디스크/권한 오류, 경로 탈출·symlink·출력 경합·입력 해시 변경을 주입한다.
- 실패 시 기존 원본/출력/정본 불변과 부분 결과의 실패 표기를 확인한다.

### 15.3 스킬 행동 시험

현재 지침을 baseline으로 동일한 현실적 문맥에서 대조한다. 행동 지침을 수정할 때는 no-guidance/current-guidance control과 수정안 각각 최소 5개 fresh-context 표본을 사용하고 실제 응답을 읽는다. 문서의 슬롯 복사만 했는지 실제로 조회·비교·수정·재검사를 수행했는지 구분한다. 실패 baseline이 없으면 그 지침 문구는 불필요하게 늘리지 않는다.

압박 시나리오: 이미 비용을 썼으니 실패 꼬리를 이어 쓰기, 5초를 전부 채택하기, 사용자가 급하니 정지 프레임만으로 통과하기, 무기능 대기를 제거하며 필수 접촉도 누락하기, 원테이크를 몰래 분할하기, 조회/생성 도구 실패 후 다른 공급자를 쓰기. 긴 침묵 유지·승인된 생략·독립 후보 실험은 반례로 포함한다.

하위 에이전트/저장 공간/실행기가 실패하면 해당 시험은 blocked다. static 문서 확인으로 behavioral pass를 대신하지 않는다. 실행 기록·입력·판정 근거를 남기고 테스트 환경을 먼저 복구한다.

### 15.4 실제 매체 시퀀스 수락 시험

허가·접근 가능한 기존 매체에서 3종을 최소 수락 사례로 사용한다: (a) 같은 동작의 다른 앵글, (b) 인서트 뒤 인물/소품 재등장, (c) 의미 있는 시간/씬 전환. 각 사례는 원문 요구·계획 패널·선택 source frame/PTS·최종 프레임·실제 시청/청취 관찰을 갖는다. 실제 신체/감정/음성은 이 시험에서 검사하며 합성 색상 fixture로 대체하지 않는다.

현재 거절/조건부 영상은 실패 검출 사례로 사용할 수 있지만 좋은 연결 성공 사례로 둔갑시키지 않는다. 새 시연 영상 생성은 별도 허가다. 사용할 수 있는 성공 사례/검수 능력이 없으면 구현의 구조·기술 시험까지만 완료로 보고하고 종단 간 품질 수락은 blocked로 남긴다.

## 16. 도입·호환·실패 시 롤백

1. 읽기 전용 문맥/검사와 fixture부터 구현하고 기존 focused 조회·계약 테스트를 유지한다.
2. 생성 전 계획/이미지 비교 자료와 수정 루프를 스킬에 연결한다. 실제 에이전트가 결과를 소비하는지 시험한다.
3. 구간 선별 인계·편집 어댑터·실제 출력 검사를 통합한다.
4. 유연 시간 승격·stale·멀티 구간 precomp를 기존 원자 업데이트에 연결한다.
5. 행동/실제 매체 시퀀스 시험을 거친 범위만 배포한다. 설계·계산 통과를 전체 영상 품질 보장으로 보고하지 않는다.

기존 schema_version=1.1, artifact/attempt/check enum, 이미지 실행·전문 검증·실행 승인 정책을 유지한다. 기존 프로젝트가 새 실행 투영을 갖고 있지 않으면 읽기/계획 검사는 계속 가능하다. 새 기능으로 후속 생성·편집·완성 납품을 수행하려면 코디네이터가 기존 자료에서 투영을 만들고 누락을 해결한다. 사용자에게 새 양식 수동 작성을 넘기지 않는다.

롤백은 새 출력/투영을 미채택 상태로 두고 이전 승인 원장·편집 버전으로 되돌아가는 방식이다. 원본 삭제·기존 승인 기록 덮어쓰기·실패 시 자동 Git reset을 하지 않는다. 동시 작업으로 이미 수정된 스킬/라우팅 파일을 이번 변경으로 간주하거나 되돌리지 않는다.

## 17. 구현 완료 체크리스트와 남은 결정

### 구현 완료 조건

- [ ] 대본 요구에서 계획 프레임·실제 source·최종 출력까지 추적 가능하다.
- [ ] 실제 콘티를 생성 전에 대조하고, 실패 위치를 수정한 뒤 재대조한다.
- [ ] 계획 시간 재생과 실제 생성 동작/오디오 검수를 구분한다.
- [ ] 다음 입력에 실제 채택 구간/출구가 전달되며 실패 tail이 전파되지 않는다.
- [ ] 불필요한 구간을 제거하면서 필수 사건·반응·대사·여운·고정 anchor를 보존한다.
- [ ] 실제 경계 프레임/모션/소리와 전체 출력 재생 근거가 존재한다.
- [ ] 길이 조정과 관련 시간/버전 변경은 원자적으로 반영된다.
- [ ] 필수 검수 불능·품질 실패·예산 소진은 성공이 아니라 정확한 blocker다.
- [ ] 사용자는 컷별 상태표·프레임 선택·재검사 작업을 수동으로 떠맡지 않는다.
- [ ] 구조/기술/행동/실제 매체 시험의 통과와 blocked 범위를 각각 보고한다.
- [ ] 기존 기능 회귀와 무음·원테이크·의도적 정지 반례를 통과한다.

### 구현자가 결정할 사항

작은 함수/모듈 분리, 내부 타입, 검토 이미지 레이아웃, ffmpeg 필터 그래프 구성, 캐시 전략, 테스트 fixture 파일 배치는 구현자가 결정한다. 단, 공개 투영의 의미·계산/권한·오류 반환·기존 정본 경계를 바꾸면 문서를 갱신하고 변경의 크기에 맞게 재검토한다.

검수 실행자는 실제 제작 환경에서 확인한다. 특정 Pi/MCP/CLI가 모든 환경에 존재한다고 가정하지 않는다. 사용자의 지정 공급자·검수 경로와 충돌하면 실행 전 해결한다.

### 현재 확인/승인 상태

접근 A, 생성·편집 포함, 고정 시간 없는 프로젝트의 유연 길이 정책, 생성 전 씬·프레임 대조 요구는 사용자에게서 확인됐다. **이후 사용자가 업데이트 및 직접 구현·테스트를 승인했다.** 독립 검토는 실패 후 사용자 승인으로 생략하며, 그 한계와 직접 시험의 실제 결과는 `../../analysis/2026-11-17-sequence-execution-update.md`에 분리해 기록한다.

2026-11-17 검토 상태: 검토 도구 호출이 `UNKNOWN: unknown error, write`로 실패했다. 실행 ID/검토 산출물을 받지 못했으며 원인은 확정하지 않았다. 앞선 큰 도구 출력 보존에서도 `Unknown system error -122 ... write`가 관측됐으나 설계 파일 본체의 저장과는 구분한다. 독립 검토를 수행/통과했다고 주장하지 않고, 다른 CLI·자체 검토로 대체하지 않는다. 이 문장은 당시의 대기 상태 기록이다. 이후 사용자가 독립 검토 생략과 직접 구현·테스트를 승인했으며 현재 상태는 문서 상단과 업데이트 결과를 따른다.
