# 캐릭터 페르소나·음성 SSOT 스킬 설계 제안

- 상태: 사용자 검토용 설계 제안. 스킬 구현·프로젝트 계약 변경·미디어 생성은 수행하지 않음.
- 목표: MBTI·에니어그램을 창작 렌즈로 사용해 행동·판단·관계·대사가 구체적인 페르소나를 만들고, 같은 캐릭터의 시각 표현과 음성 정체성에 연결한다.
- 비목표: 사람의 성격 검사·진단, 실제 인물의 미확인 유형 추정, 유형별 외형/음색 표준화, 새로운 플롯·과거사 강제, 음성 복제·오디션 자동 실행.
- 근거 구분: 외부 모델 설명과 연구 결과에는 출처를 붙인다. 이후 설계 규칙·스킬 구조·예시는 이 저장소를 위한 독자 설계 제안이며 심리학적으로 검증된 생성 방법이 아니다.

## 1. 조사 근거와 채택 범위

### 1.1 MBTI

공식 설명에서 MBTI는 E–I, S–N, T–F, J–P 네 선호쌍을 다루며 전체 성격을 설명하는 도구로 제시되지 않는다.[1] 선호는 능력과 같지 않고, 상황에 따라 선호 밖 행동을 할 수 있다.[1]

공식 네 축의 설명은 주의·에너지 방향, 신뢰하는 정보, 판단 과정, 외부 세계를 다루는 방식이다.[1] 같은 유형이어도 동기·경험·가치·기술·문화는 다를 수 있다는 설명이 함께 있다.[1]

McCrae와 Costa(1989)는 성인 468명의 자료에서 질적으로 구별되는 유형이나 진정한 이분법이라는 해석을 지지하지 못했고, 네 지표를 상대적으로 독립적인 차원으로 해석했다.[11] 다만 일부 정상 성격 차원과의 상관도 보고했으므로 이 연구를 MBTI의 모든 척도·용도에 대한 무효 판정으로 확대하지 않는다.[11] 오래된 특정 표본·당시 도구의 연구라는 한계가 있으며 최신 검사판 전체의 재검사 비율을 확인한 자료는 아니다.

**채택:** 네 축을 정보 탐색, 생각 정리, 의사결정, 계획 조정에 관한 창작 질문으로 사용한다. 유형명에 행동을 종속시키지 않는다. E를 수다/고음, I를 무능한 사회성/저음, T를 무감정, F를 비논리성으로 변환하지 않는다.

**경계:** 공식 개발사 설명은 모델이 의도하는 용도에 대한 1차 출처이지 독립 검증의 대체물이 아니다. 검사 문항·채점법을 복제하지 않으며, 이 스킬의 출력은 공식 MBTI 검사 결과가 아니다.[1]

### 1.2 에니어그램

Enneagram Institute의 체계 설명은 아홉 기본 유형, 인접 유형의 영향인 날개, 성장·압박 방향을 제시한다.[12] 이는 해당 전통의 모델 설명이며 독립 검증 결과와 구별한다.

아래는 공식 개별 페이지의 핵심 욕구/두려움을 짧게 의역한 조사 요약이다. 창작 규칙이나 유형별 필연적 행동표가 아니다.

| 유형 | 욕구 탐색 | 피하려는 상태 | 출처 |
|---|---|---|---|
| 1 | 선함·진실성·균형 | 결함·부패 | [14] |
| 2 | 사랑받음 | 사랑받을 가치가 없음 | [15] |
| 3 | 가치·의미 있음 | 가치 없음 | [16] |
| 4 | 정체성·개인적 의미 | 자기 정체성·의미 없음 | [17] |
| 5 | 유능함·능숙함 | 무능·무력 | [18] |
| 6 | 안전·지원 | 지원·안내 없음 | [19] |
| 7 | 만족·충족 | 결핍·고통 | [20] |
| 8 | 자기 보호·삶의 통제 | 해를 입거나 통제당함 | [21] |
| 9 | 내적 안정·평화 | 상실·분리 | [22] |

Hook 등(2021)의 체계적 문헌고찰은 104개 독립 표본을 검토해 신뢰도·타당도 근거가 혼재한다고 보고한다.[3] 요인분석에서 대체로 9개보다 적은 요인이 발견되었고, 검토 범위에서는 군집분석으로 9유형을 도출한 연구가 없었다.[3] 날개와 유형 간 이동 같은 부차적 이론 요소의 연구 근거도 적었다.[3]

**채택:** 핵심 욕구, 피하고 싶은 상태, 관계에서 반복하는 확보 전략, 압박 시 보호 행동을 탐색하는 창작 렌즈로 쓴다. 9유형의 경험적 확립이나 사건에 대한 필연적 반응을 주장하지 않는다.

**선택 항목:** 날개는 사용자가 요청하거나 해당 인물의 구체적 변주를 설명하는 경우에만 제안한다. 스트레스/성장 방향은 이론상의 창작 참고이지 장면 상태의 자동 계산 규칙이 아니다. 방향표 때문에 시놉시스에 없는 성장·구원·추락을 추가하지 않는다.

### 1.3 음성 도구 문서

ElevenLabs의 Voice Design 문서는 persona, emotion, timbre, pacing, delivery를 구분해 설명하며 음색이 감정적 전달이나 태도와 다르다고 명시한다.[10] 프롬프트와 미리 듣기 대사가 서로 맞아야 한다고 안내하며 결과 품질의 변동도 고지한다.[10]

**채택:** 음성 정체성, 말투, 장면별 연기를 별도 층으로 전달한다. 이 문서는 한 공급자의 지원 예시이며 모든 음성/영상 모델이 같은 제어를 제공한다는 근거로 사용하지 않는다. 공급자 문서의 나이·성별·방언 슬롯 때문에 미공급 캐릭터 사실을 발명하지 않는다.

**연결 경계:** 현재 확보한 근거는 MBTI/에니어그램 유형에서 특정 얼굴·체형·음역·음색을 자동 도출하는 규칙을 뒷받침하지 않는다. 본 설계는 그런 대응표를 제공하지 않는다.

### 1.4 근거 적용 범위

MBTI 공식 페이지, 에니어그램 체계/타입별 페이지, 음성 도구 문서는 공식 설명을 확인했다. 두 연구 논문은 PubMed의 초록을 읽었으며 전문·전체 표본별 분석을 검토했다고 주장하지 않는다. 연구 결과의 요약은 초록에 명시된 내용으로 제한한다. 타입 페이지의 유명인 분류·병리·중독 연결 등은 이 스킬의 생성 근거로 채택하지 않는다.

출처와 규칙은 버전이 있는 참조 자료로 묶는다. 캐릭터 생성마다 전 웹을 재검색하지 않고, 외부 이론 근거의 수정 또는 특정 음성 실행 도구의 기능 확인이 필요할 때만 갱신한다. 웹 연구 자체가 사용자 캐릭터 설정을 덮어쓸 권한은 아니다.

## 2. 접근 대안과 결정

| 접근 | 장점 | 위험 | 결정 |
|---|---|---|---|
| 유형명을 먼저 붙이고 전형을 확장 | 빠른 초기 콘셉트 | 유형 전형의 반복, 기존 캐릭터 설정 덮어쓰기 | 기본 경로에서 제외 |
| 기존 캐릭터 시트에 유형 태그만 추가 | 작은 수정 | 유형이 행동·연기·음성으로 이어지지 않음 | 보조 메타데이터로만 허용 |
| 행동 중심 페르소나 전문 스킬 + 기존 SSOT 인계 | 단독 호출과 기존 제작 모두 지원, 근거 추적 가능 | 소유권을 정하지 않으면 별도 바이블과 중복 | 권장 |

권장 이름은 `designing-character-personas`다. 단독 페르소나·유형 기반 허구 인물 설계·기존 캐릭터의 판단/반응 검산이라는 독립 호출이 있으므로 별도 전문 스킬을 둔다. 캐릭터 시트 담당과 경쟁하는 두 번째 프로젝트 원장을 만들지는 않는다.

MBTI와 에니어그램의 역할 분담은 독자 창작 설계다: MBTI로 **어떻게 정보를 다루고 결정하는가**, 에니어그램으로 **무엇을 확보하고 무엇을 피하려 하는가**를 탐색한다. 실제 페르소나는 이야기 역할, 가치의 우선순위, 경험/환경, 관계, 모순, 예외 조건을 함께 포함한다.

## 3. 스킬 호출과 범위

### 제안 frontmatter

```yaml
name: designing-character-personas
description: Use to create fictional character personas with MBTI or Enneagram lenses, deepen an existing character's motives and decision rules, or translate a persona into observable acting, dialogue, and voice direction. Not for real-person typing, personality assessment, or media generation.
```

- 한국어 기본 출력. 입력에서 제공한 정보는 재질문하지 않는다.
- 단독 페르소나 요청은 페르소나 패킷만 반환한다. 전체 0–33 캐릭터 시트·이미지·음성 파일을 강제하지 않는다.
- 전체 캐릭터 SSOT에서는 캐릭터 시트 담당이 이 전문 패킷을 소비한다. 공급된 이야기/인물 ID·버전·승인·잠금을 그대로 사용한다.
- 유형 적용 모드는 `none | mbti | enneagram | both`. 사용자가 이번처럼 두 모델 사용을 요청했으면 `both`; 모든 캐릭터 제작에 강제하지 않는다.
- 공급된 유형은 `supplied`; 위임된 허구 창작에서 새로 선택한 유형은 `proposal`; 미위임·미공급 유형은 `undecided`다.
- 구현 기본값: 명시적 유형/모드/제외를 먼저 반영한다. 유형 요청이 없는 경우 새 허구 인물의 명시적 창작 위임에서만 `both`를 `proposal`로 설계한다. 기존 승인 인물·실존 인물·미위임 설정에는 새 유형을 자동 부여하지 않는다. `none`은 유형 렌즈를 끄는 값이지 페르소나·표현·발화 역할의 음성 설계를 생략하는 값이 아니다.
- 실제 인물의 겉모습·말투에서 유형·심리·트라우마를 추정하지 않는다. 사용자 제공 유형도 제공 사실로 기록할 뿐 검사를 검증했다고 주장하지 않는다.
- 특정 MBTI와 에니어그램 조합을 금지하거나 모든 인물에 다른 유형을 배정하지 않는다. 같은 유형도 동기·가치·관계·표현 방식으로 구별한다.

## 4. 입력 계약

필수는 요청 범위와 최소 인물 브리프다. 나머지는 공급되면 사용한다.

- 기존 `character_id`, 역할, 시놉시스/브리프와 적용 범위.
- 확정·승인된 캐릭터 설정, 시트, 행동/대사 근거, 입력 artifact 버전.
- 허구 창작 위임 범위와 현실 인물 여부.
- 요청한 유형 모드, 공급된 유형, 유지/제외할 성향.
- 사용 매체, 인물이 말하는지, 기존 보이스 선택·음성 자료.
- 언어·방언 등 공급된 음성 조건. 이 스킬은 필요 없는 인구통계나 임상 사실을 요구하지 않는다.

각 값은 `supplied | observed | proposal | undecided`로 분리한다. `observed`에는 실제 읽은 소스·버전·검사 범위를 둔다. 창작 위임은 허구 설계 제안을 허용하지만 실제 파일·승인·검사 결과의 발명을 허용하지 않는다.

## 5. 페르소나 출력 계약

아래는 **새 패킷의 내용 계약 제안**이며 현재 project.json의 승인된 스키마를 선언하는 것이 아니다.

### 5.1 Persona Core

- 이야기 역할, 외적 목표, 실제로 보호하는 가치.
- 핵심 욕구, 피하려는 상태, 상황을 해석하는 개인적 믿음.
- 가치 충돌 시 우선순위와 넘지 않는 선.
- 겉으로 보이는 태도와 실제 의도 간 차이.
- 강점이 문제가 되는 조건과 그 비용.
- 관계에 따라 달라지는 태도·감정 공개·신뢰 확보 방법.
- 의미 있는 모순과 예외 조건. 모순은 조건 차이로 설명되어야 하며 무작위 설정 충돌이 아니다.

### 5.2 Typology Lens

MBTI: 제안/공급된 유형 또는 미정, 각 선호축의 캐릭터별 해석, 연결 행동, 반대 방식도 사용하는 조건.

에니어그램: 제안/공급된 핵심 유형 또는 미정, 욕구/회피, 반복하는 확보 전략, 압박·안정 시 달라지는 행동, 선택 날개.

모든 타입 선택에는 `design_rationale`와 `limits`를 둔다. 낮음/중간/높음 같은 설계 강도를 쓰더라도 상대적 창작 표시일 뿐 검사 점수·백분율·통계적 확률로 쓰지 않는다. 기본 경로는 인지기능 스택·트라이타입·본능 하위유형을 요구하지 않는다.

### 5.3 Behavior Rules

각 핵심 성향은 다음 구조를 가진다.

`근거/성향 → 촉발 상황·이해관계 → 해석 → 의도 → 관찰 가능한 행동·대사 → 선택/비용 → 예외 조건`

정상·압박·신뢰 관계의 상태 중 이야기에 필요한 것만 비교한다. 행동과 대사가 핵심이며 추상 형용사만 나열한 출력은 불완전하다. 이 패킷이 기존 전체 SSOT를 지원할 때는 기존 §13의 성격 5–7개와 §20의 모순 ≥3개 같은 수량 계약을 그대로 따른다. 단독 lite 요청에는 그 수량을 강제하지 않는다.

## 6. 캐릭터·음성 연결 계약

### 6.1 Expression Bridge

각 핵심 규칙을 필요한 표현으로 연결한다.

| 근거/규칙 | 행동 | 표정·자세·제스처 | 말투 | 장면별 발성 지시 | 유지·제외 |
|---|---|---|---|---|---|
| 캐릭터별 가치·의도 | 관찰 가능한 반응 | 실행 가능한 시각 표현 | 어휘·문장·침묵 | 강세·속도·어택·호흡 | 정체성 잠금과 금지 해석 |

눈·턱·체형·피부·성별·국적을 유형에서 유도하지 않는다. 잠긴 얼굴·신체·스타일을 유지하고, 페르소나는 주로 표정·몸짓·소품을 다루는 방식·연기에서 표현한다. 새 외형의 창작 제안은 별도 근거와 위임 범위 안에서만 한다.

### 6.2 Voice Identity

이 인물의 목소리를 식별하는 설계: 기본 음역, 음색·거칠기·숨 섞임, 공명 인상, 발음·문장 끝 처리, 기본 리듬, 청각적 앵커, 변화 허용 범위.

- 음색은 타입에서 자동 선택하지 않는다. 브리프/제공 음성/캐스트 구별/명시적 창작 제안에 근거한다.
- 성격과 다른 음색을 쓰는 대비도 허용한다. 밝은 목소리가 불안을 숨기는 선택은 가능하나 특정 유형의 필연적 특성으로 쓰지 않는다.
- 근거 없는 정확 Hz·속도·공명 수치를 발명하지 않는다. 공명 위치는 연기용 인상 표현이지 측정·의학 사실이 아니다.

### 6.3 Speech Style와 Performance

Speech Style은 문장 길이, 어휘, 질문·명령·완곡표현, 존댓말, 유머, 침묵 사용, 관계별 말투다.

Performance는 해당 대사의 정확 텍스트, 의도, 서브텍스트, 감정 압력, 강조 단어, 멈춤·숨·속도 변화다. 압박 상태는 새로운 보이스가 아니다. 유지할 음색·발음 앵커와 변화할 연기만 나눈다.

재사용 `voice_identity_direction`과 이번 발화의 `performance_cue`를 분리한다. 유형명이 아닌 실제 말하기 규칙을 실행자에게 전달하며, 모든 과거사/심리 설명을 음성 프롬프트에 넣지 않는다.

### 6.4 실제 도구 변환과 음성 선택

실행 단계에서 현재 도구의 보이스 목록, 지원 언어, 참조 음성, 지시문/감정 태그/속도 제어, 권리·동의·비용을 확인한다. 지원하지 않는 제어는 적용했다고 주장하지 않고 요구 간극으로 반환한다.

프로필은 기존 `voice_profile` 인계로 연결한다. 실제 voice ID·타입·모델·제공된 버전·설정·승인 샘플은 보이스 선택 기록에서 관리한다. 설계에서 `proposed/unresolved`였던 보이스를 실제로 선택됐다고 바꾸지 않는다. 텍스트 지시·seed·같은 voice ID만으로 모든 샷의 동일 음성을 보장하지 않는다.

영상 모델의 직접 음성과 별도 TTS→립싱크는 지원 기능과 승인된 제작 경로에 따라 선택한다. 이미 지정된 보이스/경로를 자동 대체하지 않는다. 청취·오디션·복제·생성 승인은 기존 절차를 따르며 이 텍스트 스킬의 완료 조건이 아니다.

무언 역할의 Voice/Speech는 이유 있는 `N/A`로 둔다. 무대사 캐릭터를 내레이터로 바꾸지 않는다.

## 7. 실행 순서와 완료 조건

1. **입력 잠금:** 공급 사실, 창작 위임, 기존 ID/버전, 무언/발화 범위를 분리한다. 완료: 유지해야 할 정보와 열린 선택이 구분됨.
2. **행동 코어:** 목표·가치·관계·촉발 상황에서 판단과 반응을 작성한다. 완료: 핵심 성향마다 행동·선택·비용이 있음.
3. **유형 렌즈:** 공급 유형을 보존하거나 요청된 허구 설계 범위에서 유형/선호 해석을 제안한다. 유형만 공급됐으면 일반 전형을 복사하지 않고 코어로 확장한다. 완료: 타입 해석마다 캐릭터별 근거·예외가 있음.
4. **관계·상태 변주:** 필요한 압박/안정/관계 변화와 의미 있는 모순을 검산한다. 완료: 달라지는 행동과 유지하는 가치가 설명됨.
5. **표현 번역:** 핵심 규칙을 시각 연기·대사·음성으로 연결한다. 완료: 필요한 표현이 관찰/청취 가능한 지시로 반환됨.
6. **Voice 설계:** 발화 역할만 고정 음성·말투·대사 연기를 분리한다. 완료: 정체성과 연기 상태가 충돌하지 않고 보이스 확보 상태가 정직함.
7. **캐스트 비교와 반환:** 얼굴이나 타입만 바꿔 구별하지 않고 목표·판단·관계·말투·음성 앵커의 실제 겹침을 확인한다. 의도된 유사성은 보존한다. 완료: 아래 품질 게이트와 반환 계약 충족.

유형과 공급 행동이 어긋나면 공급 행동을 보존하고 유형 해석의 간극을 기록한다. 행동을 억지로 전형에 맞추거나 승인된 유형을 몰래 교체하지 않는다. 향후 행동 변화는 서사 근거와 버전 변경으로 관리한다.

## 8. SSOT 소유권과 기존 구조 매핑

- 페르소나 전문가는 패킷을 반환한다. 프로젝트 coordinator만 정본 레코드를 저장한다.
- 전체 캐릭터의 심리·성향 정본은 기존 `character_sheet` SSOT다. 전문 패킷은 그 시트에 통합할 입력이며 별도 경쟁 바이블로 유지하지 않는다.
- `characters[].persona={role,personality,observable_behavior,speech}`는 현재 네 문자열을 유지한다. 상세 유형 객체를 기존 문자열 필드에 끼워 넣지 않는다. 이것은 정본 SSOT에서 만든 인계 요약이며 상세 규칙을 따로 편집하는 장소가 아니다.
- 기존 §13–20에는 Persona Core·Typology Lens·Behavior Rules를, §10–11에는 시각 표현을, §12에는 Voice Identity·Speech Style·연기 번역 규칙을 배치한다. §24–26/33에는 허용 상태와 음성 잠금/드리프트 규칙을 반영한다. 번호 0–33은 유지한다.
- `voice_profile`은 해당 캐릭터 SSOT artifact의 정확 버전을 참조하는 음성 인계 자료다. 음성 설계 자체를 SSOT와 양쪽에서 독립 수정하지 않는다.
- 실제 보이스 선택과 생성 오디오는 별도 실행 기록이다. 기존 `shots[].speech[].voice_artifact_id`와 `performance` 연결을 재사용한다.
- 필요할 때만 기존 registered artifact의 `dependencies/dependency_versions`로 계보를 선언한다. character/provider/source ID를 artifact dependency로 넣지 않는다. 단독 텍스트 호출은 프로젝트/산출물 ID를 만들지 않는다.
- 페르소나/음성 설계 버전이 바뀌면 기존 dependency 그래프를 따라 실제 종속 자료를 stale 처리한다. 실제 보이스 선택/오디오만 바뀌면 독립 이미지 승인은 유지한다. 통합 character_sheet 자체가 바뀌고 이미지/보드가 그 전체 버전에 의존하면 해당 자료도 재검토 대상이며, 현재 제안만으로 섹션별 무효화가 구현됐다고 주장하지 않는다. 외형이 같더라도 과거 버전 핀을 조용히 현재 버전으로 바꾸지 않는다.

## 9. 창작 예시와 설계 검산

아래는 창작 예시이며 실존 인물·유형 보편 특성·실제 생성 결과가 아니다. CH01은 설명용 캐릭터 ID이며 프로젝트에 등록한 artifact ID가 아니다.

### CH01: 재난 상황에서 동료를 보호하는 장비 담당자

- 렌즈 제안: ISTJ + 에니어그램 6. 날개는 이번 행동 설계에 필요하지 않아 선택하지 않음.
- 개인적 동기: 동료가 자신 때문에 위험해지는 일을 피하고 싶다.
- 정보 처리: 실제 점검 결과와 기존 절차를 먼저 확인한다.
- 가치 경계: 안전 규칙을 중시하지만 규칙 때문에 동료를 버리는 것은 허용하지 않는다.
- 모순: 남의 확인을 요구하면서, 동료가 위태로우면 승인 없이 먼저 나선다. 촉발 조건은 시간 부족과 즉각적 위험이며 무작위 돌변이 아니다.
- Voice Identity 제안: 맑은 중간 음역, 선명한 자음, 문장 끝을 짧게 닫음. 낮고 거친 목소리도 가능한 별도 캐스팅 선택이므로 유형의 정답으로 고정하지 않음.

| 검산 상황 | 해석·의도 | 행동·대사 | 시각 연기 | 음성 연기 | 유지 |
|---|---|---|---|---|---|
| 평상시 점검 | 확인된 정보로 공동 위험을 줄임 | 점검 항목을 짚고 “잠금은 확인했어?” | 체크리스트와 장비를 번갈아 봄 | 보통 속도, 질문의 핵심 ‘잠금’에 강세 | 음색·자음·문장 끝 습관 |
| 즉각적 위험 | 지금 재확인하면 동료를 잃음 | 장비를 잡고 “확인은 나중에. 먼저 나가.” | 몸을 출구 쪽으로 돌리고 길을 확보 | 문장 단축, 단단한 어택, 끝없는 고함은 피함 | 같은 보이스·발음 앵커 |
| 신뢰하는 동료의 자책 | 책임을 혼자 떠안게 하지 않음 | 옆에 앉아 “다음엔 같이 확인하자.” | 시선을 강요하지 않고 어깨 긴장 완화 | 속도를 낮추고 ‘같이’를 부드럽게 강조 | 같은 음색, 애교화하지 않음 |

검산 결론: 세 조건의 행동은 달라도 동료 보호라는 가치가 유지된다. 급박한 조건에서 절차보다 사람을 택하는 예외가 명시돼 있어 ‘계획적인 유형은 절차를 절대 어기지 않는다’는 결정론이 필요하지 않다. 이는 문서 내 논리 검산이며 모델 실행/청취 검증이 아니다.

**동일 MBTI의 다른 인물:** 같은 ISTJ를 제안하더라도 에니어그램 1을 참고하는 인물은 ‘안전 확보’보다 ‘자신의 원칙을 어기지 않는 것’을 개인적 동기로 설계할 수 있다. 같은 점검 행동의 이유·지적 방식·실패 시 수치가 달라질 수 있다. 두 렌즈 모두 창작 제안이며 유형별 정해진 대사를 뜻하지 않는다.

**같은 페르소나의 다른 음색:** CH01의 판단·말투를 유지하면서 밝고 맑은 음색 또는 낮고 거친 음색 중 브리프와 캐스트에 맞는 쪽을 선택할 수 있다. 이후 승인된 한 선택을 연속성 기준으로 관리한다.

## 10. 품질 게이트와 향후 평가

### 설계 게이트

- 요청한 모든 인물의 페르소나가 반환되며 사실/관찰/제안/미정이 구분됨.
- 핵심 성향을 행동·대사·선택으로 추적할 수 있음.
- 각 핵심 모순의 조건과 비용이 설명되고 기존 플롯을 수정하지 않음.
- 유형명만 바꾼 같은 인물의 반복이 아니며, 같은 유형인 캐릭터도 개인적 근거로 구별됨.
- 유형과 외형/음색을 자동 대응시키지 않음.
- 발화 역할에만 Voice Identity·Speech Style·Performance가 연결됨.
- 제공 음성과 권리·승인 상태를 보존하며 존재하지 않는 보이스·샘플을 주장하지 않음.
- SSOT 입력 버전, 실제 적용 범위, 미해결 사항과 다음 실행자의 요구가 반환됨.

### 스킬 구현 후 평가 시나리오 제안

| 입력 | 확인할 소비자 동작 |
|---|---|
| 유형 없이 기존 허구 캐릭터의 성향 보완 | 기존 설정 보존, 요청 없는 유형 강제 없음 |
| ISTJ+6만 주고 허구 창작 위임 | 구체적 개인적 동기·행동·예외를 제안, 공식 검사 결과 주장 없음 |
| 같은 MBTI의 허구 인물 두 명 | 유형명이 같아도 행동의 이유·관계·대사가 구별됨 |
| 공급 유형과 승인 행동의 충돌 | 승인 행동 유지, 유형 해석 간극 명시, 몰래 재설계 없음 |
| 실제 인물의 이름/사진만 제공 | 미확인 유형·심리·목소리 발명 없음 |
| 무언 캐릭터 | 이유 있는 음성 N/A, 내레이션/오디션 추가 없음 |
| 발화 역할의 중립·압박·신뢰 상태 | 동일 Voice Identity와 조건별 연기 차이 유지 |
| 승인 보이스와 제안 음색의 충돌 | 승인 보이스 우선, 교체는 명시적인 변경 제안 |
| 음성 도구가 persona/감정 제어 미지원 | 지원 가능한 입력만 변환, 적용 불가 요구를 숨기지 않음 |
| 오래된 SSOT 버전을 참조한 음성 인계 | 현재 실행용으로 거부, 영향 있는 자료만 재검토 |

향후 `evals/evals.json`에 사용자 프롬프트와 기대 동작을 작성하고 현행 스킬 대비 평가한다. 구조·보존·오용 방지는 명시적 판정으로, 입체감·캐스트 구별·페르소나와 연기의 적합성은 사람이 블라인드 비교한다. 음성 적합성은 실제 승인된 오디션을 청취해 판정한다. 이번 설계 단계에서 이 평가를 실행했다고 주장하지 않는다.

## 12. 이번 단계의 검증 범위

실제 수행: 기존 캐릭터/음성/SSOT·의존성 계약 읽기, 웹 원문 조사, 문서 내 사례의 논리 검산. Citation ledger의 일반 `verify`에서 인용 ID·출처 목록 연결 검사를 통과했다. 조사 ledger의 미채택 출처 9개에 대한 경고가 있으며, 그 경고까지 오류로 취급하는 `--strict`는 통과하지 않았다. 이 검사는 문장별 사실성이나 창작 품질을 인증하지 않는다.

수행하지 않음: 스킬 설치/구현, 실제 프로젝트 원장 변경, 자동화된 스킬 출력 평가, 이미지·음성 생성, 샘플 청취, 립싱크·영상 품질 판정. 사용자 검토가 끝난 뒤 구현 요청이 있을 때 실행 계획으로 전환한다.
