# 내레이션·자막 연출 통합 제안

상태: 검토용 초안. 스킬 복사·등록·라우팅 변경은 하지 않았다.

## 권고: 기존 총괄이 전문 스킬을 연결

- 단순 폰트/자막 배치나 이미 고정된 자막 사용은 기존 `video-production-assets` 자막 모듈을 유지한다. 분석과 타입·색·모션 설계 또는 실제 자막 재연출이 필요한 경우만 `subtitle-direction-skill/03_스킬/SKILL.md`의 `shortform-subtitle-direction`을 연결한다.
- 처음에는 로컬 외부 의존성으로 연결하고 원본 프로젝트를 정본으로 유지한다. 전체 엔진을 복사하는 대안은 독립 배포에 유리하지만 복구본·폰트·렌더 지원 계약을 중복 관리하게 된다. 원본 리포지터리 경로가 없는 환경에서는 현재 패키지의 기본 자막 계획을 제공하고 심화 렌더가 미지원임을 표시한다. 원본을 함께 배포해야 한다면 검증한 스냅샷 하나만 패키징하고 권리 및 업데이트 정책을 별도 승인한다.
- 내레이션은 공급자 라우팅과 구별한다. 내레이션 설계는 화자·의도·호흡·발음·감정 변화와 발화 원고/표시 텍스트를 관리하고, 기존 오디오 큐는 공급자 선택·승인·실측 음성을 맡는다. 숏폼에서 내레이션이 컷을 이끌면 기존 `narration-first-viral-shorts`의 타이밍 규칙을 재사용한다. 일반 영상에 해당 숏폼 포맷을 강제하지 않는다.

## 연결 순서

1. 총괄이 목적, 자막 언어, 가로세로 비율/플랫폼, 내레이션 주도 여부, 자막 요청 범위를 판단한다. 무음·무자막은 각각 독립 잠금이다.
2. 이야기 의도 → 발화/표시 원고 → 합성 또는 기존 테이크 선택 → 실제 청취·실측 정렬. 음성이 미확정이면 가편집·시각 방향만 제안하고 최종 타임코드나 실제 음성 전사를 주장하지 않는다.
3. 자막 엔진에 확정 영상/편집 버전, 자막 원고 및 잠긴 음성·구간, 플랫폼 안전 영역, 승인 범위를 넘긴다. 의미·강조 힌트와 색·모션·서체 선택은 분석 결과에 따라 선택한다. 렌더는 원본 스킬의 현재 계획 해시 승인 및 런타임 지원 확인을 유지한다.
4. 프레임/재생 검수: 말과 글의 일치 또는 명시된 표시 예외, 숫자·고유명사 보존, 줄바꿈과 크롭, 얼굴·하단 UI 침범, 등장/퇴장 타이밍, 한/영 혼용 폰트와 대비, 모바일 가독성, 내레이션 마스킹을 확인한다. 원고·음성·컷 변경으로 낡아진 결과만 다시 계산한다.

## 우선 보완과 합격 기준

1. **공통 인계 형식:** cue/shot ID, 원고 버전, spoken/display 쌍, 음성 해시, 실측·예상 타이밍, 출력 캔버스, QA 상태의 매핑. 새 프로젝트 원장은 만들지 않는다.
2. **기본/심화 경계 회귀:** 단순 SRT·기존 자막은 전체 엔진을 띄우지 않는다. 심화 자막 연출만 외부 스킬을 읽는다. 무자막·미확정 음성·엔진 미설치·승인 없는 렌더도 각각 시험한다.
3. **실제 렌더 검증:** Python/FFmpeg/폰트와 렌더러 모드가 현재 환경에서 동작하는지 확인한다. 원본 README의 240 pytest 통과는 원본 프로젝트의 과거 보고이며 현재 통합의 증거가 아니다. 폰트 배포 권리와 스타일 카탈로그의 현재 렌더 지원 여부도 확인한다.
4. **편집 검수 표본:** 한글 혼용 숏폼 한 편으로 FFmpeg/ASS 또는 실제 채택 렌더러에서 미리보기·최종 결과를 검수한다. ASR 타임스탬프만으로 청취를 대체하지 않고, 효과음·BGM 조합의 대사 가독성도 별도로 판정한다.
