# 씬·컷·연출 통합 제작 설계 — B안

> 사용자가 승인한 상세 설계다. 구현 계획·실제 평가/미디어 실행·배포의 승인은 별도다.

작성일: 2026-11-14
상태: **접근 B·상세 설계·Native 구현 사용자 승인됨 / C1 독립 판정·실패 보존 / C2 남은 소스 구현 반영·8회 중6 PASS/2 시간초과 미검증 / 총32회 소진·전체 수락/기본 적용 HOLD**
사용자가 선택한 것: 기존 오너를 유지하고 컷별 통합 설계·준비도·역대조·검증을 연결하는 B안.
상세 승인 근거: 사용자의 직접 회신 `승인한다.`. 아래 구성·V1 경계·예시·평가 방식은 이 상세 설계 승인에 포함된다. 실제 모델/평가 호출·과금·설치·Git 통합이 수행되거나 별도 승인된 것으로 해석하지 않는다.

## 1. 의도와 성공의 모습

영상 실행자가 한 샷을 배정받았을 때 다음을 추측하지 않게 한다:

> 왜 이 컷인가 → 어떤 세계 규칙/인물의 선택인가 → 첫 프레임은 무엇인가 → 그 사이에 무엇이 언제 변하는가 → 끝에 무엇을 넘기는가 → 어떤 실제 에셋/보이스/소리가 필요한가 → 무엇을 어떻게 제출하고 무엇으로 확인하는가.

이를 위해 또 다른 총괄·거대 캐릭터 시트·경쟁 원장을 만드는 대신, 기존 전문 오너의 **설계 내용과 현재 버전**을 하나의 제작용 스토리보드 안에서 샷별로 조회하도록 연결한다. 긴 문서나 필드 존재를 품질로 보지 않는다.

### 목표

1. 서사형 전체 제작에서 세계의 작동 법칙, 인물의 목표/관계/판단, 플롯의 정보 공개, 대본의 행동/발화가 샷 설계에 실제로 쓰이게 한다.
2. 모든 제작 샷의 시작→필수 중간 사건→끝을 화면·연기·카메라·음성·음향·VFX의 같은 시간 관계로 설계한다.
3. 대본/샷에서 필요한 인물·장소·도구·상태 파생물·소리·효과의 누락을 찾고, 준비된 자원과 계획만 있는 자원을 구별한다.
4. 전문 오너 문서를 실제로 읽은 입력의 locator/version과 함께 소비하고, 최종 제출문에서 무엇이 유지/누락됐는지 역대조한다.
5. 구조 검사, 내용 설계 수락, 실제 이미지/재생/청취, 사용자 수락을 각각 판정한다.
6. 기존 프로젝트·단일 요청·정적/무언/비서사/원테이크 형식을 보존한다.

### 비목표 / 실패 조건

- 새 `director` 스킬, 전역 승인 원장, 자동 실행·과금·게시 엔진을 만들지 않는다.
- 세계관 백과사전, 모든 인물의 전기, 고정 샷 수·렌즈·반응 컷 공식, 장면마다 무조건 BGM/VFX를 강요하지 않는다.
- 제공 웹툰의 줄거리·인물·디자인·대사·특정 패널 배열을 제작 자산으로 복제하지 않는다.
- 필드/문서 수만 늘었거나, 실행자가 여전히 화자·손·소품·시간·음향을 추측해야 하면 실패다.
- 실제 보이스/파일/지원 제어/검수/승인을 발명해 빈칸을 닫으면 실패다.
- 스키마 통과나 검토자의 호의적인 문장만으로 연출력 향상 또는 영상 품질을 인증하면 실패다.

## 2. 근거와 현재 기준선

감사: `docs/research/2026-11-14-scene-direction-upgrade-audit.md` 및 `.sources.json`.
- 제공 자료 목록은 당시 58회차 JPG 10,261개, 실제 시각 열람은 6회차의 고유 조각 113개다. 전수 장면 독해가 아니다.
- JPG는 긴 화면의 저장 조각일 수 있다. 파일/패널/씬/샷/시트/생성 작업은 서로 다른 단위다.
- 관찰 가능한 것은 구도·상태·공개 순서·시각적 발화/효과 표현이다. 원본의 실제 타이밍·카메라 이동·목소리·BGM은 확인하지 않았다.
- 기존 합성 보드의 카메라/행동을 일반 문구, 발화를 감정 형용사, VFX를 설명 한 줄로 대체해도 `validate_storyboard`의 구조 검사는 통과했다. 이 검증기의 의도된 범위와 실제 연출 수락을 분리해야 한다.

설계 재확인 시 HEAD: `0e1d9f3`(lip-sync·이미지 라우팅·의존 정책 정합 수정). 작업 트리에는 별도 스틱맨/조사 변경이 있다. 구현 시작 때 현재 파일을 재확인하고 이 설계와 다른 합의/변경이 있으면 좁게 조정한다. 기존 dirty 변경을 덮거나 묶어서 배포하지 않는다.

## 3. 검토한 접근과 선택

| 접근 | 장점 | 한계/판정 |
|---|---|---|
| A. 문서 설명/예시 추가 | 작고 빠른 패치 | 이미 많은 지침의 실제 소비·완성도 문제를 해결하기 어려움 |
| **B. 기존 오너 + 통합 제작 보드 + 준비도/역대조/평가** | 기존 자산을 재사용하고 누락 위치·책임·영향을 특정 | 오너 간 입력 연결과 평가를 실제로 설계해야 함. **사용자 선택** |
| C. 새 대형 감독 스킬/새 원장 | 역할 이름은 명확해 보임 | 기존 총괄/보드/카메라/음향과 책임·버전이 중복. 현 근거로 채택하지 않음 |

## 4. V1의 크기와 경계 — 승인된 설계 범위

**지침·템플릿·인계·내용 수락·행동 평가를 함께 개선하는 패키지 작업**이다. 코드부터 거대한 감독 엔진을 만들지 않는다.

- `project.json schema_version=1.1`, 카메라 스키마, 기존 ID/상태/승인/파일 저장·배포 규격을 유지한다.
- 새 스킬/의무 JSON 테이블·필드·enum·새 기본 validator profile을 추가하지 않는다.
- 기존 Markdown 템플릿에 의미 있는 구획과 샷별 통합 출력을 추가할 수 있다. 기존 필드명은 유지하고 추가 구획의 소유/적용 범위를 명시한다.
- 기존 `project_index.py --shot`을 현재 입력 조회에 재사용한다. **V1에서 임의 Markdown을 자동 해석·합성하는 의미 컴파일러나 새 `--direction` CLI는 만들지 않는다.** 읽은 자료를 묶는 것은 조정자/보드 오너의 명시적 인계이며, 원문 locator와 내용·시간을 QA에서 대조한다.
- 기존 기계 검사는 참조/버전/시간/실제 파일의 증거만 제공한다. 새 콘텐츠 기준은 별도 오너 검토와 평가의 대상이지 검증기 전체 통과의 새 의미가 아니다.
- 기존 코드가 이미 보장한다고 선언한 관계의 실제 결함이 발견되면 별도 재현/테스트로 수정한다. 이번 설계만을 이유로 전역 스키마를 확장하지 않는다.
- 평가 준비/집계 자료는 만들 수 있지만 실제 에이전트 호출·독립 평가·미디어 실행은 사용자 권한과 실제 가용 도구가 있을 때만 한다. 설계 승인 자체가 유료 생성/게시 승인은 아니다.

**선택 비용:** 자동 컴파일러가 없으므로 V1에서는 오너가 읽고 통합한 내용의 역대조가 필요하다. 대신 미확정 자연어를 자동으로 '완전함'으로 오판하는 새 시스템을 피한다. 실제 사용에서 반복되는 연결이 안정되고 코드화할 규격이 검증되면 후속 버전에서 선택적 읽기 전용 투영을 설계할 수 있다.

## 5. 적용 범위와 필요한 깊이

| 요청 | 적용 | 완료 경계 |
|---|---|---|
| 서사형 전체 영상/제작용 보드 | 이야기 세계/인물/대본·전체 샷 통합, 적용되는 모든 전문 항목 | 해당 단계의 텍스트 설계/필수 실제 파일/의미 검토를 구분 |
| 제공 대본으로 보드만 | 잠긴 사건·대사·설정 보존, 필요한 연출 빈칸만 위임 범위 안에서 제안 | 플롯 재작성/새 캐릭터 창작으로 확대하지 않음 |
| 한 씬/한 샷 수정 | 해당 구간·경계·종속물만 소비/수정 | 독립 정상 컷과 승인 보존 |
| 세계관/인물/각본 단독 요청 | 그 기존 오너의 요청 산출물만 | 전체 제작 패키지·이미지·원장 강제 없음 |
| 명시적 러프/패널 연습/프롬프트만 | 기존 좁은 계약 | 촬영용 완성 보드라고 표시하지 않음 |
| 설명/데이터/제품·비서사 | 실제 개체·정보·행동·출처/제약에 필요한 항목 | 허구 세계·인물 갈등·목소리 강제 없음 |
| 무언·무음·정적·루프·원테이크 | 선택된 형식 유지 | 발화/새 컷/이동/음악을 빈칸 채우기용으로 추가하지 않음 |
| 채팅-only | 동일한 내용 설계를 채팅으로 제공 | 파일/프로젝트 ID·실행을 자동 추가하지 않음 |

각 항목을 `적용`, `사유 있는 N/A`, `후속 단계 결정`, `미해결 요구`로 설명하되 새 artifact 상태를 만들지 않는다. 촬영 단계에 필요한 것이 미해결이면 해당 단계가 완료되지 않는다. 피치만 요청된 경우의 기존 deferred 규칙은 유지한다.

### 충돌 시 처리

1. 기존 사용자 잠금/명시적 위임과 현재 정본의 정확한 버전을 우선한다. 승인 자료끼리 충돌하면 덮어쓰지 않고 해당 선택만 반환한다.
2. ID·구간·참조·등록 상태 등 `project.json`에 있는 값은 그 값을 재사용한다. 확장 설명은 담당 오너 문서에서 가져오고 같은 사실을 독립 편집하지 않는다.
3. 보드의 상위 문서 요약은 **조회/투영**이다. 인물/세계/발화 자체를 바꾸면 원래 소유자 산출물을 먼저 버전 변경하고 종속 보드를 갱신한다.
4. 통합 본문에는 필요한 실제 내용을 넣고 source artifact ID/version/heading 또는 정확 locator를 덧붙인다. 링크/ID만 나열하는 것으로 내용 소비를 대신하지 않는다.
5. 보드에서 새로 결정하는 샷 연출과 상위의 잠긴 사실을 구별한다. 미해결 입력은 indexed 요구 패킷 하나로 조정자에게 돌려보낸다.

## 7. 전체 흐름 — 일방통행이 아니라 잠금 범위를 지키는 반복

1. **범위/입력 고정:** 형식·단계·이야기·런타임·오디오 의도와 위임/미정·기존 버전을 읽는다.
2. **이야기 기반:** story/plot/시놉·필요 세계 규칙·핵심 인물의 목표/관계를 교차 설계한다. '세계관 완성 전에는 시놉을 절대 쓸 수 없다'는 순서를 강요하지 않는다.
3. **각본 검산:** 장면의 원인/선택/결과, 정확 발화와 인물의 판단/관계 일관성을 확인한다. 잠긴 원문은 임의 수정하지 않는다.
4. **씬·샷 설계:** 화면 목적과 블로킹에서 샷과 내부 사건을 결정한다. 동시에 에셋 필요/음성·음향·효과 요구를 분해한다.
5. **전문 입력 소비:** 해당 오너의 현재 결과를 통합하고 빠진 요구를 반환한다. 텍스트 설계 단계에서 아직 없는 미디어를 준비됐다고 표시하지 않는다.
6. **배치별 준비:** 다음에 실제 실행할 샷 묶음의 필수 입력을 준비·검사한다. 미래 모든 에셋을 선제 유료 생성하지 않는다.
7. **최종 인계:** 입력 버전·필수 상태·시간과 실제 제출문의 대응을 검사한다. 모델 미정인 계획은 의미 설계를 유지하고 지원/실행은 미확인으로 둔다.
8. **결과 검사:** 실제 파일의 가독성/재생/청취/구간·상태를 비교하고 허가된 범위에서 최소 수정한다.

상위 변경은 실제 의존 그래프에만 전파하고, 같은 문서를 대사·보이스·표정·타이밍별로 제각각 수정하지 않는다.

## 8. 세계관·인물·대본 설계의 깊이

### 8.1 이야기 세계

02의 기존 `세계관 규칙` 구획을 서사형 전체 제작에서 필요한 만큼 확장한다:
- 현재의 질서/갈등과 필요한 역사·시간 층위.
- 지역·주요 공간·이동/접근 제약.
- 능력/기술/자연 법칙의 발동 조건·가능/불가능·대가·예외 근거.
- 정보가 누구에게 언제 알려져 있는지와 잘못된 믿음.
- 장면에서 규칙이 드러나는 행동/비용/가시 결과, 필요한 인물·장소·도구.

이는 새 LOOK의 복사본이 아니다. 시각 구현은 05/07과 마스터에 연결한다. 실제 장면에 쓰이지 않는 백과사전식 항목은 만들지 않는다. 짧은 작품은 몇 가지 규칙만으로 충분할 수 있다.

### 8.2 인물

기존 SSOT/페르소나를 다시 대형 양식으로 만들지 않는다. 중요한 행동/발화마다:
- 무엇을 얻거나 지키려 하는가.
- 이 상대와 이 압력에서 어떤 판단/전술을 선택하는가.
- 보이는 행동·말·침묵은 무엇이고 무엇을 감추는가.
- 어떤 비용/관계 변화/후속 제약이 생기는가.

를 검산한다. 유형명/형용사/과거사 분량은 근거가 아니다. 기존에 승인된 인물의 잠금은 보존한다. 소설처럼 풍부한 기반을 만들되 화면에 무관한 세부를 의무화하지 않는다.

### 8.3 각본과 공개

story(발생한 사건)와 plot(관객에게 공개하는 순서), 내레이션의 관점, 화면 밖 인물의 정보와 관객 지식을 구별한다. 대본의 각 장면 목적/변화/행동을 실제 샷으로 찾을 수 있게 한다. 원문 수정권이 없으면 각본의 문제를 표시하고 연출로 몰래 새 사실을 만들지 않는다.

## 9. 컷별 통합 출력 — 기존 보드 안의 확대 보기

기존 storyboard-contract의 여섯 반환 부분은 유지한다. §3 전체 샷 명세 안에서 샷별 상세 블록을 제공하고, 위의 씬 요약·아래의 패널/큐/요청문과 같은 ID를 쓴다. 대량 샷은 요약표+상세 블록으로 탐색 가능하게 하되 필요한 샷을 요약만으로 대체하지 않는다.

- 처음부터 끝까지 의도적으로 같은 상태인 hold도 유효하다. 모든 샷에 행동 변화나 추가 패널을 강제하지 않는다.
- 원테이크 내부의 변화는 같은 shot의 시간 구간이다. 프레이밍이 바뀌었다고 새 shot/생성 작업을 자동 생성하지 않는다.

## 10. 시간과 동기

기존 시간/FPS/구간 계약을 재사용한다:
- 최종 구간은 `[start_s,end_s)`. 마지막 샘플 프레임은 `end_s-1/fps`다.
- shot-local = global − shot.start. 생성 로컬은 담당 global 구간의 시작과 앞 핸들을 포함해 계산한다.
- 배속/소스 사용 구간·편집 핸들·오디오 중첩은 기존 09 필드와 현재 시간 인계 절차를 따른다.
- 실제 음성이 없으면 발화 창은 **계획 추정**이다. 읽기만 했다고 실측/립싱크 성공으로 올리지 않는다.
- 영상 사건의 프레임 기준과 오디오 파일/샘플의 시간 정밀도를 혼동하지 않는다. 동기 anchor/offset은 실제 기준과 근거를 쓴다.

06의 기존 shot-local cue timeline과 09의 컷 표를 함께 사용한다. 중요한 사건에는 연결 speech/audio cue·VFX source locator를 같은 설명에 붙인다. 별도의 이벤트 전역 ID/프로젝트 enum을 새로 만들지 않는다. 동일 사건을 복사해 독립된 세 타임라인으로 편집하지 않는다.

시간이 모자라면 무엇을 희생할지 조용히 결정하지 않는다. 승인된 행동/발화·반응을 보존하는 분할/길이/문안 변경안을 기존 승인 경계로 반환한다. 5/10/20/30초 예시는 지원 가정이나 비례 압축 공식이 아니다.

## 11. 자원 분해와 준비도

대본/샷으로부터 다음을 **필요한 만큼** 도출한다:
- 인물: 고정 외형/음성, 의상·감정·손상·변형 상태, 필요한 표현/자세/접촉.
- 장소: establishing/reverse/lateral/평면적 공간 관계 등 기존 마스터 요구와 출입·장애물·주요 기능/광원·청취 공간.
- 도구/소품: hero prop vs 장식, 상대 크기/손잡이·가동부/기능, 소유·받침/전달·분리·파손 상태.
- 생물/탈것: 형태와 구별되는 관절/지지·가동·하중·행동/공격 범위.
- VFX/그래픽: 필요한 소스/레이어·매트·깊이/가림·문구/정확 아트워크.
- 오디오: 고정 보이스/실제 테이크·비언어음·BGM·SFX·Foley·앰비언스/룸톤.

각 자원의 이유는 원문/beat/shot에 연결한다. `asset_registry`, master/derivative 계보, `required_asset_versions`, panel pins와 기존 artifact dependency를 재사용한다. 권리/지원/미관측 면을 발명하지 않는다.

다음 세 가지는 **새 status enum이 아닌 별도 판정 질문**이다:
1. 설계 내용이 충분하고 일관적인가?
2. 이번 실행 범위가 실제로 필요로 하는 입력이 준비·검사됐는가?
3. 그 실제 실행/비용/공개가 승인됐는가?

FINAL 시각 생성은 기존 asset gate를 따른다. 텍스트 설계/정직한 preliminary는 실제 에셋이 없어도 진행할 수 있지만 미준비/미검증 범위를 숨기지 않는다. 해당 배치에 필요 없는 미래 파일을 먼저 만들도록 강제하지 않는다.

## 12. 음성·음향·VFX의 구체적 수락 기준

### 음성

고정 Voice Identity, 관계별 Speech Style, 대사별 Performance를 분리하고 같은 SSOT/version을 소비한다. 정확한 발화·화자·의도/서브텍스트·강조·숨/멈춤·속도/압력과 청자 반응을 각 행에서 찾을 수 있어야 한다. 성격 타입·긴 과거사를 TTS 지시문에 복사하지 않는다.

실제 보이스 선택/voice ID·모델·설정·청취는 별도 실제 기록이며 제안 음색을 실제 선정으로 바꾸지 않는다. 화면 밖 화자/비가시 입은 기존 lip-sync applicability 경계대로 판정한다. 가림을 이유로 무조건 정면 컷을 추가하지 않는다. 비언어음은 필요한 경우 별도 cue에 두고 임의 대사/내레이터를 만들지 않는다.

### 사운드

음악은 곡/장르 이름만 아니라 진입·유보·변화·종료와 기능을 정한다. 필요한 모티프·밀도·악기/리듬 관계·대사 우선순위를 기록한다. 무음/음악 제외 의도를 보존한다. 없는 실제 BPM/다운비트/구간·측정 게인을 발명하지 않는다.

효과/Foley/환경음에는 원인·대상·재질·거리·청점·지속/꼬리·반복과 영상 동기를 연결한다. 역샷마다 소리 좌우를 자동 반전하지 않는다. 실제 파일을 선택/조립하면 권리·청취·마스킹/명료도·소형/모노 출력 등 필요한 납품 검사를 별도로 한다. 웹툰 의성어는 소리 설계의 단서이지 실제 음원 근거가 아니다.

### VFX

효과를 원인/발동자→준비→진행→상호작용/충격→소멸/잔류와 환경/배우 반응으로 설명한다. 레이어·가림/깊이·발광/반사/그림자·블러가 필수 행동을 가리지 않게 한다. 실제 FX가 필요 없으면 그 이유를 쓰고 공간/조명 현상을 억지로 합성 FX로 바꾸지 않는다. 동적 검증은 실제 결과 재생이 필요하다.

## 13. 실제 프롬프트로 옮기기

기존 11 템플릿을 최종 인계의 소유자로 유지한다:
1. 현재 보드/입력 버전, 담당 scene/shot/panel과 시간 범위를 고정한다.
2. 첫/끝/중간 목표 이미지와 실제 입력 파일·역할·해시·현재 지원 슬롯을 구분한다.
3. VISUAL에는 구간별 대상/상태·행동/반응·카메라/조명·공개/보존을 구체적으로 쓴다.
4. AUDIO에는 같은 시간 basis의 정확 발화·화자·보이스 정체성/이번 연기·cue/침묵/원근을 쓴다. 실제 지원 경로의 네이티브 오디오인지 별도 트랙인지 구분한다.
5. 원문 설계의 각 필수 항목을 **실제로 제출할 전체 본문/파라미터/첨부**의 해당 위치에 대응한다.
6. HARD_CONTROL / SOFT_PROMPT / UNSUPPORTED / UNVERIFIED를 구분한다. 모델 미선정이면 자연어 목표와 미확인 지원 상태로 남기고 가짜 payload를 만들지 않는다.
7. 누락/원문·화자 변경/중복 발화/조기 공개/소유·방향 역전/시간 충돌은 그 샷의 FIX다. 지원 부족을 이유로 요구를 조용히 삭제하지 않는다.

실제 SSOT 내용이 요청에 들어갔는지 확인해야 한다. 경로나 ID만 적힌 인계, FLF 두 장 또는 긴 줄거리 프롬프트로 중간 연출을 통제했다고 주장하지 않는다. 원테이크/샷 수/실행자·비용 변경은 기존 권한을 따른다.

## 14. 통합 출력 예시 — 새로 만든 비정본 텍스트 예시

**제공 작품의 인물·대사·세계·패널을 사용하지 않은 가상 8초 구간.** 아래 ID/초 수/연기/디자인은 설명을 위한 제안이다. 실제 프로젝트·미디어·보이스·능력/모델 검증·승인이 아니다. 전체 작품/SSOT 0–33을 대신하는 완성 패키지도 아니다.

### 씬의 기반

- 설정: 산지 신호소의 예비등은 정전 때 수동 레버를 누르고 있는 동안만 켜진다. 이 규칙은 제안된 허구 설정이다.
- 인물: CH01은 고장 원인을 먼저 확인하려는 숙련 기사, CH02는 레버를 잡고 있지만 손을 놓고 대피하려는 동료. 인물의 기능을 나열하는 데 그치지 않고 아래 행동으로 드러낸다.
- 목적: 관객과 CH02가 '레버를 놓으면 어두워진다'는 관계를 이해하고, CH02가 CH01의 경고를 받아 지지 동작을 유지한다.
- 공간/소유: CH02의 **왼손**이 레버를 누름. CH01은 그 손과 표시등을 볼 수 있는 쪽에 있다. 아래 구간에서 레버의 소유/손은 바뀌지 않는다.
- 고정 보이스 제안: CH01은 중간 음역, 건조하고 또렷한 자음, 짧게 닫는 문장 끝. 위험 시 속도/압력은 달라도 이 앵커를 유지한다. 실제 voice ID 미선정.
- BGM: 이 구간은 미사용 제안. 레버/릴레이와 짧은 경고가 사건을 전달하도록 환경음을 유지한다. 다른 씬의 음악 사용까지 금지하는 규칙은 아니다.

### SH02 확대 보기

- **첫 프레임(local 0 / global 2):** CH01 MCU, 몸은 CH02 쪽, 눈은 레버 방향. 입은 닫힘. CH02/레버는 화면 밖이지만 직전 위치·왼손 점유를 유지한다. 예비등은 계속 켜져 있음.
- **카메라:** 고정 MCU. 정보를 이미 본 관객에게 CH01의 인지와 경고를 읽히기 위한 거리. 숫자 렌즈/3D 경로는 설계하지 않았으며 공간 검증 완료 주장 없음.
- **local [0,0.25):** 레버 쪽에서 동료의 얼굴 쪽으로 눈/고개가 소폭 이동. 발화 전 짧은 들숨 의도.
- **local [0.25,1.0):** SP01 정확 원문 '놓지 마.' CH01만 발화. 의도는 동료의 손을 유지시키는 경고, 서브텍스트는 확인할 시간 확보. '놓지'에 짧은 강세, 중간 쉼 없음, 낮은 호흡량·단호한 압력. 제안된 0.75초 창이며 실제 음성으로 실측/적합성 검토 필요.
- **local [1.0,2.0):** 입을 닫고 동료의 응답 행동을 기다림. 시선은 동료 쪽에 남음. CH02가 같은 대사를 따라 말하거나 경고를 반복하지 않음.
- **끝 프레임(local 47/24 / global 95/24):** CH01 입 닫힘, 시선 유지, CH02의 다음 손 동작을 받을 연결. 예비등/배경은 직전과 같은 상태.
- **음성/립싱크:** 위 고정 Voice Identity+이번 Performance를 함께 소비. 화면상 입이 보이도록 계획했으므로 가시 구간 립싱크는 적용 대상. 실제 음성이 없어 결과 판정은 미검증.
- **음향:** AU01이 컷을 가로질러 연속. 샷에 필요한 호흡은 SP01 실제 테이크에서 보존/확인. 음악/새 충격음/내레이션은 없음.
- **VFX:** 독립 합성 효과 미사용. 예비등은 실제 장면 광원/룩의 상태이며 FX 발동을 새로 넣지 않음.
- **필요 자원:** CH01 신원·표정/의상 상태, CH02와 손/레버 점유의 연속성 기준, 신호소 reverse/MCU 배경과 광원, 레버 외형·가동부·재질, CH01 실제 보이스/테이크와 룸톤. 파일/해시/voice ID는 아직 없음.
- **첫 이미지 프롬프트 목표:** 위 MCU·닫힌 입·레버 방향의 시선과 점등 상태. 실제 실행 때 승인된 인물/장소/의상 내용 및 입력 역할을 확장해 넣음. 이 설명만으로 실제 이미지가 있다고 하지 않음.
- **끝 이미지 프롬프트 목표:** 같은 정체성/구도/조명, 동료 방향의 시선과 닫힌 입/정착. 중간 경고를 첫끝 이미지 밖의 시간 설계에서 별도로 보존.

**모델 중립 요청문 예시(실제 공급자 payload 아님):**

```text
SOURCE: noncanonical example, SH02; global [2,4), shot-local [0,2).
VISUAL:
[0,0.25) Fixed MCU of CH01. Begin with lips closed and gaze toward
  the offscreen lever; shift gaze toward CH02. Preserve location,
  clothing, light and the offscreen CH02-left-hand/lever relationship.
[0.25,1.0) CH01 delivers SP01. Make the warning readable in the eyes
  and restrained facial tension; do not add a new camera move.
[1.0,2.0) Close the mouth and hold the gaze toward CH02, waiting for
  the response. Keep the emergency lamp on. No repeated line.
AUDIO (design requirement, actual route unselected):
SP01, CH01 only, local [0.25,1.0): "놓지 마."
Voice identity: mid-register, dry tone, clear consonants, short sentence ending.
Performance: stop the partner from releasing the lever; brief emphasis on
  "놓지", firm pressure, no internal pause; preserve the voice identity.
Continue AU01 room tone. No music, narrator or second speaker.
CONTROL: natural-language intentions only; actual endpoint/audio support
  unverified. No unsupported API parameters or voice ID asserted.
```

**역대조:** SP01 원문/화자·창, 시선 변화, 입 닫힘/정착, 연속 룸톤, 레버 점유·등 상태, 고정 카메라가 실제 요청의 어느 문장에 남았는지 찾을 수 있다. 실제 인물 SSOT가 없는 예시를 실행 준비 완료로 판정하지 않는다. 실제 모델이 이 내부 타이밍을 보장한다는 뜻도 아니다.

## 15. 완료 판정과 수정

다음은 **기존 QA/approval 체계 안에서 구분해 보고할 질문**이며 새 승인 원장이 아니다.

| 판정 층 | 충분한 근거 | 이것만으로 충분하지 않은 것 |
|---|---|---|
| 구조/참조 | 기존 validator의 실제 결과, 현재 ID/버전/시간/파일 연결 | 문서가 길거나 항목이 존재함 |
| 설계 내용 | 입력/행동/시간/상태·오디오/효과와 다음 연결의 명시적 대조 | 형용사·자체 점수·'자연스럽게' |
| 실행 준비 | 해당 범위의 실제 필수 입력·지원/권리·기존 asset gate와 승인 사실 | 계획 ID·파일 경로 문자열·목표 이미지 |
| 실제 결과 | 실제 clean 이미지/재생/청취·필수 구간의 비교 기록 | 프롬프트·성공 응답·몇 장의 정지 샘플 |
| 사용자 수락 | 해당 버전에 대한 실제 사용자/위임 승인 | 구조 PASS·검토자 추천·응답 없음 |

### 제작용 설계의 차단 사유

- 필수 사건/인물/소품/음향의 누락 또는 상충.
- 첫끝에는 설명됐지만 필수 중간 행동/반응/공개가 사라짐.
- 세계 규칙·인물의 판단과 다른 행동/대사를 근거 없이 추가.
- 해당 단계에 필요한 시간·화자·대사·고정 보이스/연기·컷 연결이 미해결.
- 필요한 기술 입력을 실제로 읽지 않았거나 다른 버전을 사용.
- 중요한 요구가 최종 요청문에서 삭제/중복/역전되거나 지원 상태를 허위 표시.
- 검수하지 않은 결과를 pass 또는 generated/verified/approved로 승격.

사유 있는 N/A·피치의 후속 결정·의도된 정지/반복·오프스크린 발화·원테이크 자체는 실패가 아니다. 미검증을 해결된 것으로 쓰는 것이 실패다. 기존 KEEP/FIX/미검증의 indexed 수정표에 최소 수정·보존할 것·담당/추가 입력·실제 근거/재검수 범위를 기록한다.

- 장소/동선/소품 기능 변경: 관련 공간·차폐/접촉·카메라·연속성/프롬프트 재검토.
- 효과/음향 변경: 관련 동기·환경/배우 반응·구간/믹스·검수 재검토.
- 기존 `dependencies/dependency_versions`, `required_asset_versions`, master/derivative·panel pins와 stale 전파를 재사용한다. 누락된 의존성을 '자동 선택적 갱신'이라고 표현하지 않는다.

## 17. 검증 설계와 도입 게이트

### 대표 과제 — 최소 8유형

| 유형 | 보존해야 할 것 / 잡아낼 실패 |
|---|---|
| 관계가 바뀌는 대화 | 같은 형용사/대사 교대만 남는 결과, 원인 없는 청자 반응 |
| 무언 행동·소품 전달 | 손/점유·접촉 단계·앞끝/뒤시작, 같은 첫끝 속의 중간 사건 누락 |
| 정적/원테이크 | 무조건 새 컷/움직임/반응 할당하는 과잉 설계 |
| 비인간·변형/능력/VFX | 외형과 가동/접촉의 혼동, 능력 대가·효과 잔류 소실 |
| 다중 인물·오프스크린 공개 | 잘못된 화자/목격자, 정보 조기 공개, 음향 방향 오류 |
| 음성 중심·길이 변경 | 고정 보이스 드리프트, 발화/숨/반응 삭제, 이중 생성·시간 basis 혼동 |
| 음악/효과 중심 | 실제 오디오 없는 측정 주장, 컷만 늘린 리듬, 목적 없는 효과 |
| 제품·설명/무인·좁은 요청 | 불필요한 세계/인물/대사·전체 패키지 강제, 사실/원문 훼손 |

### 방법

1. 같은 잠긴 입력·모델/설정·도구 권한으로 현재판과 후보판을 비교한다. 비용/실행 승인 없는 상태에서 실제 모델 실행을 자동 시작하지 않는다.
2. 첫 비교는 텍스트 설계로 한정한다. 원문/SSOT·정확 ID/버전·시간·필수 사건/오디오의 보존을 실제 산출물에서 대조한다.
3. 부실 반례에는 일반 형용사만 남긴 샷, stale 보이스 핀, 첫끝만 있는 전달/복귀, 불일치 손/의상, 발화 창 부족, 조기 공개, 사라진 큐, 미지원 제어 단정 등을 포함한다.
4. 긍정 대조에는 의도적 침묵·동일 상태 hold·화면 밖 발화·동시 반응·무인 작품을 포함해 거짓 차단을 확인한다.
5. 평가자는 항목마다 입력 locator·출력 위치·관찰/불일치·영향·판단 이유를 기록한다. 작품 전체의 질을 단일 점수로 합격시키지 않는다.
6. 중요한 신규 결함/잠긴 원문 변경/권한 확장/허위 실행 증거가 있으면 후보를 기본값으로 승격하지 않는다. 평가 수와 실제 검사 범위·독립 여부를 보고한다.
7. 실제 이미지/음성/영상 검증은 승인된 별도 단계다. 텍스트 설계 평가를 연기·음향·영상 품질 개선 검증으로 확대하지 않는다.

**도입 순서 제안:** 테스트 과제/기준 고정 → 후보 지침·템플릿 → 구조 회귀+동일 입력 행동 비교 → 제한된 제안 사용 → 실제 미디어 평가가 허가된 경우 추가 → 수락된 범위의 기본 적용. 후보/실패 기록은 지우지 않는다.
