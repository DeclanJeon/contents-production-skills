# Suno 음악 스킬 설계

- 날짜: 2026-11-21
- 상태: 구현 승인. 영상 총괄의 조건부 라우팅 및 텍스트 프리프로덕션 핸드오프 포함.

## 의도와 범위

장면 브리프나 곡 아이디어를 Suno에 복사할 수 있는 필드별 입력으로 바꾼다. 프롬프트만 요청한 사용자도 끝까지 지원한다. 실행을 요청한 사용자는 별도 크레딧 승인을 거쳐서만 Suno에서 생성한다. 기존 영상 제작 오너, 일반 영상의 인앱 음향 기본값, 배포·게시 경로는 바꾸지 않는다. 음성 합성, 보이스 복제, 특정 곡 재현, 상업 이용 권리 확정은 이번 범위 밖이다.

## 검토한 접근

| 접근 | 장점과 비용 | 결정 |
|---|---|---|
| 독립 `suno-music` 스킬 + 조건부 영상 연결 | 단독 음악 요청에서도 발견되고 웹·MCP 차이를 한곳에서 관리한다. 패키지 등록과 라우팅 검증이 필요하다. | 채택 |
| 기존 편집·음향 가이드에 템플릿 추가 | 수정은 작지만 영상 없는 음악 요청에서 발견하기 어렵고 실행 규칙이 기존 음향 가이드에 섞인다. | 미채택 |

## 호출과 소유권

- Suno 프롬프트/입력 검토/음악 생성의 단독 요청은 `suno-music/SKILL.md`를 직접 사용한다. 타 제공자가 지정된 요청을 가로채지 않는다.
- 영상 제작은 `creative-production`이 계속 소유한다. Suno가 명시되거나 별도 트랙을 요청한 뒤 Suno가 선택됐을 때만 기존 [조건부 오디오 경로](../../../creative-production/references/production-routing-optional.md)에서 이 스킬을 연다. 제공자를 선택하지 않은 별도 음악 요청을 자동으로 Suno에 제출하지 않는다. 단순히 영상에 BGM이 필요하면 기존 인앱 음향 기본값을 유지한다.
- `manifest.json`에 스킬과 선택적 Suno 런타임을 등록하고, 사용자 문서에서 찾을 수 있게 한다. 새 필수 설치, 별도 상태 장부, 커스텀 API 클라이언트는 만들지 않는다.

## 입력 → 출력

사용처, 보컬 여부, 목표 길이, 장면 또는 노래의 감정 변화, 지켜야 할 가사·악기·제외 요소를 기존 브리프에서 먼저 가져온다. 템포나 편성처럼 되돌리기 쉬운 빈칸은 제안으로 표시한다. 보컬 유무처럼 경로를 바꾸고 신뢰 있게 추론할 수 없는 항목만 질문한다.

| 경로 | 프롬프트 분기 | 청취 기준 |
|---|---|---|
| 내레이션용 BGM | 무보컬 `Instrumental`; 역할 → 정서 변화 → 장르·템포 → 중심 악기 → 밀도·전개·엔딩 순으로 Style을 작성한다. 필요시 Exclude를 별도로 둔다. | 대사와 겹쳐도 알아들을 수 있는지, 허밍 등 원치 않는 보컬이 없는지, 편집 가능한 끝인지 |
| 보컬곡 | 아이디어 탐색은 Simple `description`; 확정 가사는 Custom `lyrics`, 보컬 표현과 편곡은 `style`. 섹션 표기는 힌트로 취급한다. | 가사·발음·후렴 전달 여부와 요청한 보컬 표현 |
| 짧은 스팅·루프 | Suno Sounds를 우선 검토한다. 스팅은 시작-강조-잔향, 루프는 반복 질감과 이음새를 기술한다. 실제 도구 스키마를 읽어 길이와 반복 입력의 지원 여부를 확인한다. | 컷에 맞는 타격점과 꼬리, 또는 반복 재생이 자연스러운지 |

반환물은 **선택 경로와 모드, 복사 가능한 필드별 입력, 편집 메모, 청취 체크**다. 예를 들어 미스터리 BGM은 “낮은 신스 펄스와 드문 피아노, 대사 아래 얇은 편성, 불안이 쌓인 뒤 짧게 끝남”을 생성 지시로, “반전 컷에 마지막 악센트를 맞춤”은 편집 메모로 분리한다. BPM·섹션 진입·편집 싱크를 프롬프트로 보장하지 않는다. 수정은 보존할 요소를 고정하고 한 번에 하나의 청취 문제를 해결한다.

## 실행 경계

- 웹의 Simple/Custom/Instrumental/Exclude와 MCP 필드 매핑·제약은 스킬의 별도 제공자 참조에 둔다. 실제 호출 전 라이브 스키마와 계정에서 허용되는 기능을 확인한다. Simple `description`과 Custom `style`/`negative_style`을 섞지 않고, 무보컬 요청에 `voice_id`를 쓰지 않는다. `duration_strict`는 정확한 길이나 자연스러운 엔딩의 보장이 아니다.
- 프롬프트 요청에는 생성 호출을 하지 않는다. 실행 요청에는 제공자·예상 차감·호출/결과 수·외부 전송 자료를 먼저 제시하고 해당 범위 승인을 받는다. 도구나 권한이 없으면 준비된 입력과 막힌 이유를 반환한다. 무단 재시도·대체 제공자·게시를 하지 않는다.
- 생성 요청 접수, 재생 가능, 실제 청취를 구분한다. 들을 수 없다면 미청취로 기록한다. 생성 승인과 게시 권한을 동일시하지 않는다.

## 구현 후 확인 기준

- 세 가지 대표 브리프가 올바른 필드와 편집 메모를 낸다. 단독 Suno 요청은 발견되고 일반 영상 BGM은 기존 기본값을 유지한다.
- 확정 가사 요청에서 Simple과 Custom 필드를 혼합하지 않는다. 무보컬과 `voice_id` 충돌, 짧은 루프의 곡 생성 오라우팅, 승인 없는 제출을 각각 실패 사례로 검증한다.
- 기존 스킬 도달성·라우팅·설치 동기화 회귀 검사를 실행한다. 스킬 행동 검증은 독립 시나리오의 작성 전/후 결과를 구분한다. 실제 유료 생성과 결과 청취는 별도 승인 없이는 검증 범위에 포함하지 않는다.
