# 주제 기반 프리프로덕션 에셋과 영상 제작 승인 설계

## 목적과 승인된 범위

주제만 받은 영상 요청을 사용자 지정 프로젝트 폴더 안의 검토 가능한 프리프로덕션 패키지로 만들고, 사용자의 별도 영상 제작 승인 전에는 영상 생성·렌더·편집 출력을 실행하지 않는다.

기존 `creative-production` 조정자와 `video-production-assets`를 확장한다. 새 조정자, 프로젝트 데이터베이스, 두 번째 manifest를 만들지 않는다. 이미지는 `codex-imagen` 스킬에 인계한다. 특정 소재 출처, 플랫폼, 장르, 길이, 화면비, 이진 판단 모델은 공통 기본값으로 고정하지 않는다.

## 책임과 변경 표면

- 로컬 `creative-production/SKILL.md`: 주제→프리프로덕션 우선 분기, 저장 경로 확인, 검토/실행 승인 경계. 해당 분기는 승인 전 대표 영상 샷 생성 규칙보다 우선한다. 기존 UI·3D·단일 이미지 요청은 그대로 유지한다.
- 공개 패키지 `video-production-assets/SKILL.md`: 전체 영상 패키지의 폴더와 검토 절차에 대한 명확한 참조. 단일 텍스트 산출물은 요청 범위를 유지한다.
- 새 `video-production-assets/references/preproduction-review.md`: 폴더 계약, 순서, 이미지 인계, 검수, 사용자 승인 처리의 권위 있는 절차. 로컬 조정자는 이 문서를 참조해 중복 계약을 만들지 않는다.
- 기존 `references/contract.md`: 기존 ID·상태·dependency_versions·approval 계약으로 검토 패키지와 승인 근거를 연결하는 설명만 보완한다.
- 공개 `integrations/skill-routing.md`와 `README.md`: 주제 기반 흐름, 외부 이미지 스킬 의존성, 정지 이미지와 실제 영상의 차이, 승인 전 정지 지점을 설명한다.
- 설치된 `video-production-assets`는 공개 패키지 변경과 동기화한다. 로컬 조정자나 실제 사용자의 프로젝트는 공개 저장소에 포함하지 않는다.

## 폴더 선택과 파일 계약

1. 전체 영상 프로젝트의 파일 생성 또는 미디어 요청 전에 정확한 프로젝트 디렉터리를 사용자에게 묻는다. 사용자가 이미 정확한 프로젝트 경로를 지정했으면 다시 묻지 않는다.
2. 사용자가 루트만 고르면 주제 기반의 하위 폴더 경로를 제안해 확인받는다. 이전 프로젝트의 루트를 현재 요청에 자동 적용하지 않는다. 루트를 기억하는 기능은 별도 범위다.
3. 기존 프로젝트의 계속 작업이 명시된 경우 기존 원장을 읽고 재개한다. 새 프로젝트 경로에 파일이 있으면 다른 하위 폴더 또는 명시적인 재개 선택을 받는다. 기존 파일을 덮어쓰거나 임의 삭제하지 않는다.
4. 모든 최종 프리프로덕션 파일은 하나의 프로젝트 루트 아래에 저장한다. 생성 도구에도 루트 내부의 명시적 출력 경로를 전달한다. 에셋 원장의 경로는 프로젝트 루트 기준 상대 경로다.
5. 기존 스킬이 없는 실행 환경에서는 스킬 파일을 실제 설치 위치에서 읽는다. `codex-imagen`이 없거나 인증/쓰기 권한이 없으면 미실행 조건을 보고하고 다른 이미지 공급자로 몰래 전환하지 않는다.

표준 구성은 다음과 같다. 필요한 파일만 생성하고, 빈 산출물을 완료로 표시하지 않는다.

```text
<project-root>/
  project.json
  review.md
  brief.md
  references/        # 필요한 원문 링크, 관찰, 출처와 이용범위 기록
  script/            # 적용 가능한 각본·비트·연기 메모
  visual/            # 비주얼 바이블·연속성 결정
  shots/             # 샷 리스트·스토리보드 매핑·필요한 카메라 명세
  images/            # 실제 생성된 검토 이미지
  prompts/           # 재현 가능한 이미지 프롬프트와 도구 호출 설정
  edit/              # 편집·사운드·타이밍 계획; 실제 영상 파일 아님
  qa/                # 실제 검사 결과와 미검증 항목
```

브리프와 시각 산출물의 ID·버전은 `project.json`으로 연결한다. 표·문서는 원장을 참조하는 읽기용 산출물이며 독립 상태 시스템이 아니다. 주제만 줬다고 특정 장르나 서사 모듈을 강제하지 않는다.

## 진행 순서

1. 주제, 사용자가 제공한 형식·길이·제약·검토 조건을 추출하고 폴더를 확인한다. 중요한 창작 방향은 기존 협업 절차로 선택하거나 사용자가 명시적으로 위임한 범위에서 제안으로 기록한다.
2. 요청에 필요한 근거·참고만 조사한다. 조사 경로와 판단 도구는 프로젝트 요구사항으로 결정한다. 제3자 미디어는 출처가 있다는 이유만으로 재사용 가능한 에셋으로 등록하지 않는다.
3. 적용 가능한 브리프·비트/각본·시각 기준·샷/블로킹·편집/사운드 계획을 채운다. 모든 샷의 합계가 목표 타임라인과 일치해야 한다.
4. 이미지가 필요한 패키지는 `codex-imagen`을 읽고 로컬 인증 스모크를 실행한다. 이미지 출력 수·재시도 범위·출력 경로를 명시하고, 적용되는 사용량/과금 승인을 지킨다. 인증 스모크는 생성 비용을 증명하지 않는다. 비용/권한 문제가 해결되지 않으면 생성 전에 멈춘다.
5. 첫 대표 정지 이미지로 방향을 확인하거나, 사용자가 창작 방향을 위임한 경우 요청된 이미지 세트를 생성한다. 참조 이미지는 명시적으로 전달하고 실제 출력 파일·프롬프트·사용 샷·버전을 원장에 연결한다. 모델이 반환하지 않은 seed나 비용을 만들어내지 않는다.
6. 생성 이미지를 실제로 열어 샷의 동작·인물/소품·구도·연속성을 점검한다. 구조/시간/파일/해시는 코드로 확인한다. 확률적 판단 도구를 요청받았다면 판단 결과와 검사 범위를 별도로 기록한다.
7. `review.md`와 채팅으로 정확한 폴더, 브리프·스토리보드·이미지의 경로/미리보기, 검사 결과, 가정, 미정 사항을 보고하고 사용자 검토를 기다린다. 이미지 파일을 생성하지 않았으면 텍스트 스토리보드와 구분한다.
8. 프리프로덕션 수락은 해당 에셋 버전에 대한 수락만 의미한다. 사용자가 영상 제작으로 진행하라고 명시한 뒤에만 모델 후보·실시간 기능·스키마·가격을 조사해 실행 계획을 제안한다.
9. 실제 영상 실행은 샷 범위·모델/endpoint·재시도/시간/비용 상한에 대한 명시적 사용자 승인 뒤에만 선택된 실행자에게 인계한다. 게시 권한은 별도다.

## 승인과 상태

`project.json`의 기존 artifact 상태와 `approval={by, at, evidence}`, `dependencies`, `dependency_versions`를 사용한다. `review.md`는 실제 파일/버전 목록을 갖는 검토 패키지 artifact로 등록하고 관련 입력 버전에 연결한다. 사용자가 수락한 경우에만 해당 artifact를 approved로 변경하고 원문 승인 근거를 남긴다.

- 생성된 이미지는 generated 또는 실제 검사 후 verified일 수 있지만, 이는 사용자 수락과 다르다.
- 사용자 침묵, 모델의 true/false, 검사 성공, 이미지 승인, 프리프로덕션 생성 요청은 영상 제작 승인이 아니다.
- 모델과 비용이 미정인 프리프로덕션은 유효한 검토 패키지다. 이 상태에서 실행자의 기본 모델을 호출하지 않는다.
- 영상 실행 계획은 승인된 프리프로덕션 입력 버전을 명시한다. 실제 사용자 실행 승인을 기존 approval 구조에 기록한다.
- 에셋 내용이나 버전이 바뀌면 종속 검토/실행 계획을 stale로 표시한다. 원문 승인은 이력으로 유지하되 수정 버전에 재사용하지 않는다. 영향을 받는 부분만 다시 검토받는다.
- 새 개별 영상 요청에 현재/이전 프로젝트의 승인이나 과금 권한을 자동 승계하지 않는다.

## 범위와 한계

공통 스킬에 특정 사이트의 유머 영상 조사, 고정 길이/화면비, 특정 이진 모델, 사용자 홈 경로를 넣지 않는다. 이런 조건과 해당 조건의 실행 차단 사항은 실제 프로젝트 요구사항으로만 기록한다.

이 변경은 프리프로덕션 실행 절차의 문서/스킬 변경이다. 별도의 자동 데몬, 새 SDK 의존성, 영상 엔진, 승인 판정 모델을 만들지 않는다. 기존 validator는 구조와 파일 계약 검사에 사용한다. 사람의 재미 판단, 권리 확인, 실제 영상 품질, 사용자 승인 진위를 validator 통과로 대체하지 않는다.

## 검증과 수락 기준

- 주제만 준 새 영상 요청은 파일 생성 전에 정확한 폴더를 묻는다. 이미 지정한 경로는 재질문하지 않는다.
- 루트 선택, 기존 경로 충돌, 명시적 재개, 단일 텍스트 요청, 이미지 인증 미준비, 모델 미정 분기를 각각 스모크로 확인한다.
- 실제 `codex-imagen --smoke`를 사용해 이미지 실행 준비를 확인한다. 첫 실제 패키지에서는 출력 경로, 실제 이미지 열기, 원장, 타임라인 검사까지 증거로 남긴다.
- 프리프로덕션만 요청한 경로에서 기존 대표 영상 샷·시험 렌더를 실행하지 않는다.
- 프리프로덕션 승인만 있는 경우 영상 생성은 실행하지 않는다. 사용자 승인 문자열을 확률적 모델로 판정하지 않는다.
- 검토한 버전이 바뀌면 종속 승인 재검토가 필요한 상태가 된다.
- 기존 생산/카메라 검사 스위트는 통과한다. 프리프로덕션에는 plan 검사를 적용하고 최종 영상 delivery 검사를 통과했다고 주장하지 않는다.
- 공개 패키지 변경과 설치된 제작 에셋 스킬이 일치한다. 실제 프로젝트 폴더, 자격 증명, 개인 저장 경로를 공개 저장소에 넣지 않는다.
