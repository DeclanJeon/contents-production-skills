# 씬·컷·연출 제작 설계 업그레이드 — 현황 감사와 권고

작성: 2026-11-14. **조사/설계 방향 제안이며 승인된 설계서·구현 계획·스킬 변경이 아니다.** 스킬 파일, 검증기, 기존 제작 프로젝트와 제공 원본은 수정하지 않았다. 새로운 이미지/영상/음성 생성, 외부 업로드, 유료 호출, 웹 검색은 수행하지 않았다. 원본 작품의 줄거리·캐릭터·디자인·대사를 새 작업에 복제하지 않고 일반 제작 메커니즘만 학습 대상으로 삼는다.

## 1. 요청을 어떻게 해석했는가

원하는 결과는 긴 시놉이나 필드가 많은 콘티가 아니다. **이야기 세계·인물·대본에서 출발해, 각 씬과 샷의 시작 상태→시간에 따른 사건/연기→끝 상태, 필요한 모든 자원, 실제 생성/편집 입력, 검수까지 끊기지 않는 제작 설계**다. 다른 실행자가 추측으로 빈칸을 메우지 않고 만들 수 있어야 한다.

세계관/캐릭터를 모든 영상에 강제하거나, 모든 샷에 카메라 이동·VFX·음악·새 컷을 추가하는 것은 목표가 아니다. 서사형 전체 제작에는 필요한 깊이를 기본 적용하되, 제품/교육/무언/정적/원테이크 등의 실제 형식과 승인된 범위를 보존한다.

### 웹툰과 영상의 증거 차이

- JPG 경계는 저장/분할 경계다. 한 이미지에 여러 패널이 있거나 패널이 파일 경계를 넘어간다. **JPG 수 ≠ 패널 수 ≠ 씬 수 ≠ 영상 샷 수.**
- 정지 패널에서 구도·가시 동작·시선·공개 순서·색/형태 대비·문자화된 발화/의성어를 관찰할 수 있다.
- 실제 초/프레임 단위 길이, 카메라 이동·가속도, 물리 렌즈값, 실제 목소리·BGM·SFX·믹스는 이 JPG에서 측정할 수 없다.
- 여백은 독서 간격의 단서이지 정해진 영상 홀드 시간이 아니다. 속도선은 운동 표현이지 특정 카메라 무빙의 증거가 아니다.
- 영상화용 시간/카메라/음향 선택은 **새 작품의 설계 제안**이며 원작 관찰값이 아니다. 파일 열람 권한과 에셋 재사용/생성기 업로드/음원·보이스 권리는 별개다.

## 3. 현재 취약점의 정확한 진단

**이미 있는 기능을 없는 것으로 판단하면 안 된다.** 다음은 이미 명시돼 있다:
- 샷별 첫/끝 상태와 시작/정점/끝 패널, 프레임/FPS 기준.
- 씬별 의도·관객 지식/감정·공간 관계·인접 씬 비교.
- 캐릭터 SSOT 0–33, 페르소나의 행동 규칙, 고정 음성/말투/대사별 연기 분리.
- 대사의 화자·청자 반응·J/L-cut·숨/강세/멈춤, 실제 음성 청취와 립싱크.
- 사운드 큐의 시간/소스/게인/페이드/싱크/권리, VFX 레이어와 동작 상태.
- global→shot-local→generation-local 시간 변환, 실제 최종 요청문 대응.

따라서 핵심은 **문서 존재 → 충분한 내용 작성 → 오너 간 소비 → 실제 입력 보존 → 결과 검증** 사이의 단절 위험이다. 이번 감사는 실제 실패한 사용자 제작 프로젝트를 받은 것이 아니므로, 모든 기존 산출물이 부실하다거나 특정 오너가 항상 지침을 무시한다고 결론내리지 않는다.

### 이 표본에 근거해 제안할 수 있는 오디오 설계(원작 청취 아님)

- 인지/관계 전환: 발화 중단, 들숨/멈춤, 기존 앰비언스의 유지/변화, 음악의 유보/진입을 선택지로 비교.
- 큰 효과: 예비/에너지 축적→이동→접촉 transient→저역 body→잔향/잔해의 시간·공간 관계를 새 브리프에 맞춰 설계.
- 능력 대가: 호흡/발화의 변화와 손상·피로의 잔류를 같은 상태로 묶되 새 목소리로 바꾸지 않음.
- 정보 공개: 오프스크린 소리의 출처·청취 주체·화면 공개 시점을 따로 정함.

모든 장면에 저역/라이저/침묵을 넣으라는 규칙이 아니다. 원본 BGM, 보이스, 실제 효과음이나 특정 Hz/BPM/초 수는 확인하지 않았다. 후속 오디오 학습에는 실제 들을 수 있는 허가된 영상/음향 참조가 필요하다.

### P1 — 구체적인 전문 설계의 깊이

6. **전체 에셋 분해와 샷별 준비 상태**
   - 캐릭터뿐 아니라 장소/공간뷰·세트 구조, hero prop/장식, 의상·손/발·접촉 가능한 형태, 생물/탈것, 배경/환경, 상태 파생물(젖음/손상/노화/변형), VFX 레이어, 음성·음악·Foley·SFX·룸톤, 문구/그래픽을 대본과 샷에서 도출.
   - 각 필요 항목의 정체성/스케일/상호작용·부모 버전·사용 샷·준비 상태·권리/입력 지원을 연결. 외형 이미지 한 장으로 관절/접촉/기능 검증을 주장하지 않음.
   - 설계 완결, 해당 배치의 필수 에셋 준비, 실제 실행 승인을 별개로 판정. 미래 모든 에셋을 미리 유료 생성하지 않는다.

7. **장소의 드라마·동선·가림·청취 공간**
   - 입출구·장애물·작동부·상대 크기·기준 앵커·축과 소리의 원근을 같은 장소 상태에 연결. 네 공간뷰 규칙이 이미 있으므로 새 규칙 복사보다 실제 씬 소비 여부를 검사.
   - 실제 장면별 3D 배치/경로/접촉 검증이 필요한 범위만 기존 Blender 오너가 구현·검사. 단순 서사 카메라 계획은 실행을 강제하지 않음.

8. **샷 내부 연기와 미세 행동**
   - 감정 형용사를 자극, 인지, 억제/실패, 시선/자세/손·발/호흡 변화, 선택, 정착으로 바꾼다. 필요한 경우에만 반응 지연·중단·상충하는 겉/속 행동을 구간화.
   - 첫끝 두 장이 같아도 중간 사건이 필요한 샷이 있고, 아무 변화 없는 의도적 hold도 있다. 무조건 변화/컷 수를 늘리지 않음.

9. **장면 목적에서 도출하는 카메라·컷 문법**
   - 기술명/렌즈부터 고르지 않고 누구의 정보·정서적 거리·공간 권력 관계를 언제 보여줄지 정함.
   - 정지/이동, 와이드/싱글/투샷/인서트, 초점/차폐/공개, 축 변경과 재정위, 속도/정착을 이유로 연결. 반복을 피하려고 무작위 다른 렌즈/앵글을 강요하지 않음.
   - 단일 그림의 원근에서 물리 mm·미터·카메라 궤적을 확정하지 않음.

10. **캐릭터 음성 세 층과 실제 입력의 결속**
    - 고정 Voice Identity, 관계별 Speech Style, 대사별 Performance를 모든 컷에서 같은 버전으로 소비.
    - 정확한 문구·화자·대상·의도/서브텍스트·강조/쉼/숨/속도와 실제 청자 반응을 연결. 말 없는 신음/들숨/울음/포효 등은 발화와 별도로 필요한 경우 설계.
    - 실제 voice ID/모델/샘플·권리·청취는 실행 기록. 제안 음색을 선정된 목소리로 쓰지 않으며, 타입명/긴 전기를 음성 프롬프트에 그대로 넣지 않음.

11. **씬별 음향 문법과 음악의 진행**
    - BGM 이름/장르뿐 아니라 진입·유보·전환·종료, 장면/인물 모티프, 템포/밀도·악기/대역의 기능(필요한 범위), 사건 싱크, 무음 선택을 설계.
    - SFX는 원인·대상·재질·거리·청점·지속·반복·꼬리를 연결. 충격/이동/잔해를 필요에 맞게 층화하고 대사 우선순위·ducking·잔향/공간 연속·모노/소형 스피커 가독성을 검사.
    - 실제 파일/박/템포/길이를 측정하기 전 제안값으로 유지. 웹툰 의성어를 원본 음원으로 취급하지 않음.

12. **VFX의 사건화와 환경 반응**
    - 효과의 원인/발동자, 준비→발동→상호작용→충격→소멸/잔류, 경로/차폐·발광·반사·접촉 그림자·카메라/깊이·후속 손상을 설계.
    - 효과의 규모를 사람/소품/공간 기준과 연결. 캐릭터 연기/동선·음향과 별개 장식 레이어로 두지 않음.
    - 시뮬레이션의 실제 동작은 생성/합성 결과 검사 전 미검증.

13. **편집 커버리지·관객 지식·공개 관리**
    - 행동/반응/증거 인서트와 컷 이유, 앞 끝→뒤 시작의 동작 phase·시선/위치/소유, J/L-cut/침묵/내레이션 관점, 미리 보여주면 안 되는 정보를 검산.
    - 다중 인물 장면에서 발화자 수만큼 기계적으로 싱글/리버스를 만들지 않고 선택된 원테이크/동시 반응을 보존.
    - 독서용 패널을 영상으로 1:1 복사하지 말고, 가시 사건의 묶음과 새 타이밍을 설계.

14. **모델 중립 설계 → 실제 공급자 요청문의 손실 검사**
    - 기존 11 인계에 인물·공간·소품·상태·음성·음향·VFX·타이밍의 실제 문장/입력 슬롯을 대응. 참조 파일을 첨부했거나 ID를 적었다고 소비한 것으로 보지 않음.
    - 시각/음향 의미 구획을 분리하되 지원하는 네이티브 오디오 경로에서는 같은 실제 요청에 함께 전달. 별도 TTS/편집 경로와 혼동하지 않음.
    - 실제 HARD_CONTROL, SOFT_PROMPT, UNSUPPORTED/UNVERIFIED를 표시. FLF 두 장과 긴 문장만으로 중간 행동/표정/컷 타이밍을 보장하지 않음.
    - 지원하지 못하는 요구를 삭제하지 않고 개별 샷/합성/결정적 렌더 대안을 승인 범위 안에서 비교.

15. **변경 영향과 완결된 인계**
    - 대사/음성 변경은 관련 타이밍·자막·립싱크/음향, 의상/상태 변경은 해당 샷·참조/프롬프트, 장소/동선 변경은 카메라·차폐·접촉으로 이어지는 실제 의존관계를 추적.
    - PDF·타임라인·에셋 목록·실제 제출문이 서로 다른 버전을 가리키지 않게 검산. 문서 렌더 가독성과 창작 완결성을 별도 검사.

## 6. 한 샷에서 반드시 함께 답해야 하는 질문

아래는 **수락 질문 묶음**이며 승인된 새 JSON 스키마나 또 다른 원장이 아니다. 기존 오너가 각 답을 어디서 제공할지 설계 단계에서 정한다.

1. 이 샷은 어떤 사건/정보/관계 변화를 위해 존재하는가?
2. 첫 프레임의 인물·소품·위치·시선·접촉·상태와 관객이 아는 것은 무엇인가?
3. 어떤 자극이 언제 누구에게 도달하며, 무엇이 언제 바뀌는가?
4. 필수 행동·반응·공개의 정점은 무엇이고 실제로 보이는가?
5. 끝 프레임은 무엇을 다음 샷에 넘기는가? 의도된 생략/불연속이면 왜인가?
6. 정확한 발화·화자·고정 보이스·대사별 연기·청자 반응은 무엇인가?
7. BGM/SFX/환경음/침묵은 무엇을 하며 시작/싱크/끝·청점·믹스 관계는 무엇인가?
8. 효과의 원인/층/정점/잔류와 장소/배우 반응은 무엇인가?
9. 왜 이 크기·시점·축·움직임·속도/정착·컷인가?
10. 실제 어떤 에셋/버전/입력 슬롯이 필요하며 준비됐는가?
11. 위 설계가 최종 제출문·파라미터·첨부에 어디에 들어갔는가?
12. 무엇으로 확인하고, 확인하지 못한 것은 무엇인가?

시간은 계획 추정과 실측, 첫끝 목표 이미지와 실제 파일/해시, 정지 이미지 읽힘과 영상 재생/청취를 각각 구분한다.

## 7. 도입 접근 비교 — 사용자 선택 전

### A. 기존 문서의 누락 설명/예시만 보충
빠르지만 이미 지침이 많은 현재 상태에서는 같은 누락이 재발할 가능성을 해결하지 못한다. 좁고 확인된 공백 수리에 적합.

### B. 기존 오너를 유지하고 씬/샷 통합 산출물·준비도·역대조·행동 평가를 연결 — 권고
02/03/캐릭터/06/09/11/12의 책임을 유지한다. 이야기 세계와 실제 행동의 연결을 보강하고, 기존 정본에서 한 샷의 완결된 제작 지시를 조회하도록 한다. 의미 검토와 기계 검사를 구분해 수락 기준을 시험한다. 문서의 중복은 줄이고 누락/충돌을 실제로 드러내는 방향이다.

### C. 별도의 대형 '감독 스킬'/새 제작 원장 신설
전문 역할은 선명해 보이지만 기존 총괄·스토리보드·카메라·음성/음향 책임과 중복되고, 서로 다른 버전의 설계를 만드는 위험이 크다. 현재 증거로는 새 총괄이나 새 원장이 필요하다는 근거가 없다.

**권고는 B**다. 다만 기존 필드만으로 충분히 표현되지 않는 확인된 요구가 있다면 별도의 호환성/마이그레이션 판단을 거쳐 최소 확장한다. '스키마 절대 불변'과 '필드 무한 추가' 중 어느 쪽도 미리 정답으로 삼지 않는다. 본 보고서는 승인된 설계서가 아니므로 여기서 스킬을 고치거나 실행하지 않는다.

## 8. 실제 업그레이드의 검증 설계 제안

- 서사/대사 장면, 무언 행동, 의도적 정지/원테이크, 비인간/변형 신체와 효과, 다중 인물/오프스크린 공개, 제품·설명형 등 서로 다른 대표 과제를 사용.
- 같은 잠긴 입력으로 현재판/후보판 결과를 비교. 위임된 창작 선택과 공급된 정본 보존을 구분하고 평가 조건을 고정.
- 형용사로 채운 샷, 서로 모순된 손/소유·의상, 중간 정점 누락, 같은 첫끝 속에 사라진 행동, 대사보다 짧은 샷, 잘못된 화자/반응, 사라진 음향 큐, 오래된 보이스 핀, 네이티브 음성/별도 TTS 중복, 지원되지 않는 제어 주장, 과도한 고정 샷 공식 등을 반례로 포함.
- 구조/시간/참조 lint는 결정적으로 검사 가능한 것만 검사. 연기/정보 공개/의미는 근거 위치와 판단 이유를 갖춘 별도 검토.
- 실제 이미지/음성/영상 없이 가능한 텍스트 설계 평가와, 승인된 실제 생성/재생/청취 평가를 분리. 전자를 후자 성공으로 보고하지 않음.
- 소수 표본·자체 평가만으로 '연출력 향상 검증'을 선언하지 않음. 실제 에이전트 비교/독립 검토·미디어 품질 평가는 이번 감사에서 수행하지 않았다.

## 9. 다음 승인 항목

먼저 A/B/C 중 구현 접근을 선택한다. B가 선택되면 기존 책임/정본을 유지한 상세 설계서를 작성하고, 샷 통합 출력 예시·필수/조건부 항목·콘텐츠 충분성 판정·에셋 준비도·변경 영향·검증 시나리오·호환성 경계를 확정한다. 설계 승인 뒤에만 구현 계획/테스트/스킬 변경으로 넘어간다.
