# 광고 레퍼런스 분석에서 재사용 가능한 제작 레시피로: 설계 제안

**상태: 문서만 작성한 DESIGN_PROPOSAL.** 기존 skill/code/manifest/templates/evals는 수정하지 않았다. 전체 분석 원문은 [비디오 인덱스](video-index.md), 영상별 근거는 [videos/](videos/) 아래 장별 문서, 추가30편의 source별 70개 메커니즘 표는 [gap-evidence-fast.md](gap-evidence-fast.md), 기존 저장소 역량/295 baseline은 [repo-capability-audit.md](repo-capability-audit.md)와 [repo-capabilities.json](repo-capabilities.json), 책 근거는 [book-source-notes.md](book-source-notes.md), [source-register.json](source-register.json), [creator-provenance-notes.md](creator-provenance-notes.md)에서 확인한다.

## 결정 요약

새로운 archive coordinator/ledger, 카메라/연기/조명/사운드 전문 스킬, 프로젝트 전역 ID/DB를 추가하지 않는다. 저장소에는 이미 아카이브 감사와 stable SHA identity, shot DNA, 샷/액션·카메라·빛·제품·생성 QA·누적 상태·편집·사운드·claim/CTA의 본체가 있다. 요구되는 일은 이 본체를 영상별로 실제 적용할 때 **매체/상태별 decision recipes, preconditions, 상호 인계, 반례, 관찰 가능한 검수**를 예제로 보강하는 것이다. 제안 판정은 `PRESENT`(이미 기술), `PARTIAL`(기본 슬롯은 있으나 이 재료/위상별 recipe 적용 설명의 심화 후보), `EVIDENCE_INSUFFICIENT`(제작 방식/저자/rights/오디오를 출처만으로 인증할 수 없음). 추가30편 매트릭스는 **PRESENT 30 / PARTIAL 36 / EVIDENCE_INSUFFICIENT 4, NOT_FOUND 0**이다. 분석부록18편은 아래 근거표에 연결되며, 이는 범용 갭 수나 점수가 아니다.

## 계약 분리: 원본 분석 ID가 제작 artifact ID가 아님

- `archive_id=sha256:<원본 파일 바이트 해시>`는 출처의 불변 식별자. V001…V048은 sorted display handle만이다. `C##`는 raw detector-event neighborhood/candidate, `B##`는 visual block, `G##/SG##`는 scene-level 해석, `S##.P##`는 확인된 source shot 내부 action-phase 예시다. 이 ID들은 동일 타입이 아니며 프로젝트의 storyboard panel/shot ID로 재사용하지 않는다.
- `OBSERVED`에는 직접 화면에서 본 사실/읽은 텍스트와 probe/원본 PTS 계측을 둔다. `DETECTOR_CANDIDATE`는 점수기 이벤트. `ESTIMATED`는 둘 이상 locator가 bracket한 예상 경계/시간. `INTERPRETATION`은 craft WHY + 대안/신뢰도. `DESIGN_PROPOSAL`은 새 승인 자산에 쓰는 제안. `UNKNOWN`은 미청취/미확인. creator metadata는 `DECLARED_UPLOADER_CLAIM`, ASR는 `ASR_RUN / HYPOTHESIS_UNVERIFIED`, auto caption은 `CAPTION_TEXT_AUTO_UNTIMED`처럼 별도 출처로 기록한다.
- 원본 1fps/native sample PTS는 frame locator이지 초 단위 exact cut frame이 아니다. `requested_s`와 실제 `source_pts_s`가 다를 수 있다. 전체 decode 성공, detector events, 모든 candidate sheet 열람은 모든 source edit 경계를 `SH###`로 검증했다는 뜻이 아니다. `SH###`는 실제 boundary 증거가 확보될 때만 부여한다. `scene ≠ shot ≠ action phase`: 긴 변환/조리/차량 접촉에서 여러 행동 단계를 한 지속 shot 안에 기록한다. dissolves/morphs/portal/wipes는 미확정이면 전환 후보, 컷 판정은 별도.
- 정지 프레임 검토는 continuous playback, 실제 재생 속도/편집 rhythm, camera cause, 오디오 청취를 대체하지 않는다. PTS를 초로 계측한 것은 가능한 고정도 측정값이지만 boundary는 종종 추정이다. 렌즈/거리/rig·치수, 매출/viral/view 수, 공식 제휴/권리, 대사 audible timing을 픽셀이나 title로 만들어내지 않는다.

### 분석부록 18편: 관찰 메커니즘 → 기존 조항 → 분류 → recipe/action

## 저장소 구현 전에 검토할 품질 관문

1. **Schema/control:** request 초와 실제 sample PTS를 각각 보존하는가? candidate/불확실 boundary에 `SH###`를 발급하지 않는가? scene, action phase, cut을 구분하는가?
2. **Coverage 정직성:** raw event, clustered neighborhood, 읽은 frame, scene, verified cut을 따로 세는가? 시작/종단 및 빠른 phase와 pre/post를 충분히 표본화하고 candidate를 자동 인증하지 않는가?
3. **Product/state continuity:** ingredient topology/residue, beauty liquid contact/drop, vehicle alias+chassis/contact/shadow/residue, soft material/reflection, environment/portal, endcard를 전/peak/후/재등장 frame에서 확인하는가? identity를 모르면 `UNKNOWN` 유지.
4. **표현·claim:** visible text/disclaimer/logo/CTA마다 locator/status가 있는가? caption·ASR 가설·creator tool credit를 들은 사실/검증된 claim/권리 증거로 바꾸지 않는가? 검정 또는 거의 검정인 tail도 chronology에 남기는가?
5. **배우·camera:** 행동을 목표/대상/반응으로 설명하는가? 웃는 얼굴만으로 만족/persona를 추정하지 않는가? fixed feature/solve 전에는 camera cause 대안을 남기는가?
6. **안전·권리:** 아동 운전, 위험 stunt/불, 동물 welfare, celebrity/deepfake/voice cloning, copyright, 아동 cast/guardian consent를 실제 맥락에 맞게 검토하는가? 옷 입은 아동 옆 sexual-health logo만으로 자동 blocker라 하지 않고 실제 경계 위반에만 해당 중단을 적용하는가?
7. **Timing/audio:** 상대 onset/contact/release/reaction/read-hold를 지정하는가? VO/music/sync/권리는 새 작업의 final export/timeline과 실제 청취 뒤 확정하는가? source 초를 그대로 복사하지 않는가?
8. **대안/repair:** hard cut/dissolve/shape match/morph, real geography/impossible scale, 물리 정합/의도된 fantasy 사이에 구별 가능한 대안이 있는가? repair 뒤 전후 consequence frame, endcard readability, mobile crop을 확인하는가?
9. **Transfer test:** 다른 권한 제품/cast/locale에 옮길 때 정보순서/행동/identity/claim 경계만 보존하는가? 저작권 look이나 view 성과를 복사하지 않는가? 현재 repo eval은 실제 승인 후 실행한다. 이 design 과정에서 build/eval은 실행하지 않았다.
