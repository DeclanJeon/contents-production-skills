# 시간 배치와 재생 검수

필요한 절만 적용한다. 정본은 기존 [06](../../video-production-assets/assets/06-shots-template.md), [08](../../video-production-assets/assets/08-animation-template.md), [09](../../video-production-assets/assets/09-edit-template.md)와 [보드 계약](../../video-production-assets/references/storyboard-contract.md)이다. 아래는 그 필드로 쓰는 방법과 하나의 창작 예이며 새 스키마가 아니다.

## 시간 기준과 단위

- **09 final**: 최종 시퀀스의 절대 초. 각 `cut_id`를 한 행으로 쓰며 `final_start_s`, `final_end_s`는 각각 숫자다. hard cut은 인접 경계가 맞아야 한다. 전환이 있으면 그 중첩/길이도 runtime 안에 반영한다.
- **06 local**: 해당 샷 시작을 0으로 한 초. 같은 샷의 인물·카메라·공개/hold·컷 cue가 공유한다. `final time = final_start_s + local time`은 그 샷이 정상속도로 쓰일 때의 관계다.
- **08 frames**: 해당 shot-local FPS에서 `[시작 프레임, 끝 프레임(미포함))`. FPS를 명시한 뒤 초×FPS로 계산한다. 비정수 프레임은 선택 FPS에 맞게 경계를 조정하고 합계를 다시 확인한다. 끝 패널의 표본은 `end_s−1/fps`; hold 단독 패널은 샷 시작에 둔다. 패널 표본 시각은 표시 지속시간이 아니다.
- **Source**: `source_in_s`/`source_out_s`와 `playback_rate`는 실제 소스 ID·버전·timebase에 속한다. 소스 미제공이면 UNKNOWN이다. 긴 소스 클립과 사용한 final 길이는 다르며, 속도 변경/전환이 없을 때만 `(source_out_s−source_in_s)/playback_rate = final_end_s−final_start_s`다. 원본 timestamps/가변 FPS를 임의의 CFR로 바꾸어 원래 시간을 주장하지 않는다.

key panel은 선택 상태의 증거, phase는 상태 사이의 변화, hold는 구간의 기능이다. 동작 중 긴 샷도 여러 phase를 가질 수 있고, 반응을 위해 반드시 새 샷을 만들 필요는 없다. 실제 승인 보드의 start/action_peak/end/hold 역할과 ID를 유지한다. 정지 이미지의 속도선·배열·여백은 상대 읽기 리듬의 단서이지 실제 컷 길이가 아니다.

## 수치 배치와 충돌

먼저 무엇을 알아차리고 무엇을 아직 모르며 어떤 상태가 다음 컷까지 남아야 하는지 적는다. 접촉/공개 순간과 관객의 인지, 인물의 반응 시작, 반응을 유지하는 구간, 정착 후 읽는 구간을 필요에 따라 나눈다. 반응이 의도적으로 늦으면 무엇에 늦게 반응하는지 연결한다. 효과/컷으로 필요한 행동을 가리지 않는다.

각 구간의 길이는 수행할 일과 기다림의 의미로 설명한다. 같은 길이가 의도된 비교/규칙적 관찰이면 그대로 유지한다. 단순히 총길이÷패널 수로 나눈 경우에는 실제 기능과 대조해 재배분한다. `storyboard.rhythm`은 기존 계약에 따라 요청/선언된 경우에만 사용하며, 새 필수 곡선·정점 수·ending 규칙을 만들지 않는다.

고정 runtime의 충돌은 ID별 필수 사건과 초과량을 먼저 드러낸다. 중복 준비/장식부터 줄이고, 중요 접촉·공개·반응의 선후와 잔류 상태를 보존해 재배분한다. 그래도 안 되면 이야기 축소 또는 길이 변경 승인을 요청한다. 유연 runtime은 읽힘 우선안과 간결안을 구체적인 hold/cut 차이로 비교한다. 어느 경우도 계획 초수만으로 성공을 보장하지 않는다.

## 완결 예 — 넘어지던 종이 카드를 돌로 받치기

**전부 새 창작 DESIGN_PROPOSAL.** 고정 **14초**, 예시용으로 **제안한 24 FPS**, hard cuts, 전환/크레딧 없음, 오디오·발화·화면 글자 없음. 실제 보드/소스/재생 없음. S01에서 한 손이 기울어지는 접힌 종이 카드를 붙들고, 다른 손이 작은 돌을 밑부분에 놓는다. 받치던 손을 떼어도 카드가 서 있다. 확인 뒤 손이 사라지고 카드/돌의 관계를 유지한다. 실제 기하·지지 성립은 미검증이다. 제작 시 기존 승인 구도를 사용한다; 이 예는 카메라 위치·렌즈·이동 해법을 발명하지 않는다.

### 09 컷 — final 초가 정본

소스가 없어 source 범위와 rate는 UNKNOWN이며 아래 final 값은 모두 제안이다. source 시각으로 복제하지 않는다. 음향 없음; 사운드 동기 검사는 N/A다.

|---|---|---|---|---|---|---|---|---|---|---|
| C01 | SH01 / 미제공 | UNKNOWN | UNKNOWN | UNKNOWN | 0 | 3 | 문제를 읽힌 뒤 접근 중 이탈; SH01 local 3 → SH02 local 0 접근 계속. 기존 보드에서 연결 가능성 미검증 | hard_cut/0 | N/A | 별도 반응 hold 없음; 지지 손 유지 미검증 |
| C02 | SH02 / 미제공 | UNKNOWN | UNKNOWN | UNKNOWN | 3 | 8 | 접촉→지지 해제→확인; SH02 local 5 → SH03 local 0 같은 결과. 기능 완료 뒤 결과 관찰로 컷 | hard_cut/0 | N/A | 반응 시작 5.5; reaction hold 6–7; settle 7–8; 미검증 |
| C03 | SH03 / 미제공 | UNKNOWN | UNKNOWN | UNKNOWN | 8 | 14 | 결과 유지; local 6에서 종료. 새 정보보다 유지 자체를 관찰 | none/0 | N/A | 결과 hold 8–14; 전체 재생 UNVERIFIED |

산술: `3+5+6=14 s`; 제안 24 FPS에서 `72+120+144=336 f`. SH02 각 구간 `24+12+24+12+24+24=120 f`. final frame 경계는 `0,72,192,336`이며 source frame 사실이 아니다. 06 local 반응 hold 3–4는 final 6–7에, settle 4–5는 final 7–8에 대응한다. 접근에는 3초, 접촉/지원 전환/확인에는 5초, 결과 관찰에는 6초를 가정했다. 이것은 목적별 초기안이지 지각 임계값이나 성공한 재생 결과가 아니다. SH03이 명료하지만 늘어진다면 그 hold만 줄인 유연 길이 대안을 비교한다; 고정 14초를 바꾸려면 승인을 받고, 무의미한 다른 동작으로 시간을 채우지 않는다.

## 액션 비트의 속도 배분 — 제안 예

충돌이 있는 짧은 액션은 **충돌 직전의 가속과 충돌 순간의 짧은 정지**가 리듬을 만든다. 아래는 정지 이미지 기반 실사형 애니매틱의 1.2초 예시이며 측정값·권장 공식이 아니다. 긴 고요→축적→가속→정지→폭발→여운의 대비를 쓰려면 각 구간이 관객에게 무엇을 기다리게 하는지 먼저 적는다. 실제 배분은 현재 보드의 공개·접촉·반응과 승인 runtime으로 정한다.

| 구간(예) | 화면 상태 / 기능 | 정하는 기존 필드 |
|---|---|---|
| 0.00–0.20 s | 예비 동작: 무게가 반대 방향으로 모이고 목표에 시선 고정 | 첫 hold 길이, 읽혀야 할 준비 상태 |
| 0.20–0.38 s | 급가속: 거리 압축, 필요한 경우 smear·속도선 대체 단서 | 컷 길이 단축, 이동 방향 연속 |
| 0.38–0.46 s | 충돌·정지: 접촉 프레임에서 hit stop | 접촉 phase·상태, 정지 프레임 수(08/09) |
| 0.46–0.65 s | 충격·흔들림: 반동·흔들림·충격 프레임 | 영향 프레임 삽입 여부, 흔들림 범위 |
| 0.65 s– | 후속 동작·여운: 관성으로 밀린 뒤 정착 | reaction/settle hold, 다음 컷 연결 상태 |

정지 이미지 애니매틱에서는 위 구간을 대개 **hold 길이의 대비 + 컷 위치 + 삽입 패널**로 만든다. 충돌 버트에서는 **움직임 연결 컷 + 속도 대비 + 짧은 충격 프레임 + 타이밍·스페이싱 + 소리 설계**를 함께 쓰는 조합이 자주 유용하다. 다섯을 한 번에 켜는 것이 목적이 아니라 같은 비트를 서로 보강할 때만 고른다. 소리 설계의 기준점·허용 오차·믹스는 [09](../../video-production-assets/references/09-edit.md#실행-가능한-편집사운드-큐)가 정본이고, 여기서는 타이밍만 배분한다. 속도 램프·모션 블러·카메라 흔들림은 편집·후반 또는 생성 실행자의 지원을 실제로 확인한 경우에만 계획하고, 스틸 한 장으로 이동 속도를 측정했다고 하지 않는다. 같은 이유로 그림 안의 속도선·배열은 그 패널의 양식 단서이며 컷 길이의 근거가 아니다. 표현 선택은 [편집·음향 표현](../../video-production-assets/references/edit-sound-language-catalog.md#속도타격-표현-선택표), 모션 기법은 [08](../../video-production-assets/references/08-animation.md#모션-자체의-속도타격-기법)로 넘긴다.

## 실제 검수와 수정

1. **계획 검사:** 범위 내 모든 shot의 길이·phase 합계·local/final 연결·컷 양쪽 상태와 필요한 hold를 확인한다. 미확인 소스/가림/접촉은 그대로 표시한다. 기존 구조 validator의 통과는 산술/구조 근거이지 창작 PASS가 아니다.
2. **그림 검사:** 실제 clean 보드가 있을 때 설명을 가리고 공개 순서·소유/접촉·남는 상태를 읽는다. 예에서는 돌을 놓기 전후, 손을 뗀 뒤, 결과 hold의 카드 상태를 대조한다. 이미지가 없으면 이 단계는 UNVERIFIED다.
3. **시간 재생:** 별도 승인과 실제 재생 가능한 자료가 있을 때만, 파일/보드 버전·FPS/timebase·재생 방식/속도·화면 크기·검사 구간·오디오 모드를 기록한다. 정상속도로 전체 흐름을 본 뒤 문제 지점을 다시 본다. 예에서는 지지 전환을 읽기 전 컷되는지, 확인 반응이 접촉보다 먼저 보이는지, 긴 결과 hold가 무엇을 기다리게 하는지 검사한다. 일부만 봤으면 그 구간만 보고한다. 음향이 허용된 작품은 mute 진단과 의도된 음향 재생을 구별하며, 듣지 않은 소리를 검증하지 않는다.
4. **관객/수정:** 가능하면 의도를 먼저 설명하지 않은 관객에게 무엇이 바뀌었고 어디서 기다림/혼란을 느꼈는지 물어 실제 답과 위치를 기록한다. 의도한 모호함/고요와 필수 원인의 누락을 나눈다. 기존 12 QA의 `위치`, `관찰 근거`, `수정`, `재검증 기준`, `상태`로 최소 수정과 보존할 내용을 반환한다. 수정 버전의 해당 구간과 전체 흐름을 다시 확인한다. 관객이 없으면 관객 검사는 미실행이며 수치를 발명하지 않는다.

정확한 원본 초수에는 실제 원본 시간 증거가 필요하다. 재생 통과에는 실제 버전의 재생 근거가 필요하다. 런타임/도구 오류가 나면 체크포인트와 미검증을 남기고 중단한다; 모델/CLI fallback, 임의 생성·업로드·설치로 검수를 대체하지 않는다.
