# 비트 예산 계산

길이가 먼저다. 비트 수는 결과다.

## 무성은 롱폼에 부적합하다

**먼저 읽을 것**: 무성 애니메이션은 **2분 이내 숏폼**을 기본으로 한다.

이유는 취향이 아니라 구조다:

| | 롱폼 (6~10분) | 숏폼 (≤2분) |
|---|---|---|
| 대사로 긴장 유지 | 불가 | 불필요 |
| 반복 강화 3회 | 지루해짐 | 리듬이 됨 |
| 집중 유지 수단 | 자막·내레이션뿐 (P2 위반) | 화면 동작만으로 충분 |
| 실측 렌더 | 6.5분 영상 = 8분 렌더 | 85초 영상 = 83초 렌더 |

6분 29초 무성 애니메틱을 실제로 렌더해 검토한 결과 **집중이 유지되지 않았다.** 반복 강화는 30~40초 분량의 기법이고, 그것을 6배로 늘려도 서사가 늘어나지 않는다.

**권장 기본값: 85~120초**

## 핵심 공식

```
비트 수 = 총 길이 ÷ 평균 비트 길이
```

제약:
```
평균 비트 길이 ≤ 8.0초        (원칙 P4)
비트 수 22 ~ 32
총 길이 85 ~ 120초            (원칙 P6, 숏폼)
```

## 왜 90~120비트가 아닌가

90~120비트는 **10분을 채우려고 만든 값**이었다. 2분으로 줄이면 정반대 문제가 생긴다:

| 비트 수 | 120초 기준 평균 | 판정 |
|---|---|---|
| 90 | 1.33초 | **너무 빠름** — 컷이 인지되지 않음 |
| 120 | 1.00초 | **불가** — 동작이 읽히지 않음 |
| 32 | 3.75초 | 통과 |
| 22 | 5.45초 | 통과 (여유) |

초당 1.3컷은 애니메틱이 아니라 깜빡임이다. 동작 하나가 읽히려면 최소 2초는 필요하다.

## 기본 템플릿

4막 템플릿의 원시 비트는 **19비트 / 73.5초**다.

```
setup      7비트
escalate   6비트
punchline  5비트
resolve    1비트
```

여기서 `_expand`로 22~32비트까지 늘리고 `_fit_duration`으로 85~120초에 맞춘다.
**목표를 19비트 미만으로 잡으면 템플릿을 잘라야 하고, 그때 펀치라인이 먼저 손상된다.**

## 길이 조정 (duration fit)

```
고정 구간: 첫 비트(notice), 마지막 비트(land)
조정 대상: 그 사이 모든 비트

share = (목표 - 고정길이) ÷ 조정대상수
share = clamp(share, 1.0, 8.0)
```

**함정**
- 첫 비트를 늘리면 P1(≤3초) 위반
- 마지막 비트를 늘리면 완결감이 늘어져 늘어짐으로 읽힘
- 조정 결과가 8초를 넘으면 그 비트는 **분할**한다 (늘리지 않는다)

## 프레임 정렬

```
초 → 프레임: round(초 × fps)
프레임 → 초: 프레임 ÷ fps
```

정렬하지 않으면 인코더 프레임 수와 계획 프레임 수가 어긋난다.

**권장**: 30fps. 1080×1920 세로 영상에서 60fps는 유튜브 인코딩 후 이득이 없고 렌더 시간이 2배가 된다.

## 렌더 비용 (실측)

| 호스트 | 처리 속도 | 85초 @30fps | 389초 @30fps |
|---|---|---|---|
| 8코어 로컬 | ~93 fps | 27초 | 8분 |
| 2코어 원격 | ~13.5 fps | 83초 (실측) | 17.5분 |

**타임아웃**: `max(180, duration × 6)`. 2코어 호스트에서 여유 2.7배.

## 비트 배분 예시 (85초 / 22비트)

```
setup     10비트  × 3.9초  ≈ 39초  (46%)
escalate   8비트  × 3.9초  ≈ 31초  (36%)
punchline  3비트  × 3.9초  ≈ 12초  (14%)
resolve    1비트  × 4.0초  =  4초  (4%)
```

실측 분포: `notice 1, run 10, trip 8, dive 2, land 1` — 반복 18비트로 P3(3회 이상)를 여유 있게 만족.

## 검증

```
1. 22 <= len(beats) <= 32
2. 85 <= sum(seconds) <= 120
3. max(seconds) <= 8.0

이 2.0초 하한·8.0초 상한은 수동 애니매틱 전용이 아니라 패키지 공통 기본값이다: [시퀀스 리듬 계약](../../video-production-assets/references/09-edit.md#시퀀스-리듬-계약)과 같은 값을 공유한다.
4. min(seconds) >= 2.0        (인지 가능한 동작 길이)
5. 모든 경계가 round(x*fps)/fps 와 일치
6. 첫 비트 notice <= 3.0초, 마지막 비트 land
7. plan.frames == round(plan.duration * fps)
```
