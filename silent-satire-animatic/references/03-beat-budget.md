# 비트 예산 계산

길이가 먼저다. 비트 수는 결과다. 순서를 바꾸면 10분을 채우지 못하거나 늘어진다.

## 핵심 공식

```
비트 수 = 총 길이 ÷ 평균 비트 길이
```

제약:
```
평균 비트 길이 ≤ 8.0초        (원칙 P4)
비트 수 90 ~ 120
총 길이 ≤ 600초               (원칙 P6)
```

## 왜 40~60비트로는 안 되는가

같은 총 길이에서 비트 수를 낮추면 비트당 시간이 늘어난다:

| 비트 수 | 600초 기준 평균 | P4(≤8초) 판정 |
|---|---|---|
| 40 | 15.0초 | **위반** |
| 60 | 10.0초 | **위반** |
| 75 | 8.0초 | 경계 (여유 없음) |
| 90 | 6.7초 | 통과 |
| 100 | 6.0초 | 권장 |
| 120 | 5.0초 | 통과 (하한) |

**40~60비트를 쓰려면 총 길이를 320~480초로 줄여야 한다.**

```
40비트 × 8초 = 320초 = 5.3분
60비트 × 8초 = 480초 = 8.0분
```

즉 "10분 가득"과 "40~60비트"는 양립하지 않는다. 10분 미만이면 **8분 이하로 설계하고 60비트**를 쓰는 선택지가 있다.

## 권장 계산 절차

```
1. 목표 길이 결정            예: 390초
2. 평균 비트 길이 결정        예: 5초
3. 비트 수 계산              390 ÷ 5 = 78  → 하한 미달
4. 비트 수를 90으로 올림
5. 평균 비트 길이 재계산     390 ÷ 90 = 4.33초  → P4 통과
6. 비트별 길이 배분          notice 3.0, land 5.0, 나머지 균등
```

`3`에서 하한 미달이 나오면 **길이를 늘리거나 비트를 늘린다.** 비트당 시간을 8초 초과로 늘리지 않는다.

## 길이 조정 (duration fit)

템플릿이 만든 원시 비트 합계가 목표 범위를 벗어날 때:

```
고정 구간: 첫 비트(notice), 마지막 비트(land)
조정 대상: 그 사이 모든 비트

share = (목표 - 고정길이) ÷ 조정대상수
share = clamp(share, 1.0, 8.0)
```

### 함정

- 첫 비트를 늘리면 P1(≤3초) 위반
- 마지막 비트를 늘리면 완결감이 늘어져 늘어짐으로 읽힘
- 조정 결과가 8초를 넘으면 그 비트는 분할해야 한다 (늘리지 않는다)

## 프레임 정렬

비트 경계는 프레임에 정렬되어야 한다.

```
초 → 프레임: round(초 × fps)
프레임 → 초: 프레임 ÷ fps
```

정렬하지 않으면 인코더 프레임 수와 계획 프레임 수가 어긋나 검증에서 실패한다.

```
fps 30: 정렬 단위 0.0333초
fps 60: 정렬 단위 0.0167초
```

**권장**: 롱폼은 30fps. 10분 무성물에서 60fps는 유튜브 인코딩 후 이득이 없고, 렌더 시간과 메모리가 2배가 된다.

## 렌더 비용

실측 기준 (**성능은 병목이 아니다**):

| 항목 | 값 |
|---|---|
| 순수 Python 프레임 생성 | ~93 fps (1080×1920) |
| 600초 @ 30fps | 18,000 프레임 → 약 3.2분 |
| 600초 @ 60fps | 36,000 프레임 → 약 6.5분 |
| 390초 @ 30fps 실측 | 288초 (4.8분, 오디오 포함) |

**타임아웃 설정**: `max(120, duration × 3)`. 600초면 1,800초로 실측의 약 9배 여유.

## 비트 배분 예시

### 390초 / 90비트

```
setup     50비트  × 4.3초  ≈ 215초  (55%)
escalate  31비트  × 4.3초  ≈ 133초  (34%)
punchline  8비트  × 4.3초  ≈  34초  (9%)
resolve    1비트  × 5.0초  =   5초  (1%)
```

### 500초 / 110비트

```
setup     55비트  × 4.5초  ≈ 248초  (50%)
escalate  42비트  × 4.5초  ≈ 189초  (38%)
punchline 12비트  × 4.5초  ≈  54초  (11%)
resolve    1비트  × 5.0초  =   5초  (1%)
```

## 검증

```
1. 90 <= len(beats) <= 120
2. sum(seconds) <= 600
3. max(seconds) <= 8.0
4. 모든 경계가 round(x*fps)/fps 와 일치
5. sum(seconds) >= 380   (너무 짧으면 escalate 압축됨)
6. plan.frames == round(plan.duration * fps)
```
