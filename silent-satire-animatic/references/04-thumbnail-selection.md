# 썸네일 생성

무성 영상의 썸네일은 유일한 언어-free 훅이다. 첫 3초(P1)와 함께 클릭률을 결정하는 두 지점 중 하나다.

## 핵심 규칙 — 프레임을 자르지 말고 생성한다

```
썸네일 = 이미지 생성 스킬로 만든 연출컷
        (생성 실패 시에만 펀치라인 프레임으로 폴백)
```

**프레임 캡처를 기본으로 두면 안 된다.** 렌더 프레임은 그 순간의 구도·표정·오브젝트 배치가 우연히 결정된 결과다. 썸네일은 클릭을 위해 **설계**하는 것이지, 우연히 잘 나온 순간을 줍는 것이 아니다.

실측 비교 (같은 소재):

| 방식 | 인물 크기 | 상황 가독성 | 판정 |
|---|---|---|---|
| 펀치라인 프레임 캡처 | 3% | 낮음 — 여백 과다 | 클릭 안 함 |
| 이미지 생성 | 8~12% | 높음 — 기계+동전+표정 | 후킹됨 |

이미지 생성은 "문자 없는 썸네일"을 **의도적으로** 만들 수 있어, P2(무성 원칙)와도 정확히 맞는다.

## 생성 프롬프트를 팩에서 조립한다

프롬프트를 손으로 쓰지 않는다. 팩 필드에서 조립해야 새 캐릭터에도 그대로 동작한다.

| 프롬프트 요소 | 출처 |
|---|---|
| 몸 색 이름 | `palette.body` → 최근접 색명 |
| 머리 형태 | `silhouette.head.shape` |
| 눈 구조 | `silhouette.eyes.style` (`ring` vs `panel`) |
| 연속성 문구 | `character.json` 구조 필드 (영어로 서술) |
| 금지 사항 | P2 — 텍스트/말풍선 금지 |

**한국어 원문을 그대로 넣지 않는다.** 팩은 한국어지만 이미지 모델은 영어 지시를 훨씬 잘 따른다. 구조화 필드에서 영어 문장을 만든다.

## 프레이밍 지시 — 두 함정

이미지 모델은 캐릭터를 캔버스 가장자리에 붙이는 습관이 있다. 반대로 "여백을 넓게"라고 과도하게 지시하면 캐릭터가 작아진다.

| 지시 | 결과 | 판정 |
|---|---|---|
| (지시 없음) | 손이 캔버스 밖으로 잘림 | 탈락 |
| "여백을 넓게, 작게" | 커버리지 2% | 탈락 |
| **"화면 높이의 2/3를 채우되, 사지와 테두리 사이에 배경 띠를 남긴다"** | 8~12%, 잘림 없음 | 통과 |

핵심은 **절대적 여백**이 아니라 **상대적 비율**이다.

## 생성물을 팩과 대조 검증한다

이미지 모델은 팔레트만 비슷하면 전혀 다른 캐릭터를 그려도 만족한다. 반드시 픽셀로 검증한다.

```
1. 크기 == 1080×1920           (아니면 거부)
2. 커버리지(팩 body 색 비율) ≥ 6%   (아니면 거부 — 멀리 있는 인물)
3. bbox가 테두리 안 2% 띠에 닿지 않음  (닿으면 거부 — 사지 절단)
```

색은 `character.json`의 `palette.body`에서 읽는다. 렌더러가 보는 값과 같은 출처이므로 "내가 기억하는 색"이 개입하지 않는다.

**검증 실패 → 1회 재생성 → 재차 실패 시 프레임 폴백.** 폴백은 침묵하지 않고 manifest에 사유를 남긴다.

## 서버 배포 환경 주의

이미지 생성 스킬은 **OAuth 자격증명과 계정별 쿼터**에 의존한다. 서버에서 다음 두 가지가 확인된다:

| 확인 | 실패 시 증상 |
|---|---|
| `~/.codex/auth.json` 존재 (컨테이너 HOME 기준) | `image skill not found` 또는 `credentials missing` |
| 스킬 스크립트 존재 | `image skill not found` |
| 계정 쿼터 잔여 | `HTTP 429 usage_limit_reached` |

**쿼터는 계정 단위다.** 로컬에서 많이 쓰면 서버도 429가 된다. 호스트별로 분리되지 않는다.

```
체크 순서
1. node ~/.codex/skills/codex-imagen/scripts/codex-imagen.mjs --auth ~/.codex/auth.json --smoke
2. 실제 1장 생성 테스트 (--smoke는 쿼터를 쓰지 않으므로 통과해도 429일 수 있다)
```

**컨테이너는 `HOME=/root`** 이므로 `~/.codex`는 `/root/.codex`다. 호스트의 `/home/<user>/.codex`와 다르다. 마운트하지 않으면 폴백으로 떨어진다.

이때 **폴백이 정상 동작하면 릴리스는 계속 나간다.** 다만 manifest에 `thumbnail_source: frame_fallback`과 실패 사유가 남으므로, 자동화가 이를 감시해야 품질 저하를 놓치지 않는다.

## 해상도 — pad를 쓴다

```
scale=1080:1920:force_original_aspect_ratio=decrease, \
pad=1080:1920:(ow-iw)/2:(oh-ih)/2:color=0xF9FAFC
```

**crop이 아니라 pad인 이유**: 생성물은 이미 9:16에 가깝고 캐릭터가 가장자리까지 차 있다. `crop`은 필요한 부분을 정확히 잘라낸다. `pad`는 구도를 보존하고 배경만 덧붙인다.

단, pad가 커버리지를 낮출 수 있으므로 검증은 **pad 이후**에 수행한다.

## (폴백) 프레임 캡처 — 왜 0초는 최악인가

오프닝 프레임의 특성:

- 캐릭터가 정지 자세 (`notice` 초기)
- 문제 오브젝트가 아직 등장하지 않았거나 작게 보임
- 동작 에너지가 0에 가까움

**측정 예시**: 390초 영상에서 0초 프레임은 정지한 인물 하나였고, 펀치라인(137초) 프레임은 장애물 3개와 역동적 포즈가 함께 보였다.

## 클로즈업 금지

### 배율이 곱해진다

```
최종 배율 = 샷 배율 × 변주 배율

wide   (1.0) × scale 1.24 = 1.24   ← 안전
medium (1.4) × scale 1.24 = 1.74   ← 안전
close  (2.2) × scale 1.60 = 3.52   ← 인물이 프레임 밖으로 나감
```

### 실제 실패 사례

`close`(2.2) + `scale`(1.6) 조합에서 캡처한 썸네일의 육안 판정:

> "캐릭터가 보이지 않는다. 두꺼운 파란 링과 그 아래로 뻗은 선들만 보인다."

이것은 **얼굴 일부만 확대된** 상태였다. 해상도 검증(1080×1920)은 통과했지만 정보량은 0이었다.

### 상한 규칙

샷 배율 × 변주 배율의 곱을 **2.0으로 클램프**한다. 그래야 어떤 조합에서도 인물이 프레임 안에 남는다.

```
scale_mul = clamp(shot_scale × variation_scale, 0.6, 2.0)
```

## 프레임 선택 알고리즘

```
1. 펀치라인 후보 = action ∈ {dive, trip}
2. 가독 후보 = 그중 camera.shot ∈ {wide, medium}
3. 선택 = 가독 후보의 중간, 없으면 펀치라인 후보의 중간
4. 없으면 총 길이의 중간
```

**중간을 고르는 이유**: 가장자리보다 지속 시간이 길어 프레임 추출이 안정적이고, 펀치라인의 정점에 가깝다.

## (폴백) 해상도와 크롭

```
-vf "scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920"
```

- `increase`: 비율 유지하며 목표보다 크게 확대
- `crop`: 중앙 크롭으로 정확히 1080×1920

**pad를 쓰지 않는 이유**: `pad`는 여백을 채워 인물이 작아진다. 썸네일에서는 인물이 클수록 유리하다.

## (폴백) 실패 처리

### 치명적 (릴리스 중단)

- ffmpeg 캡처 실패
- 파일 미생성 또는 0바이트
- 해상도가 배포 규격과 불일치

무시하고 진행하면 **썸네일 없는 릴리스**가 만들어지고, 유튜브가 자동 추출한 약한 프레임이 노출된다.

### 처리 방식

```
try:
    capture()
    check_size()
except ThumbnailError:
    raise (릴리스 생성 전체 중단)
```

## 검증 체크리스트

```
- [ ] manifest에 thumbnail_source ∈ {generated, frame_fallback} 이 있다
- [ ] generated 이면 generation.measure 커버리지 ≥ 6%
- [ ] generated 이면 bbox가 테두리에 닿지 않는다
- [ ] 어느 경로든 ffprobe 결과가 1080×1920
- [ ] 생성물에 텍스트/말풍선이 없다
- [ ] (폴백) 캡처 시점이 0초가 아니다
- [ ] 캡처 시점의 활성 컷이 펀치라인(dive/trip)이다
- [ ] 그 컷의 camera.shot ∈ {wide, medium}
- [ ] ffprobe 결과가 배포 규격과 정확히 일치
- [ ] 파일 크기 > 0
- [ ] 육안 판정: 인물의 머리·팔·다리·몸이 모두 프레임 안에 있다
- [ ] 텍스트/자막이 없다
```

## 육안 판정이 필요한 이유

자동 검증(해상도·파일 존재)은 **정보량**을 측정하지 못한다. 위의 실패 사례는 모든 자동 검사를 통과했다. 다음 질문으로 확인한다:

> "처음 보는 사람이 이 한 장면만 보고 무슨 일이 벌어지는지 3초 안에 짐작할 수 있는가?"
