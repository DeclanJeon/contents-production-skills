# 제작 검수·수정 라우팅

## 입력과 산출물
입력: 브리프와 실제 산출물, 버전, 목표 형식

산출물: 근거 있는 검수 결과와 수정 순서

## 실행 절차
1. 각본·스토리보드·프롬프트·애니매틱·러프컷·최종 파일 중 현재 검수 대상을 명시한다. 미리보기나 측정이 없는 항목은 미검증으로 남긴다.
2. 서사 인과 / 목표·연기 / 시각·촬영 / 조명 / 움직임 / 편집·사운드 / 사실·형식의 일곱 범주에서 문제를 찾는다.
3. 문제마다 artifact_id·scene_id·shot_id·타임코드 또는 문서 위치를 기록한다. 문제→관객 영향→수정→재검증 기준으로 쓴다.
4. 필수 메시지 누락·확인되지 않은 주요 주장·길이 오류·깨진 에셋 참조를 blocker로 분류한다. 인상 개선은 major 또는 minor로 구분한다.
5. 원인을 수정할 담당 모듈로 되돌린다. 각본이 바뀌면 관련 샷·연기·조명·프롬프트·편집의 stale 상태를 설정한다.
6. 구조 검증 통과를 작품 품질의 증명으로 해석하지 않는다. 실제 파일 없는 최종 승인, 가상의 렌더링·청취·성능 점수를 만들지 않는다.

## 완료 조건
요청 범위에 있는 모든 blocker가 해결됐는가? 계획 검수와 미디어 납품 검수를 구분했는가? 실제 확인 항목과 미검증 항목을 구분했는가?

## 근거와 적용 범위
자료 ID: 전체 읽기 가능한 자료의 통합; 검수 규격은 설계 확장. `sources.md`에서 파일 상태와 탐색 위치를 확인한다. 절차와 템플릿은 여러 자료의 개념을 결합한 독자 설계다. 저자의 규칙을 그대로 재현한 요약이나 공식 인증된 방법론으로 표현하지 않는다.

## 출력 템플릿
`assets/12-qa-template.md`를 복사해 채운다.

## 판정
pass / pass_with_notes / needs_revision 중 하나와 검사 범위를 기록한다. 미디어를 요청받은 경우 주요 미디어 항목이 미검증이면 pass로 판정하지 않는다. 무음 작품의 음성 명료도, 등장인물 없는 설명 영상의 배우 리허설 등은 N/A다.
