# AI 영상 프롬프트·연속성 인계

## 입력과 산출물
입력: 확정 샷, 캐릭터·룩 SSOT, 생성 도구 기능

산출물: 샷별 프롬프트, 참조 매핑, 재생성 로그

## 실행 절차
1. 실제 도구의 참조 이미지·클립 길이·화면비·오디오·카메라 제어 지원을 확인한다. 지원하지 않는 파라미터를 발명하지 않으며, 미확인 지원은 기존 도구 지원 확인 슬롯에 `UNKNOWN`으로 기록한다.
2. character_id·location_id·prop_id·look_id에 승인된 기준 에셋을 연결한다. seed는 공급자의 문서화된 기능과 실제 시험으로 확인되기 전까지 정체성 연속성 제어로 취급하지 않는다. 지원이 불명확하면 기존 도구 지원 확인 슬롯에 `UNKNOWN`으로 남기고 보장을 약속하지 않는다.
3. 샷 프롬프트를 대상/환경→초기 상태→하나의 주 행동→카메라→조명→끝 상태→유지 규칙 순서로 쓴다. 카메라 제어가 확인되면 prompt에는 채택한 단일 지시만 쓴다; 미확인 대안은 DESIGN_PROPOSAL로 따로 두고 실행 가능한 prompt 제어처럼 제시하지 않는다. 복합 변신·과도한 사건은 샷을 나눈다.
4. 앞 샷 끝과 다음 샷 시작의 의상·소품 손·시선·진행 방향·광원을 맞춘다. 생성 클립 길이와 최종 편집 길이·핸들을 구분한다.
5. 검수 후 문제 위치를 시간으로 기록하고 한 변수씩 수정한다. 실제 생성 전에는 프롬프트 완성으로만 보고하고 영상 완성이라고 말하지 않는다.
6. 플랫폼별 생성·편집·게시 작업은 해당 도구/스킬의 권한과 절차로 인계한다. 이 모듈 자체가 렌더링이나 외부 게시를 실행했다고 주장하지 않는다.

## 참조 패킷·제출 언어·생성 방식

다중 참조·통합 시트·지도·직전 영상·프리비즈를 쓰면 [실무 인계 R1](29-reference-driven-production.md#reference-roles)을 적용해 파일/버전/슬롯별 가져올 속성·제외할 속성·충돌 시 우선 기준을 역할표에 채운다. 첨부 순서를 바꾸면 실제 태그와 최종 전체 제출문도 다시 맞춘다. 클라이언트가 실제 보낸 전체 요청문은 기존 이력에 보존하고, 공급자 보정/변환 후 본문이 비노출일 때만 그 변환문을 NOT_EXPOSED로 남긴다. 실제 요청문 스냅샷/SSOT 소비 증거까지 생략하지 않는다. 과밀 입력과 부정 조건은 R4의 중복/충돌 정리·관측 가능한 보존 상태로 보완하며 핵심 사건/대사를 삭제하지 않는다.

번역/축약 제출이 필요한 경우에만 [R4 대응 검수](29-reference-driven-production.md#bilingual-prompts)를 적용한다. 한국어 검수문은 요약이 아니며 태그·시간·좌우·완료/부정·소유·발화 원문을 제출문과 같은 버전으로 대조한다. 문자 수 감소는 토큰·비용·품질 우월성의 증거가 아니다. 대사가 있어도 원문에 화자가 지정되지 않았다면 역할/상황으로 화자를 확정하지 않는다. 화자는 미정으로 두고 대응 번역도 동일하게 유지한다; 꼭 필요하면 그 선택만 질문한다. 실제 업로드가 없는 번역 요청은 태그/슬롯을 발명하지 않고 미배정 또는 해당 없음으로 표시한다.

새 생성·부분 수정·프리비즈 참조·실제 Extend는 [R5](29-reference-driven-production.md#generation-modes)로 구별한다. 영상 첨부/“이어줘” 문장만으로 실제 확장 사용을 기록하지 않는다. 원본 포함 출력 여부와 접합부 검사 범위를 인계한다. GUIDE-01 pp64–77의 경험 공정을 일반화한 보강이며 현재 기능·성공 증거는 별도다.

## 상태·인과 연속성 (선택적)
샷이 누적 변화·원인 동작·시점 대응·결합 응답·시간 압축·정확한 레퍼런스 중 하나에 해당하거나 앞선 샷의 후속 유지 의무를 이어받으면 [상태·인과·연속성 인계](26-state-causality-continuity.md)의 필요한 슬롯을 기존 산출물 또는 `assets/state-transition-template.md`에 채워 다음 해당 샷/검수로 넘긴다. 시작·끝 상태·유지 규칙 위에 변화 영역/속성·보존 영역/속성·후속 유지 범위·의도적 생략을 분리한다. 새 변화와 상속된 유지 의무가 모두 없는 샷에만 `상태 인계: N/A`로 닫고 필드를 강제하지 않는다.

주 행동이 명확하고 가능한가? SSOT 참조가 있는가? 시작·끝 상태와 샷 간 연속성이 맞는가?

## 근거와 적용 범위
자료 ID: 08,13,16의 제작 원칙을 적용한 package-authored 설계 확장. `sources.md`에서 개별 자료 상태와 locator를 확인한다. 대상/초기 상태/행동/카메라/조명/끝 상태/유지 규칙의 순서, 샷 간 연속성 필드, 한 변수씩 수정하는 절차는 이 패키지의 저작 운영 방식이지 서적의 직접 프롬프트 절차가 아니다. seed의 정체성 제어 효능은 공급자 문서와 실제 시험 전까지 미확인(`UNKNOWN`); 연속성 보장으로 인용하지 않는다.
