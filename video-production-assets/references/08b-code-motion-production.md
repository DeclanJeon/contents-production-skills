# 코드 기반 모션 제작: 쇼릴·제품 데모·설명

**적용:** 코드 렌더 모션, 제품 UI 영상/라이브 데모, 쇼릴, 설명형 모션이 현재 과제일 때만. 이 문서는 제작 참조다. 렌더러 선택·설치·과금·실행 권한을 열지 않는다. 기존 [모션 크래프트](08a-motion-craft.md)와 [스타일 사전](33-motion-style-library.md)은 스타일과 움직임의 정본이다. 웹 공간·스크롤이 과제라면 [실시간 모션 연출](../../open-3d-production/references/realtime-motion-direction.md)로 필요한 부분만 인계한다.

## PRE · 결과물과 시간축 결정

| 유형 | 컷별 설계 | 검수 질문 |
|---|---|---|
| 쇼릴·키네틱 타이포 | 한 문장으로 설명되는 모티프 → 다른 크기·속도·매체의 변주 → 모티프를 회수하는 마감. 음악이 있다면 BPM과 곡의 실제 첫 강박 오프셋을 분리하고 핵심 장면/카피/전환을 박자표에 붙인다. | 동작이 모두 같은 박에 몰리거나 읽을 시간을 뺏지 않는가? 전환은 형태·방향·리듬 중 무엇을 이어 받는가? |
| 제품 필름·라이브 데모 | 사용자 목표 → 시작 UI 상태 → 실제 행동 → 결과 상태. 승인된 화면 버전·디자인 토큰·샘플 데이터를 고정한다. 클릭 이전에 성공 상태가 보이지 않게 한다. | 기능이 현재 제품에 실제 존재하는가? 포인터와 입력 포커스가 맞는가? 라이브 데모와 편집용 영상 중 어느 것을 납품하는가? |
| 세션/과정 설명 | 사용자가 제공한 비식별 자료에서 문제→시도→변화로 사건을 고른다. 화면에 넣을 근거와 생략할 식별정보를 나눈다. | 작업 로그를 자동 수집하지 않았는가? 실제 사건과 합성 예시가 구분되는가? |

컷 ID마다 **시작 상태 / 행동과 시간 / 끝 상태 / 보여줄 것·숨길 것 / 큐 ID / 참조 버전**을 기록한다. UI 컷에서는 현재 화면의 강조 대상 하나를 정하고 버튼·메뉴·본문의 시각 계층이 그 대상과 충돌하지 않게 한다. 아래는 중립 예시이며 제품 사실이나 고정 시간값이 아니다.

| 컷 | 시작 → 행동 → 종료 | 확인할 조건 |
|---|---|---|
| C01 | 빈 검색창 → `자료` 입력 → 결과 세 줄 표시 | 마지막 글자 입력 전 결과를 미리 보여주지 않는다. |
| C02 | 결과 표시 → 둘째 행 선택 → 상세 카드 열림 | 포인터·포커스·카드 콘텐츠가 모두 둘째 행을 가리킨다. |

## 선택형 심화 · 해당 장면에만 적용

| 표현 | 구현 순서 | 탈락 조건 |
|---|---|---|
| **차트·단계도** | 시작 상태에 단위·기준을 먼저 제시 → 값 또는 관계를 한 번에 하나만 바꿈 → 최종 비교 상태를 멈춰 읽게 함. 개념도는 수치 축 없이도 관계를 보여줄 수 있다. | 실제 데이터와 예시의 혼용, 변경 중 축 재조정으로 생긴 과장, 값이 읽히기 전 전환. 참고: [Taxtello](https://prompt-motion.com/daniel-haida-8691d4), [Paper-style product launch](https://prompt-motion.com/ik-builds-b8bdcf). |
| **배지·파티클** | 사용자 행동 → 잠금 해제 → 시각적 강조 → 배지나 메시지가 남는 정지 상태. 입자 재생은 시드를 고정하고 가독 영역 밖에서 발생·소멸을 끝낸다. | 성취 조건 전 효과 발생, 입자가 핵심 마크·글자를 가림, 다시 스크럽할 때 입자 배치가 바뀜. 참고: [Badge unlock](https://prompt-motion.com/bthreeagency-b9b8d9), [Motion techniques](https://prompt-motion.com/lukasersil-0ed38e). |
| **형태 연결·사진 마스크** | 앞 컷에서 알아볼 모양이나 모서리를 남겨 다음 컷의 프레임으로 쓴다. 사진의 내용과 순서가 중요하면 움직임을 멈추고 사진을 보여준다. | 전환 중 앵커가 사라지거나, 사진 자체가 근거인데 잘려 보임. 참고: [UI morph](https://prompt-motion.com/twoclipping-5cba86), [Photo print](https://prompt-motion.com/twoclipping-221cab). |
| **루프·로고 공개** | 로고가 처음 식별 가능한 프레임을 정한다. 루프라면 처음으로 넘어갈 때 속도·위치·휘도·오디오가 이어지는지 실제 반복 재생으로 확인한다. | 미승인 로고 재해석, 공개 전 이미 정체가 드러남, 경계에서 프레임 중복이나 클릭음. 참고: [Logo reveal](https://prompt-motion.com/tdinh-me-815acb), [Bumper](https://prompt-motion.com/techhalla-90b8ec). |

## 컷 보조 효과: 방향 와이프

와이프는 레시피를 대체하지 않는다. 장면 전환의 방향이 피사체 움직임이나 시선과 이어지거나, 정지 화면에 진입 신호가 필요할 때만 사용한다. **한 번에 공개해야 하는 로고·답·반전에는 쓰지 않는다.** 방향이 반대여서 글자만 부분 노출되는 것이 어색하면 컷으로 단순화한다.

- **PRE:** 적용 컷, 덮개가 빠지는 방향, 시작/완전 공개 프레임, 읽기 홀드를 명시한다. 사용자 행동이나 정보 공개를 가리지 않도록 와이프를 먼저 끝낸다.
- **PROD:** 지원되는 CineForge 로컬 모션에서는 `motion.entrance`의 `kind: wipe_left | wipe_right`, `duration_frames`(30fps)로 전달한다. 0번 프레임은 가려져 있고 지정 프레임부터 완전히 보인다. 진행 중에는 일부가 노출된다. 최소 1초의 완전 공개 구간을 남긴다. 두 클립 혼합, 링 마스크, 실사 마스크는 이 실행 옵션이 아니다.
- **POST:** 실제 출력에서 첫 프레임·중간·완료 직전과 완료 프레임을 대조한다. 가린 상태에서 클릭·단계 공개·모프 시작을 지나쳤거나, 공개 후 글을 읽을 수 없으면 탈락이다.

## 텍스트 카드: 스택 · 캐러셀 · 나란히 비교

`card_sequence`는 자료를 짧은 카드로 나눈다. **스택**은 항목을 앞 카드와 함께 남겨 목록을 완성한다. **캐러셀**은 한 번에 한 항목을 읽어야 할 때, **비교**는 두 항목의 동일한 기준을 동시에 보아야 할 때 선택한다. 등급이 아니라 비교라면 같은 크기·타이포·강조를 유지한다.

CineForge 로컬은 `motion.headline`, `layout: stack | carousel | compare`, `cards`, `reveal_frames`(컷 로컬 30fps)를 받는다. 스택·캐러셀은 2~3개 24자 이내, 비교는 2개 12자 이내. 캐러셀은 8프레임 진입 후 정지 상태 30프레임 이상, 마지막 카드는 최소 30프레임 유지. 검수는 공개 전 노출, 이동 중 줄바꿈·잘림, 비교 상태의 동시 가시성을 확인한다. **실제 제품 캡처·폰 목업·사진 합성은 이 텍스트 경로가 아니다.**

## 화살표 그리기와 보상 파티클

- **선 그리기:** 관계를 강조할 때 `diagram_data`의 `connector_frames`로 각 노드 공개 직전 선을 앞에서 뒤로 길게 그린다. 두 공개 시점 사이보다 길게 두지 않고, 화살촉과 도착 노드는 지정 프레임에 함께 보인다. 자유형 경로·분기·통계 축은 별도 구현이다.
- **보상 파티클:** 성공 답장이 의미 있는 UI 컷에서만 `motion.burst={at_frame, seed}` 사용. 답장 전에는 표시하지 않고 24프레임 안에 끝낸다. 시드를 고정하고 결과 문구 아래에만 표시한다. 모든 클릭에 터뜨리거나 보상 여부를 독자적으로 판정하지 않는다. 사용자 배지 자산 합성은 별도다.
- 실제 출력에서 **선 진행 → 노드**, **답장 → 짧은 강조 → 소멸** 경계를 대조한다. 같은 프레임을 재렌더해 위치가 일치하는지, 글자 영역을 덮지 않는지 검사한다.

## 키네틱 타이포: 구절 순차 공개

말맛·반전이 핵심이면 조사를 포함한 뜻 단위로 구절을 나눈다. 한글을 임의 자모로 자르지 않는다. 첫 제목에 결말을 넣지 않고, 최종 요약/반전은 마지막 공개 시점까지 숨긴다. CineForge의 `kinetic_type` 컷에 `type_reveal={phrases,reveal_frames}`를 선택적으로 붙인다. 2~3개 구절, 각 24자 이내, 30fps에서 공개 간 최소 6프레임. 마지막 구절의 6프레임 이동이 끝난 뒤 최소 1초 읽기 시간. 출력에서 마지막 구절 전후의 카피를 비교한다. 이 기능은 음원을 듣거나 BPM을 자동 검출하지 않는다.

## 타이포 포스터 배경

CineForge `kinetic_type`에서만 `motion.poster` 옵션을 사용한다. `editorial`은 차분한 안내, `pop`은 짧은 대비와 유머, `dark`는 어두운 분위기와 밝은 글씨가 맞을 때 선택한다. 장식은 읽는 영역 바깥에 두고 글자색은 함께 검증된 팔레트를 쓴다. 구절의 공개 순서와 읽기 홀드는 바꾸지 않는다. 정지 배경 프리셋이며, 오로라·유리·사진 합성이나 실제 조명을 대신하지 않는다.

## 승인 자산 레이어: 로고·제품 화면·사진·캐릭터 자세

실제 마크·앱 화면·사진·스프라이트를 쓰려면 **사용자가 승인한 파일**이 필요하다. CineForge 로컬 모션은 `assets/motion_assets.json`의 `{path, sha256, rights}` 등록과 일치할 때만 읽는다. 경로는 프로젝트 안, PNG/JPEG, 파일당 12MB 이하. 해시가 바뀌면 렌더하지 않는다. G2 검수 후 자산 원장이 바뀌면 재검수 없이 실행할 수 없다.

- `image_reveal`: `asset_id`, `at_frame`(30fps), `mode: fade | slide | wipe`, `image_layout: logo | photo | screen`. 공개 프레임 전에는 보이지 않고, 공개 뒤 최소 1초 읽을 시간을 둔다.
- `pose_swap`: 서로 다른 두 승인 자세 `poses: [a, b]`와 `at_frame`. 자극 이후에만 두 번째 자세가 나타난다. 표정의 미세한 변화가 핵심인 장면에는 부적합하며 실사·연기 레인을 쓴다.
- 검수: 승인 원본과 화면 속 마크 모양·색·여백, 화면 속 실제 기능·문구, 인물 자세 전후 인과를 확인한다. 같은 파일에서 만든 변경이 아닌 새 로고·새 캡처를 추측해 만들지 않는다.
- **휴대폰 목업·화면 원근·제품 조명**은 이 로컬 2D 레이어의 지원 범위가 아니다. 필요하면 기존 3D·합성 레인으로 넘긴다.

## 수치 차트: 출처가 있을 때만

`chart_bars`는 `bars` 2~4개(`label`, `value`), `max_value`, `source`가 모두 있어야 한다. 막대는 하나씩 자라며 마지막에 1초 이상 유지된다. 라벨은 12자 이내, 값은 `max_value` 이하여야 한다. **출처가 없는 수치·비율·순위는 그리지 않는다.** 축·단위가 필요한 비교는 범위 밖이며 별도 차트 구현과 데이터 대조가 필요하다.

## 종이 레이어와 지도 경로

- `paper_layers`: 겹친 종이 카드 2~3장. 라벨 20자 이내, 순차 등장, 마지막 뒤 1초 유지. 질감 있는 스톱모션이 아니라 평면 레이어다.
- `map_route`: 사용자가 제공한 지도 이미지 위 정규화 좌표 2~4점과 구간별 프레임. 점은 제공 지도 안에서만 그린다. 실제 이동 경로·지명을 추측해 채우지 않고, 공간 검증이 필요하면 Blender 경로로 확인한다.

## 루프와 리듬

`loop: true`는 실제 출력의 첫 프레임과 마지막 프레임이 같아야 통과한다. 비트에 맞춘 타이밍은 **승인된 음원과 큐 시트**가 있을 때만 확정하고, 음원 없이 BPM을 추정하지 않는다. 음원을 넣은 최종 합성·믹스는 이 무음 렌더 경로 뒤 별도 단계다.

## PROD · 프레임을 반복 재현

- 편집본은 승인한 컷 편집 시간·원본 프레임 범위·FPS를 분리한다. 렌더러가 임의 프레임으로 이동해도 **장면 상태 = 같은 입력과 같은 시간의 함수**가 되게 한다. 실시간 `setTimeout`, 네트워크 대기, 무시드 난수에 프레임 내용을 맡기지 않는다.
- 입력 자산·폰트가 준비된 다음 프레임을 샘플링한다. 컷 첫/끝, 클릭 전후, 타이포가 완전히 자리 잡는 구간, 전환 이음매에서 상태를 검사한다. 모션 블러와 효과는 가독성이 살아 있을 때만 적용한다.
- 승인된 오디오가 있으면 초 단위 큐와 프레임 경계를 비교한다. 정수 프레임 반올림을 매 컷 누적하지 말고, 각 시점을 전역 타임라인에서 변환한다. 음원 미확보 상태를 실측 싱크로 표기하지 않는다.
- 라이브 데모는 스크럽·재생/정지와 모션 감소 대체 상태가 요구될 수 있다. 영상 파일에는 별도의 줄거리·읽기 시간·출력 검수가 필요하다. 한쪽 성공을 다른 쪽 성공으로 간주하지 않는다.

## POST · 실제 출력본 확인

최종 파일의 크기·길이·FPS·오디오 트랙을 확인하고, 실제 출력본에서 클릭/결과 순서, 컷 이음매, 작은 글자·자막 충돌, 박자 및 대사 싱크를 재생 검수한다. 검사 구간과 문제가 있는 컷 ID를 남기고 정상 컷을 유지한다. 프리프로덕션과 실제 영상 요청 검수는 각각 **최대 2회**라는 [기존 계약](../../creative-production/references/phase-review.md)을 따른다. 색/폰트/음악의 미승인 대체나 새 테이크는 별도 권한 없이 실행하지 않는다.

[공개 원본 카탈로그](https://prompt-motion.com/): Cinetic, HTML Demo, Product Film, TasteSkill, Session Story 및 Showreel. 지침을 새로 작성했으며 특정 기술 스택·폰트·원본 로그 읽기 절차를 번들하지 않는다.
