# 모션 크래프트 — 08 애니메이션 심화

모션 그래픽·로고 모션·색 움직임·콘티에서 움직임으로 넘어가는 작업의 방향·타이밍·검수를 더 깊게 잡을 때만 연다. [08 애니메이션](08-animation.md)의 모션 그래픽 표면 절을 확장하는 심화이며 인물 연기 절차는 08 본문을 따른다. 승인된 브랜드·타이밍·화면비는 아래 어떤 값보다 우선하며, 조정 가능한 값 묶음은 절마다 ‘시작값’으로 따로 표시한다. 실행은 [policy.md](../../creative-production/references/policy.md) 게이트와 [24 제작 실행](24-production-execution.md)을 따르고, 도구는 [선택 라우팅](../../creative-production/references/production-routing-optional.md)의 기존 레인(Remotion·FFmpeg·Blender·선택된 생성기)을 쓴다. 각색 절의 출처와 라이선스는 [open-design 이전 기록](upstream/open-design-provenance.md)에 있다.

## open-design 각색 절

### 모션 언어와 방향 결정 {#od-motion-art-direction}
- 쓰는 곳: 룩이 정해지지 않았거나 모션이 “바쁘다·싸구려·일관성 없다”로 느껴지고 원인이 솜씨가 아니라 결정일 때.
- 구성·시작값: 작품당 하나씩만 고른다: 이징 계열, 기본 시간 단위, 전환 계열, 스태거 리듬, 모션 강도, 홀드 규율. 시작값(차분·날카로운 예시): 이징 `cubic-bezier(0.22,1,0.36,1)`, 단위 0.4초(큰 이동 0.8, 미세 0.2), 매치컷+크로스페이드만, 스태거 60ms, 이동 24px 이하·스케일 0.96→1.0·오버슈트 2% 이하, 비트 뒤 0.3초 이상 정지. 이징은 퇴장용 in·등장용 out 둘까지이고 셋째 곡선은 존재 이유가 있어야 한다. 차분/키네틱×부드러움/날카로움 한 칸을 정한다. 위계는 히어로·서포트·텍스처로 순위를 매기고 위에서부터 움직이다 일찍 멈춘다.
- 움직임·타이밍: 에너지 지도는 낮은 시작→빌드→피크→정돈된 엔드카드. 긴장 뒤에 홀드로 이완한다. 핵심 순간은 오디오에 맞추고 정지·침묵도 페이싱 도구다.
- 피할 것: 프레임 전체를 동시에 움직이기(스태거하거나 시선이 머물 닻을 하나 둔다), 와이프+스핀+페이드 겹치기, 읽는 중인 텍스트 루프, 진지한·금융 콘텐츠의 오버슈트, “와우” 순간 둘 이상.
- 검수: 샷마다 스펙과 대조한다 — 비슷한 움직임에 같은 이징 계열인가(떠돌이 linear·ease 없음), 길이가 기본 단위의 배수인가, 정한 전환 계열만 쓰는가, 묶음 공개의 스태거가 같은가, 동작이 쉼 없이 쌓이지 않는가, 한 프레임에서 시선을 다투는 요소가 하나인가(뒤 샷에서 가장 두드러지게 등장하는 히어로는 정상). “아니오”는 방향 결함이다.

### 모션 성격·시간표·이징 시작값 {#od-motion-design}
- 쓰는 곳: 모션 그래픽·UI 화면 요소의 성격, 길이, 이징, 무게를 정할 때. 패키지 지침: 이 값은 UI 응답 기준이므로 영상 연출 범위는 아래 안무·시간 범위 절이 우선한다.
- 구성·시작값: 시작값 — 성격은 프로젝트당 하나: Playful 150–300ms·ease-out-back·오버슈트 10–20%, Premium 350–600ms·`cubic-bezier(0.4,0,0.2,1)`·0%, Corporate 200–400ms·`cubic-bezier(0.2,0,0,1)`·0–3%, Energetic 100–250ms·ease-out-expo·15–30%. 기본은 UI에 Corporate, 일러스트에 Playful. 브랜드 모션 상수 셋: 80% 쓰는 이징 하나, 길이 3단(빠름·표준·느림), 등장 패턴 하나. 무게별: 무거움 300–500ms·0%, 중간 200–350ms·3–5%, 가벼움 80–200ms·5–15%.
- 움직임·타이밍: 등장은 감속, 퇴장은 가속, 화면 안 이동은 양끝 부드럽게, 루프는 사인 기반. 시작값 — 등장을 퇴장보다 30–50% 길게. 시작값 — 거리 100px이 기준, 200px은 1.3배, 400px은 1.6배. 스태거는 전체 500ms 미만. 히어로가 먼저 또는 가장 두드러지게 들어오고 요소는 같은 방향으로 진입한다.
- 피할 것: 공간 이동에 linear(스피너·진행바만 예외), 중요한 상태 변화를 opacity만으로(위치·스케일과 함께), 화면 1/3 초과를 중간 키프레임 없이 이동.
- 검수: 로봇 같으면 이징·호를, 너무 느리면 요소별 길이를, 밋밋하면 보조·앰비언트 층을, 산만하면 동시 움직임 수를 점검한다. 성격이 장면 전체에서 일관한가.

### 모션 브리프·비트맵 {#od-opendesign-motion-design}
- 쓰는 곳: 모션 그래픽(키네틱 타이포·설명·프로모)을 기획하거나 고칠 때의 시작점. 산출물 형식과 내보내기는 해당 작업이 정한다.
- 구성·시작값: 사용자 자산·참조·스크립트·이전 결정을 먼저 쓰고 메시지·청중, 목적지·화면비, 길이, 정확한 카피, 필수 에셋, 시각 방향, 오디오를 정한다. 이야기가 달라지거나 결과가 오도될 때만 묻고 가정은 짧게 밝힌다. 제약 없는 단편의 시작값은 12–18초, 16:9 1920×1080, 30fps, 지어낸 보이스오버 없음이며 세로 소셜은 9:16이다. 기존 브랜드·타이밍·플랫폼·카피가 이 값을 덮는다. 비트맵은 `시간 → 시청자 takeaway → 초점 객체 → 변형 → 카피/오디오 → 퇴장` 한 줄이고 등장·읽기 홀드·퇴장 시간을 넣는다. 비트를 잇는 반복 모티프를 하나 고른다.
- 움직임·타이밍: 예시 메커니즘 — 흩어진 단어가 궤도 → 한 단어가 끌어당김 → 궤도가 타이머로 → 완료되어 워드마크. 움직임마다 의미가 바뀌어야 하며 무관한 타이틀 카드 넷은 메커니즘을 잃는다. 예시이지 보편 스타일이 아니다.
- 피할 것: 제품 주장·지표·후기·에셋 지어내기([10 근거](10-evidence.md) 규칙), 만들어 달라는 사용자에게 스타일 세 안이나 승인 라운드 강요.
- 검수: 비트마다 시청자 takeaway와 초점 객체가 적혔는가, 시간 예산이 읽기 홀드를 포함하는가.

### 움직이기 전의 아트 디렉션 {#od-opendesign-motion-design--art-direction}
- 쓰는 곳: 장면 전체를 확장하기 전에 대표 프레임 한 장의 위계·크롭·타입·팔레트·질감·초점 객체를 확정할 때. 계획만 요청받았으면 그 프레임을 글로 묘사하고 산출물을 미리 만들지 않는다.
- 구성·시작값: 주제에 묶인 구체적 시각 전제를 쓴다. 프레임을 채우는 것, 시선이 쉬는 곳, 재질 언어, 대비 구조를 정한다. 타이포는 스케일·정렬·줄바꿈·여백·글꼴 성격으로 구성하는 그래픽 객체다. 실제 언어를 덮는 글꼴과 검증한 대체 글꼴을 쓰고 캡처 전 글꼴 준비를 기다린다. 작은 팔레트와 의도된 대비, 하나의 재질·세계 논리(에디토리얼 잉크·정밀 기구·접은 종이·촉각 콜라주·벡터 기하·회화 필드 등)를 영상 전체에 유지한다. 비대칭·풀블리드·희박한 구성도 가능하다.
- 움직임·타이밍: 대표 프레임을 먼저 확정한 뒤 나머지 장면으로 확장한다. 약한 스틸은 파티클·카메라 흔들림·이펙트로 구해지지 않는다.
- 피할 것: “프리미엄·시네마틱·모던”만의 디렉션, 브리프와 무관한 기본 네온 그라디언트·글라스 카드·글로우 오브·베이지 배경, 가운데 헤드라인 아래 카드 셋의 반복, 자막·플랫폼 UI를 초점 영역에 두기(안전 여백은 목적지별로).
- 검수: 공급된 제품 화면·로고가 비율과 내용을 지키는가(늘리지 말고 의도해서 자른다), 데이터가 있으면 축·단위·값이 애니메이션 내내 맞는가.
출처: nexu-io/open-design@5a0c47777975 opendesign-motion-design

### 주의 안무와 시간 범위 {#od-opendesign-motion-design--choreography}
- 쓰는 곳: 한 장면에서 무엇이 먼저 움직이고 무엇이 받쳐 줄지 정할 때.
- 구성·시작값: 주 동작을 먼저 정하고 보조 동작이 응답한다. 독립 객체는 읽기에 도움이 될 때 어긋나게, 집단 움직임이 아이디어면 함께 움직인다. 모든 단어를 기계적으로 스태거하거나 움직이는 화면 비율을 고정하지 않는다. 세 층은 선택지다 — 주(아이디어를 나름)·보조(무게·인과: 따라오는 라벨, 가라앉는 그림자)·앰비언트(필요할 때만). 조용한 장면과 읽기 홀드는 완전히 정지해도 된다.
- 움직임·타이밍: 시작값은 작은 강조 120–220ms, 주 요소 도착 350–650ms, 의미 있는 형태 변형 600–1200ms, 큰 공개·카메라 900–1800ms다. 영화용 어림이며 UI 응답 한도가 아니다. 도착은 ease-out, 동기 있는 퇴장은 ease-in, 카메라는 부드러운 가감속, 컨베이어·시계·스캔은 등속이다. 장난스러운 재질은 오버슈트해도 되고 정밀 기구는 기본적으로 튕기지 않는다. 빠른 동작에는 준비와 회복을 둔다. 전환은 비트 관계로 고르고(매치컷·추적·마스크·컷) 핸드오프에서 속도·방향을 보존한다. 루프는 시작·끝 상태와 속도가 맞고 정지가 중복되지 않게 한다([09의 루프 검사](09-edit.md#요청된-루프의-끝시작-검수)).
- 피할 것: 설명 없는 순간이동, 변화를 위한 전환 다양화, 토폴로지가 맞지 않는 모프, 계속 최대 강도.
- 검수: 동작과 휴지가 교대하는가, 가장 강한 변형이 핵심 아이디어에 있는가, 마무리에서 모티프가 해결되고 최종 메시지가 홀드되는가.

### 시각 문법 선택: 제품·타이포·설명 {#od-opendesign-motion-design--grammar}
- 쓰는 곳: 모션 영상의 종류에 맞는 문법을 고를 때.
- 구성·시작값: 제품·브랜드 필름은 실제 이점과 구체적 행동을 중심으로, 가능하면 실제 화면으로, 바뀌는 부분을 분리해 보이고 브랜드 모티프를 엔딩 프레임까지 가져간다. 키네틱 타이포는 무게·자간·방향·변형으로 의미를 연기하고 안정된 읽기 창을 둔다. 설명·데이터는 인과 모델을 지키는 공간 은유를 쓴다.
- 움직임·타이밍: 설명은 변형 전에 객체를 먼저 보이고 관계가 바뀌는 동안 라벨을 유지하며 척도가 중요하면 값보다 축을 먼저 공개한다. 내레이션이 있으면 실제 공급·생성된 오디오 타이밍에 비트를 맞춘다. 단어 단위 등장이 이해를 막으면 구 단위로 움직인다. 공개 타이밍은 읽기 시간이 아니다.
- 피할 것: 정적 페이지 위 느린 카메라 이동만으로 시연 끝내기, 모든 줄을 회전·블러·흩뿌리기, 추측한 타임스탬프, 약한 설명을 무관한 장식으로 덮기.
- 검수: 해당하는 종류만 본다 — 제품 필름은 화면이 실제로 하는 일을 보여 주는가, 키네틱 타이포는 안정된 읽기 창이 있는가, 설명·데이터는 척도가 중요할 때 축이 값보다 먼저 읽히는가. 데이터 축이 없는 순수 타이포 필름에는 척도 검사를 적용하지 않는다.

### 아트·절차 장면과 전문 도구 작업 {#od-opendesign-motion-design--procedural}
- 쓰는 곳: 화풍 장면을 만들 때, 또는 사용자가 지정한 AE·Blender·Remotion 프로젝트가 있고 쓸 수 있어 그 모션을 고칠 때.
- 구성·시작값: 스타일의 구조(마크·재질·팔레트·구도·특징적 움직임 하나)와 표면 노이즈를 구분한다. 목판은 칼선 방향과 겹친 잉크, 칠한 밤은 일관된 곡선 붓질과 움직이는 빛, 종이 컷아웃은 평면 깊이·가장자리 그림자·힌지 동작이 구조다. 사람 정체성과 복잡한 해부는 도구가 허용하면 맞는 공급·생성 에셋을 쓰고 실루엣·팔레트·조명을 일관되게 둔다. 지정 프로젝트는 상태를 읽고 가장 작은 장면만 고쳐 편집 가능한 레이어·키프레임을 유지한다.
- 움직임·타이밍: 텍스처는 한 번 시드하고 일관된 필드로 움직인다. 정지한 그림 사이를 카메라만 오가지 말고 세계 안의 요소를 움직인다.
- 피할 것: 없는 에셋을 있는 척하기, 매 프레임 마크 재생성(깜빡임), AE·Blender·유료 제공자·새 프레임워크 설치를 기본값으로 삼기.
- 검수: 스타일 구조 요소가 모두 보이는가, 텍스처가 깜빡이지 않는가. 지정 프로젝트를 고쳤다면 최소 편집이고 편집 가능한 레이어·키프레임이 남았는가.

### 재현 가능한 모션 제작·소리 {#od-opendesign-motion-design--production}
- 쓰는 곳: 타임라인으로 모션 필름을 실제로 만들고 고칠 때(소리 정책은 영상 모션 한정이며 일반 프로토타입·문서·슬라이드·인터랙티브에는 브리프가 요구할 때만). 실행은 위 머리글의 게이트와 선택된 레인을 따른다.
- 구성·시작값: 길이·프레임 크기·팔레트·타입 스케일·이징·장면 타이밍을 작은 설정 하나에 모으고 장면별로 요소와 모션을 묶는다. 콘텐츠·데이터와 그리기를 분리하고 지오메트리·캐시 텍스처를 재사용하며 오프스크린 작업·파티클 수에 상한을 둔다. 이미 지원되는 렌더러가 있으면 다시 짓지 않는다. 음성·음악·효과를 따로 정한다. “보이스오버 없음”은 음성만 끄며 명시적 무음 요청이 이긴다.
- 움직임·타이밍: 어느 타임스탬프에서도 장면이 안정되고 앞뒤 탐색이 되게 한다. 위치·공개는 시간의 함수나 탐색 가능한 트랙으로 둔다. 음악을 음성보다 낮게 두고 액센트는 비트맵에 맞춘다. 오디오 반응 모션은 정확한 재생이 필요하면 미리 계산한 엔벨로프나 비트맵을 쓴다.
- 피할 것: 현재 시각·시드 없는 난수·0초부터 재생해야 하는 시뮬레이션에 기대기, 마스터 타임라인과 경쟁하는 독립 CSS 애니메이션, 임의 펄스를 음악 분석이라 말하기, 소리를 맥동 시각으로 대체하기.
- 검수: 오디오가 필요한데 만들지 못했으면 무음을 완성으로 납품하지 않고 막힘을 보고한다. 이유를 밝힌 의도적 무음은 유효하다. 렌더되지 않은 영상을 완성이라 하지 않는다. 오디오가 필요한 영상은 실제 출력에서 트랙이 들리는지, 핵심 소리가 계획한 시각에 나는지 확인한다.
출처: nexu-io/open-design@5a0c47777975 opendesign-motion-design

### 작업 중 점검과 결함→결정 {#od-opendesign-motion-design--review}
- 쓰는 곳: 만드는 동안 각 비트와 전환·엔딩을 점검할 때.
- 구성·시작값: 비트마다 초점·모션의 원인·읽기 시간·퇴장을 확인한다. 전환은 나가는 상태와 들어오는 상태와 겹침을, 엔딩은 해결·홀드 시간·반복 동작을 확인한다. 결함은 결정으로 바꾼다: 슬라이드쇼 같음→한 객체를 의미 있는 변형으로 운반, 모두 경쟁→주 동작을 정하고 보조를 줄이거나 늦춤, 무게 없음→이동 시간·가감속·예비·정착 조정, 텍스트 안 읽힘→홀드·대비 증가(카피 단축은 허용될 때만), 밋밋함→타입·구도·모티프 강화, 붓질 깜빡임→시드·캐시, 단조로움→샷 스케일과 동작/휴지 리듬 변화, 바쁘지만 말 없음→장식 제거하고 인과 동작 표시.
- 움직임·타이밍: 도구가 시각 점검을 허용하면 실제 크기에서 오프닝·핵심 변형·전환·텍스트 홀드·엔딩과 연속 재생을 본다. 가장 큰 결함 하나를 고친 뒤 영향받은 순간만 다시 본다. 계획만 요청된 산출물에는 재생 점검을 요구하지 않는다.
- 피할 것: 미감을 숫자 점수로 인증하기, 지어낸 품질 측정.
- 검수: 실행 가능한 파일만으로 모션 성공을 증명하지 않는다. 눈으로 본 것과 명세만 한 것을 구분하고 도구가 허용하지 않은 점검은 했다고 말하지 않으며, 쓸 만한 산출물·길이·화면비와 빠진 에셋·오디오·내보내기 능력을 간결히 보고한다.
출처: nexu-io/open-design@5a0c47777975 opendesign-motion-design

### 콘티 승인 뒤 샷별 모션 {#od-openmotion-storyboard-to-motion}
- 쓰는 곳: 정지 콘티를 승인한 뒤 제품 프로모·런칭 필름·기능 설명을 프레임 순서대로 움직일 때. 입력은 승인된 프레임·샷 순서·샷별 목표 길이·최종 카피이고, 브랜드 글꼴·실제 제품 화면·컷용 음악은 선택이다.
- 구성·시작값: 샷마다 구성을 하나씩 순서대로 두고 합치지 않는다. 정착 프레임은 승인 프레임 그대로(레이아웃·카피·크롭). 시작값(브랜드킷·사용자 브랜드 우선): 팔레트는 콘티·브랜드킷에서 가져온다(샘플: 남색 `#16223A`, 해 노랑 `#FFD54A`, 종이 `#EEF1FA`). 글꼴은 콘티의 디스플레이체와 본문용 하나. 헤드라인·숫자·라벨은 이미지에 굽지 않고 살아 있는 텍스트로 둔다.
- 움직임·타이밍: 시작값: 샷마다 등장 0.4–0.8초, 정확한 콘티 상태 홀드 1.2초 이상, 퇴장 0.3–0.5초. 레이어는 읽는 순서(배경→헤드라인→제품 증거→라벨→강조)로 80–120ms 간격. 필름 전체에 이징 계열 하나(fast-out 등장, ease-in 퇴장). 다음 샷은 앞 샷이 떠난 방향으로 이미 움직이며 들어와 샷 사이에 빈 프레임이 없다.
- 피할 것: 스틸 승인 전 애니메이션, 기능을 설명 못 할 만큼 제품 UI 단순화, 역할 없는 드리프트·바운스·무작위 회전, 한꺼번에 등장, 마지막 프레임에서 아무것도 없이 사라지는 퇴장, 지어낸 인용·숫자·사양·날짜.
- 검수: 각 홀드를 정지해 콘티 프레임과 비교하고, 이음매를 ±5프레임 훑어 빈·중복 프레임을 찾고, 샷 하나씩 따로 열어 편집되는지 본다. 없는 이미지·음성·음악 생성은 게이트를 거치고 유료는 승인 뒤에만 한다.
출처: nexu-io/openmotion@709b10fd9ac5 openmotion-storyboard-to-motion

### 로고 모션 {#od-logo-animation}
- 쓰는 곳: 인트로 스팅어·사인오프·앱 스플래시·로더 아이들 루프, 랜딩 히어로·쇼릴의 마크 공개. 영상 스팅어는 선택된 Remotion·FFmpeg 레인으로 렌더한다.
- 구성·시작값: 로고당 기법은 하나 — 선 그리기(선 마크·모노그램·서명), 마스크 와이프(채움 도형·그라디언트), 빌드온 스태거(다조각 마크·그리드), 모프(아이콘↔워드마크), 아이들 루프(로더), 워드마크(글자별 스태거). 빌드온은 기반·컨테이너→강조→워드마크 순이고 시작값은 조각 0.5초·스태거 0.08초·스케일 0.85→1이다. 정적 끝 프레임(SVG/PNG) 폴백을 함께 낸다.
- 움직임·타이밍: 공개는 0.8–2.5초. 사운드 로고가 있으면 오디오를 먼저 정하고 피크 시각을 찾아 마지막 안착 프레임을 그 피크에 맞춘다. 안착에 작은 오버슈트(스케일 1.04→1.00, 약 0.15초)를 줄 수 있다.
- 피할 것: 기법을 한꺼번에 쓰기, 브랜드 형태 왜곡(스케일·페이드는 안전, 스큐·스쿼시는 대체로 불가), 클리어스페이스에 모션 잔해, 소리와 따로 떠 있는 안착.
- 검수: 시작·중간·끝 고정 프레임에서 형태가 무왜곡이고 클리어스페이스가 비었고 끝 프레임이 반쯤 그려진 획 없는 진짜 로고인지 본다. 문제가 있으면 길이·이징을 고쳐 같은 시각을 다시 확인한다. 모션 감소가 적용되는 납품에는 최종 마크만 움직임 없이 보여 주는 경로를 항상 둔다.

### 색의 움직임: 팔레트·그라디언트·그레이드 {#od-color-motion}
- 쓰는 곳: 모션·영상의 팔레트, 그라디언트 배경, 색 전환, 무드 그레이딩, 탁한 보간 수정.
- 구성·시작값: 시작값 — 팔레트는 주색 1·강조 1·중립 2–3. 대비와 깊이는 색상 수가 아니라 명도·채도로 만든다. 어두운 장면의 강조색은 낮거나 중간인 채도·높은 명도로 하고 최대 채도는 쓰지 않는다. OKLCH에서 L·C를 고정하고 H만 돌리면 시각 무게가 같다(예: 주색 `oklch(0.62 0.19 264)`, 강조 `oklch(0.78 0.17 50)`). 중립은 주색 쪽으로 살짝 틴트한다. 보간은 OKLCH/Lab에서 하고 raw sRGB는 쓰지 않는다(웹 CSS는 `linear-gradient(in oklch, …)`). 프리미엄 그라디언트는 radial 여러 겹, 3–5% 그레인, 8–20초의 느린 ease-in-out 드리프트다.
- 움직임·타이밍: 색 전환은 등장·강조에 ease-out `cubic-bezier(0.16,1,0.3,1)`, 시작값 — 상태 변화 150–300ms, 전체 화면 워시 400–800ms, linear는 연속 루프만. 그레이딩 순서는 노출·화이트밸런스→대비→중간톤·채도→스플릿톤(청록 그림자+주황 하이라이트, 은은하게)→통일(최종 틴트·LUT·약한 비네팅)이며 작품 전체에 일관되게 한다.
- 피할 것: 색상 늘리기, 순수 회색 중립, raw sRGB 보간, 빠른 드리프트, 순서를 바꾼 그레이딩.
- 검수: 웹 팔레트·그라디언트·색 전환 납품에만 적용한다 — 시작·중간·끝 시각을 고정해 캡처하고 밴딩·탁한 회색 중간이 없고 명도가 고른지 본다. 있으면 채도·명도 조정이나 그레인 추가 뒤 같은 시각을 다시 확인한다. 구동은 하나만 두고 모션 감소에는 드리프트를 멈춘 정지 프레임을 항상 둔다.
출처: iart-ai/motion-design-skills@3c129f769d90 color-motion

### 렌더 색 관리: 색이 바래거나 이동할 때 {#od-color-motion--render}
- 쓰는 곳: 컴프 뷰어에서는 맞는데 QuickTime·브라우저·macOS/Windows에서 바래거나 밝거나 우윳빛이거나 감마가 이동할 때, 내보내기 색 태그를 정할 때. 원인은 작업 공간·렌더 태그·플레이어·디스플레이 감마의 불일치이지 작업물이 아니다.
- 구성·시작값: 원본 시작값 — 작업 공간은 SDR 영상에 Rec.709 Gamma 2.4, UI·스틸에 sRGB로 명시하고 “None”은 색 관리를 꺼 뷰어가 최종 모습을 속인다. 그레이드·그라디언트는 16 bpc로 밴딩을 막는다. 내보내기에 선택한 납품 프로파일의 태그를 명시한다. 마스터는 ProRes 422 HQ/4444 Rec.709, 웹·소셜은 H.264 Rec.709(Chrome에서 확인), HDR은 ProRes 4444/HEVC 10-bit Rec.2020 PQ/HLG(32 bpc float)가 출발점이다.
- 움직임·타이밍: 해당 없음(색 전달 문제). 웹 납품의 승인 기준 화면은 Chrome·Premiere·Resolve다.
- 피할 것: QuickTime(AVFoundation은 추가 약 1.96 감마를 적용)에서 그레이딩·승인하기, 태그 없는 내보내기(플레이어마다 기본값을 추측한다), 이동이 있는데 Preserve RGB 두기, Rec.709와 sRGB 혼용(중간톤 밝기가 이동).
- 검수: `ffprobe`의 `color_primaries`·`color_transfer`·`color_space`가 선택한 납품 프로파일과 일치하는지 본다(SDR Rec.709 예시는 bt709, HDR은 해당 프로파일 값). SDR 진단 예시: 50% 회색(RGB 128) 패치를 렌더해 다시 샘플링했을 때 150 이상이면 감마 이동이다. 모든 납품의 합격선은 아니다. 설정 위치는 앱마다 달라 같은 개념으로 확인한다. 최종 마스터 QC는 [23 피니싱](23-finishing-platform.md)과 함께 본다.
출처: iart-ai/motion-design-skills@3c129f769d90 color-motion

### 아트 애니메이션 복제 라우터 {#od-huashu-art-motion}
- 쓰는 곳: 기존 아트·영상 애니메이션을 복제하거나 같은 방식으로 새 아트 스타일을 만들어 달라는 요청. 원본은 코드 캔버스 엔진·스타일 카드로 안내하는 얇은 라우터이며 그 엔진은 들이지 않는다. 복제의 분해는 [25 레퍼런스 영상 분해](25-reference-video-analysis.md)를 따른다.
- 구성·시작값: 복제 흐름은 분해→메커니즘→복제이고, 새 스타일은 한 프레임 먼저→렌더러→움직이기다. 다섯 층 메커니즘은 고정된 장면 골격 × 막마다 살아 있는 그림(주인공 동작+스타일 모티프의 작은 루프) × 다음 스타일의 서명 언어로 전환 × 비트 격자 가속 × 연속 서사 닻과 엔딩 캐릭터 개그다. 복제는 메커니즘을 배우는 것이지 픽셀 복사가 아니다.
- 움직임·타이밍: 막마다 주 동작 최소 하나와 모티프 루프 최소 둘을 두고 프레임 차로 확인한다(전환 뒤 0.35초의 카메라 충격 제외). 난수는 시드를 쓰고 같은 시각을 두 번 렌더하면 픽셀이 같아야 한다.
- 피할 것: 새 캐릭터 해석이나 새 스타일 방향을 같은 프레임의 세 안 없이 정하기(스타일이 지정돼도 면제 없음. 이 라우터 한정이며 복제에는 걸지 않는다), 미성년자 설정 캐릭터에 짧은 의상.
- 검수: 원본은 자체 QA(안정·효율·역동감·유려)와 제작에 참여하지 않은 검토자의 완성본 시청, 둘 다를 완료 조건으로 둔다. 밝은 바탕·자막 없는 완성본이면 그래픽이 자막 영역에 들어오는지 확인한다(질감 바탕은 적용 제외).
