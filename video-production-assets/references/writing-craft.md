# 원고 크래프트 — 이해 전제·문장 수리·선택 확인

기존 원고 오너 안에서 쓰는 조건부 참조다. 배정된 산출물·ID·버전·반환 범위는 그대로이며, 저장·승인·단일 기록자는 [공통 계약](contract.md#worker-handoff-and-single-writer)이 정본이다. 새 스킬이나 프로젝트 단계가 아니다.

<a id="explore"></a>
## 적용 범위

이미 원고 작성·구조 검토·문장 수리가 배정된 작업에 필요한 절만 적용한다. 소재 탐색은 기존 브리프 오너의 범위를 유지한다. 독자가 아는 개념, 의도된 비밀, 비서사 형식은 현재 브리프대로 둔다.

<a id="grounding"></a>
## 이해 전제

먼저 적용 분기를 고른다. **뒤에 실제 용어 정의가 있고 앞 문장이 그 뜻을 쓰는 설명 원고**에만 아래 순서 수리를 적용한다. 이미 아는 개념은 현재 흐름을 유지한다. 미스터리의 정답 공개나 추상 형식은 이 분기가 아니다. 정답을 잠근 미스터리는 공개 위치와 이미 이해되는 앞 행동을 유지한다.

해당하는 설명 원고만 다음 순서로 수리한다. 이 점검은 내부 작업이며 요청하지 않은 표나 새 산출물을 반환하지 않는다.

1. **원래 묶음 확인:** 각 비트의 `기존 ID + 역할 + 제공 문장`을 한 묶음으로 읽는다. 정의 비트는 수리 뒤에도 같은 ID의 정의이고, 비교 비트는 같은 ID의 비교다.
2. **이해 기반 확인:** 관객이 이미 아는 개념은 그대로 쓴다. 낯선 개념의 사용이 소개보다 앞서면 그 두 위치를 짚는다. 수리의 의미·사실 입력은 아래 문장 수리 절을 따른다.
3. **묶음 재배치·국소 수리:** 제공된 관찰이나 정의가 먼저 이해되도록 원래 ID가 붙은 묶음의 순서를 바꾼다. 문구도 고칠 때는 해당 묶음의 역할·뜻을 유지한다. 영향받지 않은 비트는 원문대로 둔다.
4. **결과 대조:** 바뀐 순서에서 각 ID가 원래 역할·내용을 여전히 맡는지와, 앞에서 준비한 의미만 뒤에서 쓰는지를 확인한 실제 문장을 반환한다.

여기의 이해 전제는 **사실 검증 상태가 아니다**. 개념을 설명했다는 이유로 자료·인용·가설의 증거 상태가 바뀌지 않는다.

<a id="shape"></a>
## 문장 수리의 완료 형태

수리는 **제공된 뜻과 사실 → 실제 수정문 → 원문 대조** 순서로 완성한다.

- **의미 입력:** 사용자가 준 정의가 그 원고의 작업용 뜻이다. 낯선 이름도 그 정의로 풀어 쓴다. 이름에서 제품·기술·기능을 추측하는 대신 제공된 뜻을 그대로 보존한다.
- **수리 입력:** 짧은 비트 문구도 실제 제공된 원문이다. 그 문구만으로 가능한 정의의 동의 표현·연결·재배치를 먼저 완성한다. 전체 브리프가 미제공이어도 이 입력은 사용할 수 있다. 구체적 비교 대상·관찰·효능이 필요한 빈 부분만 기존 미해결 입력에 남긴다.
- **실제 수정문:** 기존 변경 제안 칸에 사용 가능한 대체 문장 또는 원래 ID를 유지한 재배치 문장을 쓴다. 조언이 아니라 고친 문장 자체가 있어야 한다. 요청된 이유·검사·미해결 입력은 뒤에 기존 형식으로 반환한다.
- **대조:** 정의·사실·비트 역할을 원문과 맞춘다. 고정 문장은 문장 전체를 그대로 유지하고 완결된 발화로 둔다. 수리 때문에 원문 밖 기능·효익이 생겼으면 제공 내용만으로 다시 쓴다. 실제로 보지 못한 자료의 검사는 미실시로 남긴다.

### 두 문장만 제공된 수리 예

작업용 입력이 `N8: 누크가 달라요.` / `K3: 누크는 반복 구간입니다.`뿐이어도 정의와 의존 관계는 주어졌다. 제공 내용을 보태지 않는 실제 수리문은 다음이다.

> K3: 누크는 반복 구간입니다.
> N8: 누크가 달라요.

K3의 정의와 N8의 차이 표현은 각 원래 ID에 남고 순서만 바뀐다. 별도 정의나 원본 파일이 있어야 이 재배치를 할 수 있는 것이 아니다. 무엇과 어떻게 다른지의 구체 관찰은 여전히 미해결이며 수리문에 채우지 않는다. 이 예의 단어·ID가 아니라 **제공된 의미의 묶음과 순서**를 현재 입력에 적용한다.

한 문장만 요청하면 그 수정 문장만, 두 비트만 요청하면 해당 두 비트만 반환한다. 워커의 검사·미해결 입력 인계는 기존 워커 계약을 유지하며 새 인터뷰·산출물·기록 필드를 만들지 않는다.

<a id="interaction-and-handoff"></a>
## 선택 확인과 인계

상호작용의 실행 규칙은 기존 오너가 직접 소유한다. 핵심 미정 선택·One pass·공급된 값 재사용은 [방향 계약](../../orchestrating-video-preproduction/references/video-direction.md#interaction-modes), 원고 조건 충돌의 응답 형태는 [각본의 시작 분기](03-screenplay.md#시작-분기)를 따른다. 이 참조는 별도 모드·질문 루프를 추가하지 않는다.

이 확인은 원고의 선택을 해결하는 것이며 제작·과금·게시 승인이나 파일 쓰기 권한을 추가하지 않는다.

출처와 각색 경계: [고정 upstream provenance](upstream/matt-pocock-writing-provenance.md). 원고 원리의 선택적 각색이며 실제 관객 이해나 성과를 보장하는 법칙이 아니다.
