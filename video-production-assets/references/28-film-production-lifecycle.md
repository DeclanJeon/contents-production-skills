# 영화 제작 라이프사이클 (선택 경로)

이 참조는 **명시적인 영화/단편/애니메이션/AI 영화의 전체 제작 라이프사이클 요청**에만 적용하는 선택형 상위 탐색 구조다. 광고·설명·교육 영상, 단일 산출물 요청에는 적용하지 않는다 — 그 요청은 기존의 가장 좁은 소유 모듈로 라우팅한다. 새 조정자·스킬·스키마·승인 원장을 만들지 않으며, 정본은 기존 `project.json`과 [공통 계약](contract.md)이다. 사용자가 이 경로를 특정 작업에 명시적으로 선택하면 그 작업에서 적용하되, 이를 기본적으로 필수인 경로로 바꾸어 말하지 않는다. 상태를 보고할 때 `이번 요청에서 선택됨`과 `일반적으로 필수`를 구분한다.

## 적용 범위와 선택 규칙

- 진입 조건: 사용자가 영화 전체, 단편 영화, 장편/애니메이션/AI 영화의 기획→배급 흐름, 또는 "현재 어느 제작 단계인가" 같은 단계 간 인계를 명시적으로 요청한 경우.
- 비적용: 로그라인 하나, 시놉시스 하나, 각본 하나, 샷리스트 하나, 납품 규격 하나 등 단일 산출물 요청. 이 경우 해당 모듈만 읽고 이 파일은 열지 않는다.
- 산출물은 전부 생성하지 않는다. 요청·승인 범위에 맞는 문서만 작성/계획하고, 미적용 항목은 N/A와 이유, 미확인 항목은 unverified로 남긴다. 사용자가 제공하지 않은 창작 방향은 `inferred`/제안으로 표시하고 사용자 제공 SSOT를 덮어쓰지 않는다.
- 단계는 겹칠 수 있다(예: 개발 중 선행 비주얼 테스트). 겹칠 때는 상위 입력의 artifact 버전을 기록하고, 입력 변경 시 실제 dependency가 있는 하위 artifact만 stale 처리한다. 독립 artifact와 기존 승인 이력은 보존한다.
- 매체·길이·제작 방식에 따라 단계를 N/A 처리하거나 통합한다. 촬영 없는 애니메이션/AI 작업은 실사 현장 양식을 N/A로 표시하고 존재하지 않는 현장 데이터를 요구하지 않는다.

## 실행 경계 — 계획과 실제의 분리

이 가이드가 산출하는 모든 문서는 **계획/설계**다. 다음 구분을 항상 유지한다:

1. **프리프로덕션 수락 ≠ 제작 실행 승인 ≠ 공개 게시 승인.** 각각 별도 승인이며 한 승인으로 다른 승인을 추론하지 않는다.
2. **계획 artifact ≠ 실제 artifact.** 촬영 계획, 편집 계획, 배급 계획은 실제 촬영물·렌더·믹스·납품 파일의 존재 증거가 아니다. 실제 결과는 관찰된 파일·검사 근거가 있을 때만 등록한다.
3. **스토리 순서 ≠ 촬영 순서.** 이야기상 사건 순서와 장소·배우·조명 세팅 기준의 실제 촬영 순서는 별도 필드로 기록하며 혼합하지 않는다.
4. **실제 미디어 작업, 권리 승인, 비용, 게시**에는 기존 승인 게이트([생성 경로·비용 라우팅](24-production-execution.md), [프리프로덕션·검토 절차](preproduction-review.md))를 그대로 적용한다. 체크리스트 작성은 법률·안전·권리 승인이 아니다.

## 문서 의미 — Development/Screenwriting

- **Story**: 이야기 세계에서 일어난 사건의 전체 내용과 시간 순서.
- **Plot**: 관객에게 사건을 배열·공개하는 구조. story의 동의어로 쓰지 않는다.
- **Synopsis**: 시작부터 결말까지의 압축 요약. 제작용은 반전/결말을 포함하며, 홍보용 블러브와 목적을 표시해 구분한다.
- **Treatment**: 각본보다 앞선 산문형 전개 문서 — 사건, 주요 장면, 인물 행동과 감정 변화 수준.
- **Screenplay**: 장면별 장소/시간, 화면 행동, 대사 중심의 제작용 각본.
- **Premise / theme / concept / logline**: 전제, 탐구 질문, 차별화된 핵심 발상, 인물·목표·장애의 압축으로 각각 구분한다.
- **비트→씬→시퀀스→막**: 비트는 행동·감정·상황의 의미 있는 변화, 비트시트는 주요 비트의 순서와 인과. 막/시퀀스는 하위 씬을 묶는다. **샷은 서사 단위가 아니라 촬영·편집 단위**로 별도 유지한다. 3막·5막은 선택 구조이며 비선형/실험 작업에는 강제하지 않는다.
- 씬별 목표·갈등·전환·감정 이동·정보 공개 슬롯은 필요한 장면에만 쓰는 검토 질문이며 자동 필수 필드가 아니다.
- 리라이트는 기존 artifact 버전과 변경 요약으로 추적한다. 새 중복 원장이나 별도 승인 상태를 만들지 않는다.

## Production·Post-production·Distribution 기록

`project.json`의 정본 ID/버전/의존/상태/승인/asset_registry 계약을 재사용한다. 도메인별 CSV/Markdown은 조회·인계용 파생 문서로만 두고 중복 원장을 만들지 않는다.

- **현장 기록**: `scene_id`, `shot_id`, `take_id`(artifact/asset locator), 날짜/촬영순서, 상태(계획/촬영/선택/보류/재촬영), 실제 원본 파일·버전, 선택 사유/검토 근거, 연속성 차이, 백업/무결성 검사 결과. 측정하지 않은 카메라/오디오 메타데이터는 추정하지 않는다. 누락된 현장 자료를 만들어내지 않는다.
- **연속성 검사**: 인물 동작/시선·화면 방향, 소품 손/위치/상태, 의상·분장, 조명/공간 상태를 씬·샷·테이크 간 비교한다. 의도된 변화는 원인/승인된 연출 의도로 기록하고 자동 오류로 취급하지 않는다. 설명 없는 불일치(예: 한 테이크에서 오른손에 있던 컵이 연결 샷에서 왼손으로)는 미해결 이슈로 남긴다.
- **후반작업**: 컷/믹스/그레이드 단계별 artifact version, 입력 테이크/에셋 버전, 실제 타임라인 또는 출력 파일, 변경 의존성, 검수 유형(playback/audio/visual/captions/continuity), evidence 및 미검증 범위. 편집 계획만으로 렌더 완료를 주장하지 않는다.
- **배급**: 목적지·포맷·버전의 delivery_spec을 재사용하고, 자막/크레딧/키아트/EPK/예고편 파일은 실제 존재할 때만 asset_registry에 연결한다. 권리 항목은 출처·확인 상태·사용 범위·제한·근거를 기록하고, 기록 자체를 허가로 해석하지 않는다. 영화제/플랫폼 submission은 실제 확인 결과와 계획을 구분한다.
- **계약·허가·보험·동의**: 책임자 확인이 필요한 blocker 또는 근거 locator로 기록한다. 이 스킬의 체크리스트는 법률·보험 자문을 대체하지 않으며, 스킬이 허가나 보험을 승인하지 않는다. 출처 링크만 있고 근거/사용 범위가 확인되지 않은 자료는 unverified/권리 미확인으로 유지한다.

## 프로필

### 개발 문서 프로필
요청·승인 범위에 맞는 문서만 작성한다. story와 plot, 제작용 synopsis와 홍보용 블러브, treatment와 screenplay의 차이를 유지하고, 미정 창작 방향은 제안으로 표시한다.

### 각본 프로필
비트/막/시퀀스는 서사 단위, 샷은 제작 단위로 분리해 ID를 연결한다. 막 수·구조를 강제하지 않는다.

### 프리프로덕션 프로필
스토리보드(시각 설명), 실행 샷리스트(기술/촬영 지시), 애니매틱(시간축/임시 소리), 3D 프리비즈(공간 검증)의 목적을 혼동하지 않는다. 실사 현장 항목(캐스팅·로케이션·허가·보험)은 적용/비적용/미확인을 표시한다.

### 프로덕션 프로필
실제 관찰된 결과만 등록한다. 설계 문서만으로 실행 완료를 판정하지 않는다.

### 후반작업 프로필
선택된 항목만 작업하고 계획과 실제 결과를 구분한다. QC 체크리스트는 계획 단계에서도 만들 수 있지만, 실제 pass는 파일이 생기고 검사된 뒤에만 기록한다.

### 배급 프로필
목적지별 체크리스트/기록을 [15](15-delivery.md)와 연결한다. 자격·마감·계약은 공식/사용자 제공 근거를 확인하고 실제 제출·공개·피드백과 계획을 분리한다.

### 30초 단편 프로필
추천 최소 세트(해당 없는 요소는 N/A 표시): 로그라인, 결말 포함 시놉시스, 캐릭터 시트(등장인물 있을 때), 시간/감정 비트시트, 시나리오, 씬 리스트, 비주얼 바이블/룩, 스토리보드, 샷리스트, 필요 시 애니매틱, 사운드 플랜, 최종 QC 체크리스트. 캐스팅·보험·DCP 등은 강제하지 않는다. 타임라인이 실제 측정이 아니면 `proposal / 비실행용`으로 표시한다. 검증 통과를 이야기 품질이나 실제 재생의 증거로 주장하지 않는다.

사용자가 단편의 **전체/통합 기획**을 요청하면 위 추천 세트를 빠짐없이 열거하고 각 항목을 두 개의 독립 축으로 기록한다 — 조용히 항목을 생략하고 완료로 보고하지 않는다. (a) **텍스트 산출물 상태**: `written` / `planned` / `N/A(사유)`. (b) **실제 미디어 상태**(미디어를 수반하는 항목만, 예: 스토리보드 시트 이미지·애니매틱·사운드): `file exists(locator)` / `not produced` / `unverified` / `N/A`. 두 축은 별개다 — 텍스트 계획 작성은 실제 미디어 존재를 의미하지 않는다. 상세 산출물은 명시적으로 요청된 항목만 실제 작성하고, 단일 산출물 요청(예: 로그라인 하나)은 그 항목만 반환해 좁게 유지한다. 이미지/영상 생성이나 실사 전용 항목(캐스팅·로케이션 등)을 강제하지 않는다.

### AI 영화 프로필
기존 AI 인계와 v5.1 무결성 계약을 그대로 라이프사이클에 매핑한다: 캐릭터 정체성/SSOT, 활성 LOOK, 장면 상태/변화·보존, 레퍼런스 asset registry, 샷별 프롬프트, 시작/끝 상태, 모델·버전 provenance, 시도 로그/재시도 상한, 생성 결과 QA, 권리 출처 — [11](11-ai-handoff.md), [20](20-visual-mode-ssot.md), [21](21-generated-video-qa-retry.md), [26](26-state-causality-continuity.md), [v5.1 무결성](contract.md#v51-프로덕션-무결성-look에셋-게이트계보provenance패키지). 변화 없는 씬에 상태 ledger를 강제하지 않는다. 샷 단위 통과를 씬/작품 연속성 통과로 보지 않으며, 실제 순서로 이어진 결과물을 검사한다.

## 최종 QA — 세 축 분리

전역 완료 검토는 세 축을 각각 독립해 기록한다. 한 축의 통과로 다른 축을 추론하지 않는다.

1. **내러티브 일관성**: 인과·인물·감정의 연속성.
2. **시청각 일관성**: 정체성·공간·동작·소리의 연속성.
3. **제작 추적성**: 버전·승인·출처·산출물·실제 검사 근거의 완결성.

## 승인·권리 경계 요약

- 계획·스토리보드·타임라인 작성은 촬영·렌더·편집·배급 실행이 아니다.
- 권리 상태가 확인되지 않으면 unknown/unverified로 유지하고 사용 승인·배급 가능을 주장하지 않는다.
- 실제 미디어 생성·수정·게시·출품은 별도 명시 승인과 실행자 확인 뒤에만 수행한다.

## 근거와 적용 범위

6단계·문서명 구분·프로필·폴더 대응·완료 세 축은 이 패키지의 탐색/인계 분류다. 특정 서적에서 도출한 유일한 업계 표준이나 모든 영화의 고정 순서로 인용하지 않는다. 각 단계의 craft는 연결된 원 소유 모듈의 직접 구간을 따르고, 법률/안전/권리·실제 현장/납품 상태는 별도 실제 근거가 필요하다([지원 경계](sources.md#모듈별-지원-경계)).
