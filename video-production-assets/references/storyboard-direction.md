# 스토리보드 — 연출과 상태 설계

완전 제작용 텍스트·이미지 보드 설계/수정/검토의 필수 정본이다. [완전성 core](storyboard-contract.md)의 모든 반환 구획·샷/패널 슬롯을 함께 적용한다. 기존 절 번호 §n은 core의 호환 절과 해당 정본을 가리킨다. 실제 이미지 QA는 [media](storyboard-media.md), 파일 납품은 [delivery](storyboard-delivery.md), JSON 편집은 [schema](storyboard-schema.md) 단계에서만 추가한다.

### 대사별 발화 얼굴과 청자 반응

대사가 있는 제작용 보드는 **모든 발화 ID를 실제 화자·화면 안/밖·화면 구간에 연결하고, 정보·감정·행동을 바꾸는 중요한 반응을 읽히게 설계**한다. 발화마다 화자 얼굴과 청자 반응을 별도 샷으로 배정하는 규칙은 아니다. 별도 싱글, 투샷/와이드 안의 블로킹, 청자를 유지하는 화면과 화면 밖 화자, 원테이크 중 프레이밍을 장면 목적에 맞춰 선택한다. 기존 샷/패널 표에 발화 ID, 화자·청자, 선택한 화면/반응 구간과 패널 ID를 연결한다. `start / action_peak / end / hold` 패널 역할 enum은 그대로 두고 발화/반응 기능은 기존 행동·연기 설명에 기록한다.

- 발화 구간: 정확한 원문·화자·발화 구간, 화면 안/밖, 말의 의도와 시선 대상을 지정한다. 입이 보이면 립싱크를 검사하고 화면 밖이면 사유 있는 N/A로 기록한다. 화자의 얼굴이 항상 보일 필요는 없다.
- 반응 컷: 어느 말/정보가 반응을 일으키는지, 청자와 반응 시작·정점·정착, 다음 컷으로 이어지는 상태를 지정한다. 눈·눈썹·입·고개·몸·시선 중 실제로 변하는 것을 적고 정점이 중요한 경우 해당 패널을 만든다. “더 극적으로/재미있게”라는 형용사만으로 대체하지 않으며 강도는 브리프·인물 설정에 맞춘다.
- 반응 중 앞 화자의 소리가 이어지는 J/L-cut은 기존 오디오/편집 명세에 연결한다. 화면에 보이는 청자가 그 대사를 말하는 것으로 바꾸거나 같은 발화를 두 번 생성하지 않는다. 반응 컷의 입은 청자의 실제 발화가 시작되기 전까지 말하지 않는 상태다.
- 이미 끝난 발화는 반응의 원인 ID로 행동/연기 설명에 참조한다. 반응 패널의 `speech_ids`에는 실제 그 구간에 이어지는 발화만 연결하며, 원인 참조를 현재 발화로 중복 등록하지 않는다.
- 다음 차례에 청자가 화자가 되면 실제 발화와 중요한 반응의 연결을 갱신한다. 한 반응 구간이 여러 발화를 받으면 해당 ID와 구간을 명시한다. 별도 반응을 제시하지 않는 발화는 반응 없음/유보/동일 프레임 내 처리와 그 이유를 기존 행동·연기 설명에 적는다. 새 정보나 선택이 없는 말마다 표정 변화를 만들지 않는다.
- 잠긴 원테이크에서는 컷을 삽입하지 않고 필요한 발화/반응을 같은 프레임의 동시 연기 또는 프레이밍 변화로 읽히게 한다. 독백·화면 밖 청자·나레이션·무음처럼 청자 반응이 비적용이면 이유를 해당 행에 남긴다. 고정 패널 수로 중요한 상태 변화를 표현할 수 없으면 기존 수량/스토리 충돌 절차로 반환한다.

모든 발화의 화면/음성 대응과 중요한 반응의 증거 또는 사유 있는 유보/N/A가 연결되고, 필요한 표정·몸짓·관계 변화를 실제 패널에서 읽을 수 있을 때 해당 커버리지가 닫힌다. 와이드라는 이유만으로 통과/실패시키지 않고 출력 크기에서 필수 반응이 읽히는지 검사한다. 텍스트 설계만 있으면 이미지·발화·립싱크 검수는 여전히 미검증이다. 생성 길이에 따른 전달은 §7의 [타임라인 인계](../../creative-production/references/storyboard-timing-to-prompt.md)를 따른다.


### 씬별 카메라 의도와 인접 씬 비교

완전한 제작용 보드에는 기존 `scene_id`와 해당 `shot_id` 목록으로 연결한 **씬당 한 행**의 간결한 카메라 의도 표를 같은 보드 문서/시트 안에 둔다. 별도 원장이나 새 필수 `project.json`/기계 판독 스키마 필드를 만들지 않는다. 먼저 장면의 목적·정보/감정 변화·블로킹·제약을 정하고, 그 목적에 맞춰 씬의 카메라 처리와 개별 샷을 설계한다. 움직임을 먼저 고른 뒤 이유를 붙이지 않는다.

| 씬별 기록 | 필수 결정 |
|---|---|
| 연결 | 기존 scene_id와 이 의도가 적용되는 shot_id 목록 |
| 씬 목적 | 전달해야 할 이야기·정보·감정 변화 |
| 진입 → 종료 지식/상태 | 관객과 화면 속 주체가 전후에 알거나 느끼는 것 |
| 장면 리듬 | 기존 shot/panel ID 순서로 축적·변화·쉼/여운의 위치, 샷 내부 행동 비트와 컷/hold 이유; 적용되지 않는 단계는 사유 |
| 감정 가독성 | 자극→관찰 가능한 변화→선택/결과, 그 변화를 읽을 화면 크기·시점과 감정을 공개하거나 유보할 이유 |
| 공간 관계 | 시작→끝 거리·장벽·높이·시선/배치와 관계 의미의 유지/변화; 평면/추상/인물 없음은 해당 정보 위계 또는 사유 있는 N/A |
| POV와 축 | 관객의 관점, 피사체/행동 축, 계획된 재정위 |
| 카메라 문법 | 프레이밍/샷 크기 진행, 주목점 위계·구도, static/무빙 선택 |
| 무빙 동기 또는 static 이유 | 무빙의 시작 계기·따라가거나 공개할 대상·샷 로컬 타이밍·정착/컷; static이면 왜 정지가 더 적합한지 |
| 인접 씬 관계 | 앞/뒤 씬과 목적·관객 지식 변화·POV/축·프레이밍 진행·static/무빙·공개/행동 타이밍을 비교한 대비 또는 연속성의 이유. 첫/마지막 씬은 존재하는 이웃만, 단일 씬은 이웃 없음으로 표시 |
| 재사용 이유 | 씬 사이에 같은 세팅/처리를 의도적으로 반복할 때 유지할 축·모티프·POV·리듬·대비 등의 목적 |
| 상태/증거 | planned / inspected / unverified와 실제 검사 범위; 이미지/프리비즈 증거는 실제 존재하고 검사했을 때만 ID/위치로 연결 |

이 행은 위의 **모든 샷별 슬롯을 요약·비교할 뿐 대체하지 않는다.** 각 샷은 비트에 맞는 카메라 선택과 이유, 시작/끝 프레이밍, 이동이 중요할 때 행동/공개와 연결된 로컬 타이밍을 유지하고 필요한 수치 공간 명세도 별도로 연결한다. 반복 처리는 값이 채워졌다는 이유만으로 통과하지 않지만, 씬마다 다른 렌즈·각도·무빙이나 수치적 고유성 점수는 요구하지 않는다. Static도 동등한 선택이며 가독성을 약화시키는 장식적 무빙은 제거하거나 동기를 보완한다. 대안은 결과에 중요한 미해결 선택에만 비교하고 잠긴 방향은 재사용한다.

씬 의도·카메라 필드·무빙·scene_id만으로 Blender 실행을 요구하지 않는다. 서사/일반 2D 카메라 계획과 3D 배치 검증을 구분하며, 수치 설계만 있고 실제 3D 검증 산출물 요구가 없으면 미렌더 geometry는 `UNVERIFIED`다. 명시적 Blender/프리비즈 요청, 또는 경로·가림·간격·블로킹·접촉 등 실제 씬별 3D 배치의 검증에 의존하는 결과는 아래 전문 인계 분기를 따른다. 텍스트-only에서는 실행하지 않고 필요한 검증을 planned/unverified 또는 blocker로 남긴다.


### 장면 리듬과 감정 가독성

최종 패널 전에 위 씬 의도 표와 기존 샷·편집 필드로 다음을 설계하고, 이야기 순서로 검수한다. 이는 패키지의 정성 설계/QA 절차이며 관객 반응의 실측이나 기법별 효과 보장이 아니다.

1. **목적에서 시간으로:** 관객이 시작/끝에 무엇을 다르게 알거나 느끼는지 정하고, 중요한 자극·행동·공개·반응·선택·결과를 해당 shot/panel ID에 연결한다. 축적·전환·쉼은 장면에 필요한 것만 선택한다. 정보/추상형에는 갈등·반전·감정 고조를 강제하지 않는다.
2. **샷 내부와 컷 사이:** 같은 샷 안의 시선·호흡·몸짓·초점/주목점 변화와, 샷 사이의 크기·시점·움직임·명암/색·소리 변화를 나눠 본다. 컷마다 들어갈/나올 계기와 남길 반응/정착을 적는다. 유지·반복에는 기다림·억제·비교·모티프 등 그 구간의 기능을 적으며, 새 동작을 채워 넣어야만 hold가 성립하는 것은 아니다.
3. **감정의 거리:** 미세 표정이 핵심이면 실제 출력에서 읽히는 MCU/CU 등을 검토한다. 손·자세가 핵심이면 인서트/MS, 관계·고립이 핵심이면 투샷/와이드·여백, 감정 유보가 목적이면 거리/가림/뒷모습 등을 비교해 필요한 정보와 잃는 정보를 기록한다. 이는 선택지이며 감정=CU, 와이드→미디엄→CU의 고정 순서가 아니다. 결정적인 접근·반응의 시점과 그 전후 대비가 비트에 맞는지 본다.
4. **공간의 의미:** 관계를 표현하는 거리·장벽·높이·시선·전경/중경/배경이 어떤 행동으로 유지/변화하는지 시작/끝 상태를 대조한다. 숫자 거리·깊이 단서의 존재만으로 관계 전달을 통과시키지 않는다. 평면 구도나 고정 거리가 의도에 맞으면 보존한다.
5. **무빙의 기능:** 무엇을 따라가거나 드러내고 언제 멈추는지, 왜 컷/고정보다 적합한지 확인한다. 고정이어도 화면 안 행동·기대·침묵·정보 유보로 리듬을 만들 수 있다. 무빙/컷 수·샷 크기 비율·일정 초 간격을 **보편 품질 기준**으로 쓰지 않는다. 보드가 `storyboard.rhythm`을 선언한 경우 검사 대상은 선언과 계획·실측의 **자기 일관성**이며, 외부 표준과의 일치는 검사하지 않는다. 선언이 없으면 기존 규칙 그대로다.

시트의 중요한 무빙은 기존 카메라 캡션·시작/끝 패널·로컬 cue로 방향과 공개 순서를 찾아볼 수 있게 한다. 주석이 필요하면 clean 이미지 밖 검토 영역/연결 표에서 인물 동선과 카메라 동선을 구별한다. 생성 이미지 안에 화살표를 그리는 것으로 동작 증거를 대신하지 않는다.

**시간 검수는 이미지 읽힘과 별개다.** 리듬의 실제 통과를 요청받으면 승인 범위 안의 러프 애니매틱 또는 시간에 맞춰 넘기는 보드를 재생해 장면 전체의 공개·반응 지연·hold·컷 시점과 해당 음향을 대조한다. [09-edit](09-edit.md)의 신체/감정/사건 리듬과 기존 편집 표에 위치·관찰·수정을 기록한다. 무음 작품에는 소리를 추가하지 않는다. 텍스트-only/이미지 시트만 요청이면 설계와 이미지 가독성까지만 검사하고 시간 재생은 planned/unverified로 남긴다. 이 규정이 애니매틱·음성·영상 생성이나 추가 지출을 자동 허용하지 않는다.


### 씬 카메라 수락 검사

아래를 이야기 순서의 보드에서 대조하고 실패/미검증 위치를 기존 §6 수정표의 scene/shot/panel ID로 반환한다.

1. 모든 씬에 의도 행과 담당 shot ID 연결이 있어야 한다. 누락 씬이나 연결되지 않은 샷이 있으면 FIX다.
2. 모든 샷의 카메라 선택이 해당 비트/씬 목적에 맞고 기존 기술 슬롯이 채워져야 한다. 사유 있는 N/A·단계에 맞는 deferred·명시적 blocker는 구분해 기록한다. 씬 요약으로 샷 슬롯을 대신하거나 미결정 실행 슬롯을 완성으로 보고하면 FIX다.
3. 모든 인접 씬 전환에 목적·관객 지식 변화·POV/축·프레이밍 진행·static/무빙·공개/행동 타이밍에 근거한 대비/연속성 결정이 있어야 한다. 의도적 반복에 이유가 없거나 어느 씬에나 붙일 일반 문구뿐이면 FIX다. 같은 렌즈/무빙 값 자체는 실패 사유가 아니다.
4. 순서대로 축·화면 방향·공개/접촉 타이밍·필수 행동 가독성을 대조한다. 조기 공개·설명 없는 축 혼란·가려진 필수 동작 등 요구와 모순되는 위치는 FIX이며 필요한 증거가 없으면 미검증이다.
5. 텍스트 계획 검사와 실제 이미지/프리비즈 검사를 별도로 보고한다. 아직 열어 검사하지 않은 이미지/3D 주장은 `UNVERIFIED`로 남긴다. 필드 채움이나 구조 validator 통과만으로 시각·창작적 수락을 선언하면 FIX다.
6. 위 장면 리듬 설계를 같은 씬 안의 샷 순서와 인접 씬 전환에서 대조한다. 중요한 자극/공개보다 반응이 앞서거나, 필요한 표정/몸짓·관계가 선택한 화면에서 읽히지 않거나, 반응/결과를 읽기 전에 자르는 위치는 해당 ID의 FIX다. 계획만 있으면 결함 가설과 실제 관찰을 구분한다.
7. 동일 크기·길이·구도·무빙의 반복은 기능과 중요한 비트의 가독성으로 판단한다. 근거 없는 기법 추가나 발화별 자동 교차 편집으로 장면의 필요한 호흡을 없애면 FIX다. **의도적 균등 템포는 `cadence: steady`와 사유를 곡선에 적으면 그대로 통과한다.** 선언 없이 균등한 경우도 실패는 아니지만, 리듬 리뷰에서는 `observation: 균등 템포`로 1회 보고한다.
8. 텍스트 설계 / 실제 이미지 가독성 / 시간 재생의 범위·근거·미검증을 각각 보고한다. 정지 시트나 설명만 보고 장면의 실제 리듬까지 통과시키면 FIX다. 요청에 없는 시간 재생은 실행하지 않고 그 검증 한계를 적는다.

이 검사는 텍스트 설계의 완결성과 실제 시각 증거를 구분한다. 텍스트-only의 계획 검사를 통과해도 이미지/3D 검사가 완료된 것은 아니며, 요청된 단계에 필요한 미검증 항목은 기존 blocker/미검증 규칙을 따른다.


### 카메라·공간/Blender 분기

정확한 좌표·피사체 거리·렌즈/경로 요구, 여러 피사체 접촉·가림·축 전환, 또는 Blender 요청이면 `camera-spatial-design`을 필수 적용해 미터 좌표·카메라 후보·전 프레임 경로/거리/화각 검사를 작성한다. 단순 정보 그래픽은 공간 수치 N/A 사유를 기록할 수 있다. 화면 좌우와 월드 X를 같은 것으로 가정하지 않는다.

실제 3D 배치 검증이 요청됐거나 수치만으로 가림/카메라 경로를 판단할 수 없으면 `blender-previsualization`에 **동일 shot/scene ID·fps·명세 버전**을 인계한다. 실제 3D 배치가 필수가 아니면 카메라 수치만으로 해부학적 동작/접촉을 통과시키지 않는다. Static BBox, raycast, or centerline-only proxies cannot verify articulated contact, prop ownership, crouch/reach, or handoff. 필수 접촉 beat는 해당 프레임의 articulated body와 실제 접촉면 상태를 검사한다. 근거가 없으면 claim을 `UNVERIFIED`로 두고 겹침·가시성·카메라 적합성만으로 통과시키지 않는다.
요구 접촉 근거가 없을 때 반환하는 **indexed missing-evidence packet**은 기존 요청/검토 결과 안의 행으로 작성한다(새 승인 원장이나 미디어 아티팩트 아님). 필드: `scene_id`, `shot_id`, `beat_id`, `panel_id`, `frame_time_s` 또는 필요한 프레임 구간, 요구 동작/접촉 대상·접촉면, 실제 확인한 증거와 locator/version/hash 또는 `NONE`, 빠진 증거, 필요한 articulated asset/pose/runtime와 소유자, 차단되는 dependent asset/generation, 재검사 가능한 수락 기준. 미확인 값은 `UNKNOWN`으로 두고 번호가 없는 샷을 추정하지 않는다. [프리프로덕션 검토](preproduction-review.md#3-검토용-이미지는-codex-imagen-기본-경로)와 [스토리보드 스킬 인계](../../storyboarding-video/SKILL.md#missing-specialist-inputs)는 같은 packet을 사용한다.


### 씬 경계와 시트 페이지화는 별도 결정

씬(scene), 샷(shot), 패널(panel), 시트(sheet)는 서로 다른 설계 단위다. 씬 경계는 이야기의 연속성과 장면 목적을 기준으로 정한다. 시간·장소·상황의 의미 있는 리셋이나 극적 목적·관객/인물의 지식 상태 변화가 있으면 새 씬을 검토한다. 반대로 대사, 리액션, 정보 공개, 카메라/샷 변경만으로 씬을 나누지는 않는다. 같은 시공간에서 이어지는 행동은 기본적으로 beat/shot/panel에서 표현하고, 의미 있는 씬 전환은 기존 씬 목적·인접 씬 비교 행에 이유를 남긴다. 이 판단으로 사용자 고정 패널 수나 승인된 이야기 순서를 바꾸지 않는다.

씬→샷→패널의 정본 순서를 확정한 다음 시트를 독립적으로 페이지화한다. 한 시트에 여러 씬이 들어갈 수 있고, 한 씬이 여러 시트에 걸칠 수도 있다. 페이지 수·시트 채우기·장면 개요 수를 맞추려고 씬 ID나 패널을 만들거나 연속된 씬을 분할하지 않는다. 페이지 경계는 최대 8패널을 지키고, clean 이미지와 캡션이 출력 크기에서 읽히도록 필요하면 더 적게 배치한다. 씬 경계와 페이지 경계가 맞으면 유지할 수 있지만, 이를 강제해 커버리지나 가독성을 해치지 않는다.

**제작용 기본 밀도는 시트당 최대 4패널이며, 총 패널 수의 기본값이 아니다.** 표정·접촉·긴 캡션·세로 화면처럼 세부 판독이 중요하면 1–2패널, 간결한 개요는 실제 출력 크기에서 읽히는 것을 확인해 6–8패널까지 명시적으로 선택한다. 8은 현재 제작 시트·검증·추출 도구의 지원 상한이지 더 좋은 이야기를 만드는 숫자가 아니다. 3×3·9패널은 러프 아이디어/외부 참조 배치일 수 있지만 제작 시트의 고정 규격으로 가져오지 않는다. 승인된 이야기가 9패널이면 9개 모두 보존하고 여러 시트로 나눈다.

페이지화 검수에서는 정본 순서·전체 커버리지와 함께 실제 전달 크기에서 얼굴/손/공개 정보·캡션의 판독성을 확인한다. 읽히지 않으면 이미지·글자를 줄이기보다 시트당 패널 수를 낮춘다. 마지막 장이 비어 보인다는 이유로 패널을 추가하지 않으며, 필요하면 `--panels-per-sheet`를 조정해 같은 정본을 다시 배치한다. 시트의 여백·페이지 전환은 컷 길이나 장면 리듬의 증거가 아니다.

스토리·감정·정보 전달에 영향을 주는 시각 선택이 미해결이면, **최종 패널 이미지 전에** 해당 비트/씬의 저비용 썸네일 수준 대안으로 샷 크기·시점·스테이징·공개 순서를 비교한다. 대안은 승인된 이야기·사건 순서를 보존하고, 차이가 실제로 중요한 씬에만 만든다. 목적이 분명한 씬마다 대안을 강제로 만들거나 최종 이미지 수에 중복 산입하지 않는다. 대안별 효과와 위험을 짧게 적고 추천 방향과 승인 상태를 표시한다. 콘셉트 피치가 미승인 방향을 제시하는 단계라면 대안은 제안으로 남기며, 촬영 실행 사양으로 확정하지 않는다. 텍스트·러프 계획은 미디어 생성 승인이 아니며, 실제 썸네일 이미지 생성은 기존 이미지 실행 승인·비용 규칙을 따른다.


### 단일 프레임 3단 상황 압축과 정지화 역동성 변환 (Kinetic Still Translation)

컷별 정지 이미지(Key Panel Still)의 목적에 맞는 읽힘을 위해 아래 선택 레시피를 사용한다. 1초 내 이해나 특정 감정 전달을 보장하지 않는다. 3단 깊이·C/S자·광각·안면 부위 수는 과장된 인간형 액션에 해당할 때만 적용하며, 평면/정적 구도·비인간·얼굴 유보에는 대체 큐 또는 사유 있는 N/A를 허용한다. 기존 필드의 optional/strict 구분과 승인된 적용 가능한 프로젝트 제약은 유지한다. 4의 단발 I2V 구조 조건은 그대로 적용한다.

1. **3단 깊이 상황 압축 (`focal_hierarchy`)**: 한 프레임 안에 단순 행동 동사만 그리지 말고, **① 1순위 초점(전경/주점: 카메라 코앞까지 뻗어 나온 손·소품·위협 실루엣)** → **② 2순위 상호작용(중경: 주체의 핵심 행동·안면 표정·상대방과의 시선/거리 벡터)** → **③ 3순위 배경 맥락(배경: 장소 상태·시간·직전 사건의 잔류 흔적)**을 깊이(Depth)로 배치해 전후 인과를 한 장에 압축한다.
2. **정지화 역동성 단서 (`kinetic_cues`)**: 액션·추격·충돌·급전환 컷의 `action_peak` 패널에서는 수직 기립 정자세를 금지한다. **① 무게중심 붕괴와 C/S자 동세선(Line of Action)**, **② 광각(14–24mm)·로우/더치 앵글 기반 포어쇼트닝(Foreshortening)**, **③ 2차 물리 관성(Secondary Action: 급격한 이동/정지 반대 방향으로 휘날리는 코트 자락·머리카락, 지면 마찰 먼지·파편·스파크, 배경 방향성 스피드 블러)**을 명시한다.
3. **안면 해부학 및 신체 텐션 (`expression_pose`)**: `"긴장한"`, `"설득한다"` 같은 추상적 라벨 단독 기재를 금지한다. 캐릭터 SSOT §10(`Expression DNA`)과 연동하여 **눈(동공 수축·크게 뜬 흰자위 노출·초점 방향), 눈썹·미간(비대칭 찌푸림·치켜올림), 입·턱(악문 어금니·벌어진 입술·턱 근육 긴장), 목·어깨·손끝의 경직도** 중 최소 2개 이상을 구체적 시각 단어로 기록한다.
4. **한·영 이중 프롬프트 (`image_prompt`) 및 단발 액션 I2V 키프레임 (`keyframe_mode: single_i2v`)**:
   - 패널별 `image_prompt`는 한국어 사용자가 즉시 상황을 파악하는 `[KO 연출 직관 요약]`과 이미지/영상 생성기의 광학·물리 토큰 반영률을 높이는 `[EN 시네마틱 프롬프트]`를 함께 기록한다.
   - 기본 변화 샷은 `start`와 `end`(필요 시 `action_peak`) 패널을 모두 갖추지만, 2초 이하의 빠른 단발 액션·컷인(Cut-on-Action) 샷에서 I2V 단일 프레임 앵커링을 사용할 때는 `shot.keyframe_mode = "single_i2v"`를 선언하고 단일 `start` 또는 단일 `action_peak` 패널 1장만으로 구성할 수 있다.


### 동작 중심 패널의 장면 통합

- 스토리보드 이미지는 정지 keyframe이지만, 동작/상호작용이 장면의 핵심일 때는 해당 시점의 진행 상태를 보여야 한다. start/action_peak/end 패널은 실제로 구별되는 before/action/after 상태를 보이며, 각 전환에서 변한 자세·손·시선·제품 위치/접촉 상태·카메라 구도를 명시한다. 필요한 상태 변화가 하나도 보이지 않으면 panel을 추가/수정하거나 해당 동작을 `UNVERIFIED`로 둔다. 같은 정면 포즈 반복이나 카메라 크롭만으로 행동 변화를 대신하지 않는다.
- 제공된 인물/캐릭터 이미지는 정체성·외형 reference이고, 제품 packshot은 형상·라벨·재질 reference다. 별도 collage/reference-board 요청이 아닌 한 해당 이미지를 완성된 인물/제품 컷아웃처럼 배경 위에 붙이지 않는다. 장면마다 포즈·블로킹·카메라를 새로 스테이징하고 제품을 물리적 공간 안에서 다룬다.
- 정확한 패키지 아트워크는 제품 면에 맞는 원근·시점·스케일로 적용한다. 광원·반사·접촉 그림자·가림·깊이를 장면과 맞춰야 하며, 정면 packshot이 손 앞에 뜨거나 경계가 분리된 평면 컷아웃처럼 읽히면 실패다. 작은 라벨 문구를 모델이 새로 그리도록 강요하지 말고 승인된 아트워크를 통합한다.
- 제품을 집거나 열거나 떨어뜨리거나 도포하는 행위는 패널에서 손-제품 접촉과 물리적 상태 변화를 읽을 수 있어야 한다. 화살표·캡션·모션 블러만으로 정지 참조 이미지를 동작 장면이라고 간주하지 않는다. 정적 hero/packshot은 콘티가 의도한 `hold` 비트에서만 사용한다.

실제 clean 이미지 QA에서 각 동작 비트의 증거 panel ID를 기록한다. 캡션을 숨겨도 행위와 제품의 공간적 통합이 보이는지, 인접 keyframe이 요구된 before→after 상태 변화를 실제 픽셀에서 보여주는지 검사한다. 실패한 panel은 프롬프트/스테이징을 고쳐 재생성하거나 물리 통합을 다시 합성하고, 전체 순서의 정체성·연속성을 다시 검사한다.


## 9. Craft 근거와 적용 한계

§2–3의 축·가독성·구도 점검과 §6의 수정 절차 중 일부는 아래 READ-PARTIAL 구간의 craft guidance에 근거한다. 정확한 rendition 지문과 범위는 [자료 근거 원장](sources.md)의 “스토리보드 craft 추가 직접 대조” 절에 있다. 인용 시 자료 ID, 저자/짧은 제목, locator를 원장과 일치시킨다. 서로 다른 ID의 locator를 합쳐 하나의 인용으로 제시하지 않는다.

| 계약 범위 | 직접 근거 | 적용 한계 |
