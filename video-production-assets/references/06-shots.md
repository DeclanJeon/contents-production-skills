# 블로킹·촬영·스토리보드

## 입력과 산출물
입력: 각본, 룩, 장소, 인원·장비

산출물: 샷 리스트, 블로킹, 스토리보드 설명, 커버리지

## 실행 절차
1. 장면의 정보 공개 순서와 인물의 힘 관계를 먼저 정한다. 인물 위치·이동·시선·행동 축을 기록한다.
2. 각 샷에 보는 대상과 관객이 새로 알 정보, 감정 목적을 붙인다. 멋진 움직임만 있는 샷은 삭제하거나 동기를 부여한다.
3. 와이드·싱글·투샷·리액션·인서트 중 장면에 필요한 커버리지만 선택한다. 대사를 전부 정면 교차 편집으로 해결하지 않는다.
4. 이동은 시작 위치·끝 위치·속도·동기·종료 프레임을 정의한다. 인물 움직임과 카메라 움직임을 별도 항목으로 쓴다.
5. 시선·화면 방향·180도 축·행동 매치를 검수한다. 축을 넘으면 중립 샷·연속 이동·새 공간 설명 등 관객을 재정위시키는 수단을 명시한다.
6. 편집 핸들, 룸톤, 소품 인서트와 반응 샷을 확보한다. 장소·광원·세팅으로 촬영 순서를 묶고 이야기 순서와 구분한다.
7. 스토리보드가 텍스트 설명뿐이면 이미지가 완성됐다고 말하지 않는다. 실제 그림/프리비즈가 있으면 카메라와 블로킹을 비교한다.

## 완료 조건
각 샷에 이유가 있는가? 편집 가능한 커버리지와 방향성이 확보됐는가?

## 근거와 적용 범위
자료 ID: 04,05,06,07,08. `sources.md`에서 파일 상태와 탐색 위치를 확인한다. 절차와 템플릿은 여러 자료의 개념을 결합한 독자 설계다. 저자의 규칙을 그대로 재현한 요약이나 공식 인증된 방법론으로 표현하지 않는다.

## 출력 템플릿
`assets/06-shots-template.md`를 복사해 채운다.

## 실제 패널 인계
스토리보드가 요청되면 `assets/storyboard-panels.csv`로 panel_id와 shot_id를 연결한다. 이미지가 생성됐으면 실제 image_asset_id를 원장에 등록한다. 텍스트 패널만 있으면 drawing_pending 상태를 표시한다.

## 전문 스킬 인계
`$camera-spatial-design`으로 위치·거리·렌즈·각도·구도·전 프레임 경로를 수치화한다. 실제 3D 비교는 `$blender-previsualization`으로 수행한다. camera_spec.json의 로컬 프레임을 기존 샷의 start_s/end_s와 연결하고 total duration을 대조한다.
