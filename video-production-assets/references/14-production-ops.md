# 제작 일정·예산·에셋 운영

## 실행 절차
1. 필요한 역할·장소·장비·참조 파일·촬영/생성/편집 단계를 명시한다. 제작 방식에 없는 부서나 절차는 N/A로 둔다.
2. 장소·조명 세팅을 기준으로 촬영 순서를 묶고 장면·샷 ID를 연결한다. 세팅·리허설·촬영·이동·정리 시간을 분리한다.
3. 비용은 수량×단가, 통화, 확정/견적/추정, 출처로 기록한다. AI 생성은 요청당 비용·예상 재시도·상한·중단 기준을 적는다. 실제 요금이 필요하면 현재 공급자 정보로 확인한다.
4. 필요한 실제 파일은 asset_registry에 등록한다. 계획 에셋은 경로를 null로 두고 상태 planned로 기록한다. 장소·소품·인물·룩 참조의 버전과 사용 샷을 연결한다.
5. 파일명은 project_id/shot_id/version/take를 포함하고 원본·선택 테이크·편집본을 구분한다. 파일 교체 시 원장을 갱신하고 기존 선택 버전을 보존한다.
6. 실제 사용하는 음악·사진·폰트·인물 등의 이용 가능 범위와 출처를 기록한다. 없는 자료에 불필요한 승인 절차를 만들지 않는다. 현장 위험 작업은 실제 제작 책임자의 준비 사항에 포함한다.
7. 입력 버전이 바뀐 산출물과 그 종속 산출물을 stale로 표시한다. 실패한 샷은 단순 반복 대신 조치·한도·대체 샷을 결정한다.

## 프리프로덕션 준비 추적 (영화 라이프사이클)

영화·단편 라이프사이클 요청에서 03 Pre-production의 준비 상태는 이 템플릿의 준비 표로 추적한다. 각 항목에 **적용 여부(적용 / N/A+사유 / 미확인), 책임 담당(owner), 근거 위치(locator), 의존 입력·blocker, 해당 산출물 버전**을 기록한다. 체크를 채우는 것은 준비 상태의 추적이며 법률·보험·안전 승인 선언이 아니다 — 허가·계약·보험·위험평가는 실제 책임자 확인과 근거 문서가 있을 때만 `확인됨`으로 기록하고, 없으면 미확인/blocker로 둔다. 이 스킬이 법적·안전 판정을 내리거나 대체하지 않는다.

## 실제 촬영 기록 (실사 프로덕션)

실사 촬영이 있는 영화 작업은 날마다 `assets/film-production-day-template.md`를 복사해 실제 관찰 결과만 기록한다.

- 이 양식은 버전이 붙은 artifact/인계 문서이며 `project.json`, `asset_registry`, `generation_attempts`, `continuity-ledger.csv`를 대체하는 두 번째 정본이 아니다. 실제 미디어 파일은 `asset_registry`에 등록하고 이 양식은 그 ID/버전을 참조한다.
- **관찰되지 않은 값은 채우지 않는다.** 테이크·카메라/오디오 기술 값·백업 결과·검토 선택은 실제로 보고 확인한 것만 쓰고, 미확인은 unverified로 둔다. 누락된 현장 자료를 만들어내지 않는다.
- 실제 촬영 순서는 이야기 순서·계획 촬영 순서와 별도로 날짜·순번으로 기록한다.
- 관측된 연속성 상태의 정본은 `continuity-ledger.csv`이며 그 열 의미로만 기록한다. 일지 양식은 정본 행을 참조하고 해당 날짜의 대조 판정(일치/의도된 변화/불일치/미검증)·issue 연결만 남기는 검토 뷰다. 의도된 변화는 원인·승인된 연출 의도를 적고, 설명 없는 불일치는 미해결 이슈로 남긴다([상태·인과·연속성](26-state-causality-continuity.md)의 판정 규칙 적용).
- 촬영 없는 애니메이션·AI 작업은 이 양식 전체를 `N/A`로 두고 기존 `generation_attempts`·생성 QA([21](21-generated-video-qa-retry.md))로 실제 결과를 추적한다.

무거운 실행 작업의 동시성은 워커/에이전트 동시성과 별도로 관리한다. 선택한 워크플로에서 실제 사용하는 자원 풀(예: 공급자 작업, GPU 추론, 브라우저 캡처, CPU 인코딩)만 구분하고, 각 상한은 검증한 실행기 제약과 실측한 장비 용량으로 정한다. 다른 프로젝트의 과거 수치를 그대로 가져오지 않는다. 가능하면 작업별 출력을 격리한다. 완료 전 임시/부분 파일을 납품물로 승격하지 말고, 작업 완료 후 디코딩 가능 여부와 의도한 작업 결과인지 확인해 원장에 등록한다. 재개 시 파일 존재만 보지 말고 실행 상태와 미디어 무결성을 확인한다. 기존 시도 이력과 에셋 원장을 사용하며 별도 큐나 프로젝트 원장을 만들지 않는다.
