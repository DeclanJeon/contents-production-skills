# 애니메이션 연기·타이밍

## 입력과 산출물
입력: 인물 모델, 연기 비트, 샷, fps

산출물: 포즈 계획, 타이밍·스페이싱, 애니매틱 지시

## 실행 절차
1. 인물 비율·실루엣·관절 범위·무게·소품 접촉을 고정한다. 표정 이름보다 생각과 목표가 읽히는 포즈를 설계한다.
2. 핵심 포즈를 실루엣으로 확인하고 행동선·무게중심·시선 방향을 기록한다. 모든 신체 부위를 동시에 움직이지 않는다.
3. 준비→주 행동→오버슈트/정착을 구분한다. 과장 정도는 스타일과 장면 목표에 맞추며 모든 동작에 큰 예비동작을 강제하지 않는다.
4. 타이밍은 포즈 사이 프레임 수, 스페이싱은 프레임마다 위치 변화로 구분한다. 정지·가속·감속·호의 근거를 적는다. 이동 카메라와 맞춰야 하면 샷 로컬 시간/FPS basis와 동작 phase를 공유한다.
5. 발 접지·손 소품 접촉·체중 이동·후속 동작을 검수한다. 걷기/정지가 핵심이면 발 plant·체중 이동이 읽힐 구간과 화면 내 증거를 기록하고, 발이 가려지거나 프레임 밖이면 접촉은 미확인으로 두고 제한을 인계한다. 모든 샷에 발 접촉 증거나 프레임 내 발을 강제하지 않는다. 립싱크는 실제 음성이 확보된 후 음소와 중요한 발화 강세에 맞춘다.
6. 애니매틱으로 감정·길이·화면 가독성을 확인한 후 세부 동작으로 진행한다. AI 생성에서는 프레임 제어 가능성을 확인하고 불가능하면 행동 구간으로 표현한다.

## 모션 그래픽 표면(애프터 이펙트 등)

타이포그래피·UI·도해를 다루는 모션 디자인은 위의 인물 애니메이션 절차와 다른 규칙을 쓴다. 한 샷에 둘을 섞으면 레이어 소유자를 먼저 나눈다(인물 연기 vs 그래픽 요소). After Effects가 이 시스템에 없으면 같은 개념(컴포지션·레이어·키프레임·렌더)을 가진 EffectCraft로 진행할 수 있다 — 매핑과 조건은 [선택 라우팅의 데스크톱 앱 폴백](../../creative-production/references/production-routing-optional.md#desktop-app-fallback-artcraft)을 따른다. 어떤 앱이 실제로 돌았는지 결과에 명시하고 AEP와 동일하다고 주장하지 않는다.

| 표면 | 필요한 것 | 흔한 실패 |
|---|---|---|
| 일러스트 애니메이션 | 요소별 이동/회전/스케일 궤적, 색 보존, 편집 가능한 도형 레이어 | 한 덩어리로 전체를 밀어 개별 움직임이 사라짐 |
| 종이 콜라주 | 시차용 레이어 분리(전경/중경/배경), 스텝(홀드) 모션, 리깅 | 모든 레이어를 같은 속도로 이동해 평면처럼 보임 |
| SaaS/제품 UI | 실제 앱 화면·브랜드 자산, 화면 전환, 타이포 등장 타이밍, 로고 리빌 | 없는 화면을 상상해 만들거나 텍스트를 폰트 이미지로 굽기 |
| 프레젠테이션 | 슬라이드 위계 보존, 텍스트/이미지 등장 시점, 음악 비트 동기 | 슬라이드 순서·위계를 재해석해 내용을 바꿈 |
| 화이트보드 | 커서 이동 경로, 스티키 노트/화살표 순차 등장, 손그림 주석 | 주석과 본문이 동시에 떠서 시선이 분산됨 |
| 텍스트 현지화 모션 | 언어별 텍스트 리플로우·자간·줄바꿈, 동일 타이밍 유지 | 번역문이 프레임을 넘치거나 자막이 겹침 |

규칙:
1. **타이밍 기준을 하나 정한다**: 음악 비트, 내레이션 큐, 또는 샷 로컬 프레임. 세 기준을 섞지 않는다.
2. **레이어/키프레임 편집 가능성**을 유지한다. 텍스트·도형·화면 요소는 나중에 수정할 수 있어야 한다(렌더된 이미지로 굽지 않는다).
3. **텍스트 안전 영역**과 최소 읽기 시간을 지킨다. 모션 속도로 읽기를 희생하지 않는다.
4. **현지화 버전**은 레이아웃·타이밍·애니메이션을 보존하고 텍스트·타이포만 조정한다. 언어별로 읽기 시간과 글리프 렌더링을 다시 검사한다(15의 자막/납품 검사와 연결).
5. 생성 이미지가 필요한 콜라주·일러스트 소스는 패키지의 승인된 이미지 실행자로 만든다. 데스크톱 앱 작업 자체는 납품·게시 승인이 아니다.
