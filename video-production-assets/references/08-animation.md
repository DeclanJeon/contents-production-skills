# 애니메이션 연기·타이밍

## 입력과 산출물
입력: 인물 모델, 연기 비트, 샷, fps

산출물: 포즈 계획, 타이밍·스페이싱, 애니매틱 지시

## 공통 시각 연출 — 필요한 표현만

시각적 비교 기준, 자극 이후 힘의 변화, 여러 몸/소품의 행동 소속과 접촉이 중요하면 [공통 시각 연출](visual-scene-communication.md)의 액션·연기 절을 적용한다. 기존 포즈·접촉·스페이싱 칸을 쓰며 정지 그림의 잔상/동세를 실제 속도·프레임 수로 측정했다고 하지 않는다.

몸 구조/부상에 맞는 수행이나 주의 전환 뒤의 지지·물체 결과가 핵심이면 [비인간 몸](performance-and-style-recipes.md#nonhuman-performance)·[행동 중단](performance-and-style-recipes.md#interrupted-action)의 선택 예시를 기존 포즈/접촉 칸에 쓴다. 가림으로 전이를 생략하는 안과 실제 연속 변형 시연이 필요한 안은 구분한다.

코드 렌더 쇼릴·제품 UI 데모·과정 설명이면 [코드 기반 모션 제작](08b-code-motion-production.md)을 연다. 타이밍만 필요한 일반 작업에 새 런타임을 요구하지 않는다.

모션 원칙·키프레임·로고 모션·색 움직임·콘티→모션이 필요하면 [모션 크래프트](08a-motion-craft.md), 모션 스타일을 고르면 [모션 스타일 사전](33-motion-style-library.md) 색인부터 연다.

## 실행 절차
1. 인물 비율·실루엣·관절 범위·무게·소품 접촉을 고정한다. 표정 이름보다 생각과 목표가 읽히는 포즈를 설계한다.
2. 핵심 포즈를 실루엣으로 확인하고 행동선·무게중심·시선 방향을 기록한다. 모든 신체 부위를 동시에 움직이지 않는다.
3. 준비→주 행동→오버슈트/정착을 구분한다. 과장 정도는 스타일과 장면 목표에 맞추며 모든 동작에 큰 예비동작을 강제하지 않는다.
4. 타이밍은 포즈 사이 프레임 수, 스페이싱은 프레임마다 위치 변화로 구분한다. 정지·가속·감속·호의 근거를 적는다. 이동 카메라와 맞춰야 하면 샷 로컬 시간/FPS basis와 동작 phase를 공유한다.
5. 발 접지·손 소품 접촉·체중 이동·후속 동작을 검수한다. 걷기/정지가 핵심이면 발 plant·체중 이동이 읽힐 구간과 화면 내 증거를 기록하고, 발이 가려지거나 프레임 밖이면 접촉은 미확인으로 두고 제한을 인계한다. 모든 샷에 발 접촉 증거나 프레임 내 발을 강제하지 않는다. 립싱크는 실제 음성이 확보된 후 음소와 중요한 발화 강세에 맞춘다.
6. 애니매틱으로 감정·길이·화면 가독성을 확인한 후 세부 동작으로 진행한다. AI 생성에서는 프레임 제어 가능성을 확인하고 불가능하면 행동 구간으로 표현한다.

반복 동작/시네마그래프가 요청되면 주기의 시작과 끝에 포즈뿐 아니라 이동 방향·속도·동작 phase·카메라/광원 상태를 대응시킨다. 실제 반복 출력과 음향 접합 검수는 [09의 루프 검사](09-edit.md#요청된-루프의-끝시작-검수)에 연결한다. 일반 샷에 순환 동작이나 끝 상태의 초기화를 강제하지 않는다.

## 모션 그래픽 표면(애프터 이펙트 등)

타이포그래피·UI·도해를 다루는 모션 디자인은 위의 인물 애니메이션 절차와 다른 규칙을 쓴다. 한 샷에 둘을 섞으면 레이어 소유자를 먼저 나눈다(인물 연기 vs 그래픽 요소). After Effects가 이 시스템에 없으면 같은 개념(컴포지션·레이어·키프레임·렌더)을 가진 EffectCraft로 진행할 수 있다 — 매핑과 조건은 [선택 라우팅의 데스크톱 앱 폴백](../../creative-production/references/production-routing-optional.md#desktop-app-fallback-artcraft)을 따른다. 어떤 앱이 실제로 돌았는지 결과에 명시하고 AEP와 동일하다고 주장하지 않는다.

| 표면 | 필요한 것 | 흔한 실패 |
|---|---|---|
| 일러스트 애니메이션 | 요소별 이동/회전/스케일 궤적, 색 보존, 편집 가능한 도형 레이어 | 한 덩어리로 전체를 밀어 개별 움직임이 사라짐 |

| SaaS/제품 UI | 실제 앱 화면·브랜드 자산, 화면 전환, 타이포 등장 타이밍, 로고 리빌 | 없는 화면을 상상해 만들거나 텍스트를 폰트 이미지로 굽기 |
| 프레젠테이션 | 슬라이드 위계 보존, 텍스트/이미지 등장 시점, 음악 비트 동기 | 슬라이드 순서·위계를 재해석해 내용을 바꿈 |
| 화이트보드 | 커서 이동 경로, 스티키 노트/화살표 순차 등장, 손그림 주석 | 주석과 본문이 동시에 떠서 시선이 분산됨 |
| 텍스트 현지화 모션 | 언어별 텍스트 리플로우·자간·줄바꿈, 동일 타이밍 유지 | 번역문이 프레임을 넘치거나 자막이 겹침 |

규칙:
1. **타이밍 기준을 하나 정한다**: 음악 비트, 내레이션 큐, 또는 샷 로컬 프레임. 세 기준을 섞지 않는다.
2. **레이어/키프레임 편집 가능성**을 유지한다. 텍스트·도형·화면 요소는 나중에 수정할 수 있어야 한다(렌더된 이미지로 굽지 않는다).
3. **텍스트 안전 영역**과 최소 읽기 시간을 지킨다. 모션 속도로 읽기를 희생하지 않는다.
4. **현지화 버전**은 레이아웃·타이밍·애니메이션을 보존하고 텍스트·타이포만 조정한다. 언어별로 읽기 시간과 글리프 렌더링을 다시 검사한다(15의 자막/납품 검사와 연결).
5. 생성 이미지가 필요한 콜라주·일러스트 소스는 패키지의 승인된 이미지 실행자로 만든다. 데스크톱 앱 작업 자체는 납품·게시 승인이 아니다.

## 정지 키프레임(Key Panel)의 역동적 포즈·스피드 설계

스토리보드 정지 이미지(`start / action_peak / end`)에 동작의 읽힘이 필요할 때만 아래 단서를 선택한다. 인간형의 과장 액션 예시이며 얼굴 없는/비인간 대상·절제된 움직임·의도적 정지에 강제하지 않는다. 기존 역할/필드와 승인된 적용 가능한 strict 프로젝트 제약은 유지하되 사유 있는 대체 큐/N/A를 허용한다.

- **동세선(Line of Action)과 비대칭 실루엣**: 강한 C/S자 곡선이나 비대칭을 선택할 수 있다. 달리기·도약·추격의 **25–45도 기울기**는 특정 과장 포즈의 후보이지 고정 각도나 모든 `action_peak`의 조건이 아니다. 실제 형태·지지·접촉과 장면 목적을 우선한다.
- **예비 동작(Anticipation) → 극단 정점(Extreme/Impact) → 오버슈트(Overshoot/Settle)**:
  - `start`: 에너지를 압축해 몸을 웅크리거나 시선이 목표에 먼저 꽂히는 순간.
  - `action_peak`: 신체가 가장 크게 뻗어 나오거나(포어쇼트닝) 충돌·방향 전환으로 물리적 변형(옷자락·머리카락의 관성 지연, 지면 먼지·스파크)이 극대화된 순간.
  - `end`: 동작 에너지가 빠져나가며 관성에 의해 한 반발 더 밀렸다가 정착(Settle)하는 여운의 순간.

### 모션 자체의 속도·타격 기법

포즈 사이 간격을 채우는 선택지다. 기존 열(`포즈/행동`, `시작 프레임`, `끝 프레임(미포함)`, `스페이싱`, `보조 동작`, `접촉 잠금`)로 적으며 새 열을 만들지 않는다. 필요한 동작에만 쓰고 모든 동작에 같은 폭으로 강제하지 않는다.

| 기법 | 선택 조건 | 실패 조건·실제 검수 | 기존 08 칸 |
|---|---|---|---|
| Easing(가속·감속 곡선) | 무게·마찰·추진력이 구간마다 다르게 읽혀야 함 | 전 구간 등속으로 무게 소실, 접촉 직전 감속 없음; 프레임 간 위치 차이 대조 | `스페이싱`, `시작/끝 프레임` |
| 예비 동작 → 오버슈트 → 정착 | 강한 동작의 힘과 여운이 사건에 필요(위 정지 키프레임 절과 같은 계열) | 모든 동작에 큰 예비 동작, 방향 전환마다 동일 폭 오버슈트; 실제 재생 | `포즈/행동`, `시작/끝 프레임` |
| Follow through(후속 동작) | 몸통·주체가 멈춘 뒤 머리카락·옷·팔·소품이 뒤따라 멈춤으로 무게가 읽힘 | 정지 프레임에서 모든 부위가 동시에 멈춤, 다음 컷에서 관성 초기화; 재생 확인 | `보조 동작`, `스페이싱`, `끝 프레임` |
| Smear frame(잔상·늘어남) | 1~2프레임 안에 통과해 정상 포즈로는 속도가 읽히지 않음 | 여러 프레임에 지속되어 형태 오류처럼 보임; 영향 프레임 지속시간 확인 | `시작/끝 프레임`, `스페이싱`, `보조 동작` |
| Hit stop / hit pause | 충돌·타격의 접촉 프레임이 있고 관객이 그 순간을 인지해야 함 | 정지가 접촉 전후 상태를 바꾸거나 접촉이 안 읽힘; 접촉 프레임과 정지 길이를 실제 프레임으로 확인 | `시작/끝 프레임`, `접촉 잠금`, 09 컷 이유 |

프레임 단위 정지·잔상은 실행자가 프레임을 통제할 때만 계획이다. 생성 모델이 지원하지 않으면 행동 구간으로 요청하고 결과 프레임에서 확인한다. 정지 이미지 한 장의 잔상·속도선은 그 프레임의 양식 단서일 뿐 실제 hit stop·smear·이동 속도의 증거가 아니다. 타임라인 쪽 속도 조작은 [속도·타격 표현 선택표](edit-sound-language-catalog.md#속도타격-표현-선택표)가 정본이다.

### 스페이싱 산슬 예 (선택)

평면을 미끄러지는 단단한 소품 하나가 0.25초에 90단위를 이동한다고 가정하면, 제안 24 FPS에서 노출 프레임은 `0.25 × 24 = 6`개이고 `f=6`은 끝 경계(추가 노출 프레임 아님)다. `x = 90(3u²−2u³)`, `u = f/6`로 계산한 프레임별 delta 합은 90이 된다. 이것은 **1차원 산슬 예시**이며 무게·마찰·발 미끄러짐·카메라·실제 영상 생성은 검증하지 않는다(모두 NOT_RUN). 인물 동작에는 예비·접촉·무게중심·후속 동작을 별도로 설계한다.
