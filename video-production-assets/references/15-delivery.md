# 자막·접근성·출력·납품

## 실행 절차
1. 실제 납품 목적지의 화면비·해상도·프레임레이트·코덱/컨테이너·오디오·파일 크기 조건을 확인해 delivery_spec에 기록한다. 플랫폼 규격을 고정된 상수로 재사용하지 않는다.
2. 오디오 의도를 기록한다: 무음은 no_audio, 대사 없음은 no_dialogue, 일반 음성은 dialogue. no_dialogue에는 음악·효과가 있을 수 있고 no_audio에는 실제 오디오 큐를 넣지 않는다. 효과음만 요청에는 음악·말을 추가하지 않고, 음악 제외는 음악 레이어만 비운다. 세부 의도 분류와 endpoint 지원 확인은 [편집](09-edit.md)의 오디오 의도 절차를 따른다.
3. 자막은 최종 음성과 맞추고 시작/끝 시간·줄 나눔·화자·의미에 필요한 소리를 검수한다. 타이밍은 최종 음성·파일에서 실제 측정한다; 최종 음성이 없으면 원고 기반 타이밍을 임시(provisional)로 표시하고 동기화를 미검증으로 둔다. 번역본은 인명·단위·고유명사·화자를 원문과 대조하고 운문은 행 구분·리듬·승인된 각색을 구분한다. 원문 의미를 지우는 윤문으로 대체하지 않는다.
4. caption_mode를 none/sidecar/burned_in으로 정하고 외부 자막 파일과 영상 내 자막을 구분한다. 하드 자막을 크롭·재배치·가림·번역 자막으로 보존/대체할지는 먼저 실제 문구·가독성·타이밍·원본 자막의 추출 가능성을 확인해 결정한다. 미검사 상태에서는 보존·대체를 확정하지 말고 조건부 선택지와 필요한 검사를 제시한다. 소스 미디어를 세로형 짧은 영상으로 각색하면 [소스 자막·세로 프레이밍](../../creative-production/references/marketing-source-adaptation.md#4-source-media-adaptation-shortform-vertical)도 적용한다. 자막·CTA가 작은 화면과 목적지 UI에 가려지는지는 실제 미리보기에서 확인한다.
5. 색과 텍스트만으로 필수 정보를 전달하지 않는지, 대사 명료도·자막 대비·읽기 시간·시각 정보 설명의 필요성을 확인한다. 해당 없는 검사는 N/A와 이유를 남긴다.
6. 계획 단계는 --profile plan, 실제 파일 납품 직전은 --profile delivery로 검사한다. 납품 검사는 파일 존재·해시·원장 상태를 확인하며 영상 디코딩·청취·미관 평가를 대신하지 않는다.
7. 실제 재생·측정·청취 결과를 delivery_checks에 적고 blocker가 열린 상태로 납품 완료를 선언하지 않는다. 검사 도구가 없으면 해당 항목은 unverified로 남긴다. 계획 패키지는 미디어 파일 없이 완료할 수 있다.

## 입력·산출물
확정 브리프와 해당 제작 원장을 입력받고 아래 템플릿을 채워 인계한다.

## 자막 파일과 타이밍

요청된 형식(SRT 등)으로 만들고 각 항목이 start<end, 시간 순서, 유효한 길이와 겹침 규칙을 만족하는지 요청한 규격·읽기 기준·실제 렌더로 검수한다. 읽기 속도·줄 수·줄 길이·화자 표기는 브리프와 목적지 기준으로 판단하고 고정 상수를 발명하지 않는다. 원고의 글자 수나 띄어쓰기만으로 발화 시각을 역산해 프레임 정확 동기인 것처럼 만들지 않는다. 최종 음성이 바뀌면 그 음성에 종속된 자막 타이밍·립싱크만 재동기화 대상으로 표시하고 확인 전에 동기화 통과로 보고하지 않는다.

## 근거와 한계
09·12의 편집/검수 원칙에 연결한 현대 제작 운영 확장. 목적지 규격은 첨부 서적에서 확인한 고정값이 아니다.

## 영화 배급·패키지 기록 (라이프사이클 요청 시)

영화·단편의 배급 단계([28](28-film-production-lifecycle.md)의 06)가 배정됐을 때 `assets/film-distribution-template.md`를 사용한다. 납품만 요청된 작업에는 이 양식을 강제하지 않고 위 절차와 `delivery_spec`/`delivery_checks`만으로 좁게 처리한다.

배급은 네 가지를 항상 분리한다: **계획 작업 ≠ 실제 에셋 ≠ 실제 제출/공개 ≠ 관객 반응.** 마케팅 계획을 만드는 것만으로 해당 파일·출품·개시·피드백이 존재한다고 취급하지 않는다.

- **홍보·납품 에셋**(키아트/포스터, 티저/트레일러, EPK): 실제 파일이 존재할 때만 버전·SHA-256과 함께 `asset_registry`에 등록하고 원본 마스터 버전을 연결한다. 계획된 에셋은 `path=null`의 planned 상태로 두고 완성된 매체로 취급하지 않는다. 제작 계획 문서를 실제 포스터·트레일러로 표시하지 않는다.
- **목적지 전략**: 극장·OTT·온라인 등 목적지별로 `delivery_spec` 항목을 분리해 둔다. 각 규격(해상도·컨테이너·코덱·오디오·자막·패키징)은 사용 시점에 공식 문서나 사용자 제공 원본에서 확인해 근거·확인 일자를 남긴다. 규격을 기억이나 다른 프로젝트에서 재사용하지 않고, 확인되지 않은 규격은 unverified로 둔다. DCP·ProRes 마스터 같은 목적지 전용 산출물은 실제 요청·확인된 경우에만 계획한다 — 모든 영화 패키지에 DCP를 강제하지 않는다.
- **권리·라이선스 범위**: 음악·초상·소스 등 배급 관련 권리는 항목별 출처·확인 상태·사용 범위(매체·지역·기간)·제한·근거 locator를 기록한다. 기록 자체를 허가로 해석하지 않고, 근거가 없는 항목은 unverified로 남긴다. 권리 미확인 상태에서 배급 가능·사용 승인을 주장하지 않는다.
- **영화제 제출**: 자격·마감·규정은 실제 공식/사용자 제공 원본에서 확인해 근거·확인 일자와 함께 적고, 확인되지 않으면 unverified로 둔다 — 영화제 규칙을 기억으로 작성하지 않는다. 계획된 출품·접수 완료·실제 결과(선정·탈락·상영)를 구분하고, 스킬이 자동으로 출품하지 않는다.
- **공개 후 피드백**: 공개일·방식·실제 관객 반응(유지율·리뷰·코멘트)을 근거와 확인 일자로 기록한다. 없는 수치를 추정·발명하지 않고, 해석은 관측된 데이터와 분리한다. 계획된 공개를 실제 개시로 세지 않는다.

열린 blocker(권리 미확인, 규격 미확인, 미제출)가 있는 상태에서 배급 완료를 선언하지 않는다.
