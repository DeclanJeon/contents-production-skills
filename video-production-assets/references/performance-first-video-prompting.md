# 연기 중심 영상 프롬프트 — 장면·샷·발화 계약

적용: 표정·시선·호흡·청자 반응이 서사를 진행하거나, 화면 안팎의 대사가 컷을 넘거나, 사용자 요청에 동시 생성 대사와 립싱크가 포함된 영상. 일반 몽타주·무성 영상·제품 루프에 이 양식을 강제하지 않는다. [11 인계](11-ai-handoff.md)의 SSOT와 실행 게이트, [22 대사·립싱크](22-dialogue-lipsync.md)의 보이스 규칙은 그대로다. 이 참조는 설계 절차이며 생성 기능이나 성공을 보장하지 않는다.

## 1. 공통 고정 → 샷별 변화 → AUDIO

- **GLOBAL:** 장소·시대·팔레트·광원, 인물별 ID와 변하지 않는 얼굴·연령·머리·의상·목소리, 상대 위치와 거리, 목표 화면비·러닝타임·촬영 질감. 고정 항목과 의도적으로 바뀌는 항목을 분리한다. 두 사람 사이의 180° 축, 카메라를 두는 반평면, 화면 좌/우와 각자의 시선 방향을 잠근다. 화면 밖 위치도 표에 남긴다. 독립 생성이면 공통 고정을 각 호출에 동일하게 직렬화하고, 승인 참조를 지원하는 슬롯에 실제로 등록한다.
- **SHOT:** `shot_id | 편집 [in,out) | 샷 크기·광학 의도·고정/무빙 | 연기 비트 | 발화/반응·시선 | 종료 상태·컷 트리거`. 한 롱테이크 안의 여러 감정 비트는 필요할 때만 구간을 나눠 적고 임의 편집 컷으로 바꾸지 않는다. 리버스 샷은 같은 축·시선·광원에 묶는다. 렌즈 수치나 필름 표현은 도구가 직접 제어할 수 없는 경우 시각 목표이지 보장 사양이 아니다.
- **PERFORMANCE:** 비트마다 `자극 → 내적 목적 변화 → 눈에 보이는 1–2개 반응 → 다음 상태`. 예: 반박하려다 상대의 한 단어에서 멈춤 → 상대를 보던 눈이 내려가고 한 번 삼킴 → 대사 없이 헤아리는 상태. 눈·입·호흡·손 중 핵심을 우선한다. AU 번호는 선택적인 사람용 메모이며 모델 제어값처럼 쓰지 않는다. 제출문에는 관찰 가능한 표정 언어로 쓴다. 모든 줄에 눈물·고함·강한 움직임을 중첩하지 않는다.
- **AUDIO:** `line_id | 화자 | 발화 언어·정확한 문장 | 시작·종료/말 걸림 | 억양·쉼·호흡 | 화면 안/밖 | 청자`. 화면에서 말을 안 하는 사람은 입 모양과 음성을 빼고 반응만 적는다. 목소리는 인물별로 구별하되 실제 배우를 음성·외형 목표로 삼지 않는다. 환경음·공간감·음악/무음·자막 생성 금지는 명시적 선택이며 전 장르 기본값으로 삼지 않는다.
- **경계:** 대사가 컷을 건너면 발화 ID·목소리·공간음 하나가 이어진다. 이번 샷의 화면 밖 화자가 다음 샷에서 보이면 전후 음절 경계를 표시한다. 실제 편집에서는 채택한 음성 구간을 J/L컷으로 연결해 중복·단절을 막는다. 같은 문장을 양쪽 샷에 통째로 새 발화시키지 않는다. [연속성 게이트](26-state-causality-continuity.md#storyline-continuity-gate)를 사용하고 화면 밖 상태를 리셋하지 않는다.

## 2. 프롬프트를 보내기 전에 시간·지원 충돌부터 해결

1. 편집 시간과 공급자가 생성하는 길이를 분리한다. 모든 [in,out)이 겹침·빈틈 없이 목표 길이를 채우는지 확인하고, 실제 발화 언어로 의도한 강도와 호흡을 살려 읽어 계측한다. 영어는 예비 진단으로 말할 시간(할당 − 호흡 − 리액션 홀드)과 분당 단어 수를 산출할 수 있지만 획일적 합격 기준으로 쓰지 않는다.
2. 예를 들어 18단어를 3.7초에 넣으면 쉼 없이도 약 292 WPM이다. 1초 마지막 컷에 0.3초 홀드가 있고 5단어가 들어가면 숨을 빼기 전에도 약 429 WPM이다. 이런 경우 `TIMING_CONFLICT`를 적고, 의미·화자·총 길이 중 잠긴 항목을 확인한다. 대사와 총 길이가 잠겼으면 내부 재배치안을 제시한다(가능하면 발화 시작을 앞 컷으로 옮겨 오디오를 이어 붙인다). 불가능하면 총 길이 변경 또는 대사 수정의 선택지를 제시한다. 대사를 말없이 자르거나 강제 배속으로 숨과 감정을 희생하지 않는다.
3. 선택한 모델/호출 표면에서 **네이티브 대사 오디오**, 복수 화자, 최대 길이, 화면비, 참조 입력, 멀티샷/시간 지시의 실제 지원을 확인한다. 미확인은 `UNKNOWN`, 미지원은 `UNSUPPORTED`. 예: 20:9를 지원하지 않으면 21:9로 조용히 교체하지 않는다. 지원 소스에서 최종 20:9로 만드는 크롭, 화면의 시선·입·구도 보존 등을 명시하고 조건이나 제작 범위를 바꾸는 경우 기존 승인 경로를 따른다. 실제 출력 FPS와 24fps처럼 보이는 촬영 질감도 구분한다.
4. 생성 단위는 검증된 지원에 맞춰 고른다. 한 호출에서 긴 대사/여러 샷을 지원한다는 근거가 없으면, 보드 샷이나 발화 비트의 경계에서 분리하고 컷 핸들·승인된 인물/음성 앵커·연속 환경음을 이어준다. 요청이 네이티브 동시 대사라면 무음 + TTS를 몰래 대체하지 않는다. 무음 스틸/CLI 검사로 립싱크를 통과시키지 않는다.

## 3. 원본이 아닌 재사용 예시

가상의 새 장면: 두 동료가 폐업한 수선집 열쇠를 누가 보관할지 결정한다. 고정된 창가 조명. A는 화면 왼쪽에서 오른쪽, B는 오른쪽에서 왼쪽을 본다. A가 조용히 질문한다. B는 곧바로 답하지 않고 마른 입술을 한 번 눌렀다가 시선을 손의 열쇠로 옮긴다. 다음 샷에서는 A의 입이 보이지 않고 질문의 마지막 음절만 화면 왼쪽에서 이어진다. B의 호흡이 가라앉은 뒤 열쇠를 상대에게 건네고 컷을 끝낸다. 비정본 샘플(8초, 낭독 검증 전): S01 [0.0,2.6) A 근접, L01이 1.1초에 시작. S02 [2.6,5.8) B 어깨너머, L01은 화면 왼쪽에서 3.1초까지 이어지며 B는 침묵. 3.1–4.0초 숨/시선, L02는 4.0–5.4초. S03 [5.8,8.0) 열쇠를 건네는 손, 새 발화 없음. 오디오 행: L01 A (1.1–3.1) “Do you want the key?” / L02 B (4.0–5.4) “No. You keep it.” 실제 제출 전에 낭독 시간을 확인하고 편집 시간 또는 말을 조정한다. 기존 작품의 인물·배우·대사·장면을 복제하거나 참고 원문을 공개 예시로 배포하지 않는다.

## 4. 실제 납품 전 증거

[생성 QA](21-generated-video-qa-retry.md#대사-반응과-보드-타임라인-대조)의 정속 영상+청취, 무음 반응, 의심 구간 스텝 검사, 음성만 듣기를 사용한다. ① 실제 들리는 문장·화자·발화 언어, ② 보이는 입과 목소리·묵음 청자, ③ 감정 전환 순서와 과장 유무, ④ 축·시선·정체성·조명, ⑤ 컷 경계의 마지막 음절/호흡/환경음과 지정된 마지막 홀드를 기존 shot/line ID 및 타임코드에 기록한다. 소리가 들린다고 네이티브 발화나 립싱크 통과라는 뜻은 아니다. 화자 혼선·대사 절단·순서 역전·얼굴/축 드리프트는 `needs_revision`; 관측하지 못한 품질은 `unverified`. 실패한 변수 하나만 좁혀 재시도하고, 증거와 승인 범위는 기존 계약을 유지한다.
