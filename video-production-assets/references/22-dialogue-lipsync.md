# 대사 연기·립싱크 (온디맨드 심화)

모듈 04(연기 디렉팅), 08(애니메이션), 09(편집·사운드)의 심화. 인물이 말하거나·인터뷰·논쟁·농담·속삭임·내레이션·노래하듯 말하기·입 동기화·듣는 행동이 필요할 때 연다.

## 원칙

연기는 의도에서 세우고 입은 그 다음에 동기화한다.

## 캐릭터 설계 인계

기존 캐릭터 `character_sheet` SSOT·`voice_profile`이 공급되거나 프로젝트에서 배정된 제작 인계라면 발화/대사 작업 전에 해당 최신 설계를 읽는다. 단독 대사·립싱크·연기 큐 요청은 공급된 대사·승인 보이스·요청 범위만 사용하며, 미공급 캐릭터 시트나 전체 페르소나를 새로 만드는 단계로 확대하지 않는다. 인계 패킷은 적용되는 다음 항목을 식별한다:

- **버전 고정:** 공급/배정된 `character_sheet` artifact ID·버전과 `voice_profile` ID·버전. 단독 작업의 미배정 ID/버전은 미배정으로 두고 발명하거나 시트 제작을 강제하지 않는다. 참조가 있는 경우 오래된 핀은 현재 실행용으로 쓰지 않는다 — 조용히 현재 버전으로 갱신하지 말고 재검토 요구로 반환한다.
- **`voice_identity_direction`:** 모든 발화에 그대로 재사용하는 고정 음성 정체성 한 줄 — 청각 앵커·발음·문장 끝 습관·기본 리듬과 허용 변화 범위. 각 대사의 `performance_cue`(의도·서브텍스트·숨·강세·멈춤)와 분리해 유지한다.
- **유지 vs 변화:** 압박·신뢰 등 상태 변주는 고정 음색·발음 앵커를 유지한 채 연기 매개변수만 바꾼다 — 새 보이스가 아니다.
- **지원 제어 확인:** 현재 음성 도구가 지시문·감정·속도·참조 음성 등 어떤 제어를 실제 지원하는지 확인하고, 지원하지 않는 요구는 적용했다고 주장하지 않고 요구 간극(unsupported control gap)으로 기록·반환한다.

설계 단계의 `proposed`/`unresolved` 보이스 상태는 선택된 보이스로 취급하지 않는다 — 실제 voice ID·모델·설정은 아래 선택·청취 절차의 기록에서만 생긴다. 권리·동의·승인 상태와 보이스 연속성(same ID·설정만으로 보장되지 않음 — 실제 청취 검수 필요)은 기존 절차 그대로 유지한다.

**변경 영향 구분:** 실제 보이스 선택/오디오만 바뀌면 실제 의존 그래프를 따라 그 음성에 종속된 캡션·립싱크·타이밍 산출물을 stale로 표시하고 독립 이미지·스토리 승인은 유지한다. `character_sheet` SSOT 자체의 버전이 바뀌면 `voice_profile`뿐 아니라 그 이전 버전에 실제 의존하는 모든 산출물이 재검토 대상이다. 섹션별 부분 무효화가 구현됐다고 주장하거나 음성 관련 절만 수정했다는 이유로 같은 SSOT에 의존하는 이미지의 승인을 자동 보존하지 않는다.

## 절차

1. 대사마다 목적·서브텍스트·감정 압력·관계/지위·대사 중 무엇이 변하는지 정한다.
2. 연기 타이밍을 표시한다: 숨·픽업·강조·가속·망설임·멈춤·끼어들기·중첩·해소.
3. 가능하면 정밀 립싱크 전에 최종에 가까운 음성을 먼저 생성/녹음한다. 플레이스홀더 타이밍에 애니메이션하고 나중에 정확한 싱크를 기대하지 않는다. 보이스 선택·생성·청취는 "보이스 선택과 청취" 절차를 따른다.
4. 강세 음절과 중요한 입 닫힘/열린 모음을 표시한다. 모든 음소를 기계적으로 과다 조형하기보다 강조 단어의 지각적 싱크를 우선한다.
5. 듣는 사람을 디렉팅한다: 눈 이동·숨·미세 반응·지연 응답·적절한 신체 정지. 대화는 번갈아 움직이는 입이 아니다.
6. 코미디는 셋업/펀치 간격과 반응 창을 지키고, 드라마는 침묵과 듣기를 지킨다.
7. 컷을 가로질러 목소리 정체성·억양/언어·연령·에너지·마이크 원근·실내 음향을 유지한다.
8. QA: 오디오-입 오프셋·얼어붙은 청자·과도한 입 움직임·반복되는 일반 제스처·빠진 숨·부자연스러운 끼어들기·불일치 룸톤.

## 대사 주석 최소 필드

문자 그대로의 텍스트 · 의도 · 서브텍스트 · 핵심/강조 단어 · 앞뒤 숨/멈춤 · 청자 반응 · 신체 행동. `assets/performance-cue-template.md`의 표를 쓴다. 제작용 스토리보드 인계 시 각 발화는 대사(dialogue) 또는 내레이션(narration)으로 종류를 분리하고, 화자 캐릭터 ID, 선택된 보이스 프로필/artifact ID, 립싱크 적용/비적용과 그 이유, 연기 방향을 함께 넘긴다. 화면 밖 발화는 립싱크 not_applicable과 그 이유를 기록한다.

실제 음성이 생성·확정되기 전의 시간은 추정이다: 텍스트 분량과 연기 지도로 추정 범위를 계산하고 `estimated`로 표시하며, 실제 측정은 생성된 오디오를 들은 뒤에만 한다. 추정치를 실측으로 기록하거나 대사 시간을 근거 없이 단언하지 않는다.

무대사·무음 또는 사용자가 지정한 무오디오는 존중한다: 무대사라고 내레이션이 자동 추가되지 않고, no_audio/no_dialogue는 발화 배열이 비어 있는 유효한 선택이다. 침묵을 표현 수단으로 쓰는 경우에도 "침묵" 자체를 큐로 명시할 뿐 대사를 발명하지 않는다.

## 립싱크 우선순위

정확한 타이밍은 단단한 폐쇄음과 두드러진 강세 음절에서 가장 중요하다. 자연스러운 턱/볼 움직임을 유지하고 말을 입술만으로 취급하지 않는다. 오디오 편집을 먼저 맞추고 그 다음 입 애니메이션/생성을 맞춘다.

## 보이스 선택과 청취

선택 전에 실제 사용 가능한 음성 도구/실행자를 확인한다: 현재 보이스 목록, 지원 언어와 발음 지시 수단, 속도·톤·감정 등 지원하는 표현 제어, 권리/동의 요건, 비용. 확인 시점과 근거를 남기고 존재한다고 가정한 보이스·제어·제공자를 쓰지 않는다. 특정 보이스 제공자나 복제(cloning)를 기본값이나 필수로 요구하지 않는다; 실제 선택은 현재 가용성·요구·승인으로 정한다.

사용자가 음성 실행자·보이스·정체성을 지정했으면 그대로 유지하고 조용히 대체하지 않는다. 미지정이면 요청한 언어·톤·연기 방향에 맞춰 실제 가용 보이스 후보를 비교하고, 실제 샘플 청취가 필요한 최종 선택은 범위가 한정된 오디션 승인으로 얻는다. 복제·커스텀 보이스는 요청됐을 때만 다루며 실제 권리/동의 근거를 먼저 확인한다.

선택한 보이스는 실제 voice ID·타입·모델·버전·적용 설정을 버전이 있는 연결 artifact(성능 큐나 편집 산출물)에 기록하고, 정체성/권리 근거도 같은 곳에 둔다. 실제 생성·비용은 해당 승인 범위 안에서만 한다. 요청된 복제·커스텀 보이스가 실제로 불가능하면 자동으로 다른 보이스로 대체하지 않고, 현재 가용 후보의 샘플 청취·승인 절차로 되돌아간다.

편집·립싱크에 넘기기 전에 실제 생성 음성을 끝까지 듣고 텍스트 정확성·발음·숨·속도·톤·컷 간 정체성 일관성을 검수한다. 듣지 않은 음성은 미검증으로 인계한다. 확정된 음성이 바뀌면 그 음성에 종속된 캡션·립싱크·타이밍 산출물만 stale로 표시하고 영향 없는 단계의 승인은 유지한다(계약의 버전 변경 규칙).

## 광고·내레이션 보이스 브리프와 생성 QA

광고·내레이션에는 한 번의 **잘 준비된** 첫 테이크를 목표로 간결한 voice brief를 만든다. 한 번의 시도는 목표·승인된 횟수이지 품질 보증이 아니다. 카피 작성/러닝타임 배분은 [03 각본·내레이션](03-screenplay.md), 연기 의도는 [04 연기 디렉팅](04-performance.md), 음악·효과·믹스와 `audio_cues`는 [09 편집·사운드](09-edit.md)의 소유다. 이 참조는 그 입력을 보이스 실행과 QA에 연결할 뿐 카피·큐 스키마·원장·enum을 새로 만들지 않는다. 필요할 때 `assets/performance-cue-template.md`의 간결한 보이스 브리프를 쓴다.

### 생성 전 — 승인과 실행 가능성

브리프에는 요청에 필요한 값만 채우고 모르는 값은 미정으로 둔다. 실제 입력:

- 승인된 정확한 한국어 발화문·버전, 대상 청중, 전달 기능과 짧은 음성 품질 기준을 잠근다(예: 자연스러운 한국어 연결, 명료도, 피할 기계적 박자). 문구 수정은 03으로 돌려 승인된 카피를 갱신한다.
- 요청/근거로 확인한 한국어·원하는 억양/방언과 고른 실제 보이스의 적합성 근거를 구분한다. 모델의 한국어 지원 표기만으로 특정 억양·발음·보이스 품질을 입증하지 않는다. 최종 후보는 대상 한국어 카피와 위험어를 실제로 포함한 승인 샘플을 들어 확인한다.
- 같은 `voice_identity_direction`의 청각 앵커와 허용 변주를 고정하고 짧고 행동 가능한 연기 아크를 둔다. 구간별 목적/전환, 속도, 숨·멈춤 위치와 예상 길이, 강조 단어를 표시한다. 목표 러닝타임과 구간/쉼 시간은 생성 전 모두 `estimated`다; 속도·강조는 의도한 큐이지 실측이나 보장이 아니다.
- 이름·브랜드·외래어·숫자 등 위험 발음은 정확한 단어, 승인된 발음, 영향 구간과 확인된 교정 방법을 함께 적는다. 철자/풀어 쓴 수 표기 등 카피 수정은 03 승인을 거친다. IPA·태그·속도·감정 등은 현재 실행자/모델이 지원한다고 확인된 수단에만 연결한다; 미지원 제어는 요구 간극으로 남긴다.
- 필요한 공급자·모델·보이스·언어/억양 근거, 적용 가능한 제어, 비용, 승인된 생성 횟수/상한을 실행 시점에 확인한다. 한 번만 승인한 테이크는 첫 생성만 제출하며, 간결한 브리프도 결과 품질을 보장하지 않는다.
- 09에 보이스의 믹스 우선순위와 BGM/SFX의 상대 관계를 인계한다. 편집/믹스는 09의 소유자이며 음악으로 연기 결함을 숨기지 않는다.

질문 전 기존 프로젝트/SSOT·09의 큐와 선택된 live endpoint의 읽기 전용 조회/견적으로 확인 가능한 보이스 ID·제어·비용·믹스 사실을 먼저 확인한다. 사용자에게는 이 근거들로 해결할 수 없는 창작 선택이나 카피·발음·비용·시도 승인을 가장 작고 구체적인 한 요청으로 묶어 묻는다; 조회 가능한 사실을 사용자 clarification으로 되돌리지 않는다.

승인 카피, 위험 발음, 보이스 적합성/지원 제어, 비용 또는 시도 승인 중 하나라도 미해결이면, 채워진 듯한 실행용 공급자 payload나 ready-to-run 지시를 반환하지 않는다. 대신 확인된 사항과 미해결 사항을 구분해 보고하고, 필요한 항목 하나를 해결할 최소한의 구체적 clarification/approval만 요청한다. 공급자 필드명·제어·실행 인자를 추정해 채우지 않는다.

**Eleven v4를 실제 선택한 경우에만 적용.** 일반 [ElevenLabs TTS 가이드](https://elevenlabs.io/docs/eleven-creative/playground/text-to-speech)는 목표 언어로 학습된 보이스 사용을 권하며, 보이스 선택이 음색·억양·케이던스에 큰 영향을 준다고 설명한다. 별도로 [Eleven v4 모델 문서](https://elevenlabs.io/docs/overview/capabilities/text-to-speech/eleven-v4)는 생성 언어가 참조 보이스의 언어와 다를 때 원래 억양을 보존하기보다 목표 언어의 유창하고 자연스러운 출력을 지향한다고 설명한다. 이는 일반 보이스 선택 권고와 v4의 교차 언어 동작 설명이며, 둘 다 특정 선택 보이스의 한국어 locale·방언·브랜드 발음 역량을 입증하거나 보장하지 않는다. 실제 보이스·요청된 한국어 억양·위험어를 함께 담은 승인 샘플 청취가 적합성 기준이다.

[v4 모델 문서](https://elevenlabs.io/docs/overview/capabilities/text-to-speech/eleven-v4)는 Style/Speed 슬라이더와 SSML 미지원을 명시한다. [v4 프롬프팅 가이드](https://elevenlabs.io/docs/overview/capabilities/text-to-speech/best-practices#prompting-eleven-v4)는 태그 순응이 완전하지 않다고 경고한다. 짧은 태그는 필요한 곳에만 두고, 쉼/속도감은 지원되는 구두점·문장/줄바꿈·태그로만 지시한다; Speed 제어와 `<break>`를 가정하지 않는다.


생성/미리보기는 비용이 들 수 있다([TTS 플레이그라운드](https://elevenlabs.io/docs/eleven-creative/playground/text-to-speech)). [무료 재생성 규칙](https://elevenlabs.io/docs/help-center/account/general/do-i-use-quota-on-every-generation)은 웹 UI 전용이며, 같은 텍스트·보이스·모델을 유지(보이스 설정값 조절만 허용)하고 첫 생성 후 2시간 안에 같은 페이지에서 재생성할 때만 적용된다. 페이지를 새로고침하거나 이탈하면 자격이 사라진다. 현재 UI의 자격과 잔여 횟수를 확인하지 않으면 무료로 가정하지 않는다.

v4 태그는 문맥에 맞는 보컬 전달 방향용이며 위험어 발음 교정을 대신하지 않는다. IPA는 [ElevenLabs 발음 가이드](https://elevenlabs.io/docs/overview/capabilities/text-to-speech/best-practices)가 설명하는 v4 지원을 실제 선택한 실행 경로에서 확인했을 때만 위험어에 선택적으로 쓰고, 실제 결과를 청취한다. 특히 비영어 발음은 지원을 확인하지 않은 채 IPA를 가정하지 않는다.

### 생성 후 — 듣기·최소 교정·재검수

각 이미 승인된 생성 결과를 실제로 검수한다. 결과 ID/버전과 대상 텍스트를 고정하고 (1) 전체 보이스 단독 청취로 정확한 문구·위험어 발음·숨·자연스러움·속도·톤·정체성 앵커·연기 아크를 대조하고, (2) 최종 믹스/장면 맥락에서 다시 들어 명료도와 BGM/SFX 마스킹·균형을 확인한다. 앞·뒤나 일부 표본만 들었다면 들은 범위만 기록하고 나머지는 미검증이다.

문제는 `timecode/단어 → 근거(직접 청취 / 사용자 제공 관찰 / 도구 출력 / 추론) → 관객 영향 → 최소 수정 → 같은 기준의 재검수`로 적는다 ([12 제작 QA](12-qa.md)). 직접 들을 수 없으면 사용자가 “기계적”이라고 한 것은 귀속된 사용자 보고로만 기록하고 주관적 음성 품질은 미검증으로 둔다. 파형·codec·ASR 결과는 실제 확인한 좁은 항목(예: clipping, 무음, 텍스트 일치)만 뒷받침할 수 있으며, 자연스러움·억양·연기·믹스 청취를 대신하거나 전체 voice pass를 만들지 않는다.

수정은 들린 결함의 원인에 맞춰 한 가지 주요 변수를 바꾸고 성공한 특성을 유지한다:

| 관찰된 결함 | 최소 교정 |
|---|---|
| 승인 문구·숫자 불일치 | 03에서 표기/문구를 승인 교정하고, 수정 원고를 기준으로 다시 생성·대조한다. |
| 위험어·이름·방언 오발음 | 해당 보이스의 적합성 근거를 재확인한 뒤 확인된 발음 제어를 적용하거나 03에서 표기를 승인 교정한다. |
| 정체성 앵커 이탈 | 입력 SSOT/승인 보이스 핀을 재확인하고, 잘못 고른 보이스라면 대체를 제안해 승인받는다. |
| 기계적 박자·단조로움·빠진 강조/쉼 | 보이스 적합성이 맞으면 문제 구간의 아크/단어 큐 또는 실제 지원되는 성능 제어만 조정한다; 보이스가 기준에 맞지 않으면 교체를 제안하고 승인받는다. |
| 보이스 단독은 적합하나 믹스에서 묻힘 | 생성 음성은 유지하고 09의 BGM/SFX 레벨·ducking·배치를 조정한다. |

원인을 구분할 수 없으면 크게 재작성하지 말고 미해결/미검증으로 기록한다. 미지원 조절값을 꾸며내지 않는다. 수정한 오디오는 단독 및 최종 믹스에서 같은 수락 기준으로 다시 듣는다.

새 테이크는 기존 비용·재시도 상한 및 실행 승인 안에서만 제출하며 [21 생성 매체 QA·재시도](21-generated-video-qa-retry.md)의 시도 기록, 한 번에 한 변수, 성공 속성 보존 규칙을 재사용한다. 무료 재시도를 가정하거나 한도를 넘지 않는다. 승인된 시도가 없거나 상한에 닿으면 멈추고 현재 버전을 `needs_revision` 또는 실제로 듣지 못한 항목은 `unverified`로 반환한다; 새 예산/시도는 별도 승인을 받아야 한다. 반복 시도 후에도 판단은 [12](12-qa.md)의 `pass` / `pass_with_notes` / `needs_revision`와 검사 범위를 사용하며, 주요 오디오가 미검증이면 pass가 아니다.
