# 외부 분해 백엔드 어댑터 (선택)

[레퍼런스 영상 분해](25-reference-video-analysis.md)의 **선택적 측정 백엔드**다. 새 스킬·새 원장·새 승인 경로가 아니며, 25의 크래프트 절차와 증거 등급 체계를 대체하지 않는다. 25는 도구가 없어도 그대로 성립하고, 이 문서는 측정값을 얻을 수 있을 때만 25의 관찰 칸을 더 채워 주는 입력이다.

## 적용 조건

| 조건 | 처리 |
|---|---|
| 사용자가 로컬 영상 파일/폴더를 주고 컷·제작방식·자막·음원·복제 경로 측정을 요청 | 이 어댑터 적용 가능 |
| 사용자가 링크만 줌 | 영상을 먼저 로컬에 준비하도록 요청한다. 이 어댑터는 링크 다운로드를 하지 않는다 |
| 컷 경계 후보만 필요 | [컷 전용 경로](#컷-경계만-필요한-경우)를 먼저 확인한다. `rea-video`는 필수가 아니다 |
| 전체 분해에서 rea-video CLI 미설치 | **자동 설치하지 않는다.** 25 수작업 경로로 폴백하고, 부재 사실과 설치 방법만 보고한다 |
| 상업적 재사용·대본형 드라마 역복원 목적 | 이 어댑터 범위 밖이다. 시리즈 대본 분해는 별도 선택 사항이며 이 문서가 승인하지 않는다 |

## 전체 분해 절차 (rea-video)

0. `rea-video --help`로 존재를 확인한다. 없으면 중단하고 25 수작업 경로로 돌아간다.
1. `rea-video memory`로 사용자 선호(기본 엔진·VLM 사용 여부)와 이전 정정 유형을 확인한다.
2. 분해 실행. `--lang`은 `zh|en`만 지원한다.
   - 한국어·기타 언어 소스: `--lang en`으로 실행하고, **사용자 응답은 사용자 언어로 쓴다.** 한국어 리포트 파일이 필요하면 `report.md`를 번역해 `report_ko.md`로 두고 `report.html`은 영어임을 밝힌다.
   - 한국어 소스는 OCR·음성이 별도 언어다: `--ocr-lang ko`, `--asr-lang ko`.
   - VLM 설정이 없으면 `--vlm`·`--env-file`을 빼고 실행한다. 이 경우 `made` 판정은 더 약해지므로 3단계 검수가 필수다.
3. `rea-video summary <out>/breakdown.json`을 읽고 **`VLM:` 줄을 반드시 확인**한다. `failed`/`not_configured`면 VLM이 실제로 안 돈 것이므로 그 사실을 보고서에 적는다.
4. `rea-video review <out>` → 에이전트가 이미지를 직접 보고 `review_answers.json` 작성 → `rea-video apply-review <out> --by <이름>` → `summary` 재실행. **이 단계 없이 도구 출력만으로 결론을 내지 않는다.**
5. 읽기 순서를 지킨다: `VIDEO.md`(카드+지도) → `video/timeline.md` → 필요한 주제 파일(`cast`/`look`/`sound`/`packaging`/`remake`) → 특정 컷 검증 시 `video/shots/NN.md`. **`breakdown.json` 전문을 읽지 않는다.**

## 컷 경계만 필요한 경우

사용 권한이 확인된 로컬 영상에서 컷 경계 후보만 필요할 때, 이미 사용 가능한 [PySceneDetect](https://github.com/Breakthrough/PySceneDetect)를 선택할 수 있다. OCR·전사·제작방식·음원 분리가 포함된 전체 분해의 대체물이 아니다. CLI가 실제로 있는지 확인하고, 없으면 자동 설치하지 않는다. 수작업 경로로 돌아가며 확인하지 못한 경계는 미확인으로 둔다.

검출 시각·설정·소스 버전을 기존 컷 후보 기록에 남긴다. 결과는 `DETECTOR_CANDIDATE`이며, 경계 양쪽 원본 프레임을 직접 보아 실제 하드 컷을 확인해야 `SH###`로 승격한다. 플래시·급격한 카메라 이동·디졸브는 하드 컷과 구분한다. 검출 시각을 원본 프레임 PTS나 전체 분해 결과로 표기하지 않는다.

## 신뢰도 승격·강등 규칙 (핵심)

도구 출력을 그대로 `OBSERVED`로 쓰지 않는다. `assets/shot-dna-template.md`의 상태 열에 다음으로 매핑한다.

| rea-video 표현 | Shot-DNA 상태 | 이유 |
|---|---|---|
| 컷 검출·ffprobe·좌표 측정 | `DETECTOR_CANDIDATE` | 검출 점수·프레임 차이는 경계 검증이 아니다 |
| `VIDEO.md` 무표시 필드 | `DETECTOR_CANDIDATE` | VLM 판독도 직접 관찰이 아니다 |
| 물결표 필드(`made~`, `material~`) | `ESTIMATED` | 도구가 스스로 추론으로 표시한 값 |
| 에이전트가 프레임/파형을 직접 확인 | `OBSERVED` | locator(`requested_s`/`source_pts_s`)를 함께 기록 |
| 확인 못 함·범위 밖 | `UNKNOWN` | |

- `SH###`(확정 하드 컷)은 **경계 양쪽을 직접 확인**했을 때만 부여한다.
- 컷 시각은 도구가 준 초 단위 값이며 `source_pts_s`와 같지 않다. 측정 컷 시각을 PTS로 적지 않는다.
- 알려진 오차: 플랫폼 트랜스코딩 후 오프라인 분류는 실사 영상 상당 부분을 AI로 오판한다. 결정론적으로 앵커링된 효과음 후보는 실제 효과음 비율이 낮다. 둘 다 4단계 검수 대상이다.
- 음원: `stems/`(인물·음악) 청취 없이 "들었다"고 쓰지 않는다. 스트림 메타데이터는 청취가 아니다.

## 필드 매핑 (`VIDEO.md` → Shot-DNA)

| rea-video | Shot-DNA 필드 | 비고 |
|---|---|---|
| `video/timeline.md` `seen`·`act` | 피사체·행동 시작/정점/끝 | 관찰 아님 → `DETECTOR_CANDIDATE` |
| `camera` + `look`(실사만) | 프레이밍·카메라 무빙 | 각도·자립/삼각 여부는 `ESTIMATED` |
| `look` 그레이드 · AI/3D 화면의 광묘사 | 빛·색 | AI/3D는 "촬영안"이 아니라 생성 프롬프트용임을 명시 |
| 컷·전환·컷 리듬 | 컷·전환·리듬 | `SH###`는 2단계 검수 후 |
| `sound` + `stems/` | 오디오 큐·동기 기준점 | stem 청취 전 `UNKNOWN` |
| `story.role`/`point` | 기능 | **해석**으로 표기, 관찰 칸에 넣지 않는다 |
| `flag` · `confidence` | 관찰/추정·연속성·난이도 | 그대로 승계 |
| `source.sha256` | 소스 표 "검사한 버전/구간" | provenance |

## 경계

- 도구의 `report.html`/`report.md`는 **산출물이 아니다.** 사용자가 그 리포트를 명시적으로 요청했을 때만 그 파일을 전달한다.
- 새 `project.json`·타임라인·두 번째 승인 원장을 만들지 않는다. 실제 프로젝트 쓰기는 조정자와 단일 기록자 계약을 따른다.
- `rea-video remake`, `remake-run`, `drive` 등 **유료 생성 호출은 이 문서가 승인하지 않는다.** 별도 실행·과금 승인이 필요하다.
- 복제 금지 요소(캐릭터·브랜드·특정 디자인·대사·음악)는 25의 재사용 규칙을 그대로 적용한다. 도구가 복제 경로를 제안해도 보호 표현을 새 브리프 요소로 옮기지 않는다.
- 도구 출력의 "왜 떴는가"류 서사 해석은 관객 데이터가 아니다. 성과·완주율 판단으로 확장하지 않는다.
