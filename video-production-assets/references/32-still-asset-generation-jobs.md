# 스틸 에셋 일괄 생성 — 목록·의존 순서·병렬 상한

S07에서 정한 에셋과 시작/끝 프레임을 실제 이미지로 만드는 단계다. 기본 실행자는 `codex-imagen`이며([생성 경로·비용 라우팅](24-production-execution.md)), 이 문서는 **무엇을 빠짐없이 만들고 어떤 순서로 돌리며, 실패·중단을 어떻게 남기는지**를 정한다. 정본은 기존 `project.json`의 `asset_registry`이고 새 원장·새 상태 파일을 만들지 않는다. `status: available`은 파일이 있다는 뜻일 뿐 에셋 QA 잠금(`verified`)이 아니다.

## 1. 필수 에셋 목록

스토리가 반복해서 쓰는 정체성은 한 번만 마스터로 만들고, 장면별 차이는 파생으로 둔다([v5.1 무결성](contract.md#v51-프로덕션-무결성-look에셋-게이트계보provenance패키지)).

| 종류 | 최소 구성 | 참조 입력 | 만들지 않는 경우 |
|---|---|---|---|
| 캐릭터 정체성 시트 | 전신 정면·3/4·측면·후면 + 얼굴 정면·3/4·측면 = **7뷰 한 장** | 승인된 인물 참조·SSOT | 인물이 화면에 실제로 등장하지 않음 |
| 의상(WD) | 정면·후면·착용 전신 3면, 해당 캐릭터 7뷰를 참조 | 캐릭터 마스터 | 의상이 한 장면에서만 보이고 연속성 위험이 없음 — 그래도 그 장면 프레임에는 의상을 명시 |
| 장소 마스터 | establishing·reverse·lateral·top-down **4공간뷰**, 출입구·창·장애물·광원 앵커 | 세계관 SSOT | 사건이 그 장소에서 일어나지 않음 |
| 배경·환경 플레이트 | 인물 없는 넓은 플레이트(장소 마스터의 파생) | 장소 마스터 | 장소 마스터 한 장으로 컷을 모두 덮음 |
| 소품 | 정면·후면·측면·3/4, 상태 변형, 실제 스케일 기준 | 세계관·서사 | 연속성이 문제되지 않는 장식. 장식용 보드를 위해 만들지 않음 |
| LOOK | 프로젝트 전체 시각 문법 1장(매체·비율·팔레트·조명) | 승인된 참조 | 이미 승인된 LOOK이 현재 버전으로 잠겨 있음 |
| 컷 시작·끝 프레임 | 컷마다 정확한 상태·조명·카메라 | 해당 컷의 캐릭터 마스터 + 의상 + 장소/소품 | 컷이 존재하지 않음 |

컷 프레임의 참조는 **그 컷에 실제로 등장하는 마스터와 의상**으로 한정한다. 무관한 캐릭터·소품을 참조에 넣어 화면을 오염시키지 않는다. 반대로 그 컷에 필요한 참조가 `planned`면 프레임 작업은 대기다.

## 2. 의존 순서

```
LOOK ─┐
캐릭터 마스터 ─→ 의상 ─┐
장소 마스터 ─→ 배경 플레이트 ─┼─→ 컷 시작/끝 프레임 ─→ (영상 인계)
소품 ────────────────────────┘
```

- 한 작업의 참조가 모두 `available` 이상이 된 뒤에만 그 작업을 시작한다.
- 참조 파일은 경로가 아니라 **등록된 에셋 ID+버전+해시**로 고정한다. 같은 ID의 파일이 바뀌면 하위 작업은 `stale`이다.
- 순환 참조·자기 참조·중복 ID는 작업을 시작하지 않고 오류로 반환한다.

## 3. 병렬 실행 상한

- 실행 중인 이미지 작업은 **최대 5개**다. 5개는 프로젝트별이 아니라 그 실행 호스트 전체의 상한이며, 여러 프로젝트가 동시에 요청하면 대기한다.
- 상한은 "터미널 창을 5개 띄운다"는 뜻이 아니다. 감독 프로세스가 자식을 독립 세션으로 띄우고, 완료·실패를 회수해 다음 작업을 채운다. 감독 프로세스가 끝나면 남은 작업은 `planned`로 남고 자동 재개되지 않는다.
- `codex-imagen` 정지 이미지는 유료 견적·비용 상한 판정 대상이 아니다. 다만 **인물 사진 등 참조 전송 범위와 요청된 출력 범위**는 사용자 승인 범위 안이어야 한다. 영상·음성·다른 공급자는 기존 비용·승인 게이트를 그대로 따른다.

## 4. 실패·불명·재개

| 상황 | 처리 |
|---|---|
| 요청이 명확히 거부됨(인증·정책·입력 오류) | 그 작업만 `failed`로 기록하고 원인을 남긴다. 같은 입력으로 자동 재시도하지 않는다. |
| 타임아웃·프로세스 종료·결과 미확인 | **불명(uncertain)**으로 기록하고 자동 재제출하지 않는다. 파일이 일부 저장됐다면 실제 파일과 해시를 확인해 채택 여부를 사람이 정한다. |
| 참조가 바뀜 | 하위 작업을 `stale`로 두고 다시 승인·재생성한다. 상위 작업만 조용히 갱신하지 않는다. |
| 부분 성공 | 성공한 작업의 ID·경로·해시는 보존한다. 실패 하나 때문에 전체를 다시 만들지 않는다. |
| 감독 프로세스 중단 | 완료 영수증이 있는 작업은 재사용하고, 불명 작업은 사람 확인 전 재실행하지 않는다. |

## 5. 등록과 보고

- 각 성공 파일은 `asset_registry`의 해당 에셋에 `path`, `sha256`, 확인된 `provider`·`model`·`prompt`·`source_asset_ids`만 기록한다. 확인할 수 없는 값은 `UNKNOWN`/`NOT_EXPOSED`다.
- 같은 에셋을 다시 만들면 기존 항목을 덮어쓰지 말고 버전을 올려 새 항목으로 등록하고, 이전 버전은 계보로 남긴다.
- 보고에는 계획 수·성공·실패·불명·대기 수와 각 작업의 참조 ID를 적는다. **파일 존재와 해시는 시청·품질 검수가 아니다.** 실제 프레임 검수와 최종 사용자 수락은 별도다.
- 최종·납품 게이트는 `available`이 아니라 `verified`를 요구한다([asset_gate](contract.md#v51-프로덕션-무결성-look에셋-게이트계보provenance패키지)).

## 6. CineForge 인계(선택)

CineForge CLI가 단계를 감독하면 다음 파일이 이 계약의 투영이다. 스킬은 이 파일들을 정본으로 삼지 않고, 인계 패킷을 받아 실제 생성을 수행한 뒤 결과를 돌려준다.

| 파일 | 내용 |
|---|---|
| `assets/image_prompts.json` | `prompt_id`, `kind`(character_sheet·wardrobe·location_spatial_sheet·prop_reference·start_frame·end_frame), `refs`, `view_ids`, `negative`, `params`, `ssot_versions` |
| `assets/supplied_images.json` | 사용자가 이미 제공한 파일의 `prompt_id → 상대경로` |
| `assets/image_outputs.json` | 성공한 `prompt_id → 상대경로` |
| `assets/asset_registry.json` | 위 파일의 `path`·`sha256`·`status` 반영 |
| `assets/image_jobs/` | 작업별 불명·실패 로그(있으면) |

`--image-limit` 같은 CineForge 옵션은 **실행·참조 전송 범위** 상한이며 비용 승인이 아니다. 영상 생성 권한(`execution`)과 섞지 않는다. CineForge가 없으면 위 목록·순서·상한을 에이전트가 직접 지킨다.
