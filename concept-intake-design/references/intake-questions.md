# 인테이크 질문 — 9개 판단 요소와 선택 순서

요청문을 먼저 읽고, 이미 들어 있는 값은 다시 묻지 않는다. 판단 요소마다 `provided`(있음) · `partial`(일부) · `missing`(없음)을 판정하고, 없으면 아래 '없을 때'의 방식으로 채운다.

| # | 판단 요소 | 확인 질문 | 없을 때 | 채워지는 곳 |
|---|---|---|---|---|
| 1 | script | 대본·각본이 있나? | 기획안 확정 후 AI가 대본 작성 | 대본·스토리 SSOT |
| 2 | scenario | 시나리오(시놉시스)가 있나? | AI가 시놉시스 작성 | 기획안 |
| 3 | reference | 원하는 레퍼런스가 있나? | 콘셉트 라이브러리로 설계(레퍼런스는 구조·리듬만 참고) | 기획안 |
| 4 | plot_concept | 원하는 플롯이나 콘셉트가 있나? | 장르·소재·관계·세계관 선택 또는 추천 | 선택 |
| 5 | lead_character | 주연으로 쓰일 캐릭터가 있나? | AI가 주연 캐릭터 바이블 설계 | 캐릭터 SSOT |
| 6 | voice | 목소리(대사·내레이션)는? | 사운드 축(무성/대사/내레이션/음악/ASMR) 선택 | 선택 |
| 7 | content_concept | 만들 콘텐츠의 콘셉트는? | 형식·문화권·시대·장르·길이 선택 | 선택 |
| 8 | story_development | 스토리 전개(서사 구조)는? | 12개 서사 구조 중 선택 + 감정 곡선·후킹 | 선택 |
| 9 | direction | 영상의 연출은? | 연출 8개 하위 축 + 제작 방식 선택 | 선택 |

## 선택 순서

[concept-taxonomy.yaml](concept-taxonomy.yaml)의 `selection_order`를 따른다.

형식 → 문화권·드라마 스타일 → 시대 → 장르 → 세부 장르 → 로맨스 콘셉트 → 세계관 → 이야기 성격 → 배경 → 관계 → 서사 구조 → 연출(질감·시점·카메라·표현·편집 리듬·색감/조명·현실감·사운드) → 감정 곡선 → 비주얼 미학 → 제작 방식 → 후킹 → 길이(15/30/60/90초) → 화면비

필수 축: 형식, 장르, 서사 구조, 연출(질감·표현·사운드), 감정 곡선, 제작 방식, 길이, 화면비. 나머지는 열려 있어도 진행한다.

## 기본은 추론·제안, 물을 때만 한 번에

요청에서 합리적으로 추론할 수 있는 되돌릴 수 있는 축(플랫폼·안전영역, 톤, 길이, 구조, 스타일)은 묻지 않고 `inferred`와 한 줄 이유로 기록한 뒤 계속한다. 아래 형식은 핵심 축(주제·목적)을 전혀 추론할 수 없거나 사용자가 고르기·논의를 요청할 때("골라볼래", "같이 정하자")만 쓴다. 권리·실행·비용·게시 승인은 여기서 묻지 않고 각자의 게이트에서 묻는다.

## 꼭 물어야 할 때의 형식(예)

```
남은 선택 6개 — 번호로 답하거나 Enter(기본값), ?(추천), !(나머지 전부 맡기기)
① 서사 구조: 1 결말 선공개형 2 반전형 3 미스터리 회수형 … (추천: 결말 선공개형)
② 감정 곡선(최대 3): 1 웃음 2 공감 3 감동 … (추천: 웃음 → 공감)
③ 화면비: 1 9:16 세로 2 16:9 가로 3 1:1 4 4:5 (기본: 9:16)
…
```

- 맡긴 항목은 `sources`에 `inferred`(CLI는 `ai`)로 남긴다.
- 대사 없음 제약이 있으면 사운드 축에서 대사/내레이션 중심 선택지를 빼고 묻는다.
- 같은 질문을 두 번 하지 않는다. 이후 단계의 스킬은 이 패킷을 상속하고 다시 인터뷰하지 않는다.

## 프리셋

YAML `presets`의 A(좀비 생존 숏드라마), B(졸라맨식 풍자 코미디), C(첫사랑 단편), 1998 타임슬립 K-드라마, 60초 코미디(결말 선공개)를 출발점으로 제시할 수 있다. 사용자가 프리셋을 골랐으면 사용자가 고른 값으로, 에이전트가 제안한 프리셋이면 `inferred`로 기록한다.
